| 报告与门禁 | `review_manager::replay_recorded_routes_with` |
| Python | 仅 `RuntimeCore.execute_command("review_parity_replay")` 转发，**零数学、零表读取** |

主动退役的旧实现：

- `flashloan/src/dex/runtime/v4_offchain_parity_bridge.py`（直读管理器表 + Python 做数学）
- `scripts/arch2b_offchain_parity_replay.py`（同上）

两者现在都是**薄转发器**，并有架构守卫测试（禁止导入 `sqlite3`、
禁止出现管理器表名、禁止出现 Uniswap 数学）。

## 3. 修复的三个行为缺陷

### 3.1 池快照 TEXT 类型读取失败（严重）

`v4_exchange_pool_liquidity_snapshots` 的 `sqrt_price_x96`（256 位）与 `liquidity`（128 位）
在 SQLite 里是 **TEXT**。旧读取端当 `i64` 读，每行静默失败，失败被吞掉后
整条路由均报 "no live pool state available" —— Rust 首次实测出现
`routeCount=5925` / `comparableCount=0` / `gatePassed=true`（**错的通过**）。

修复：按文本读取后解析（十进制或 `0x` 十六进制），并加回归测试
`pool_manager::parity_state::tests::a_text_typed_snapshot_is_read_as_a_number`。

### 3.2 链上负收益的负号丢失

链上把亏损路由报成 `-0x...`（负号在进位前）。只认 `0x` 前缀的解析器会把它当成
"没有数字"，回退被当成"无收益"——抄换成了"缺少证据"，
而不是"真实的否定"。修复：先读符号再读进位。

### 3.3 负向 `stateAgeSeconds`

池状态可能比复核时间还新（本地库在复核之后被刷新过）。
负年龄会把"状态不对"误表为"状态很新"。修复：年龄截断在 0，
并用独立字段 `statePostdatesReview` 显式标记。

### 4.1 证据分类（**本轮最重要的发现**）

报告新增 `evidenceBreakdown`，按**链上收益的来源**分开计数：

| 链上收益来源 | 一致 | 偏差 | 性质 |
|---|---|---|---|
| `offline_v4_sqlite_route_snapshot` | 9 | 8 | **循环**：链上幂算也读本地 SQLite 路由快照 |
| `native_rust_contract_preview` | **0** | **10** | **独立**：链上预览 vs 链下本地算本 |
| `native_contract_rate_delta_estimate` | 0 | 2 | 估算 |

**口径裁定（强制）**：之前的 "34 match / 20 mismatch" 中那 34 条“匹配”的链上收益来源
全部是 `offline_v4_sqlite_route_snapshot`，即**链下与链上读的是同一份本地数据**，
一致是构造性的，**不是独立证据**。真正能否证链下算本的
**12 条独立对比全部偏差**。任何后续引用都必须使用 `evidenceBreakdown`。

## 5. 选择口径的变更

旧 Python 实现选出 **54 条**（最后一个扫描会话内的 3 条路由的各次尝试）；
Rust 首次实测选出 **5925 条**（会议表全部符合路由形状的记录）。

差异根因已完整追溯：旧 Python 用的是**带时间窗的临时 SQL**，不是一条可描述的规则。
本轮改为**显式、可选、可审计**的选择，并在报告里输出 `selection` 字段：

- `newestPerEvaluableRoute`（**默认**）：每条不同路由的最新一次尝试，且每个池都能在本地找到可用状态。
- `newestPerRoute`：不要求池状态完整。
- `allAttempts`：全部记录历史，用于追溯。
