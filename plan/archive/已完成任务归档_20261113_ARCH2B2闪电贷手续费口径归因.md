## 1. 任务

> **12 条独立对比逐条归因**：区分"链上预览语义差异"与"链下算本不精确"

ARCH-2b 首次实测报告 `arch2b_parity_replay_20261113_rust.json` 显示：
`deviationCount=29`，其中真正独立的对比
（`native_rust_contract_preview` + `native_contract_rate_delta_estimate`）**12 条全部偏差**，
零匹配。

本任务要求把每一条偏差归因清楚：到底是**链上预览语义与链下模拟器的差异**，
还是**链下算本本身不精确**。

---

## 2. 根因

**链下模拟器把闪电贷手续费硬编码为 5 bps，而生产链路上链上根本不收手续费。**

### 2.1 链上事实（逐笔取证，非推断）

生产路由走 `OfficialV4FlashArb` 语义，**直接向 Uniswap V4 PoolManager 借币**：

```solidity
contract.functions.runArbitrageBest(
    Web3.to_checksum_address(token_z),
    keysets,
    directionsets,
    int(amount_in_raw),
    1,                      // <- minProfit = 1 wei 的利润下限，**不是手续费**
)
```

合约结算为 `required = amountIn + minProfit`，
**Uniswap V4 PoolManager 本身不收闪电贷费**。

副本库中 12 条独立对比的链上 revert
（选择器 `0x16301234` = `ArbitrageNotProfitable(received, required)`）
逐条解码后**完全一致**：

| 字段 | 链上值 | 链下假设 | 差额 |
|---|---|---|---|
| `requiredRepay` | `1000000000000000001` | `1000500000000000000` | `500000000000000` |
| 有效手续费 | **0 bps** | **5 bps** | **恰好 5 bps** |

**17 条** `offline_v4_sqlite_route_snapshot` 的链上收益与链下算本之差，
**逐条都恰好等于** `ceil(本金 × 5 / 10000)`，无一例外。
这排除了"巧合"的可能：偏差是**确定性的手续费口径差**。

### 2.2 这是一处真实的生产缺陷

`repayAmountRaw`（链上要求偿还的金额）此前被 5 bps 虚增 **0.05%**。
链上只需偿还本金，链下却多算了费用。这会系统性地：
- 低估每条路由的可执行性；
- 在临界路由上把可盈利判成不可盈利。

## 3. 修正

### 3.1 架构（功能性任务仍全部在 Rust 管理器内）

| 职责 | 归属管理器 |
|---|---|
| 从链上结算推导有效手续费 | `review_manager::effective_flash_fee_bps` |
| 判定假设费与链上费是否一致 | `review_manager::chain_fee_matches` |
| 手续费假设偏差的独立归因 | `ParityAttribution::FlashFeeAssumption` |
| 遗留 5 bps 残差识别（历史证据） | `review_manager::legacy_fee_residual` |
| 链上利润下限（1 wei） | `review_manager::CHAIN_MIN_PROFIT_RAW` |
| 默认值（链上事实） | `review_manager::DEFAULT_FLASH_FEE_BPS = 0` |
| Python | 仅 `RuntimeCore.execute_command("review_parity_replay")` 转发，**零数学、零表读取** |

### 3.2 设计要点

**手续费不再由常量决定，而由链上自己的结算推导。**

理由：链上手续费是 **owner 可变的适配器参数**
（`setFlashSourceAdapter(kind, enabled, source, feeBps, metadataHash)`），
因此"推导"永远优于"假设"。链上结算给出
`requiredRepay = amount + fee + minProfit`，而 `minProfit` 是已知的 1 wei，
于是 `fee = requiredRepay - amount - 1` 可被精确还原。

`CHAIN_MIN_PROFIT_RAW = 1` 被单独识别为**利润下限**，
**不得**当作手续费，也**不得**当作利润。

### 3.3 Python 侧：区分"链上手续费"与"链下预检余量"

此前二者被混为一谈（同一个 `5.0` 常量）。现已拆分：

| 常量 | 含义 | 值 | 允许进入 |
|---|---|---|---|
| `CHAIN_FLASH_LOAN_FEE_BPS` | **链上真实手续费**（链上事实） | `0.0` | 链下算本净收益、链上要求偿还金额 |
| `DEFAULT_FLASH_LOAN_FEE_BPS` | **链下预检余量**（gas / 滑点 / 状态漂移门槛） | `5.0` | 提交门槛、预检余量字段 |

涉及文件：

- `flashloan/src/market/binance_market/dex_surfaces.py`
- `flashloan/src/market/binance_market/dex_surface_route_quotes.py`
- `flashloan/src/market/binance_market/dex_surface_overview.py`
- `flashloan/src/market/binance_market/dex_route_test.py`
- `flashloan/src/dex/runtime/dex_onchain_quote_evidence.py`
- `flashloan/src/dex/intent_trade/chains/robinhood/chain_test_pack.py`

**证据中显式携带的 `flashLoanFeeBps` 仍是权威值**
（它代表当时配置的适配器），只在**没有证据**时才回落到链上事实。
