# 文档完善记录 v9.7（2026-11-14）

## 1. 审查发现

1. “版本 1”在多份文档中含义分散，缺少统一的可交付范围定义。
2. 文档多次使用“候选池、推荐池、备用池、观察池”，但没有说明当前 schema 中角色来自哪些表和 manager 输出。
3. 阶段交付物列出了 JSON 和 checksum，但缺少统一的最小字段、三态结论和失败码，无法机械判断阶段是否真正退出。

## 2. 完善措施

- 新增版本 1 范围定义：允许多跳闭环，但每一跳必须 single-tick；跨 tick 接口不进入候选、复核或广播。
- 新增池角色权威源：候选来自 candidate edge/exchange 物化，推荐来自 recommendation 标记，备用来自 backup 列表，Y-Z 观察池来自 observation 表；不虚构单一角色枚举。
- 新增统一证据契约：阶段报告必须包含模式、生产写入标识、版本、row count、checksum、passed/blocked/failed、failure codes、回滚点、RPC 请求数和测试摘要。
- 新增 P0-7 和对应 checklist，将范围、角色与证据契约在实施前冻结。

## 3. 安全边界

本轮仅完善文档，没有修改业务代码，没有执行 production prune，没有写入生产数据库。
