#### 编排器动作定义

- [ ] **TASK-114** **L1 代币层自动修复**：编排器在 L1 判定失败时自动执行
      估值刷新（`token-manager value-tokens` → `land-valuations`）、
      `token-manager materialize-libraries`，或对单个坏币调用
      `POST /v1/tokens/resolve`。修复后只读复验 `layers.tokens.valid`；
      不通过则回滚该层并记录原因。
- [ ] **TASK-115** **L2 池层自动修复**：编排器自动执行
      `pool-manager ensure-depth-schema` / `materialize-scope` / `depth` / `refresh-key`
      （或 `POST /v1/pools/scopes/repair`），消除 `pool_depth_insufficient`
      与 `badReadings`；修复后只读复验 `layers.pools.valid`。
- [ ] **TASK-116** **L3 闭环层自动修复**：编排器自动执行
      `composite-manager materialize-arbitrage`（或 `POST /v1/closed-loops/rebuild`），
      确认闭环库写入 **core4 scope** 的 `pool_scope_checksum`，
      `consumers_need_rebuild` 归零，`pool_scope_drift` 消失；
      复验 `layers.closedLoops.valid`。
- [ ] **TASK-117** **L4 复核层自动收敛**：编排器循环执行
      `POST /v1/reviews/run`（携 `expectedUpstream`）、`rereview_missing_pnl`、
      `fill_missing_reviews`、`rereview_historical_positive`，
      直到**每个复核都有明确盈亏数值**；缺值**不得**以估算值或零值代替；
      收敛判据 `reviews.stats.missingValue == 0`。
- [ ] **TASK-118** **L5 广播层自动检测与修正**：编排器检测自动广播交易；
      失败尝试按分类处理——`transaction_rejected` 经
      `POST /v1/broadcasts/finalize` 终态化；`pool_state_unavailable` /
      `stale_pool_state` 退回到 L2 修复；`rpc_unavailable` 交由运行时重试；
      `no_profit` 与 `pending` **不修**。持续观察并统计套利交易盈亏。
