## 1. 施工中发现的功能缺陷（本轮的实质产出）

### 1.1 缺陷描述

`flashloan/rs-src/src/execution.rs` 的 `build_v4_flash_executor_request()`（约 529 行）在构建执行请求时
强制以下闭合性检查（约 604–610 行）：

```rust
if first_input != token
    || first_output != second_input
    || second_output != third_input
    || third_output != token
{
    return Err("reviewed executor route is not a closed three-hop token path".to_string());
}
```

而 `token` 是这样取到的（约 551 行）：

```rust
let token = route_config
    .get("token")
    .or_else(|| route_payload.get("token"))
    .and_then(Value::as_str)
    .ok_or_else(|| "reviewed executor route token is required".to_string())?
    .to_ascii_lowercase();
```

**`token` 从未被与该闭环自己的锚点交叉核对。** 这个检查是**自指的** ——
拿 `token` 和路径自己的端点比较，因此只要 `token` 与路径端点自洽，它就一定通过。

### 1.2 为什么这是功能缺陷

闭环的**容量、signed 利润、借款币种**三者**全部以锚点计价**（内核注释
`flashloan/tools/closed_loop_manager/src/lib.rs` 约 2188–2193 行：
*"The borrow token is the anchor token…"*）。锚点早已在闭环身份里 ——
`loop_key = "{anchor_address}:{y_address}:{z_address}"`（同文件约 2390 行）。

因此，一个"用 A 闭环的容量去借 B 闭环的币种"的请求在构建层不会被拦下：
**用一条闭环的额度，去开另一条闭环的仓**。

### 1.3 锚点在哪里可取

`route_config["routeAddresses"]` 是 4 元素闭合路径，**锚点 = `routeAddresses[0]`**（== `routeAddresses[3]`）。
该路径已被 `flashloan/rs-src/src/closed_loop_identity.rs` 的
`ClosedLoopCatalog::identity_for(&addresses)` 用于解析 Manager 发布的闭环身份
（`flashloan/rs-src/src/worker_pool.rs` 的 `apply_closed_loop_identity()` 在 `run_native_review` 中调用它）。

**即：锚点信息本来就在手上，只是执行请求这一层没有把它接上。**

## 2. 实现

**文件**：`flashloan/rs-src/src/worker_pool.rs`

### 2.1 `closed_loop_anchor(route_payload, route_config) -> Option<String>`

从 `routeAddresses` 取闭合路径（首元素 == 末元素），返回首元素作为锚点。

**关键设计**：锚点按**普通地址**处理。
`address(0)` 与 WETH 地址**走完全相同的代码路径**，**不新增** `isNative` / `isAddressZero` 分支。
二者本来就是**两个独立锚点、两条独立闭环**，闭环身份本身已经把它们分开了
（主网 chain 4663 实测：ETH 锚点 26 条、WETH 锚点 6 条，键完全分离）。

**未闭合路径**（首元素 != 末元素）**不是闭环**，因此**没有锚点**，函数返回 `None` ——
守卫保持沉默，而不是猜一个。

### 2.2 `anchor_binding_blocks_broadcast(route_payload, route_config, request) -> Option<String>`

请求的 `token` 必须等于**自己闭环**的锚点；不等则返回：

```
executor_request_anchor_mismatch:anchor=<anchor>:token=<token>
```

### 2.3 接入点

`eligible_executor_batch_request()` 在 `reviewed_min_amount_out()` 检查之后调用该守卫。
**fail-closed**：不等则**不出批**，不进入广播队列。

## 3. 离线回归（5 项，全部新增于 `flashloan/rs-src/src/worker_pool.rs`）

| # | 测试名 | 断言 |
|---|---|---|
| 1 | `the_executor_request_is_bound_to_the_anchor_of_its_own_loop` | ETH 锚点闭环的请求 `token` = `address(0)`；WETH 锚点闭环的请求 `token` = WETH 地址；**二者互不串用**，各自绑定自己的请求 |
| 2 | `a_request_that_borrows_another_loops_anchor_is_refused` | **借用他闭环锚点**的请求被拒，错误以 `executor_request_anchor_mismatch` 开头（该用例走**预置 `executorRequest`** 路径，正是守卫存在的意义） |
| 3 | `an_unclosed_route_has_no_anchor_to_bind` | **非闭合路径**无锚点，守卫**保持沉默**而不是猜一个 |
| 4 | `a_prebuilt_request_naming_its_own_anchor_is_accepted` | 守卫**只**拒绝外来锚点，不变成一刀切的否决 |
| 5 | `the_anchor_is_the_address_the_closed_path_starts_and_ends_at` | 锚点 = 闭合路径的首末元素 |

**测试夹具要点**（供后续维护参考）：
- 闭合 3 跳的池键形状必须是 `key0=(anchor,middle)` / `key1=(middle,third)` / `key2=(anchor,third)`，
  方向 `[true, true, false]`；否则 `build_v4_flash_executor_request` 会先以
  `"reviewed executor route is not a closed three-hop token path"` 拒绝，请求根本到不了守卫。
- 路由载荷需带 `status = "profitable_amount_found"`、`selectedAmountRaw`、`outTb`、`outTa`、`outTz`。
- `route_config` 需带 `manualBroadcast: true`（绕过 gas 门禁）、`minProfitRaw`、`hopSqrtPriceLimits`，
  以及 `poolManager`（否则 `pool_registry` 为 `None` 时会先以
  `executor_request_pool_manager_unavailable` 失败）。

## 8. 绑定性约束（重申，不得违反）

1. **ETH 与 WETH 是两个独立的资金锚点**，各闭环用各自锚点代币结算，**不互相转换、不特殊处理**。
   `address(0)` 与 WETH 地址**都是普通地址**，走**完全相同**的代码路径，
   **不新增** `isNative` / `isAddressZero` 分支，**不引入**任何包装/解包能力。
2. **不引入任何"旋转"能力**，不把"旋转命中"写成验收项、指标或测试断言。
3. **不回填历史深度/业务数据**；**不用默认零或估值掩盖缺值**；**测得零 ≠ 未测量**。
4. **Python 是纯消费者**；金额/容量/利润/闭环身份由 Rust 内核决定。
5. **链库严格隔离**：无跨链读写。
6. **真实广播需独立、明确的链/账户/限额/时间窗口授权**；没有授权**不发送**。
7. **任务编号不复用**；**下一个可用编号为 `TASK-156`**。
