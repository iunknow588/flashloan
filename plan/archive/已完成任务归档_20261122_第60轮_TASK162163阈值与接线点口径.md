## 2. `TASK-162`｜新鲜度是**两个**阈值（口径纠正）

| 阈值 | 取值 | 来源 | 判定什么 |
|---|---|---|---|
| **观测阈值** | **600s** | `TASK-143` 证据采集器常量 | 「这条复核还新不新鲜」的**读数与报告**口径 |
| **自动广播门禁** | **120s**（未来时钟偏移容差 **30s**） | **Rust 源码常量** `flashloan/tools/review_manager/src/lib.rs`<br>`MAX_AUTOMATIC_BROADCAST_REVIEW_AGE_SECONDS = 120`（源码 sha256 `8c5b31e9e4ea…a9a6d4`）<br>由 `review_is_fresh_for_automatic_broadcast()` 使用 | **「L3 广播请求能否生成」——即 L3 是否成立** |

- **`theTwoThresholdsAreNotInterchangeable = true`** —— 两者**不得混用**。
- **`theL3CriterionIsDecidedBy = "automaticBroadcastGate"`** —— **L3>0 由 120s 门禁判定，不是 600s**。
- **门禁确实被真实应用**（`theGateIsActuallyApplied`）：
  - `gateCallSiteFound = true`（`review_is_fresh_for_automatic_broadcast()` 存在并被调用）
  - `broadcastRequestPublishSiteFound = true`（`BroadcastRequestRow` 推送处，`review_manager/src/lib.rs:1623-1661`）
  - `allPreconditionsPresent = true`，4 项前置全为 true：
    ① `reviewStatusMustBeCompleted` ② `signedPnlAmountMustBePositive`
    ③ `reviewMustBeWithinTheGate`（**≤120s**）④ `hopSqrtPriceLimitsMustBeExactlyThree`（**恰好 3 跳**价格限制）
- **`theGateIsNotRelaxedByThisTask = true`** —— 本任务**只做口径分离**，**不改动任何阈值**。

> **为什么必须分离**：一条复核可以在 600s 观测窗口内是「新鲜的」，同时被 120s 门禁拒绝。
> 只报 600s 一侧会**掩盖**「广播请求根本不会生成」这一事实。

### 3.1 由此得到的两条硬结论

1. **`manager_broadcast_library_state` 为空是「结果」不是「原因」** ——

   所以「表里没有行」等价于「**从来没有广播请求**」，**不是**「开关关了」。
   （第 57 轮已得同一结论，本轮从代码路径侧**独立复核**。）
2. **接线动作在复核产出侧** —— 由**复核完成、门禁新鲜、盈亏为正**的记录
   **生成 `manager_v4_review_broadcast_requests` 行**。submit 侧只是**消费方**。
   **接线本身不广播**（属动态记录写入，需单独授权）。

## 6. `TASK-161`｜采集器**注册表读取缺陷**修正（本轮真实缺陷）

### 6.1 缺陷

`plan/runtime_evidence/tools/collect_task161_system_stability_status_20261122.py` 把注册表键路径写成
`HKLM\SYSTEM\...`（**漏掉 PSDrive 冒号**）。`Get-ItemProperty` 对这种路径**静默解析失败**，
`-ErrorAction SilentlyContinue` 又把错误吞掉，于是脚本把**实际存在**的值误报成
「not set (default)」。

### 6.2 影响与修正

| 项 | 修正前（误报） | 修正后（实测） |
|---|---|---|
| `CrashDumpEnabled` | 「not set (default)」 | **`7`** |
| `AutoReboot` | 「not set (default)」 | **`1`** |
| `MinidumpsCount` | 「not set (default)」 | **`5`** |
| `DumpLogLevel` | 「not set (default)」 | **`0`** |
| `PagingFiles` | 单行、读不出分项 | **`C:\pagefile.sys 0 0` + `E:\pagefile.sys 10240 512000`** |

修正内容：键路径改为 `HKLM:\SYSTEM\...`；新增 `read_registry_values()` 逐元素读取多值
`REG_MULTI_SZ`；`read_crash_forensics()` 改用结构化 `pagefileEntries` /
`systemDrivePagefileIsSystemManaged` / `kernelDumpPossible` / `measuredFacts`。

### 6.3 结论**未被推翻**（重要）

修正后的实测**与 v12.4 的判定完全一致**：
- **`CrashDumpEnabled` 本来就是 `7`**（自动内存转储）—— 不是「完全没有 dump 能力」；
- **`C:\pagefile.sys` 本来就是系统托管 `0 0`** —— **内核转储不可行**的原判定**成立**；
- E 盘 `10240 512000` 的页面文件**不算数**（内核转储只认系统盘）。

> **诚实边界**：本次修正**只改了测量工具的读数准确性**，
> **没有改任何门槛、没有改任何结论、没有做任何写库或状态变更**。
