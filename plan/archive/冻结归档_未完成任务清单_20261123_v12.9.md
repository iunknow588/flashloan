- 生产 apply / 广播需要授权；**禁止以历史数据回填掩盖当前计算缺陷**。
- **【排序原则 · 继承】**

  2. **性能优化最后**：性能调优类工作**一律排在全部功能性任务之后**。
  3. **耗时 / 需授权的测试靠后**：实盘广播、长时间窗口、需要写库授权的动作**排在最后**。
- **【推论 2 · 继承】授权前先取只读读数**：凡需要**写库授权**的任务，**先做完只读部分**再申请授权 ——
  只读读数**没有授权门槛**，且**能把授权范围收窄**到具体动作。**不得**在只读定位未做时就申请广播授权。
- **【推论 3 · v12.9 新增，纯结构性】**：**只读诊断已完成的，不再列为"开放任务"，改为"已确认事实"**，
  写进 §1.2 的事实台账。**开放任务表只列"还要动代码 / 还要写库 / 还要取读数"的事项。**
  理由：第 63 轮的主要浪费是把**已经测完的诊断**（L3 上游陈旧、复核陈旧）
  反复当作"待办"重新排查，而**真正缺的那一环（发布链路）反而没有立项**。

### 0.3 写库分类学（**继承 · 绑定性规则**）

> **使用者指示（2026-11-21）**：*"基础框架库要实盘写入，动态记录可以不写。"*

| 类别 | 内容 | 性质 | 处置规则 |
|---|---|---|---|
| **基础框架库**（baseline framework） | DDL / migration / 表结构 / 列 / 约束 / 索引 / 视图 | 结构性、版本化、**幂等**、**保数据**、与链上实时状态无关 | **验证通过 ⇒ 必须实盘写入目标生产库**（该链的 DB）。**不需额外授权。** |
| **动态记录**（dynamic records） | review / depth / ladder / PnL / closed loop / broadcast attempt 等测量与运行记录 | 每次运行都变；受"**实测零 ≠ 未测**"、"**不历史回填**"、"**需当前链状态**"约束 | **可以不写**；要写时按 §3 的授权流程走 |

**判定口径**：一次写入若**不改变任何测量值、只让结构与代码对齐**，就是**基础框架库**；
若**写入的是某时刻的测量结果**，就是**动态记录**。

**本版落点**：`TASK-165` 的产物是**代码**（Rust 发布链路），**不是**写库动作。
它**触发**的复核物化属于**动态记录**，按 §3 授权流程走 —— 两者**必须分开表述**，不得混为一谈。

### 0.4 记录读取归属（**继承 · 绑定性规则**）

> **使用者指示（2026-11-21）**：*"RUST 管理器工具应该提供记录的读取功能……不应该由 python 侧实现读取记录的功能，
> python 侧仅仅消费展示即可。"*

| 类别 | 谁负责 | 内容 | 纪律 |
|---|---|---|---|
| **记录的拥有与读取** | **Rust Manager** | 复核记录、广播记录、闭环目录、闭环身份、复核完整性 | Python **不得**直查 manager 拥有的表（架构守卫 `test_python_never_reads_the_manager_business_tables_directly` 已立） |
| **记录的展示与转发** | **Python**（消费侧） | 页面渲染、脚本消费、报告生成 | Python **只复制 Manager 已发布的内容**，**不重推、不重算、不补齐** |

**推论（三条，绑定性）**：

1. **不得**在 Python 侧实现任何"记录读取"逻辑（无 SQL、无 JOIN、无重算聚合）。
2. **不得**把记录信息缓存在**内存对象**里当权威；需要展示时**直接读 Manager 工具接口**。
3. Manager **未发布**某项读数时，**如实显示"未发布 / 未测量"**，**不得**由 Python 侧代为推导。
