## 二、缺陷 1（本轮新发现，**严重**）：一次探针故障会摧毁全部已知估值

### 现象（缺陷 1）

编排器首次端到端跑时，探针返回 **194 个 `api_unavailable`**
（Trading API 在本机网络不可达），而落库**照单全收**，
把库里已有的 **197 行**（162 `route_found` + 35 `no_route`）
**全部覆盖成 194 行未知**。

### 后果

估值库被清空 ⇒ 门禁读不到任何估值 ⇒
**194 只股票代币全部变成 `pending`** ⇒
**整个股票池的成员关系依据被一次网络故障抹掉**。

### 修法（缺陷 1）

`land_valuation_report()` 在写入前读取该网络/链已存的所有 verdict，
遇到**未知** verdict 且该代币已有**已知** verdict
（`route_found` / `no_route`）时**拒绝这次写入**并计入 `protected`。

语义依据：**未知不是观察**。`api_unavailable` 只说明"探针没问出结果"，
不说明"该代币有没有路径"。用一个未知覆盖一个已知，
等于**把一次传输故障变成一次经济事实的变化**。

但当该代币**本来就没有任何记录**时，未知**仍然写入**——
因为"我们试了，问不出来"和"我们从没量过"是不同陈述。

### 实测（副本库）

同一份全未知探针再落一次：

```text
=> {"written":0,"valued":0,"unvaluable":0,"unknown":194,"protected":194,"applied":true}
```

库中仍是 `route_found=162` + `no_route=35`；
门禁仍给出 `excludedStock=69` / `pending=0`；成员关系**零变化**。

### 回归测试

| 测试 | 断言 |
|---|---|
| `an_unknown_observation_never_overwrites_a_known_one` | `protected=2`、已知行**原样保留** |
| `an_unknown_observation_is_recorded_when_nothing_is_known_yet` | 无已知时未知**照写** |
| `a_real_negative_still_replaces_a_real_negative` | **真负**仍可覆盖旧观察（保护只针对未知） |

## 三、缺陷 2（本轮新发现）：批量估值全串行，端点不可达时要跑数小时

### 现象（缺陷 2） 原先**完全串行**：194 个代币 ×
（20 秒超时 × 1 + 2 次重试）⇒ 端点不可达时单次全量探针需**数小时**。
第一次跑编排器时实测 **15 分钟未完成**。

### 修法（缺陷 2）

**1. 并发化**

`value_tokens_to_usdg_batch_with_concurrency()`，默认 **8** 个工作线程。
结果按索引回收 ⇒ **输出顺序与调用方顺序严格一致**：
并发不改变报告的可比性，两次跑同一输入必须长得一样。

**2. 熔断**

连续 **3** 次**传输类**失败即打开熔断，后续代币不再发请求，
记为 `api_unavailable` + `failure_kind=Transport`，
**绝不记为 `no_route`**（"没问" ≠ "问了没有"）。

### 实测

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 194 只全量探针（端点不可达） | 数小时 | **107 秒** |
| 30 只子集（端点不可达） | 数十分钟 | **64 秒** |

熔断打开后，被跳过的代币带明确说明：
`"the valuation endpoint was unreachable; the probe stopped asking"`。

## 四、缺陷 3（本轮新发现）：编排器读不到 API Key，探针静默全空

### 现象（缺陷 3） 由环境变量提供，而 key 实际存放在
`flashloan/app_runtime/.env`。编排器**不加载**该文件 ⇒
探针对**每一个**代币返回 `api_unavailable`（`failure_kind=MissingApiKey`），
而**看起来**只是一个普通的全未知结果。

### 修法（缺陷 3）

编排器新增 `_load_env_file()` 桥接：

* 只读 `KEY=VALUE`；跳过注释与空行；支持 `export ` 前缀；
* **只填空缺、不覆盖已有环境变量** ⇒ 显式环境变量**优先于**文件；
* 文件不存在时静默跳过。

## 六、`VAL-4-11`：口径文档（`05_数据口径与统计.md` §10）

新增 **§10「经济门禁与 `capacityGate` 的边界」**，写明：

* 两者**作用对象不同**：门禁管**代币库成员关系**，
  `capacityGate` 管**单池可成交容量**；
* **关键区分**：USDG 取代的是**计价作用**，**不是深度信号**；
* `usdgPegPolicy` 的**完整** `allowedUses`（6 条）/ `forbiddenUses`（6 条）——
  禁止项包含 `depth_admission` / `capacity_admission` /
  核心 / 测试 / 扩展池成员关系 / 广播金额定量；
* **三类代币的 USDG 约束互不相同**：
  * **股票代币 = 硬约束**：不能与 USDG 兑换 ⇒ 不得进股票代币表
    ⇒ 也不会进资金池代币；
  * **核心代币 / 测试代币 = 无约束**；
  * **扩展代币 = 传递性约束**：自身不需要估值，池子要满足深度，
    USDG 关系通过股票代币或核心代币间接建立；
* **失败语义**：只有 `no_route` 是真负；未知**绝不覆盖已知**；
  **未测量 ≠ 测量为 0**。
