## 2. 已完成工程项

### 2.1 闭环复核与数值契约

- `NoProfitableRoute` 的 signed 盈亏解码、`netProductDeltaRaw` 回填和缺失原因透传已完成。
- `SwapNotResolved` 已单独保留为合约诊断，不再直接当作普通无利润结论。
- 复核输出区分具体负收益、正收益未执行确认、报价不可用和结构化失败。
- 未确认利润不进入广播；保守零仅用于明确未确认利润的展示，不作为可广播利润。
- 中间池 PoolKey 恢复已接入观察表和 `v4_exchange_pools.pool_key_json` 回退路径。

### 2.2 状态机、调度和 Rust 执行桥

- Rust worker pool、execution 组件、RPC busy/failover 和 Python 编排桥已完成工程接线。
- `execution_not_requested`、`broadcast_result_missing` 等终态已纳入状态机。
- `ClosedLoopRuntimeMetrics` 已接入状态变更和 worker 完成回调；UI 清零只清零运行计数，不回灌历史事实。
- 按链运行时、数据库路径和 Web `PageContext` 的统一入口已完成工程实现。

### 2.3 池与候选池质量工程

- 固定费率、无 hook、动态/特殊费率隔离规则已完成。
- live liquidity evidence、live thin 和旧派生 thin 的判定边界已明确。
- Rust `pool-manager` 已具备 `audit`、`cleanup`、`add-pair`、`refresh-pair`、`refresh-key` 骨架和定向测试。
- 候选池清理不直接删除闭环表，采用“上游候选变更、下游按依赖重建”的原则。

### 2.4 UI 清空记录行为

- UI 清空操作已要求显式 `record_kind=submission|review|all`。
- SQLite 不可用时返回 503，不再伪造清空成功。
- 主网提交记录清空不删除复核记录。
- 本轮已有实际操作证据：主网提交记录 `cleared=2`、`remaining=0`；复核记录保留。

## 4. 尚未完成，不得归档为完成

- Token Manager 四库 schema 和 M0 底座已就绪，但目前仍不是实际代币准入系统；
  `M1/D1` 尚未执行主网导入与 API 切换。
- Pool Manager 尚未成为所有候选、观察和总览的唯一上游。
- Candidate Edge Pool Manager、Candidate Exchange Pool Manager、Closed-loop
  Manager、Review Manager、Broadcast Manager 和 Composite Manager 尚未全部迁移为
  独立 Rust 管理模块。
- UI 尚未完全改为直接消费管理模块接口。
- 当前数据库快照中的闭环数量、运行态数量和旧残留需要重新对齐。
- 主网没有形成“正收益复核 -> 自动广播 -> success/failed 终态”的稳定连续证据。
- 30 分钟连续观察和更长时间盈利统计尚未完成。
- Web 大 surface `deepcopy` 引发的延迟、内存和线程增长问题尚未完成治理。
