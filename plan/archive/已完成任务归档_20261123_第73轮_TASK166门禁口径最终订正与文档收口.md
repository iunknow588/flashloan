## 一、为什么第 72 轮之后还需要第 73 轮

第 72 轮把「签字门禁整体撤销」写进了**开发计划 / 任务清单 / checklist / README / 裁定稿**
共 5 份文档，**但漏掉了 `03-迁移实施与验收.md`** —— 而这份是**设计稿**
（阶段划分 / 退出条件 / 回滚路径的**权威来源**），不是变更说明。

漏改的后果是**两份文档互相打架**：

| 文档 | 第 72 轮后的说法 |
|---|---|
| `开发计划_20261123.md` §9.9.2 | `TASK-166` **已闭合**，`H1 – H4` **已裁定** |
| `03-迁移实施与验收.md` §0.1 | **`TASK-166` 仍卡在「换池读数与归因已产出，并经人工签字」 ⇒ P1 不得开工** |
| `03-迁移实施与验收.md` §2.1 | P0 的退出条件里写着**「换池读数与归因已产出并经人工签字」** |

**只读设计稿的人会读到「P1 不得开工」**，而读开发计划的人会读到「P1 已开工」——
**这正是使用者指出的判断不准**：说 `TASK-166` 还卡在 **H1 – H4 待人工签字**。

> ⚠️ **根因不是门禁本身没裁定，而是**「裁定只写进了变更说明，没写回被裁定的那份设计稿」**。
> **撤销一个门禁，必须同时撤销**它**出现过的每一处**，否则它会以旧文本的形式复活。
