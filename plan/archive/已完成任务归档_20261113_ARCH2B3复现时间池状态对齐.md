## 二、根因取证

### 2.1 记录本身携带了它当时的池状态

`cow_execution_reviews.payload_json` → `quote.candidate_pools[]` 里每个池都带有：

| 字段 | 含义 |
|---|---|
| `poolId` | 池标识，与 `poolPathKey` 逐个对应 |
| `sqrtPriceX96` | **复现时刻**的平方根价格 |
| `liquidityIndex` | 活跃流动性指数（`L / 1e18`） |
| `fee` / `tickSpacing` / `token0` / `token1` / `hooks` | 池身份 |
| `liquidityReadAt` / `liquidityBlockNumber` | 读取时刻与块高 |

与当时的链下算本对比：两侧用的是**同一份快照**，不是两个市场。

### 2.2 池深度单位逐条取证（副本库 179 条记录）

记录里的 `liquidityIndex` 就是存储表的 `liquidity_index` 列，而该列在
`flashloan/src/core/db/storage_v4_exchange.py::_normalized_liquidity_fields` 中定义为 `L / 1e18`。

| 换算方式 | 正确条数 | 其他 |
|---|---|---|
| `liquidityIndex × 1e18` | **179 / 179** | 0 |
| `liquidityIndex`（不缩放） | 0 | 179 |

因此 `LIQUIDITY_INDEX_SCALE = 1e18` 是唯一正确口径。

> **注：JSON 科学计数法**：`serde_json` 对大指数输出 `9.901032566577074e+17`，
> 解析必须同时支持普通写法与科学计数法。首版实现只支持普通写法，
> 导致了 4 条记录的池状态被**静默丢掉**，已由专项回归测试锁定。

### 2.3 手续费口径与复现时间口径合归后的完全一致

15 条偏差在扣除**遗留 5 bps**手续费后**精确相等**（差额仅数十个原始单位的舍入尘）。
这证明归因链路完整：**链下算本 + 复现时间状态 + 0 bps 手续费** 三者一致。

### 3.1 边界不变的说明

- 复现时间的池状态来自 **Review Manager 自己的表**（`cow_execution_reviews`），
  因此它属于 Review Manager，不属于 Pool Manager。
- 当前池快照仍然只通过 **Pool Manager 公开 API**（`read_pool_parity_states`）读取，
  仅在记录未携带状态时作为回退。
- Python 不做任何数学，不直读任何管理器表。
