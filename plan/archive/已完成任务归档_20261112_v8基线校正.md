## 1. `D7` — 闭环 scope 校验和缺陷（✅ 修复）

**缺陷**：`flashloan/tools/closed_loop_manager/src/lib.rs` 中，闭环发布时**复制了**
观测层的 `candidate_exchange` 校验和，而不是**自己**的 `core4` scope 校验和。
这导致闭环层与它自己的 scope 配置**永久不一致**，漂移审计永远无法收敛。

**修法**：闭环改为发布自身的 `core4` scope checksum。

**回归**：新增 4 项回归测试，`closed_loop_manager` **14 passed**。

## 2. healer 漂移审计语义（✅ 修复）

**缺陷**：`scripts/mainnet_arbitrage_healer.py` 把**所有层**的 checksum
与**单一 `core4`** 比较，而不是各层与**自己的 scope 配置**比较。
在多 scope 体系下这是**结构性错误**，会持续报假漂移。

**修法**：改为**逐 scope 比较**（每层对齐自己的 scope 配置值）。

**回归**：healer **97 passed**。

## 6. `ARCH-1a` — 推荐池主排序键（✅ 已落地）

**排序键（唯一真源：`flashloan/src/core/db/pool_depth_keys.py`）**：

```text
主键：capacityBindingRaw DESC      （链上实测，token 计价，decimals 归一化）
次键：priceImpactBps ASC           （同等容量下冲击更小者更优）
三键：方向价分 DESC                 （仅在等容量等冲击时打破平局）
末键：pool_id ASC                  （稳定，保证确定性）
禁止：estimated_tvl_usd 作为主键
```

**关键边界**：

- **只定义"已准入池"的排序，不重新定义"谁被准入"。**
  准入判据 `has_confirmed_liquidity` 语义**未放宽**（并**恢复**了此前被误删的
  `LIVE_STATE_EVIDENCE_SOURCES` 准入门）；ARCH-1a 容量仅作为**新增**放行路径。
- **方向价分保留在容量键之下**：V4 池是**双边市场**，同一物理池可能是最好的
  `A→B` 场所、却是最差的 `B→A` 场所。若丢弃方向价分，
  前向/后向推荐会退化为同一集合，`yc_zc_same_set` / 镜像方向语义随之失效。
  方向价分**永不参与深度/容量准入**，也**从不**使用 `estimated_tvl_usd`。
- **缺失测量保持缺失**：未测量容量 = `0.0`，不伪造、不放行、不排到已测池之前。

### 8.1.2 关键语义澄清（**作废对象 ≠ 作废单位**）

| 维度 | 正确表述 |
|---|---|
| **作废对象** | **外部 fiat 价格源**（预言机 / 交易所指数价 / 人工报价 / 链下股票报价） |
| **不��废** | **USD 作为计价单位**——USDG **取代 USD 承担计价作用** |

> 任何外部 USD 价都取不到；而 USDG 在绝大多数情况下有兑换，
> 所以 USDG 足以充当计价锚。

## 8.3 追加：ARCH-1 生产路径核实与**致命静默失效修复**（2026-11-12 续）

### 8.3.1 判断更正

上一轮记的「ARCH-1 尚未在生产生效」是**判断错误**。

`flashloan/app_runtime/run.py` → `initialize_runtime_background()` →
`runtime.scanner.start(chain_id=..., protocols=["uniswap_v4"])` →
`run_forever()` 线程（`_background_enabled` 默认 `1`，
`periodic_scan_enabled` 默认 `True`）。
**Python 扫描器就是生产扫描器**，版本触发确实在生产路径上。

### 8.3.2 致命缺陷：触发器**永久沉默**

```text
旧：from core.db.storage_chain_markets import load_v4_pool_liquidity  ❌
新：from core.db.storage_v4_exchange  import load_v4_pool_liquidity  ✅
```

`ImportError` 被 `except Exception` 吞掉并返回空行集 ⇒ 指纹恒空 ⇒
版本恒"未变化" ⇒ **触发器永不触发**。
与 `recent_swap_active` 全 NULL 同属**静默失效**类陷阱。

### 8.3.3 修复

| 项 | 修法 |
|---|---|
| 导入路径 | `core.db.storage_v4_exchange` |
| **失败可见** | `_pool_state_rows()` 返回 `(rows, error)`；失败时 `available=False` + `error`，**绝不**伪装成"未变化" |
| 状态暴露 | `pool_state_status()` 暴露 `available` / `error` / `lastCheckedAt` |
| **节流** | 默认 **5s**（`DEX_POOL_STATE_VERSION_CHECK_INTERVAL_SECONDS`）——循环最快 1s 一次，生产表 4669 行 |
| 指纹体积 | 502KB 拼接串 → **SHA-256（64 字符）**；仍按排序条目计算，顺序无关性不变 |

### 8.3.4 生产数据实测（`local_store_4663.sqlite3`，链 4663）

| 项 | 实测值 |
|---|---|
| 读取行数 | **4669** |

| `recent_swap_active` 非空 | **0 / 4669**（全部 NULL） |

| 指纹构建 | ~21ms |
| 指纹长度 | **64** |
| 重复读稳定性 | **稳定**（不误触发） |
| 首次触发 | `changed=True, available=True, queued=True` |
| 第二次触发 | `changed=False, queued=False` |
