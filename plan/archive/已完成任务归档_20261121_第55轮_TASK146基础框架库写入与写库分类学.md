## 一、本轮的概念纠正：把"写生产库"拆成两类（**绑定性规则**）

### 1.1 触发

使用者提问：

> *"验证通过的为什么不写生产库？逻辑是什么？是记录库还是信息库？基础框架库要实盘写入，动态记录可以不写。"*

### 1.2 此前文档的错误

此前计划文档把"**写生产库**"当成**一个**动作，并整体挂在"需单独授权"的闸门下。
由此推出"迁移 `011..013` 双链实物核验 …… **不写生产库**"。

**这是概念错误**，因为它把两类性质完全不同的写入混为一谈：

1. **基础框架库**（baseline framework）：DDL / migration / 表结构 / 列 / 约束 / 索引 / 视图。
   结构性、版本化、**幂等**、**保数据**（不重写业务行）、**与链上实时状态无关**。
2. **动态记录**（dynamic records）：review / depth / ladder / PnL / closed loop / broadcast attempt。
   每次运行都变，受"**实测零 ≠ 未测**"、"**不历史回填**"、"**需当前链状态**"约束。

### 1.3 纠正后的规则（已写入三份活动文档）

| 类别 | 内容 | 处置规则 |
|---|---|---|
| **基础框架库** | DDL / migration / 表结构 / 列 / 约束 / 索引 / 视图 | **验证通过 ⇒ 必须实盘写入目标生产库**；**不需额外授权** |
| **动态记录** | review / depth / ladder / PnL / closed loop / broadcast attempt | **可以不写**；要写则走 §3 授权流程 |

**判定口径**：一次写入若**不改变任何测量值、只让结构与代码对齐** ⇒ **基础框架库**；
若**写入的是某时刻的测量结果** ⇒ **动态记录**。
