## 3. 归档纪律

1. 完成项不得在活动任务清单或 Checklist 中保留 `[x]`。
2. 完成项一律先写**机器证据 JSON** + **人工摘要 Markdown**，再登记**归档索引**，最后从活动文档删除。
3. 活动清单与 Checklist 每轮结束必须复核 `[x]` 计数为 0；发现遗留 `[x]` 即视为归档纪律缺口，需立即补登记索引并从活动文档移除。
   （说明：四份活动文档中出现的 `[x]` 字样均为**描述该纪律的正文引用**，不是任务勾选状态。）
4. 归档前必须对当轮活动文档正文做**逐字节冻结快照**，命名 `冻结归档_<文档名>_<日期>_v<版本>.md`。
5. 已归档编号（`TASK-*` / `AC-*`）不得再作为活动条目出现；已归档编号必须登记在归档索引中。
6. 每轮归档后必须做一致性复核：活动文档版本号一致、`[x]` 计数为 0、已归档 ID 不再作为活动条目出现、
   归档索引登记项与冻结快照可解析、证据路径存在、文件格式为 UTF-8 无 BOM / LF / 无 U+FFFD / 末尾换行。
7. 编号契约：活动任务使用 `TASK-001` 至 `TASK-106`，验收条件使用 `AC-001` 至 `AC-170`；
   完成时必须在机器证据 JSON 中引用所有相关 `TASK-*` 与 `AC-*` 编号。
8. 归档不得触碰生产库：主网写入、合约部署、链上广播与网络切换均需**显式授权**，
   且必须在归档证据中记录 `productionDatabaseWritten=false`、`broadcastSent=false`、`contractDeployed=false`。
9. **配置项不得因"看似冗余"而删除**：若某配置仍被代码或部署流程依赖，
   必须**迁移路径**并同步所有引用与守卫 allowlist，而非删除。
