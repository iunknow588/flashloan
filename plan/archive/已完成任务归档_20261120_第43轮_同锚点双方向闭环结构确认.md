## 一、问题

一个闭环分组下存在两个方向闭环 `X-Y-Z-X` 与 `X-Z-Y-X` 时，当前系统是否支持该查询结构？
是作为两个独立闭环，还是同一条闭环的两个方向？

## 二、结论

**支持，且实现方式是「两个完全独立的闭环」**，不是同一条闭环的两个方向视图。
系统在任何一层都不合并、不归一化、不重排。

闭环身份 = **资金锚点 + 方向池子**。`X-Y-Z-X` 与 `X-Z-Y-X` 共享锚点但方向池子不同，
因此是两条闭环，各自拥有独立的 loop key、pool ids、折叠单 tick 容量、绑定池、
USDG 估值与跨 tick 阈值。`X-Y-Z-X` 的路由**绝不会**借用 `X-Z-Y-X` 的容量或池集合。

## 三、四层实现定位

| 层 | 实现 | 区分两个方向 |
|---|---|---|
| Manager 发布 | `loop_key = format!("{anchor}:{y}:{z}")`；生成器为**有序双循环** `for y { for z { ... } }`；中间方向键 `{y}->{z}` **有向**，Y→Z 与 Z→Y 是不同条目 | 是 |
| Rust 内核目录 | `BTreeMap<Vec<String>, ClosedLoopIdentity>`，键为**有序 3 地址路径**；`identity_for` 精确匹配 | 是 |
| Python 运行时状态机 | 行键 = `normalize_physical_loop_key(loop_key)`（anchor:y:z）；`_state_identity_matches` 要求完全相等 | 是 |
| review 管理器 | `validate_evidence_membership` 精确命中已发布键，未命中报 `UnknownClosedLoop`；`build_review_rows` 以精确键索引证据 | 是 |
