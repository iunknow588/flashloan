## 一、问题

主网 legacy review 大面积报 `single_tick_capacity_unavailable`，而 Manager 库发布的 **164 条闭环容量全部 > 0**
（无 NULL、无 0）。容量缺失**不在 Manager 的发布列上**，必须在 **Manager → 内核快照 → review 输入** 这条链路上定位。

## 二、根因（沿链路逐层定位）

`app_runtime
  Manager 发布        manager_v4_closed_loops 表确有 path_addresses_json 列，164/164 行非空  → 发布侧无缺陷
  内核 SQL 投影      sqlite_read::load_manager_closed_loop_rows 的 SELECT 遗漏 path_addresses_json  → 责任层
  内核目录构建        closed_loop_identity::catalog_from_rows 以有序 3 地址路径为键；
                     path_addresses_json 缺失 → address_path 恒空 → len != 4 → 每一行都被丢弃 → 目录恒空
  内核身份匹配        catalog.identity_for 查空目录 → 恒 None → 路由只写 closedLoopIdentityStatus="mismatch"，
                     不写 closedLoopKey / singleTickCapacityRaw → 容量永不落地
  review 输入         payload 中 closedLoopKey、singleTickCapacityRaw、closedLoopIdentityStatus 三者全缺
                     （连 "mismatch" 都没有）→ 与"目录恒空"一致，反证输出未进入 review 输入
`
闭合验证：把该列补回 SELECT 后，目录条目数 **0 → 164**，容量 > 0 条数 **0 → 164/164**。

## 三、修复

`rust
