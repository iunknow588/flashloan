并把「存量旧值 vs 重算旧值」**单列为漂移诊断**（`capacityDrift`）。两者**不得**混算。

## 三、新发现（实锤缺陷）· 快照写入方漂移

**现象**：`v4_exchange_pool_liquidity_snapshots` 的
`single_tick_max_token0_raw` / `single_tick_max_token1_raw`
**相对同一行的 `sqrt_price_x96` / `tick` / `liquidity` 已经过期**。

**根因（两个写入方，只有一个维护边界）**：

| 写入方 | 位置 | 写价格列 | 写边界列 | 结果 |
|---|---|---|---|---|
| Rust 池管理器 | `tools/pool_manager/src/lib.rs:2654` `write_depth_snapshot` | ✅ | ✅（**同一条语句**） | **自洽** |
| Python 证据通道 | `rs-src/src/evidence.rs` upsert | ✅ | ❌（**从不重写**） | **边界停留在更早的价格上** |

**判据（可复核，无需新增字段）**：行的 `liquidity_read_at == refreshed_at` ⇒ 最后写入方是 Rust ⇒ 自洽；
不等 ⇒ 最后写入方是 Python ⇒ 可能漂移。

**影响面（已界定，不得夸大）**：闭环层的**容量是重算**的
（`closed_loop_manager::folded_path_capacity` 用**池表**状态重算）⇒ 漂移**不污染容量**；
存量边界只被 `read_single_tick_bounds` 用于**“边界为零 ⇒ 该池不可用”**这一处判断
（`tools/closed_loop_manager/src/lib.rs:1698`）。

**处置**：另立 **`TASK-172`**（验收 `AC-221`），排在 **P1c**（P1 之后、P2 之前）。
方向层**先按「自己重算边界」实现**（`DPO-10`），漂移修复只是把「重算」换回「读存量」。
