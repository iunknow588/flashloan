## 2. 执行顺序（不可越级）

1. 资金池：固定线程增量刷新，游标持久化，先完成 eligible 池扫描。
2. 候选 YC/ZC：候选锚点构建，只在资金池完成后运行。
3. 市场观察：YZ 路径增量扫描，依赖候选完成。
4. Dex 总览：依赖市场观察与闭环游标，刷新快照。
5. 闭环：X-Y-Z-X 闭环重建，依赖市场观察完成。
6. 链上复核：消费闭环数据，实时 `eth_call`/preview。
7. 广播执行：消费正向盈利闭环，`execution_success`/`tx_hash` 落库。

任何上游未 complete 时，下游返回 `blocked_upstream`，不直接形成闭环。

## 3. 线程与队列

- Rust 已统一管理 worker pool：主 dispatcher + 每组状态线程 + review 并发信号量 + 全局 `ExecutionQueue` 与 1-8 执行 worker。
- Python 只负责桥接、SQLite 持久化与 Web 侧容器；不再另起独立扫描线程。
- 资金池、候选池、市场观察、Dex 总览、闭环各由独立维护线程管理；链上复核与广播 watchdog 只检查 Rust 原生线程，不重复执行。
- 已完成并归档：P2 Rust/Python 线程统一、P3 独立作用域索引器、P4 动态创建/回收线程、P5 闭环状态机 CAS 领取，线程总数上限 16/可配 32。
- 剩余执行队列观察：P1 在 2/4/8 worker 下记录 `executionQueue` 摘要，确认无饿死、无重复广播；等待 M3-1 恢复扫描后执行。

## 4. 每轮 SOP

1. 确认 5000/5001 监听进程；不擅自启动/重启。
2. 只读核对 `cow_execution_attempts`、`cow_execution_reviews` 总数与 `max(created_at)`。
3. 有新窗口才重跑四类 evidence；无新窗口沿用最近一份报告。
4. 扫描 `readyForTransactionPreflight`、`chain_submission_candidate`、`can_submit_order`、`checks_passed`、`execution_success`、`tx_hash`。
5. 出现新 live-ready 触发 M1-2；出现新 success 触发 M2-2 -> M2-3 -> M2-4。
6. 复检 M5-2：live strict、predeploy fork、主网只读 gate 一律 `--no-write`。
7. 追加执行记录：时间、SQLite 窗口、触发状态、evidence 路径、阻塞原因。

## 8. 安全边界

- 禁止手工修改 evidence、SQLite、`latest.json` 或运行时 API；readiness 只能由 CLI 写入。
- 禁止把 SQLite 参考 P&L 标记为 eth_call 链上复核结果。
- 禁止跨 RPC 重发广播/提交；RPC failover 只用于只读复核。
- 禁止将 `replacement transaction underpriced` 作为提高 gas 自动重试的触发条件；该错误属于同 nonce pending 冲突，应停止广播，由策略框架自动核对 nonce/回执并落终态，不重发、不替换。
- 错误处置全部由策略框架按错误分类自动决定；人工只在设计阶段修改策略矩阵，运行阶段只读告警与审计，不作为执行决策路径。
- 禁止擅自启动、重启、kill 生产进程；受控操作前确认无进行中复核。
- 禁止在无链上 evidence 时调整参数或搜索模式。
- 禁止将历史 success（仅存 evidence）伪造成在线 SQLite 记录，或作为 M9-1 已满足依据。
- 有流动性池、无流动性池、候选池均通过增量扫描自动维护，不依赖旧库人工复原。
