## 2. S1：口径修正（零副作用）

### 2.1 `AUD-P0-1` 池子审查计数去重

- `scripts/mainnet_arbitrage_healer.py:490` `pool_depth_audit()` 的 `COUNT(*)` 改为
  `COUNT(DISTINCT d.pool_id)`；`adequateDepthPoolCount` / `insufficientDepthPoolCount`
  同样按唯一池聚合。
- 新增 `candidatePoolRows`（原行数）与 `uniquePoolCount`（唯一池数）两个字段。
- `pool_depth_replacement_report()` 与 `pool_depth_audit()` 统一 distinct 口径。
- **验收**：生产库实测 `uniquePoolCount=16`、`candidatePoolRows=47`、`adequateDepthPoolCount=16`。

### 2.2 `AUD-P0-4` PnL 统计口径

- `pnl_stats()`（`healer.py:296`）的 `nonPositive` 改为 `len(values) - positive_amount`
  （此前误用 `executable_positive`，把估算正收益也算作"非正"）。
- 新增 `positiveEstimateOnly`（`selected_profit_source = native_contract_rate_delta_estimate`
  且值 > 0 的条数）、`estimatedProfitOnlyCount`、`confirmedSum`（排除估算值后的合计）。
- `print_report()` 补全 `positiveAmount` / `positiveEstimateOnly` / `nonPositive` 三项。
- **验收**：24h 窗口实测 `nonPositive=1185`（修正前 1286）、`positiveEstimateOnly=76`、
  `confirmedSum=0.0`、`positiveAmount=101`。

### 2.3 `AUD-P1-3` 最佳交易量审查

- `best_amount_audit()`（`healer.py:427`）的 `insufficient` 改为 `len(below_gas) + len(too_small)`；
  `too_small` 变量此前计算后从未使用，现真正参与判定。
- 新增 `tooSmallCount` / `insufficientCount` / `tooSmallSamples`。
- **转下一批次**：「候选池 TVL 分布作为池深不足的独立触发源」未实施——本轮池深触发源已由
  `badReadingCount` / `unpricedPoolCount` 与 capacity 判据覆盖，该项并入 S2。

### 2.4 `AUD-P1-4` TVL 上界

- `pool_depth_audit()` 加上界 `<= 1e9`（`MAX_POOL_TVL_USD`），越界池**排除**而非仅打标签。
- 新增 `badReadingCount`（越界 TVL 计数）。
- **验收**：全库 1287 条 `>1e9`（含 `1e43`）坏读数全部排除；候选集内 `badReadingCount=0`。
- **转下一批次**：与 Rust `MAX_CANDIDATE_TVL_USD` 的跨语言共享配置源仍在 `AUD-P3-4`（阶段 4）。

### 2.5 `AUD-P2-1` SQL 类型安全

- 所有池深 SQL 的 `COALESCE(s.estimated_tvl_usd,0)` 改为
  `CAST(COALESCE(s.estimated_tvl_usd,0) AS REAL)`（含 `pool_depth_replacement_report`）。
- 抽取公共 SQL 片段常量，避免后续分散引入异构写法。
- **根因**：SQLite 对 TEXT affinity 列与绑定参数做字典序比较，`('100000',)` 绑参时
  `>= 100000` 对所有存量值恒假，历史已踩过一次。
- **回归测试**：`test_pool_depth_audit_casts_tvl_text_to_real`。

### 2.6 `AUD-P2-5` 查询窗口

- `review_rows()`（`healer.py:283`）默认加 LIMIT 并参数化（`REVIEW_QUERY_LIMIT = 20000`）。
- `audit_reviews` / `best_amount_audit` / `missing_review_candidates` 调用点统一传入窗口。
- 新增 `pool-manager ensure-indexes` 子命令（**必须 `--apply`**），创建
  `idx_cow_execution_reviews_scope_created_v2 ON cow_execution_reviews(network, chain_id, created_at DESC)`。
  原索引第三列为 `category`，无法 seek `created_at` 范围（EXPLAIN 走
  `USE TEMP B-TREE FOR ORDER BY` 扫全表）。
- **healer 仅在 `--mode repair` 调用该命令**；`--mode check` 全程只读
  （healer 的 `connect()` 是 `mode=ro`，无法直接建索引，故必须经 CLI）。
- **转下一批次**：`cow_execution_reviews(selected_profit_source)` 单列索引未建
  （收益低于 `created_at` 范围扫描收益，且全表读取已受 `REVIEW_QUERY_LIMIT` 约束）。
- **验收**：3345 MB 库上 `--mode check` 耗时 19.87s（基线 19.37s），不回退。

## 3. S1.5：池深算法根因修复

### 3.1 关键事实更正（原计划前提有误）

实施过程中实测推翻了原计划的两条前提，**已按实测结论实施，不得再沿用原表述**：

| 原计划表述 | 实测结论 | 处置 |
|---|---|---|
| `liquidity_index` 是深度信号，验收指标 `corr(log10 li, log10 TVL) > 0.7` | 相关性仅 **+0.09**（候选集 16 池）；`li = L / 1e18` 是集中流动性原始尺度 | 指标**作废**，改用「真实储备排名一致性 + 坏读数清零」 |
| `li<1` 的 4 个池是伪深池，应排除 | 实测这 4 个 ETH/USDG 池真实储备 **$97.8K–$4.96M**，本就是真深池；`li=0.02854432` 承载 **24 条闭环跳** | 排除规则**作废**，会误删真深池并打断闭环 |

### 3.2 `DEP-P0-1` / `DEP-P1-1` / `DEP-P1-2` 真实储备 TVL

文件：`flashloan/src/dex/intent_trade/chains/robinhood/v4_pool_index.py`

- 移除 `DEFAULT_ETH_PRICE_USD`（$3000 硬编码默认值）。
- 新增多源实时 ETH 价：`ETH_PRICE_SOURCES = (binance_us → kraken → coingecko)`。
  实测 `api.binance.com` 返回 **HTTP 451 不可用**；`api.binance.us` / `api.kraken.com` /
  `api.coingecko.com` 均 HTTP 200。
- 新鲜度与区间校验：`ETH_PRICE_MAX_AGE_SECONDS = 900`、
  `ETH_USD_PRICE_MIN = 500` / `ETH_USD_PRICE_MAX = 20000`；
  另留 `ROBINHOOD_MAINNET_ETH_PRICE_USD` 运维覆盖开关。
- `_liquidity_reserve_metrics()` 改用**池自身** `token0Decimals` / `token1Decimals`。
- **双边均需有价才产出 TVL**；任一侧无价 → `estimatedTvlUsd = None` → `depthStatus='unpriced'`，
  **拒绝回退为 0**（避免薄池被 `TVL=0` 混入）。
- 新增输出字段：`reserveUsdToken0` / `reserveUsdToken1` / `priceSource` /
  `priceObservedAt` / `depthBasis='true_reserve_estimate'`。
- 稳定币**按地址**识别：`CANONICAL_USD_STABLE_ADDRESSES`（USDC `0x5d3a1ff2…`、
  USDG `0x5fc5360d…` decimals=6）。链上另有 3 个同符号 "USDG" 假币
  （`0x391f08bf…` / `0x69a17d84…` / `0xe9e75444…`，均为 `chain_live_erc20`），
  定价必须按地址而非符号。

### 3.3 `DEP-P2-1` / `AUD-P1-5` 阈值同源

- `flashloan/tools/pool_manager/src/lib.rs:18-20` 新增同源分带常量
  `DEPTH_BAND_DEEP_USD = 1e6` / `DEPTH_BAND_MEDIUM_USD = 1e5` / `DEPTH_BAND_SHALLOW_USD = 1e4`。
- `depth_band_json_for()` 改用这些常量，边界语义统一为 **`>=`**；
  Python 侧 `_liquidity_depth_status()` 同步改 `>=`。

### 3.4 `DEP-P0-2` / `DEP-P1-3` capacity 准入

- **主判据**改为链上可成交容量：`capacity(i) = max{ a : priceImpact(a) ≤ ε }`。
- **ε = 10 bps (0.1%)**，复用 `DEFAULT_HOP_PRICE_IMPACT_LIMIT_BPS`，
  不另立 0.5% 阈值（避免第三套阈值）。
  Rust 侧：`CANDIDATE_PRICE_IMPACT_LIMIT_BPS = 10.0`。
- 准入门槛：`MIN_CANDIDATE_CAPACITY_USD = 10_000.0`，即
  `depth_score_usd >= MIN_CANDIDATE_CAPACITY_USD`（capacity ≥ gas_profit / unit_profit）。
- **取消 `liquidity_index > 0` 排除规则**。
- 排序主键由 `liquidity_index DESC` 改为 `depth_score_usd DESC` + 真实 TVL DESC tie-breaker。
- `RawEligiblePool` 新增 `depth_score_usd` 字段；
  `upsert_eligible_pool_rows` 把 capacity 证据写入 `balances_json`
  （原为空 `{}`）：`{"depthScoreUsd","estimatedTvlUsd","priceImpactLimitBps","depthBasis":"capacity"}`。
- TVL 降级为辅助信号，不再单独决定准入。

### 3.5 新增：最佳交易量 fail-closed 止血（不属于原 DEP 表）

文件：`flashloan/src/dex/runtime/rust_closed_loop.py`

- 新增 `BEST_AMOUNT_LADDER_MIN_PROBE_ROWS = 2`、
  `BEST_AMOUNT_LADDER_INCOMPLETE_KIND = "best_amount_ladder_incomplete"`。
- `best_amount_ladder_incomplete = len(probe_rows) < BEST_AMOUNT_LADDER_MIN_PROBE_ROWS`；
  为真时 `best_amount_confirmed=False`、`confirmed_best_amount=None`、`best_amount_missing=True`。
- `best_amount_missing_fails_closed` 条件扩展为 `not profitable and (never_ran or incomplete)`。
- 失败 kind 区分：阶梯不完整 → `best_amount_ladder_incomplete`；否则 → `best_amount_missing`。
- `bestAmountConfirmationReason` 新增 ladder 分支文案。
- 广播跳过白名单 `review_failure_kind in {...}` 增补该 kind。
- healer 侧 `best_amount_state()` 增加 `ladderIncomplete` / `probeCount`；
  `audit_reviews()` 统计 `ladderIncomplete` / `ladderIncompleteCurrentLoop`；
  `audit_reviews()` 与 `best_amount_audit()` 将此类复核归入 `missingBestAmount`
  （**复核错误类型**，非池深错误）。
- **未改** `_liquidity_cap_raw` / `balances` 链路——根因修复留给后续批次
  （需真实储备数据先由 B1 落地）。
