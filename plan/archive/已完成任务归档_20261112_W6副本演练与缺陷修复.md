## 1. 新发现并修复的缺陷

### D1｜`ensure-indexes --apply` 退出码 1（索引其实已创建）

**现象**：在 3.5GB 生产库副本上执行 `pool-manager ensure-indexes --apply` 报

```text
Invalid column type Text at index: 3, name: detail
```

退出码 1，索引却**已成功创建**。

**根因**：`EXPLAIN QUERY PLAN` 的第 4 列 `detail` 在 SQLite 中的类型是 **TEXT**，
代码却按整数读取：

```rust
row.get::<_, usize>(3)   // 旧
```

**修复**（`flashloan/tools/pool_manager/src/lib.rs`，2 处）：

```rust
row.get::<_, String>(3)  // 新
```

**影响面**：失败发生在索引创建**之后**的读取阶段，因此索引无缺失，
但命令返回非 0 会让调用方（healer `--mode repair --apply`）误判为失败并中断。

**回归测试**：`tests::ensure_indexes_survives_sqlite_text_query_plan_detail`
—— 真实建表 + 插行 + 调 `ensure_indexes`，断言
`profitSourceQueryPlanUsesIndex == true` 且评审窗口计划命中
`idx_cow_execution_reviews_scope_created_v2`。

**复验（副本库）**：

```text
exit 0
indexes[].exists = true (×2)
reviewWindowQueryPlan       = SEARCH cow_execution_reviews USING COVERING INDEX
                             idx_cow_execution_reviews_scope_created_v2 (...)
profitSourceQueryPlan       = SEARCH cow_execution_reviews USING COVERING INDEX
                             idx_cow_execution_reviews_scope_profit_source_created (...)
profitSourceQueryPlanUsesIndex = true
```

### D2｜`balances_json` 恒为 `{}`（最佳交易量阶梯不展开的**根因**）

**现象**：生产库 `v4_exchange_pool_liquidity_snapshots.balances_json`
非空率 **0/4669**；`depth_score_usd` 同为 0。

**根因链**（此前只观察到症状，未定位到写入侧）：

```text
pool_manager write_depth_snapshot   → 从未写 balances_json（恒 "{}"）
  → dex_quote_evidence_size._pool_borrow_side_amount()  → balances 缺 token0/token1
  → _liquidity_cap_raw()                                  → 恒 (None, None)
  → rust_closed_loop.py cap_raw is None                   → maxProbeAmountRaw = initial * 64
                                                              （固定 64 tokens 上限）
  → probeRecords 长度恒为 1                               → 阶梯从未展开
  → bestAmountConfirmed 无法成立 / best_amount_ladder_incomplete
```

**修复**（`flashloan/tools/pool_manager/src/lib.rs`）：
`write_depth_snapshot` 现在写入 token 计价的完整负载，
并新增 `human_amount(raw: u128, decimals: Option<i64>) -> Option<String>`
把 wei 转成人类单位（decimals 取值域 `0..=77`，越界返回 `None`）。

```json

  "token1": "0.139739802748784309",

  "capacityToken1": "0.139739802748784309",
  "token0Decimals": 6,
  "token1Decimals": 18,
  "capacityToken0Raw": "9527283",
  "capacityToken1Raw": "139739802748784297",

```

**回归测试**：`tests::depth_snapshot_writes_token_denominated_balances_payload`
—— 断言 `token0` / `token1` / `capacityToken*` / decimals / `capacityRaw` /
`capacityBindingRaw` / `depthBasis` 全部正确写入。
