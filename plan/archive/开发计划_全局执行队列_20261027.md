# 全局执行队列开发计划（2026-10-27）

## 1. 背景与目标

当前 Rust `ClosedLoopWorkerPool` 中，复核与广播（执行）在同一个 review worker 线程内顺序完成：`run_native_review()` 复核出 `profitable_amount_found` 后立刻调用 `maybe_broadcast()`。这带来两个问题：

- 复核线程在广播 RPC 和确认等待期间不能继续复核其他闭环，复核吞吐被执行耗时拖住。
- 执行顺序不可控，无法保证“先复核通过且预期利润为正”的闭环先执行。

目标：把“复核”和“执行”拆成两级独立队列。复核通过且预期利润为正的闭环进入全局执行队列；固定数量的执行线程按“复核通过时间（`verified_at`），越早越优先”消费执行队列。643 个（去重后约 321 个）闭环不需要按数量创建线程，执行并发有硬上限。

## 2. 设计

### 2.1 执行任务模型

```text
ExecutionTask
  group_key       复核对 group key（anchor|middle1|middle2）
  chain_id        链 ID
  config_json     执行所需完整 config（rpcUrl/arbAddress/minProfitRaw/privateKey 等）
  review_payload  复核通过且预期利润为正的完整 payload
  verified_at     复核通过时间（RFC3339），执行排序键
  state           queued | running | done | error | skipped
  attempts        执行尝试次数
  last_error      最近错误
```

执行队列使用 `BinaryHeap`：排序键为 `(priority, verified_at, sequence)`。普通任务 `priority=1`，`verified_at` 越小越优先；同组多次复核通过时保留最早 `verified_at`，避免同组反复刷新导致一直被往后挤（饥饿）。

### 2.2 入队条件

复核结果满足以下全部条件才进入执行队列：

- config `broadcastEnabled == true`（Python 侧广播 gate 已打开）。
- config `deferBroadcast == true`（新执行队列开启时由 Python 注入）。
- review payload `status == "profitable_amount_found"`（复核通过且预期利润为正）。

不满足条件时保持现行为：复核结果只记录不广播，或直接广播（`deferBroadcast=false` 兼容模式）。

### 2.3 执行线程

- `ClosedLoopWorkerPool` 新增固定数量执行线程，默认 2，最大 8，可用 `DEX_CLOSED_LOOP_EXECUTION_WORKERS` 配置。
- 执行线程从执行队列 `pop_next()` 取最早任务，执行 `maybe_broadcast()` 和前置信检查，更新 group 的 broadcast history 后标记 `done`。
- 广播失败不无限重试：任务标记 `error` 并保留 review payload；下一轮该闭环复核再次通过时按新的 `verified_at` 重新入队。
- group 被 stop 时执行线程跳过该任务并标记 `skipped`，保证停止语义不倒退。

### 2.4 配置与状态

新增环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `DEX_CLOSED_LOOP_EXECUTION_QUEUE_ENABLED` | `true` | 是否启用独立执行队列 |
| `DEX_CLOSED_LOOP_EXECUTION_WORKERS` | `2` | 执行线程数，上限 8 |

`status_json()`/`compact_status_json()` 新增 `executionQueue` 摘要：`enabled`、`workers`、`activeExecutions`、`queued`、`running`、`done`、`error`，完整状态额外携带最近 5 条执行记录。

## 4. 验收

- `cargo test worker_pool --lib` 全部通过，新增执行队列单测覆盖排序与去重。
- `pytest` 相关单测通过。
- 受控重启后 `status.json` 出现 `executionQueue`，`queued/running/done` 计数可观察。
- 测试网 180 秒扫描窗口继续出现 `execution_success` + 非空 `tx_hash`，且广播由执行线程完成。
- 主网不注册周期扫描；如手动观测一轮，`activeConcurrency <= 16`、`executionQueue.workers <= 8`。

## 5. 回退方案

如出现广播丢失或执行混乱，设置 `DEX_CLOSED_LOOP_EXECUTION_QUEUE_ENABLED=false` 后受控重启，恢复复核线程内直接广播的旧行为；不回退 `.env` 备份，不手工改 evidence/SQLite。
