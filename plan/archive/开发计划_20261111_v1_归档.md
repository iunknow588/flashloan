## 1. 计划目标

本轮开发只服务于 Robinhood Mainnet `4663` 的 Uniswap V4 DEX 套利链路，
按以下顺序收敛：

0. ~~**先让数字可信**~~ —— ✅ 已完成（S1，归档）。
1. ~~**再修深度度量**~~ —— ✅ 已完成（S1.5，归档）。
   用 capacity 主判据 + 真实储备 TVL 辅助信号替换错误的 `liquidity_index` 判据
   （**不排除** `li` 小的池——实测证明它们是真深池）。
2. **先补池深后续（S2.5）**：接入股票侧价格来源并打通 `balances` 链路，
   让 capacity 有真实非零值、复核阶梯能正常展开、`ladderIncomplete` 归零。
3. **然后补门禁（S2）**：让编排器能正确识别候选集↔闭环集脱节、
   修复链死锁与归因缺失。
4. **之后重建闭环（S3）**：在停机窗口内重建闭环，消除 42/106 环池零命中。
5. **再推权威收敛（S4）**：Token → Pool → Candidate → Closed-loop → Review →
   Broadcast → Composite 迁移到 Rust Manager。
6. **最后治理（S5）**：UI/API 收口、长期盈利统计、日志轮转与命名兼容。

### 1.1 最终完成定义

- 主网闭环 `106` 条全部指向候选集内真实存在的池，`pool_ids` 命中率 `100%`。
- 三方 `pool_scope_checksum`（`pool_scope_config` / `manager_dex_candidate_library_state`
  / `manager_v4_closed_loop_library_state`）完全一致，且 `consumers_need_rebuild`
  经验证为**真值零**而非字段伪错。
- 池深度判据满足：**capacity 成为主判据**（价格冲击 ≤ 10 bps），
  真实储备 TVL 排名与链上可成交容量一致，候选集内**无坏读数**（越界 TVL 全部排除）。
  ~~`corr(log10(liquidity_index), log10(TVL)) > 0.7`~~ **已作废**：
  实测该指标仅 +0.09，证明 `liquidity_index` 不是深度信号。
- 每条复核都有明确 `bestAmount`（非 `none`）与明确 PnL；
  `positive(executable)` 数量与广播 attempt 终态可对账。
- 每个数据范围仅一个权威写入模块，不长期双写；切换后旧写入立即关闭。
- 所有生产结论绑定 `scope + authority + PID + 数据库 checksum + 观察窗口`；
  工程测试与 dry-run 不替代生产验收。

### 2.3 不可违反的执行判断

1. **深度算法修好之前，不重建闭环。** S1.5 已把判据换成 capacity，
   但 capacity 仍无真实非零值（`unpriced` 12 池 / `balances` 链路未通），
   因此 **S2.5 必须先于 S3**；否则重建出的闭环仍引用无法判定的池，命中率验收失去意义。
2. **深度算法修好之前，不下架任何 token 对。**（保留约束，S1.5 后继续有效）
3. **不因 `unpriced` 判定池无效。** `unpriced` 表示**缺价格来源**，
   不等于池浅；缺价时必须保持 fail-closed，不得回退 0，也不得据此下架。
4. **闭环重建必须停机**，不得在守护器与 `run.py` 运行中执行。
5. **口径修正先行。** 数字不可信时，任何门禁判断都是噪声。
6. **只读盘点可并行，破坏性操作一律串行。**
7. **不得改写历史证据**；新结论使用新时间戳。

> 准入改用 **capacity 主判据 + 真实 TVL 辅助信号**。

### 5.1 根因回顾

`v4_pool_index.py` 以全区间近似计算 TVL：

```
amount0 = (L / sqrtPrice) / 10^decimals0
amount1 = (L * sqrtPrice) / 10^decimals1
```

`L / sqrtPrice` 的除法使**价格越小的池 TVL 被放大得越厉害**，
导致 TVL 与真实流动性几乎无关（相关性 +0.04 / 候选集 +0.09）。

**第二个根因（本次仅止血，未修链路）**：复核产出链路的 `probeRecords` 长度全为 1
（阶梯从未展开，`bestAmount` 实为"初始探测 1.0 token 的二分下界"）；
且 `balances` 字典从未写入 `token0`/`token1`，导致 `_liquidity_cap_raw` 恒返回 `None`，
`maxProbeAmountRaw` 回退成 **64 tokens 固定上限**。本批以
`best_amount_ladder_incomplete` fail-closed 止血，根因修复留待后续批次。

## 13. 失败停止条件

出现以下任一情况立即停止当前批次：

- scope 不完整，或混入其它 network/chain/protocol/market。
- source report、数据库、schema 或 checksum 不一致。
- ~~TVL 修正后 `corr(log10 li, log10 TVL)` 仍 `< 0.7`~~ —— **该停止条件作废**：
  实测证明 `li` 与真实 TVL 相关性仅 +0.09，`li` 不是深度信号，相关性指标无判别力。
  替代停止条件：真实储备 TVL 无法产出、或坏读数（越界 TVL）被计入 `adequateDepthPoolCount`。
- 依据 `li < 1` 排除候选池（该规则已作废，会误删真深池并打断 24 条闭环）。
- 任何 `estimated_tvl_usd` 越界（`< 1e4` 或 `> 1e9`）被计入 `adequateDepthPoolCount`。
- 依据未修正的 TVL 结论下架任何 token 对。
- copy DB 与生产前基线存在未解释差异。
- rollback 未演练，或 checkpoint 无法恢复。
- `bestAmount` 为 `none` 的复核进入广播候选。
- S2.5 未完成即进入 S3 闭环重建（`unpricedPoolCount` 未归零，或 `ladderIncomplete` 未归零）。
- S2.5 期间仍有闭环跳引用 `unpriced` 池（当前 58 条）却未登记为阻塞项。
- 股票侧价格不可用时回退为 0 / 回退到固定默认价（必须保持 `unpriced` fail-closed）。
- `balances` 仍未写入真实储备 `token0`/`token1`，导致 `maxProbeAmountRaw` 继续回退 64 tokens。
- 闭环深度分未取 `min(各跳 capacity)`，却按单跳深度放行整环。
- PnL、单位或来源不完整时尝试生成广播请求。
- Manager 不可用却回退业务 SQLite 或生成可写命令。
- 生产 apply、重启或观察结果与本计划不一致。
- 引入新的测试失败，或既有失败集扩大。

停止后保留原始输出和失败样本，不通过改口径、删除 finding 或覆盖证据继续。
