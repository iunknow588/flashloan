# `MID_CHANGE_RATE` 单独分析：这个阈值**还需要吗**？

**日期**：2026-11-23  **任务**：`TASK-166` / `AC-215`
**问题**：三个阈值里，`_MID_CHANGE_RATE_`（中间跳选池变化率）**单独看**还有存在必要吗？
**性质**：**建议稿** —— 供使用者裁定。

---

## 0. 结论

**需要，但它的角色必须被重新定义 —— 它不是"第三道独立的门"，而是"另外两道门的**前置条件与解释器**"。**

用一句话说清三者的真实关系：

```text
_MID_CHANGE_RATE_  ──►  回答「主序要不要重审」（口径层）
        │                      │
        │                      ▼
        └──►  解释 ──►  _LOOP_NET_RATE_  ──►  回答「产能损失多少」（业务层）
                                  │
                                  ▼
                            _PROFIT_DROP_  ──►  回答「经济代价多少」（金额层）
```

**关键修正**：`_MID_CHANGE_RATE_` **不是** `_LOOP_NET_RATE_` 的**替代品**，
而是它的**上游诊断**。三者的**量纲**与**触发含义**都不同（详见 §4）。

---

## 1. 先看它实际测到了什么（2026-11-23 只读波次实测）

`_MID_CHANGE_RATE_` 当前采用的口径是 **Δ2 换宇宙**
（`changedTargetUniverseRateTriples`，脚本 `:2501`）：

| 指标 | 值 |
|---|---|
| 三元组总数（分母） | **1420** |
| 变化数（Δ2 换宇宙） | **82** |
| **实测值** | **5.77 %** |
| （参考）Δ1 同宇宙 | 114 = **8.03 %** |
| （参考）并集口径 | 128 = **9.01 %** |

### ⚠️ 但这个 5.77 % **掩盖了三件事**

#### (1) **分母里 97.3 % 的代币对根本没变**

| 事实 | 值 |
|---|---|
| 不同 `(X,Y)` 方向对总数 | **1020** |
| **零变化**的方向对 | **992（97.3 %）** |
| 有 ≥1 次变化的方向对 | **28（2.7 %）** |

**含义**：所谓"5.77 % 的换池"**不是均匀分布的普涨**，而是**极少数代币对的集中翻转**。
top-10 代币对就占了 **82 次变化中的 42 次（51.2 %）**。

#### (2) **82 次变化只涉及 12 个不同的新池**

| 事实 | 值 |
|---|---|
| 变化的三元组 | **82** |
| 其中涉及的**不同新池** | **12** |
| 可用池总数 | 86 |

**含义**：换池不是"大面积重新洗牌"，而是**少数几个池挤掉了另外几个池**。
`5.77 %` 这个数字看起来很大，**底层只有 12 个池的位移**。

#### (3) **它与闭环层后果之间隔着一层巨大的衰减**

```text
82 次三元组换池
      ↓  （大部分变化被下游门禁/容量约束吸收）
30 条闭环的中间池变了（26 保留但换池 + 4 消失）
      ↓
22 条闭环的容量真的变了（负 18 / 正 4）
      ↓
0 条闭环测得利润为正（旧利润：实测负 14 / 未测量 154）
```

**衰减比：82 → 30 → 22 → 0。**

⇒ **这是本节最重要的发现**：`_MID_CHANGE_RATE_` 是这条链上**最灵敏**的指标
（最先动、动得最多），而 `_PROFIT_DROP_` 是**最钝**的（最后动、动得最少）。

---

## 2. 那它是不是**冗余**的？—— 与另两个阈值逐个对比

### 2.1 vs `_LOOP_NET_RATE_`：**不冗余，两者是"诊断 ↔ 后果"**

| | `_MID_CHANGE_RATE_` | `_LOOP_NET_RATE_` |
|---|---|---|
| 分母 | **1420 三元组** | **168 闭环** |
| 实测 | 5.77 % | **0.00 %** |
| 测的是 | 换池**决策**变了多少 | 闭环**目录**少了多少 |
| 盲区 | **换池但闭环没变** ⇒ **测不到** | **闭环没少但换池了** ⇒ **测不到** |

**关键**：实测 **净变化 0 %**，但 **26 条闭环换了中间池**、**4 条消失 + 4 条新增**。
⇒ **`_LOOP_NET_RATE_` 在本次波次里完全"看不见"这次口径变更**（净 0 ⇒ 不命中）。
若没有 `_MID_CHANGE_RATE_`，**这次变更就会从门禁上完全消失**。

**这正是 `_MID_CHANGE_RATE_` 不可替代的地方**：它是**唯一**能发现
"净数没动、但底层大面积换池"的指标。

### 2.2 vs `_PROFIT_DROP_`：**不冗余，且它是它的前置**

`_PROFIT_DROP_` 当前**测不出来**（旧利润 154/168 未测量，新利润只读不可算）。
而 `_MID_CHANGE_RATE_` **测得出来**，且**已经产出 82/1420 的实数**。

⇒ 若先删掉 `_MID_CHANGE_RATE_`，就会变成：
**唯一测不出来的指标成为唯一可用的门禁** —— 这显然不合理。

### 2.3 它能不能被**容量差**替代？—— **不能**

实测：**26 条闭环换了中间池，但只有 22 条容量有非零差**。
（差值中位 0、零差 142、负 18、正 4。）

⇒ **换了池但容量恰好相同**的 4 条，会被容量指标**完全漏掉**。
且容量口径本身**已被明令不得改动**（`02 §9.2` 门禁不放宽），
用它当门禁会引入"门禁依赖另一个门禁不许动的量"的**循环依赖**。

## 3. 但它**确实有四个真实缺陷** —— 必须修

### 缺陷 1：**分母选错了**（最严重）

分母用 **1420 三元组**（含**锚点维度**），而"换池"这件事**本身是池维度的**。
同一批池的换池被**多个锚点重复计数**（平均 1.39 个锚点/方向对）。

**后果**：这个数**同时被两件事放大** —— 真实的换池幅度 + 锚点重复。
实测 82 次变化只涉及 **12 个池**，说明**分母的放大效应显著**。

**建议**：**主判据改为池维度**，例如
「**换池所涉及的不同 `(pair, direction)` 组占比**」或「**涉及的不同新池数 / 可用池数**」。
当前的 1420 分母可**保留为辅助读数**（它有诊断价值：反映"波及面"）。

### 缺陷 2：**口径没写死**（已在前文提出）

实测报告同时给了 **三个**变化率（5.77 / 8.03 / 9.01 %），脚本只用了 Δ2。
**只写数值而不写口径，这个阈值仍然是不完整的。**

**建议**：裁定书写成
`_MID_CHANGE_RATE_ = 10 %，判据 = changedTargetUniverseRateTriples（Δ2 换宇宙），并集口径辅助记录`。

### 缺陷 3：**它是"决策层"指标，却用"结果"语言表述**

阈值表写的是「中间跳选池变化率 > X % ⇒ 回到 01 §4.1 **重审主序**」。
但 §4.1（Q1）讨论的是**"兑换最多"用哪个量** —— 是**排序主序的定义**。

**而本次波次恰恰证明了主序定义是对的**：
主序 = `directional_output`（价格质量）→ tick → fee → pool_id，
**与现有两侧跳的 `recommend_direction` 完全一致**（`02 §3.3`）。
中间跳改过来只是**补齐**，不是**改设计**。

⇒ **命中这个阈值时该做的事，与"重审主序"不完全一致**。
正确动作更接近：**逐条解释这 82 次变化（集中在哪些代币对 / 是否集中在方向 0 或 1）**，
以及**确认这些变化是否源于主序本身的缺陷**。

**建议**：把命中动作改成**两段式**：
1. **先做归因**（变化的 12 个池 / 24 个方向对集中在哪？是特定代币对的问题，还是普遍现象？）；
2. **归因结果**再决定是否需要回到 §4.1。

### 缺陷 4（附带）：命中阈值时**还应同时看绝对量**

实测 82 次变化 ÷ 1020 个方向对中只有 28 个方向对涉及。
⇒ 一个"换池率 10 % 但只集中在 1 个代币对"的场景，与"10 % 均匀分布"的严重性**完全不同**。

**建议**：加一个**并列触发条件** —— 「涉及的不同方向对数 ≥ N」或「涉及的不同池数 ≥ N」。

---

## 4. 为什么三个阈值的量纲不能统一

| 阈值 | 分母 | 实测 | 它回答的问题 | 灵敏度 |
|---|---|---|---|---|
| `_MID_CHANGE_RATE_` | 1420 三元组 / 建议改池维度 | 5.77 % | **主序**要不要重审？ | **最灵敏**（最先动） |
| `_LOOP_NET_RATE_` | 168 闭环 | 0.00 % | **产能**损失多少？ | 中 |
| `_PROFIT_DROP_` | 26 条受影响闭环的中位数 | **未测量** | **金额**代价多少？ | **最钝**（最后动） |

⇒ 三者是**一条衰减链上的三个采样点**，不是三个可互相替代的同类指标。
**把 `_MID_CHANGE_RATE_` 删掉，等于砍掉链条的源头，只留两个下游采样点 —— 而其中一个还测不出来。**

## 5. 最终建议

### **保留 `MID_CHANGE_RATE`，但按下列四条修订**

| # | 修订 | 具体做法 |
|---|---|---|
| **1** | **改分母** | 主判据改**池维度**（不同 `(pair, direction)` 组占比，或涉及池数 / 可用池数）；1420 三元组口径**保留为辅助读数** |
| **2** | **写死口径** | 明写 Δ2 换宇宙，并集口径辅助记录 |
| **3** | **改命中动作** | 从"直接回 §4.1 重审主序"改为**两段式**：先**归因**（集中度分析），再决定是否回 §4.1 |
| **4** | **加绝对量触发** | 并列条件：涉及的不同方向对数 / 池数 ≥ N，避免"高比率但高度集中"被误判 |

### **建议数值（修订后）**

| 口径 | 建议阈值 | 实测 | 判定 |
|---|---|---|---|
| **主判据（池维度）**：涉及的不同 `(pair, direction)` 组占比 | **10 %** | 28 / 1020 = **2.75 %** | 不命中 |
| **辅助**：涉及的不同新池数 / 可用池数 | **20 %** | 12 / 86 = **14.0 %** | 不命中 |
| （参考）原三元组口径 | 10 % | 5.77 % | 不命中 |

**三个口径在修订后仍全部不命中** ⇒ 建议阈值**不会因口径选择而翻转结论** ——
这使该阈值**稳健**，是选它的又一个理由。

### **裁定栏**

| 项 | 内容 |
|---|---|
| 阈值 | `_MID_CHANGE_RATE_` = **10 %**（主判据：池维度） |
| 口径 | 不同 `(pair, direction)` 组中发生换池的占比（Δ2 换宇宙）；并集口径辅助记录 |
| 辅助触发 | 涉及的不同池数 ≥ **20 %** 可用池 |
| 命中动作 | **先归因**（集中度分析），再决定是否回 `01 §4.1` 重审主序 |
| **裁定人** | （**待填**：使用者） |
| **裁定日期** | （**待填**：2026-11-23） |
