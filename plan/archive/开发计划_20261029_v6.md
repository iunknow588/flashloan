> 权威基线：`plan/待完善任务清单_20261027.md`；每轮 SOP：`plan/可执行计划_20261027.md`；错误处置矩阵：`plan/错误处置策略_20261029.md`。

## 3. 执行顺序（A -> B -> C）

1. A 轨（本轮实施）：M3-2 与 M6-3 并行，代码修改与定向回归相互独立。
2. A 验收通过后：更新任务清单“已收口摘要”，解除 M3-2 前置门禁；M3-1 生产扫描启动仍需用户确认维护窗口。
3. B 轨（用户确认后执行）：只读恢复前 snapshot、按已批准增量范围运行、必要时 `--verify-only` 顺序重建、重跑四类 evidence 与 validate。生产进程启动/重启仍须用户明确确认。
4. C 轨（恢复扫描后）：M1/M2/M6-2/M8-1/P1 按触发条件观察；M4/M5 按证据与审批触发。

## 4. A 轨交付

### A1：M3-2 作用域完整性门禁

1. 修改 `flashloan/src/dex/tools/refresh_robinhood_v4_live.py::_v4_incremental_database_state`。
2. eligible 口径：known token universe（`robinhood_v4_idle_maintenance._known_pool_token_addresses`）、`fee>0 AND fee<=3000 AND (fee & 8388608)=0`、no-hook；复用 `_candidate_eligible_missing_liquidity_count`，不新写第三份过滤实现（函数内局部导入，避免与 `idle_maintenance -> refresh` 现有导入形成循环）。
3. 输出新增：`eligiblePoolCount/eligibleConfirmedCount/eligibleZeroCount/eligibleUnknownCount/genericUnknownCount/totalPoolCount`；`complete = eligiblePoolCount>0 AND eligibleUnknownCount==0`；eligible zero 是终态，generic unknown 只计数不参与判断；保留旧字段以兼容调用方。
4. `_resolve_v4_scan_decision` 与 `--from-block`/`--full-index-scan` 语义不变。

### A2：M6-3 错误处置策略框架化

1. `error_registry.py`：`ErrorDefinition` 增加 `disposition/action`；新增 `resolve_disposition(...)` 与规范化错误名映射，覆盖策略矩阵 3.1-3.4；`manual_review` 降级为通知字段；未知默认 `DESIGN_BLOCKED`。
2. `revert_parser.py`：解析结果增加 `disposition`；无子错误/无法解析一律 `DESIGN_BLOCKED`。
3. 广播结果桥接：失败结果透传 `errorKey/errorCode/disposition`。
4. `closed_loop_consumer.py`：广播失败按 disposition 执行 `VERIFY_CHAIN_STATE`（复用 `dex_route_rpc.fetch_dex_tx_receipt`，confirmed/failed/pending/absent 四态与 Rust pending nonce 辅助）、`CLOSE_AND_QUARANTINE`、`STOP_BROADCAST_SCOPE`；全部落自动终态或隔离，无 `wait_for_manual` 分支。
5. 隔离：状态机新增轻量表 `v4_closed_loop_error_isolation`，键 `(network, chain_id, protocol, scope_key, error_fingerprint)`，默认冷却 `DEX_ERROR_ISOLATION_COOLDOWN_SECONDS=300`；`dex_opportunity_scanner_rust_mixin` 提交前检查隔离命中并跳过。
6. 审计：`broadcast_failure_audit.py` 记录新增 error key、原始错误、disposition、attempt、generation、owner、下一状态、下次执行时间与隔离原因；读取端兼容旧行。
7. v1 边界：不修改 Rust；`RESUBMIT_SAME_RAW_ON_TRANSPORT` 默认关闭（`DEX_RESUBMIT_SAME_RAW_ENABLED=0`），缺 raw 或关闭时 unknown/transport 结果 verified 后按 `CLOSE_AND_QUARANTINE` 落终态；禁止抬 gas、改 nonce、重签。

## 8. 安全边界

- 禁止手工修改 evidence、SQLite、`latest.json` 或运行时 API；readiness 只能由 CLI 写入。
- 禁止跨 RPC 重发广播；RPC failover 只用于只读复核。
- 禁止将 `replacement transaction underpriced` 作为提高 gas 重试的触发条件；出现该错误视为同 nonce pending 冲突，停止广播后按策略自动核对并落终态。
- 错误处置不依赖人工复核，人工只读告警与审计。
- 禁止擅自启动、重启、kill 生产进程；生产扫描启动必须用户确认。
- 禁止将历史 success 伪造成在线记录或作为 M9-1 依据。
- 38664 个 generic 池不作为 YC/ZC 盲扫对象；候选回补仅在方向候选少于 5 时触发。
- 工作区既有未提交改动不回退、不覆盖；涉及文件仅增量修改。
