## 3. FIX-R19-01（核心修复）：composite_manager 跨 scope 假阳性

### 3.1 根因

`flashloan/tools/composite_manager/src/lib.rs` 的 `assess_upstream()` 将
`closed_loop.pool_scope_checksum` 与 **`candidate_exchange.pool_scope_checksum`** 比较。
但两者分属**不同 scope**：

| scope | 表 | filter_mode | checksum |
|---|---|---|---|
| `core4` | `v4_exchange_pools_core4` | `edge_any` | `sha256:335f0bbf05c03ec6a3d780d6e4b462abf3fdcff992baea98d8332c7349c041e9` |
| `candidate_exchange` | `v4_exchange_pools_candidate_exchange` | `both_end` | `sha256:aae839c344abc67c73ab387147a6d715bd2703db57a7e13426509f5b6c34f5dc` |

`closed_loop` 属于 `core4`，**永远不可能**与 `candidate_exchange` 相等 →
永久假阳性 → `CompositeError::UpstreamInconsistent` **阻断整个 pipeline refresh**。

`closed_loop_manager/src/lib.rs` 的 `closed_loop_pool_scope_checksum()` 已有明确注释说明
同一原则（closed loop 属 core4，必须使用 core4 checksum），这证明 composite_manager
的比较是**缺陷**而非设计。

### 3.2 修复

比较对象改为 `snapshot.candidate_edge.pool_scope_checksum`（同为 `core4` scope），并加注释说明。

### 3.3 回归测试

新增 `closed_loop_pool_scope_checksum_is_compared_against_the_core4_scope`
（`flashloan/tools/composite_manager/src/lib.rs`）：

- fixture：`enabled_libraries()`（4 个库全 enabled）、`pool_scope.enabled=true`，
  materialized / live 均为 `CORE4_SCOPE`；
- 断言 1：edge=core4、exchange=candidate_exchange、closed_loop=core4 → `consistent=true`；
- 断言 2：closed_loop=stale-core4 → `consistent=false`，且 issue 期望值为 `CORE4_SCOPE`。

**反向有效已验证**：临时把修复改回 buggy 版本 → 测试 FAILED；恢复修复 → 测试 ok。

## 4. FIX-R19-02：陈旧 `consumersNeedRebuild` 标志

`consumersNeedRebuild` 是 **sticky transient** 标志：materialize 时置 `checksum_changed`，
只有后续**无变化**的幂等 materialize 才清除（见 `closed_loop_manager` 既有测试
`repeated_apply_is_stable_and_idempotent`）。该标志曾使 assessment 仍报告
`closed_loop.consumersNeedRebuild`，尽管底层数据已经一致。

通过 dry-run 后 apply 的幂等 rebuild 收敛，测试网 `consumers_need_rebuild=0`，
assessment 变为 `consistent=True`、`issues=[]`。**该收敛仅作用于测试网数据库。**
