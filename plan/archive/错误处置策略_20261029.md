# Robinhood V4 错误处置策略基线（2026-10-29）

> 本文件定义运行时错误的自动处置口径。运行时不得等待人工复核；人工只在设计、评审和发布阶段修改策略矩阵。未分类错误必须自动阻断并生成设计阶段待分类记录。
> 适用范围：Robinhood V4 测试网 46630 的报价、链上复核、广播、回执和闭环消费路径。

## 1. 设计原则

1. 错误处理顺序固定为：标准化错误 -> 解析错误类型 -> 查策略矩阵 -> 执行动作 -> 落库状态 -> 记录审计。
2. `manual_review` 不能作为运行时阻塞状态。历史字段可以保留用于告警兼容，但不得产生 `wait_for_manual` 分支。
3. 每个已知错误必须有确定的 `disposition`、最大尝试次数、退避、状态迁移和幂等键行为。
4. 未知或无法安全判定的错误统一执行 `STOP_AND_QUARANTINE`：停止当前广播、标记失败或待核对、隔离本路由/闭环、生成设计阶段分类事件；不重发、不等待人工决定。
5. 设计阶段允许人工新增或修改策略；策略发布前必须有单元测试和回放测试，运行阶段只执行已发布矩阵。

## 2. 统一自动动作

| disposition | 自动动作 |
|---|---|
| `CLOSE_NO_OPPORTUNITY` | 当前机会正常结束，关闭/冷却闭环，不广播，不记为系统故障 |
| `REQUOTE_AND_RETRY` | 丢弃旧报价，刷新 live quote/size probe，在预算内重新计算；不复用过期交易 |
| `REFRESH_POOL_SCOPE` | 标记池或方向暂不可用，触发候选/流动性刷新，短期隔离该池 |
| `RETRY_READONLY` | 仅重试 eth_call、quote、receipt 等只读请求；按 RPC 错误预算和退避执行 |
| `VERIFY_CHAIN_STATE` | 跨 RPC 查询 nonce、transaction、receipt；根据 confirmed/pending/absent 自动落库 |
| `RESUBMIT_SAME_RAW_ON_TRANSPORT` | 仅在同一签名 raw tx、原交易未确认、幂等状态允许且错误确定为传输失败时有限重投；不重新取 nonce、不改 gas、不重签 |
| `CLOSE_AND_QUARANTINE` | 当前闭环失败落库，隔离路由/池/错误指纹，阻止立即重试 |
| `STOP_BROADCAST_SCOPE` | 关闭当前链/合约/路由广播门，保留只读观察，等待设计策略或配置版本更新 |
| `DESIGN_BLOCKED` | 运行时自动 fail-closed，生成设计阶段分类事件；不依赖人工临场判断 |

## 3. 已知错误策略矩阵

### 3.1 报价、收益和流动性

| 错误 | 自动 disposition | 结果 |
|---|---|---|
| `profit_too_low` | `CLOSE_NO_OPPORTUNITY` | 正常无利润，关闭当前机会；不广播、不重试同一报价 |
| `not_profitable_after_costs` / `route_unprofitable` | `CLOSE_NO_OPPORTUNITY` | 关闭当前机会；下一轮扫描生成新报价 |
| `slippage_exceeded` | `REQUOTE_AND_RETRY`，超预算后 `CLOSE_AND_QUARANTINE` | 刷新报价或降低输入量；不重发旧交易 |
| `not_enough_liquidity` | `REFRESH_POOL_SCOPE` | 排除当前池/方向，刷新流动性；不立即重复同一请求 |
| `pool_not_initialized` | `REFRESH_POOL_SCOPE` | 标记池未初始化并刷新索引；不广播 |
| `live_quote_failed` / `quoter_failed` | `RETRY_READONLY`，预算耗尽后 `CLOSE_AND_QUARANTINE` | 只读重试，禁止进入广播 |
| `size_probe` 失败 | `REQUOTE_AND_RETRY` 或 `CLOSE_NO_OPPORTUNITY` | 重新选择可执行金额；没有可行金额则关闭 |

### 3.2 RPC、提交和回执

| 错误 | 自动 disposition | 结果 |
|---|---|---|
| connection refused/reset/timeout/429/502/503/504 | `RETRY_READONLY`；广播结果未知时先 `VERIFY_CHAIN_STATE` | 只读请求可换 RPC；广播不直接重签重发 |
| 广播传输超时且结果未知 | `VERIFY_CHAIN_STATE` | 查 receipt 和 transaction；confirmed=成功，pending=已提交，absent 才按幂等策略决定是否同 raw 有限重投 |
| `already known` | `VERIFY_CHAIN_STATE` | 视为 raw tx 已进入节点，查 receipt/pending；不重新签名 |
| `nonce_too_low` | `VERIFY_CHAIN_STATE` | 查询该 nonce 的交易和 receipt；不得增加 gas 重发 |
| `replacement_tx_underpriced` | `VERIFY_CHAIN_STATE` + `CLOSE_AND_QUARANTINE` | 视为同 nonce 冲突；不自动提高 gas、不替换、不重新取 nonce |
| `receipt_failed` / receipt timeout | `VERIFY_CHAIN_STATE` | 跨 RPC 只读确认；不能确认时进入自动隔离状态，不等待人工 |
| `broadcast_not_accepted` | `VERIFY_CHAIN_STATE` | 保存 raw fingerprint、nonce 和错误；按 confirmed/pending/absent 分支落库 |

### 3.3 合约和策略错误

| 错误 | 自动 disposition | 结果 |
|---|---|---|
| `execution_reverted` | 先解析子错误，再执行对应策略；无法解析则 `DESIGN_BLOCKED` | 不把通用 revert 当作 RPC 重试 |
| `paused` | `STOP_BROADCAST_SCOPE` | 当前合约广播关闭，只读保留 |
| `not_owner` / `bad_initiator` | `STOP_BROADCAST_SCOPE` | 配置或调用身份错误，自动阻断当前 scope |
| `adapter_missing` / `flash_source_missing` | `STOP_BROADCAST_SCOPE` | 配置缺失，自动阻断并记录设计配置事件 |
| `bad_flash_callback` / `not_pool` / `bad_initiator` | `CLOSE_AND_QUARANTINE` | 隔离路由和合约配置，不重试同一交易 |
| `router_call_failed` | `CLOSE_AND_QUARANTINE` | 当前路由失败，重新报价前不重发 |
| `transfer_failed` / `insufficient_balance` / `insufficient_allowance` | 按授权/余额策略自动刷新；仍失败则 `CLOSE_AND_QUARANTINE` | 不重复广播同一 raw tx |
| `bad_flash_repayment` / `repayment_insufficient` | `STOP_BROADCAST_SCOPE` | 资金安全错误，自动关闭广播，进入设计配置修正 |
| `reentrancy` | `STOP_BROADCAST_SCOPE` | 安全错误，自动关闭广播，不重试 |
| `out_of_gas` | `CLOSE_AND_QUARANTINE` | 保存 gas 证据；不得自动抬 gas 重试，需由设计阶段调整 gas 策略后发布 |
| `deadline_expired` | `REQUOTE_AND_RETRY` | 旧交易作废，生成新报价和新 deadline |

### 3.4 校验、作用域和内部错误

| 错误 | 自动 disposition | 结果 |
|---|---|---|
| `invalid_request` / `route_invalid` | `CLOSE_AND_QUARANTINE` | 拒绝当前请求，保留输入快照，不重试原请求 |
| `scope_mismatch` / `chain_scope_required` | `DESIGN_BLOCKED` | 自动阻断错误 scope，生成配置/设计事件 |
| `broadcast_disabled` / gate not ready | `STOP_BROADCAST_SCOPE` | 只读继续，广播不提交 |
| `execution_queued` / `broadcast_deferred` | 非错误，进入队列状态 | 由唯一广播消费者继续处理，禁止旁路执行 |
| `internal` / `flow_missing` / 未知错误 | `DESIGN_BLOCKED` | fail-closed、隔离、记录完整错误堆栈；不能由运行人员临场决定 |

## 4. 设计阶段必须解决的“不可直接处理”项

以下不是运行期交给人工的问题，而是发布前必须补齐的设计工作：

| 项目 | 设计阶段交付 |
|---|---|
| 错误无法解析 | 增加错误模式、错误码和 disposition；补充回放样本与单元测试 |
| 同 nonce 状态不确定 | 完成 receipt/transaction/pending nonce 三态机，定义 confirmed/pending/absent 的唯一迁移 |
| 合约 revert 无子错误 | 增加 ABI 解码或稳定 fallback；fallback 必须 `DESIGN_BLOCKED`，不能自动广播 |
| 路由或池持续失败 | 定义错误指纹、冷却时间、隔离范围和自动恢复条件 |
| gas/nonce 策略需要调整 | 在设计阶段更新版本化配置、回归测试和发布门禁；运行期禁止动态抬 gas 或改 nonce |
| 新错误未登记 | CI/启动门禁拒绝未登记错误；运行时执行 `DESIGN_BLOCKED` 默认策略 |

## 5. 运行时闭环要求

1. `closed_loop_consumer.py` 必须消费结构化 `error_key/error_code/disposition`，不能只根据字符串是否为空决定成功或失败。
2. `manual_review` 只能作为通知字段，不能阻止 `complete_loop`、不能要求人工点击、不能让队列无限等待。
3. 每个自动动作必须记录：错误 key、原始错误、disposition、attempt、generation、owner、下一状态、下次执行时间和隔离原因。
4. 每个未知错误必须有自动终态或自动隔离结果；测试不得出现“等待人工复核”作为唯一验收条件。
5. 设计阶段修改策略矩阵后，必须重新运行错误回放、闭环状态机、广播回传和重复广播回归测试。
