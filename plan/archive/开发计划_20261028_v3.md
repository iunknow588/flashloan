# Robinhood V4 测试网 M0-M8 + P1-P5 开发计划（2026-10-28 v3）

> 权威基线：`plan/待完善任务清单_20261027.md`。本计划是可交付、可照单执行的完整排期视图，不替代源任务清单；任务编号、推进类型、触发条件与验收均以源清单为准。逐项 SOP 见 `plan/可执行计划_20261027.md`。
> 适用范围：只推进 Robinhood V4 测试网 46630 实盘观察与 M0-M8、P1-P5；主网 4663 只读对照，广播保持关闭；M9 主网开启不作为本轮执行项。

## 1. 目标与执行口径

- 目标：恢复并在维护窗口确认后持续保持 46630“自动扫描 -> 实时链上复核 -> 可盈利自动广播 -> `execution_success`/`tx_hash` 稳定落库”连续窗口；M7-4/M7-5/P1-P5 等工程项在不阻塞恢复的前提下自主推进。
- 执行依据必须是实时行情/链上 Quoter（`dex_quote_routes`、live Quoter 或 `eth_call`）；历史快照只作审计，不作可执行依据。
- readiness 只由 CLI 写入；无 signed 值时 P&L 保持 `null` + `missingReason`，不用零占位、不把 SQLite 参考标注为 eth_call 结果。
- 在线分析命令全部显式指向 46630 独立库 `flashloan/db/local_store_46630.sqlite3`；默认不读写遗留统一库 `flashloan/db/local_store.sqlite3`。
- 线程统一由 `V4MaintenanceWorkerManager` 与 Rust `worker_pool` 管理：资金池、候选池、市场观察、Dex 总览、闭环、链上复核、广播执行按固定顺序依赖；Python 只作桥接与持久化，不另起平行扫描通道。
- evidence 仍写入 `flashloan/src/runtime/evidence/robinhood-testnet/*`，`latest.json` 只由脚本刷新；不手工修改 evidence、SQLite、`latest.json` 或运行时 API。

### Phase A：文档与基线收口（立即）

1. 生成 `plan/开发计划_20261028_v3.md` 为当前完整排期视图；将 `plan/开发计划_20261027_v2.md` 归档到 `plan/back/`；更新 `plan/back/README.md` 指向。
2. 维持 `plan/待完善任务清单_20261027.md` 为唯一权威基线，`plan/可执行计划_20261027.md` 为逐项 SOP；本轮不修改两份正文的执行口径。

### Phase B：M7-4 链上复核值落库与 UI 对比（自主推进）

1. 在 `cow_execution_reviews` 与 `cow_execution_attempts` 增加可空列 `selected_profit_raw`（TEXT）、`selected_profit_amount`（REAL）、`selected_profit_amount_symbol`（TEXT）、`selected_profit_source`（TEXT）、`selected_profit_missing_reason`（TEXT）。
2. 沿用现有 `PRAGMA table_info + ALTER TABLE` 迁移模式，仅新写入行填充；历史行保持 `null`，不 backfill。
3. 在 `rust_closed_loop.py` 已透传的 `selectedProfitRaw/Amount/AmountSymbol/Source` 基础上，于 CoW 写入路径（`storage_cow_execution.py`、`cow_execution_mapping.py`）落列；无原生 signed 值时写 `null` + `missingReason`。
4. 提交记录页与报价/路由页展示“链上复核值 vs 参考执行估算值”及 `delta`；来源文案只认 `selectedProfitSource`，不把 SQLite 参考误标为 eth_call 结果。
5. 验收：新复核/成功记录四列可查询、历史行 null、UI 无来源误标；新增存储与页面回归。

### Phase C：M7-5 路由执行门禁回归（自主推进）

1. `quotes_render.js` 已满足“仅 worker busy 灰化实时链上复核、链上执行始终可点击”，本轮只补回归断言。
2. 断言 `route_unprofitable`/静态参考未确认最优量时 broadcast 按钮无 `disabled`；仅 worker busy 时“实时链上复核”灰化。
3. 断言点击“链上执行”先 `static_call` 复核、确认最佳交易量后再 `auto` 提交；未确认最优量时不提交并落 `__broadcastError`。
4. 验收：新增页面门禁回归通过，`route_unprofitable` 不再阻断按钮可点。

### Phase D：M6-2 广播结果回传断点排查（自主推进）

1. 补 `rust_closed_loop.py` 到 `dex_opportunity_scanner_rust_mixin.py` 的透传测试，断言 `last_result` 保留 `broadcast`、`broadcastError`、`executionQueued`、`executionQueueAt`。
2. 覆盖 `deferBroadcast` 开关两条路径与 `executionQueued=true` + `executionQueueAt` 场景。
3. 若断言失败则修复透传，不重发历史广播、不补历史 `txHash`。
4. 验收：广播结果回传测试通过，`execution_success`/`tx_hash` 落库前提确认。

### Phase E：P5/P4/P2 状态机与线程统一（自主推进）

1. P5：闭环状态机核心已落地；本轮把 `closed_loop_state_machine.py` 接入复核/广播消费路径：扫描到到期闭环先写 `offchain_estimate`，复核线程 `claim_loop(operation=review)` 成功才启动，完成后 `complete_loop`；复核通过 `enqueue_execution`，广播线程 `claim_loop(operation=broadcast)` 后执行，结果 `complete_loop` 落 `execution_success`/`execution_failed` + `tx_hash`。
2. P4：在 `worker_pool.rs` 增加动态 supervisor：任务到来且并发未满时按 loop key spawn 复核/广播线程，完成即回收；空闲超时默认 60s 退出；统计 `createdTotal`、`active`、`completed`、`idleExits`；均先 CAS 领取状态，重复复核/广播计数恒为 0。
3. P2：Rust `worker_pool` 负责原生复核与广播，`V4MaintenanceWorkerManager` 负责 7 个维护槽位；Python 仅作桥接与持久化；Rust 不可用时保留 Python fallback，但必须走同一状态机。
4. 线程上限统一为 `DEX_CLOSED_LOOP_MAX_WORKERS`（默认 16、硬上限 32）。
5. 验收：状态机接入与动态线程单测通过，`cargo test worker_pool --lib` 通过，重复复核/广播为 0。

### Phase F：P3 独立作用域索引器（自主推进）

1. 新增 `v4_scope_indexer.py`：按 `pool_id` 精确查询候选/市场观察/闭环归属，支持作用域标签与增量游标。
2. 新增只读 CLI `scripts/refresh_robinhood_v4_scope_index.py --chain-id 46630 --verify-only`，复用 `chain_business_initialization` 游标，不改变在线表结构。
3. 验收：索引器可精确查询池/方向/闭环归属，单测通过，避免无目的全量重扫。

### Phase G：M3-1 恢复与 M1/M2/M8-1/P1 观察（等待维护窗口）

3. M2 条件触发：新 unique success 后依次验证 P&L、auto-scan、expected-vs-actual、差异逐跳分析。
4. M8-1/P1：连续观察“live-ready 复核 -> 自动广播 -> success 落库”无断点；在 2/4/8 worker 下记录 `executionQueue` 摘要，确认无饿死、无重复广播。

## 7. 安全边界（禁止事项）

- 禁止手工修改 evidence、SQLite、`latest.json` 或运行时 API；readiness 只能由 CLI 写入。
- 禁止用旧 `live_verified` 记录或手工 attempt JSON 冒充当前包。
- 禁止把 SQLite 参考 P&L 标记为 eth_call 链上复核结果。
- 禁止跨 RPC 重发广播/提交；RPC failover 只用于只读复核。
- 禁止擅自启动、重启、kill 生产进程；受控操作前确认无进行中复核。
- 禁止在无链上 evidence 时调整参数或搜索模式。
- 禁止将测试网历史 success（仅存 evidence）伪造成在线 SQLite 成功记录，或作为 M9-1 已满足依据。
- 禁止直接对遗留 `flashloan/db/local_store.sqlite3` 或 3.6GB 生产库执行非 dry-run 分库/迁移。
