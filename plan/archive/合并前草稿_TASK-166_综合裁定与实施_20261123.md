## 0. 裁定摘要（一页版）

```text
【一】三个数字的**身份**：由「参数（门禁）」降级为「读数（归因依据）」
      · 删除的是**门禁语义**，不是**数字本身**
      · A 的 10 % / 5 % / 20 % **保留为观察线**，但**不再否决任何阶段**
      · 观察线命中时**不阻塞**，只触发**归因升级 + 人工复核**

【二】门禁的替代物：**不是数值，是流程**
      · 删除「变化幅度超阈值 ⇒ 不得进入 P1」
      · 替换为「**换池读数与归因**已产出并**经人工签字** ⇒ 方可进入 P1」
      · 它挡的是「没查清就开工」，**不是**「数值太大就停工」

【三】`_PROFIT_DROP_`：数值保留（20 %），**推迟生效**
      · 当前测不出来（旧利润 154/168 未测量，新利润只读不可算）
      · 登记为 **P2 退出条件**：实盘波次必须实测一次

【四】选池算法（B）：**采纳 B 的三处修正**，作为方向层落地的算法口径
      · 备用池 = **合格但落选**的池，**不是**现有 `abnormal` 层（实测 339 个异常池过真准入数 = 0）
      · 候选数 `N = min(N_max, 合格池数)`；实测最大仅 4，「5」只能是**上限**
      · 「最少 1 个」是**下界承诺**，不是配额（72.8 % 的方向链上无池，不得凑数）

【五】「最近一周有交易」：**独立立项**，本波次**不阻塞**
      · `recent_swap_active` 2486/2486 全 NULL，系统无交易信号
      · B 的算法第 0–5 层**全部可执行**；第 6/7 层等新数据源
```

> **一句话**：**参数与读数的区别，不在于有没有数字，而在于数字被用来做什么。**
> 门禁型数字回答「准不准许」，必须有明确的比较对象与**否决后果**；
> 读数型数字回答「发生了什么」，只需要**口径清楚 + 可复算**。
> 本系统对这次变更**没有否决后果可承担**（P1 并存不动现网、闭环目录每次物化整体替换），
> 因此这三个数字**只能**是读数；而**读数可以带一条观察线** —— 这就是 A 与 C 的调和点。

### 1.2 D1 的调和：**删掉「参数」这个壳，留住「数字 + 口径」**

C 的核心区分是：

```text
「参数」= 一个需要被「写死」、用来做「是/否」判定的数
「读数」= 一个必须被记录、用来做「解释」的数
```

**但 A 提出的 10 % / 5 % / 20 % 并不是无用之物** —— 它们是**观察线**：

| | 门禁（参数） | **观察线（读数）** |
|---|---|---|
| 用来回答 | 「准不准许」 | 「**变了多少、变在哪**」 |
| 比较对象 | 必须有 | 有则更佳，**无则不否决** |
| 命中后果 | **否决 + 退回** | **归因升级 + 人工复核** |
| 谁来判 | 机器 | **人**（脚本只报不判） |

⇒ **裁定**：三个数字以**「读数 + 观察线」**的双重身份写入文档：

- **读数身份（强制）**：每次口径变更波次**必须产出**，口径必须写清，数值必须可复算；
- **观察线身份（非强制）**：命中观察线**不阻塞任何阶段**，只**升级归因**并要求人工复核；
- **门禁身份（取消）**：不再作为 P0→P1、P1→P2 的准入门禁。

### 1.3 D2 的调和：**用「流程门禁」替换「数值门禁」**

| | 原（数值门禁） | **新（流程门禁）** |
|---|---|---|
| 条件 | 换池率 > 10 % ⇒ **不得进入 P1** | **换池读数与归因已产出 + 人工签字** ⇒ 方可进入 P1 |
| 依据 | 一个待写死的数 | C §4.3 的**两段式归因**（归因必做 → 判定人工） |
| 挡的是 | 「数值太大」 | 「**没查清就开工**」 |
| 失效风险 | 数值失真 ⇒ 误挡 / 漏挡 | 归因缺失 ⇒ 开工后才发现问题 |

⇒ **「不得进入 P1」这条禁令被删除**，理由不是「阈值不重要」，而是：

1. **无可保护对象** —— P1 是纯并存：新表写入、旧链路**一字不变**、可回滚（`03 §2.2`）；
2. **无旧值需要守住** —— 闭环目录每次物化**整体替换**（`replace_closed_loop_rows` 先 `DELETE` 再 `INSERT`）；
3. 因此原禁令保护的是一个**不存在的风险**。

### 1.4 D4 / D6 的裁定：**采纳 B 的三处修正**（方向层算法口径）

| # | 修正 | 依据（只读实测） |
|---|---|---|
| **1** | **备用池 ≠ 异常层**：备用池 = **合格但落选**的池 | `abnormal` 层 **339** 个池，按真准入（费率 ≤ 30000、无 hook、status=active）检查**通过数 = 0** |
| **2** | **「最少 1 个」是下界承诺，不是配额** | 中间跳候选数为 **0** 的方向 **1034 / 1420 = 72.8 %**（`no_reachable_v4_pool` 1004 / `only_abnormal_pools` 30）⇒ 不得凑数 |
| **3** | **候选数 `N = min(N_max, 合格池数)`** | 中间跳候选数分布 `{1: 73, 2: 53, 3: 6, 4: 36}` ⇒ **最大只有 4**，「5」只能是上限 |
| **4** | **顶替须可判定**：同一 `(pair, direction)` 组内按主序键比较，顶替后**重排序位**（保 I-6） | 不得跨代币对比 `directional_output`（单位不同，`01 §4.2`） |
