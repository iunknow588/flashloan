## 2. 核心缺陷一：闭环池解析只看锚点作用域，共享桥接池被整体丢弃

### 2.1 现象

主网 `db_closed_loop_sequences(...)` 返回 **0** 条序列，`closedLoopSequences=[]`，
`test_mainnet_closed_loops_use_fixed_fee_pools_without_hooks` 断言失败。

### 2.2 证据（主网 4663 实测）

| 指标 | 数值 |
|---|---|
| `v4_closed_loops` | 46 |
| `v4_closed_loop_hops` | 138 |
| 闭环节点中**不在观察面**的跳数 | 92 |
| 闭环节点中**不在候选面**的跳数 | 88 |
| 26 个桥接池（hop_index=2）中**完全不在候选面**的 | 19 |
| 链级 `v4_exchange_pools` 对闭环池的覆盖 | **36/36** |
| 链级 `v4_exchange_pool_liquidity_snapshots` 对闭环池的覆盖 | **36/36** |

关键点：**闭环池本身 100% 存在于链级表中**，只有锚点作用域面缺行。

### 2.3 机理

候选面与观察面按锚点（anchor）建表。桥接腿的池是**跨锚点共享**的，
只会记录在"发现它"的那个锚点下。而闭环解析 `_anchor_candidate_pool()`
只查当前锚点的作用域面，查不到即返回 `None` → 该跳被跳过 →
`len(route_rows) != 3` → **整条序列被丢弃**。

即：一条跳的锚点作用域缺行 = 全市场零序列。

### 2.4 修复

`flashloan/src/dex/intent_trade/chains/robinhood_common/market_observation_core.py`
→ `_anchor_candidate_pool()`：锚点作用域面查不到时，**回落到链级
`v4_exchange_pools` / `v4_exchange_pool_liquidity_snapshots`**。

链级表才是市场的物理真相，锚点面只是派生视图。

## 3. 核心缺陷二：Rust 内核准入判决没有发布到链级流动性快照

### 3.1 机理

`has_confirmed_depth()` 消费 Rust 内核发布的 `kernelAdmitted` 判决。
`business_builder.rs` 只把它写进 `dex_candidate_pools.depth_band_json`
（**锚点作用域**），而 `v4_exchange_pool_liquidity_snapshots`（**链级**）
2480 行里 `kernelAdmitted` 覆盖率为 **0/2480**。

于是任何从链级表读池子的消费者都得到 `kernel_verdict_missing` → `admitted=false`：
连 TVL $719M、`depth_status=deep` 的池子也被判为"未准入"。

### 3.2 修复（判决仍然归 Rust 内核，Python 不新增任何阈值）

| 文件 | 变更 |
|---|---|
| `flashloan/rs-src/src/evidence.rs` | `attach_kernel_admission_verdict()` 把判决发布到链级快照的深度文档 |
| `flashloan/tools/pool_manager/src/depth_config.rs` | 共享 `admit_candidate_pool_with_liquidity()`，阈值仍读 `flashloan/config/depth_policy.json` |
| `flashloan/tools/pool_manager/src/lib.rs` | `depth_band_json_with_admission()` 在候选面与链级快照两处都发布判决 |

**符合"Python 没有自己的标准"**：判决唯一来源仍是 Rust 内核 + 共享策略文档。

## 4. 链无关性证明（核心 vs 链特定）

| 链 | 修复前序列 | 修复后序列 | 残余阻塞 | 性质 |
|---|---|---|---|---|
| 主网 4663 | 0 | **6** | 无（ETH/WETH/NVDA 路线） | — |
| 测试网 46630 | 0 | 0 | 16 个闭环池中 8 个实测为 `dust`/`shallow`，38 条闭环**全部**被至少一个 dust 池挡住 | **链特定数据条件** |

判定依据：测试网 38 条闭环、114 跳，逐跳统计准入判决后
**fully_admitted=0、blocked=38**，阻塞原因全部是
`depth_verdict_rejected:dust` 或 `:shallow`——这是市场深度事实，不是流程缺陷。

> **结论**：核心缺陷（两处）与链无关；主网/测试网的差异只来自链上池子深度数据本身。
