## 3. 任务拆解与排期

### Phase 0：基线核对与候选恢复准备（立即）

1. 只读核对生产进程：确认 5000/5001 监听进程，不擅自操作。
2. 只读核对测试网库：`cow_execution_attempts`/`cow_execution_reviews` 的总数与最新 `created_at`。
3. 生成候选恢复前 snapshot：记录 `v4_closed_loops`、`v4_closed_loop_hops`、`dex_candidate_pools`、`dex_candidate_anchor_tokens`、`dex_candidate_pool_pairs` 当前值。
4. 准备 46630 库备份：只有在用户确认维护窗口后才停止扫描/auto-execute，再复制备份，绝不直接在运行中库上执行全量重建。
5. 运行 `--verify-only`/dry-run 验证候选 backfill 参数链，不写入在线库。

### Phase 0.5：独立维护线程与增量游标（已落地，生产待下一个维护窗口重启生效）

资金池、候选池、市场观察、Dex 总览、闭环重建、链上复核、广播执行分别由独立线程维护，统一由 `V4MaintenanceWorkerManager` 管理：

1. `v4_pool_liquidity_worker`：固定线程做资金池增量刷新；游标持久化在 `chain_business_initialization`，每轮只读下一批 eligible pool（`skip_index/skip_build/prune=False/replace_evidence=False`），成功后推进游标，失败保留游标，避免整库重扫。
2. `v4_candidate_yc_zc_worker`：候选 YC/ZC anchor 重建，只在资金池游标 complete 后运行。
3. `v4_market_observation_worker`：市场观察重建，只在候选游标 complete 后运行，工作量更轻。
4. `v4_dex_overview_worker`：Dex 总览快照刷新，依赖市场观察与闭环游标。
5. `v4_closed_loop_worker`：闭环 SQLite 重建，依赖市场观察游标。
6. `v4_onchain_review_worker`：轻量 watchdog，只检查 Rust 原生复核线程是否存在并落“reviewer_watch_ok”，实际 `eth_call` 仍在 Rust worker 执行，避免重复复核。
7. `v4_broadcast_execution_worker`：轻量 watchdog，只记录 `executionQueue` 与广播 gate 状态，实际广播仍在 Rust 执行线程执行，避免重复广播。

执行顺序固定为：资金池 -> 候选 YC/ZC -> 市场观察 -> Dex 总览/闭环 -> 链上复核 -> 广播执行；上游游标未 complete 时下游返回 `blocked_upstream`。`run.py` 已接入 `ensure_v4_maintenance_workers_running()`，仅对 46630 测试网生效；当前 5000/5001 无监听进程，待用户确认维护窗口后受控启动，不擅自启动/重启。

### Phase 1：M0-1/M3-1 候选闭环恢复（第一优先级）

用户确认维护窗口后执行，顺序固定：

1. 受控停止周期扫描/auto-execute；确认无进行中复核后停止生产进程或暂停扫描入口。
2. 备份 `flashloan/db/local_store_46630.sqlite3` 到带时间戳文件。
3. 小 batch 验证：
   `python flashloan/src/dex/tools/refresh_robinhood_v4_live.py --network robinhood-testnet --chain-id 46630 --candidate-backfill --pool-ids <样本> --batch-size <小值> --skip-liquidity`
4. 检查候选表增量，确认 `v4_closed_loops` 开始恢复；在维护窗口内逐步扩大批次。
5. 恢复扫描并重跑四类 evidence（见第 6 节）与 validate。
6. 验收：`v4_closed_loops>0`、候选门槛为 1 条活跃候选/5 为推荐池数量上限、T21 出现 signed 值、P&L/auto-scan 有可复核闭环。
7. 维护窗内如出现 `broadcast_result_missing` 且无对应 attempt，按第 5 节“广播结果回传排查”处理。

### Phase 2：M1 持续观察（每轮 SOP）

每轮按以下顺序执行：

1. 确认 5000/5001 监听进程。
2. 只读核对 attempts/reviews 总数与最新 `created_at`。
3. 有新窗口则重跑四类 evidence 与 validate；无新窗口则不重复生成，只沿用最近一份报告。
4. 扫描 `readyForTransactionPreflight=true`、顶层 `chain_submission_candidate` / `can_submit_order` / `checks_passed`。
5. 扫描 `execution_success` / 非空 `tx_hash`；有则触发 Phase 3 M2 链。
6. 复检 M5-2：live strict、predeploy fork、主网只读均 `--no-write`。
7. 追加执行记录：时间、SQLite 窗口、触发状态、evidence 路径、阻塞原因。

M1-2 触发条件：出现可提交 live-ready attempt。执行命令：

```powershell

python flashloan/src/dex/tools/audit_robinhood_chain_test_package.py --network robinhood-testnet
python flashloan/src/dex/tools/check_robinhood_live_testing_readiness.py --strict-live --no-write
```

验收：`--strict-live --no-write` 不再报 stale，且当前包不依赖旧 route_capture。

### Phase 3：M2 链上成交验证（条件触发）

出现新 unique success 后按顺序执行：

1. M2-1：新 signed 正向窗口落入 P&L evidence。
2. M2-2：确认 `broadcast_history` 自动落库为 `execution_success`/`tx_hash`；验收为 `broadcastCount>0` 且 `uniqueSuccessCount>=1`。
3. M2-3：运行 expected-vs-actual，验收为复核报告与链上回执一致。
4. M2-4：仅当 `nonZeroDifferenceCount>0` 时生成含金额、slippage、fee、gas 的逐跳分析 evidence。

### Phase 4：M6-2 广播/落库排查（持续观察）

- 观察广播 gate、live-ready 与 `execution_success` 落库。
- 若仍大量出现 `broadcast_result_missing` 且无对应 attempt，则在 `rust_closed_loop.py` 到 `dex_opportunity_scanner_rust_mixin.py` 的广播结果回传链补测试，确认 worker `broadcast`/`broadcastError` 字段能在 `last_result` 中带回。
- 对历史 4 条 failed 不修改、不补 `txHash`、不重发广播。
- 验收：出现可解释的成功落库，或明确 live-ready 落盘且无断点。

### Phase 5：M7-4/M7-5/M8-1/P1 可自主推进

- 无原生 signed 值时，明确标注来源或 revert 原因，不把 SQLite 参考值误标为 eth_call 结果。
- 验收：字段落库、UI 对比、单测与在线验收完成。

M7-5：

- 验收：`route_unprofitable`/静态参考未确认最优量时“链上执行”仍可点击；非空闲仅灰化实时复核按钮。

M8-1/P1：
- 连续观察“live-ready 复核 -> 自动广播 -> `execution_success` 落库”窗口无断点。
- 在 2-8 worker 下观察 `executionQueue` 吞吐与延迟；确认无执行饿死、无重复广播。
- 验收：连续窗口不再出现复核已通过但无广播/无 success 的断点；`executionQueue` 摘要正常。

## 8. 安全边界（禁止事项）

- 禁止手工修改 evidence、SQLite、`latest.json` 或运行时 API；readiness 只能由 CLI 写入。
- 禁止用旧 `live_verified` 记录或手工 attempt JSON 冒充当前包。
- 禁止把 SQLite 参考 P&L 标记为 eth_call 链上复核结果。
- 禁止跨 RPC 重发广播/提交；RPC failover 只用于只读复核。
- 禁止擅自启动、重启、kill 生产进程；受控操作前确认无进行中复核。
- 禁止在无链上 evidence 时调整参数或搜索模式。
- 禁止将测试网历史 success（仅存 evidence）伪造成在线 SQLite 成功记录，或作为 M9-1 已满足依据。
- 禁止直接对遗留 `flashloan/db/local_store.sqlite3` 或 3.6GB 生产库执行非 dry-run 分库/迁移。
