## 4. 本轮修复的**真实缺陷**

### 4.1 缺陷描述

`FixedRefreshPipeline`（Python 侧遗留回退件）**缺少 Rust 模式闸门**：

| 组件 | 是否有 Rust 闸门 | 修复前 |
|---|---|---|
| `ReviewSupervisor`（Python） | ✅ 有 | `dex_opportunity_scanner_engine.py:159-166`：`if self._supervisor_enabled and not self._native_rust_closed_loop else None` |
| `FixedRefreshPipeline`（Python） | ❌ **无** | `dex_closed_loop_review_queue.py` 的 `start()` **无条件**起线程 |

**实测证据（修复前）**：`DEX_CLOSED_LOOP_NATIVE_RUST=1` 时：

```
native_rust_closed_loop = True
review_supervisor       = None          <- 正确闸门
legacy python threads: ['fixed-closed-loop-refresh-0', 'fixed-closed-loop-refresh-1', 'fixed-closed-loop-refresh-2']
python pipeline executed refresh for: ['weth|usdg|nvda']
=> Python-side review ran while Rust backend active: True
```

即：**Rust 后端激活时，Python 仍起 3 个线程并真实执行复核**。
被执行的 `_fixed_refresh_group`（`dex_opportunity_review_engine_fixed.py:36`）会走
`_closed_loop_review_one_route` → `_run_manual_route_review_and_broadcast`
（`:290`），**包含 auto-broadcast 分支**（`:68-72` `broadcast_executed` → `_record_session_executed`）。

**危害**：Python 侧复核 **绕过 Rust 的复核新鲜度门禁**（120s）与统一流水线，
可能在 Rust 判定之外产生广播尝试 —— 这与 R-164-A 直接冲突。

### 4.2 修复内容（3 个文件）

| 文件 | 改动 |
|---|---|
| `flashloan/src/dex/runtime/dex_closed_loop_review_queue.py` | 新增 `native_rust_enabled` 能力探针参数；新增 `_rust_owns_scheduling()`；`start()` 与 `run_once()` 在 Rust 拥有调度时**直接返回** |
| `flashloan/src/dex/runtime/dex_opportunity_scanner_engine.py` | 把 `native_rust_enabled=lambda: bool(self._native_rust_closed_loop)` 注入流水线；`_native_rust_closed_loop` 的取值**提前**到流水线构造之前 |
| `flashloan/app_runtime/tests/unit/test_architecture_guards.py` | 新增 **2 条架构守卫** |
| `flashloan/app_runtime/tests/unit/test_dex_closed_loop_review_queue.py` | 新增 **4 条行为单测** |
| `flashloan/app_runtime/tests/unit/test_pool_candidates_scanner.py` | 新增 **1 条扫描器级接线单测** |

探针抛异常 → 视为 Rust 拥有调度 → **不得**把复核调度悄悄交还给 Python。

### 4.4 明确**未**改动的部分（避免过度改动）

本轮**没有**改 `/api/dex/closed-loop-groups/<group_key>/refresh` 路由。
理由：该路由是**首次投喂 / 重建路线**的语义，与"手动复核只清零等待时间"是**两种不同操作**。
曾尝试把"已是常驻 worker 的 refresh"也改成清零等待，**导致 2 条既有单测失败**
（`test_scanner_rust_refresh_feeds_group_without_python_pipeline`、
`test_scanner_rust_refresh_uses_closed_loop_manager_for_unobserved_anchor`），
**已完整回退**。手动复核/广播（`manual-review` / `manual-broadcast`）**本就已是**
清零等待的纯 Rust 路径，无需改动。
