### 10.2 profit 信息完整性修复

根因：

- 主网复核已经调用 `previewBestPoolDetailed`，其 `netProductDeltaRaw` 为 signed 数值（可正可负），但 Python 读取侧只把 `selectedProfitRaw`/`arbitrageNotProfitable` 当作 signed 值，`poolPreviewDetailed.netProductDeltaRaw` 仅作为 rate delta 展示，不进入 `selectedProfitAmount`。
- 因此大量 `NoProfitableRoute()` 复核记录显示 `selectedProfitRaw=0x0`、`selectedProfitAmount=0.0`、`no_native_signed_profit:route_unprofitable`，用户无法看到具体数值。

修复：

- Rust `execution.rs`：
  - `previewArbitrageBestAmount` 与 `previewBestPoolDetailed` 的 `NoProfitableRoute` 分支解码 `ArbitrageNotProfitable(received, required)`，生成 `arbitrageNotProfitable.profitDeltaRaw` 与 `reportedNetProfitRaw`。
  - ladder 与 inner-single-call 的 `attempts[].profitRaw` 在无正收益时优先携带 signed `reportedNetProfitRaw`。
  - `official_v4_preview_and_ladder_inner` 在 pool 预览成功但 ladder 不盈利时补齐 `poolPreviewDetailed` 与 `runArbitrage`，避免丢失链上具体数值。
- Python `rust_closed_loop.py`：
  - `_signed_native_profit_value` 增加从 `poolPreviewDetailed.arbitrageNotProfitable` 与顶层 `arbitrageNotProfitable` 读取 signed 亏损。
  - `_native_worker_evidence` 对负 `netProductDeltaRaw` 用 `rate_delta * 输入量` 回填具体亏损（`selectedProfitRaw/selectedProfitAmount`，来源 `native_contract_rate_delta_estimate`）；对正 `netProductDeltaRaw` 不再伪装为正收益，保留 `positiveRateDeltaUnconfirmed`，blockers/conclusion 明确“runArbitrage 返回 NoProfitableRoute，正 rate delta 未执行确认”。
  - block/conclusion 写入具体 `netProductDelta` 数值与 raw。
  - `build_native_worker_attempt` 优先沿用 costs 内更精确的 `netProfitAmountMissingReason`。

验证：

- 新增 `test_build_native_worker_attempt_records_contract_rate_delta_loss`、`test_build_native_worker_attempt_keeps_positive_rate_delta_unconfirmed`、`test_signed_native_profit_reads_detailed_arbitrage_not_profitable`。

- `flashloan/src/core/db/cow_execution_mapping.py` 新增 `_not_executable_reason_sources()` 与 `_enrich_missing_reason()`：读取层 compact 时统一从 `blocked_reasons`、`live_onchain_evidence.blockers/conclusion`、顶层 `conclusion`、`errorStack` 提取可读原因；已有通用占位文案时替换为具体来源，完全无来源才保留 `no_native_signed_profit`。
