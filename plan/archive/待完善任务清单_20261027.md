- 恢复并保持 46630 候选/闭环，持续观察“自动扫描 -> 实时链上复核 -> 可盈利自动广播 -> `execution_success`/`tx_hash` 稳定落库”的连续窗口。

### M3-2 实施明细（本清单内工程前置项之一）

1. 修改入口：`flashloan/src/dex/tools/refresh_robinhood_v4_live.py::_v4_incremental_database_state`；`_resolve_v4_scan_decision` 的 `--from-block`/`--full-index-scan` 显式语义保持不变。
2. 完整性口径改为 YC/ZC eligible 作用域：
   - eligible 池 = known token universe + fixed fee<=3000 + 非动态费 + no-hook；
   - eligible 池必须有显式 `has_liquidity` 快照（0 或 1），`has_liquidity=0` 是终态，不算 incomplete；
   - `complete = eligiblePoolCount > 0 AND eligibleUnknownCount == 0`；
   - 38664 个 generic unknown 池只计入 `genericUnknownCount`，不参与 `complete` 判断。
3. 口径与运行时保持一致：复用/抽取 `robinhood_v4_idle_maintenance.py` 中 `_known_pool_token_addresses`、fixed-fee/no-hook 筛选与 `_candidate_eligible_missing_liquidity_count` 的同一过滤条件，避免 CLI 与维护线程口径分裂。
4. 回归测试调整：
   - `test_robinhood_v4_sqlite_rebuild_tool.py` 中现有 guard 测试从“全库 confirmed == pool_count”改为“eligible unknown==0”；
   - generic unknown 池存在且 eligible unknown=0 时，`scanMode` 必须为 `incremental`；
   - eligible unknown>0 时仍允许 `full_forced_db_incomplete`；
   - eligible zero 池存在时仍为 `incremental`，zero 不重复进入普通扫描；
   - 方向候选 `<5` 才进入 backfill，每方向上限保持 5。
5. 只读验收命令（先于生产恢复扫描执行）：
