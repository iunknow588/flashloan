# Robinhood 主网自愈编排器开发计划 v10.18（2026-11-20）

## 1. 目标与完成定义

构建链无关的代币→池→闭环→复核→广播自愈链。所有交易量、容量和盈亏结论由 Rust 内核使用当前内存状态计算；只有证据完整、状态新鲜、利润为正且权限符合时才允许进入广播。实现完成与生产稳定是两个不同结论：生产稳定须连续 3 个至少 30 分钟的窗口满足 `blockers=[]`、`missingValue=0`、`positive>0`，且复核、广播请求和链上回执可关联。

## 3. 架构约束

### 3.1 内存对象处理约束（MIO-1..MIO-8）

- **MIO-1** SQLite 只在初始化/持久化/审计时读写；review/depth 处理循环不得逐条 SQL 查询业务状态。
- **MIO-2** 全局内存上下文持有池、闭环和运行时快照；运行期计算只消费该上下文。
- **MIO-3** token decimals 是内存上下文的一部分，金额缩放必须使用对应 token 的精度。
- **MIO-4** WSS/监控器更新内存快照；状态版本和新鲜度必须随计算证据传播。
- **MIO-5** Review Manager 通过 Rust 内核/管理接口消费业务状态，不由 Python 另建权威路径。
- **MIO-6** Python 只消费内核发布的金额、利润、路线和状态，**不重算、不拼接闭环身份**。
- **MIO-7** Rust 内核发布有符号利润及 `signedPnl.amount`，包含 raw 值、币种/精度、来源和测量状态；测得零与未测量严格区分。
- **MIO-8** 每条链使用独立 SQLite、chain ID、RPC、权限和内存状态，禁止跨链读取或写入。

### 3.2 闭环身份与路径匹配

> **闭环起点是闭环业务身份的一部分。起点不同即不同闭环。**

禁止对 token path 做循环旋转归一化，禁止借用另一起点闭环的 loop key、pool IDs、capacity、USDG valuation 或 threshold。Rust catalog 必须按 Manager 发布的**完整有序身份**精确匹配；精确匹配失败时不借用其他闭环的任何字段，并 fail-closed 返回可定位的 identity mismatch。对应开放任务为 `TASK-149`，验收为 `AC-214`。

**两个命名空间必须分开**：

| 命名空间 | 键 | 规则 |
|---|---|---|
| **Manager 闭环身份** | `loop_key` / `pool_ids` / `single_tick_capacity_*` / `borrow_token_usdg_value_*` / `cross_tick_*` / review→loop 归属 | **绝对禁止** Python 侧旋转裁决；只精确匹配 |
| **运行时状态行** | `v4_closed_loop_runtime_state.loop_key` | 允许同方向旋转做**状态行 alias merge**（同一物理闭环的多个历史锚点收敛到同一行）；**不承载** capacity / pool / USDG / threshold，不决定 review 归属 |

**判定标准**：一个 Python 旋转调用是否违规，取决于它是否跨越 **Manager 闭环身份**边界。旋转结果若被用于**选择** Manager 发布的身份字段或**决定 review 归属** → 违规；旋转结果若只用于**运行时自身状态表的行归并** → 允许，但必须保留 fail-closed 诊断。

**实现落点**：Rust 闭环目录与身份匹配层（`flashloan/rs-src/src/closed_loop_identity.rs`、`worker_pool.rs`）及其桥接测试。**不在** healer、Python 复核或脚本层做路径规整；Python 侧只消费内核权威结果。

**关闭条件**：旋转路径必然 lookup miss，且 miss 后不继承任何被借用闭环的容量、估值、阈值与池身份；且**实盘证据齐备**（仅通过单元测试不构成关闭依据）。

### 3.3 级联与计算边界

- 处理顺序固定为代币→池→闭环→复核→广播；某层失败只关闭该层执行路径并继续诊断，不删除候选项或越级放行。
- 关键 token 字段优先由代币管理器修复；只有无法修复的关键字段才允许删除，且必须清理所有依赖引用。池代币精度以 token admission 为权威。
- 闭环身份匹配遵循 §3.2 的起点与有序路径契约；缺少精确身份时按未解决依赖处理，**不得猜测或复用其他闭环的容量与估值**。
- Rust 负责单 tick 起始量、跨 tick 最佳金额、容量和利润。跨 tick 使用真实闭环输入/输出和既有 double/halve 搜索，不执行 tick 遍历；**单 tick 初值为 0 时不得启动跨 tick**。
- 未测量的金额或利润必须**缺值并附责任原因**；不能用默认零、历史估算或 SQL 回填伪装测量。
- 广播前检查正利润、具体金额、链/账户/nonce/gas/目标/快照/授权和幂等性。**无明确授权不得真实提交。**

### 3.4 `pool_depth_audit` 分类口径（已变更，随代码归档）

“坏读数（TVL 超上限）”与“薄池（TVL 低于下限）”是**两个不同分类**，不可混同：

| 情形 | 判定 | 报告字段 |
|---|---|---|
| TVL 读数超过 `MAX_POOL_TVL_USD`（1e9）且 `estimated_tvl_usd` 无效 | **读数无效**，不计入薄池 | `staleTvlReadingPoolCount` |
| TVL 读数有效但低于 `MIN_POOL_TVL_USD`（1e5） | **池确实薄** | `thinPoolIdCount` |
| TVL 读数有效且充足 | 合格 | `adequatePoolIdCount` |

超过 TVL 上限的读数**不**再使 `classification` 变成 `pool_reading_invalid`，也**不**触发 `remeasure_pool_depth` 修复路径。旧口径已随 `scripts/tests/test_mainnet_arbitrage_healer.py` 同步更新并归档。

## 4. 目录职责与脚本位置裁决

- 仓库根 `scripts/` 保持为仓库级 CLI、运维、诊断、迁移、审计和验证工具入口；它由根 README、`.replit`、pytest、Python imports 和现有调用路径引用。**不得在计划整理中迁入 `plan/`。**
- `scripts/tool/` 放共享 CLI、链配置、清理和配置验证工具；`scripts/tools/` 放较窄的协议/运行探针；`scripts/tests/` 放这些脚本自身的测试。
- `flashloan/tools/` 放 Rust Manager crates 及其业务工具；`flashloan/tools/test-token_create/scripts/` 是该 Hardhat/ethers 子项目内部工具，不与根级 Python scripts 混为一类。
- `flashloan/src/` 与 `flashloan/app_runtime/` 放运行时业务代码和应用测试；`flashloan/rs-src/` 放 Rust 内存内核；`plan/` 只放计划、清单、checklist、证据、归档与计划辅助脚本。
- 后续若需重组脚本，先提出独立迁移任务，扫描路径依赖并以兼容入口、测试和文档更新作为验收；**不得在计划整理中顺手移动**。

## 7. 保护与证据

- 每项完成结论引用任务/验收编号、代码测试、证据文件、链 ID、数据库绝对路径、schema/checksum 和时间。
- 数据库迁移按链分别验证目标路径、版本、checksum、可读备份与迁移后状态；**禁止回灌历史深度或闭环业务数据**。
- 主网写入、apply 和任何真实交易均需清晰授权、幂等键、操作记录和回滚点；**只读/dry-run 不可写成生产完成**。
- 证据过期、状态缺失、review 不新鲜、金额/利润缺失、权限不匹配或回执无法关联时**一律按未知/阻塞处理**。

## 8. 全局停止条件（任一命中即停止广播并归档）

- 缺 amount / PnL、快照陈旧、闭环身份不唯一、签名授权不足、重复提交或 receipt 无法关联。
- 无完整正利润且无用户明确授权。
- 任何跨链读取/写入，或跨链状态污染。
- 用历史深度/业务数据回填，或用默认零/估值掩盖缺陷。
