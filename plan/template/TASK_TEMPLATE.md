## 1.0 编号逻辑（**本任务的编号从哪来**）

> **本节是固定部分。** 每个任务都必须**自己**声明编号逻辑，
> 使读者**不看编号册**也能知道「这个编号属于哪个模块的号段」。

| 项 | 值 |
|---|---|
| **本任务编号** | **`T-<模块>.<序>`** |
| **本任务验收编号** | **`AC-<模块>.<序>`** |
| **编号作用域** | `{{模块内 / 跨模块}}` |
| **编号所依据的模块** | **`M-n`**（`{{模块名}}`） |
| **模块内序号** | 第 `{{序}}` 个（该模块号段内递增，**不复用**） |
| **同号段其它任务** | `{{该模块号段内的其它任务号，或「无」}}` |

**规则**：

1. **一个任务只服务一个模块** ⇒ 编号落在**该模块的号段内**（模块内编号）。
2. 若本任务**同时改动多个模块** ⇒ **主改动模块**决定编号号段，
   其余模块属**被强制牵连**，在 §1.1 逐条列明。
3. **禁止**把两个**平级独立**模块的工作合并成一个任务 ⇒ 那会**平铺**号段，
   破坏「编号即定位」的前提。
4. **不同模块的序号互不消耗** —— M-10 做到 `.09` **不影响** M-5 的 `.04`。
5. **前置与顺序只按模块号 `M-n` 表达** —— **禁止**写「等 `T-x.yy` 完成」。

**登记**：本任务的号段占用情况登记在
[`plan/TASK_REGISTRY.md`](../TASK_REGISTRY.md) §4.2（**编号唯一真相源**）。

### 2.3 技术文案（`docs/`）

本任务的**独立技术文案**放在同目录 `docs/`：

- **只写本任务相关的** —— 不做跨任务的技术综述；
- **只引用不复制** —— 引用别的任务时**给链接**，不复制正文；
- **口径唯一** —— 同一口径在 `docs/` 与本文件**不得矛盾**；
- **不参与回归** —— `docs/` 是说明性文档，**不含**可执行验收项。

### 2.4 三条执行纪律

1. **编译 ≠ 测试**：只改接口签名时，`cargo build --offline --workspace` 足以暴露类型破坏 ⇒
   **不必**跑全部 crate 的测试。
2. **跨 crate 的公开接口改动**才需要加跑**调用方**的测试；**内部实现**改动**不需要**。
3. **Python 侧同理**：`flashloan/app_runtime/tests/unit/` 有大量文件，
   **只跑受影响的那几个**。

## 4. 归档

**闭合后必须移出 `plan/tasks/`** —— `plan/tasks/` 只放**未闭合**任务。

```powershell
# 打包四文件 ＋ docs/ → plan/archive/，并登记索引，最后删除本目录
python plan/runtime_evidence/tools/archive_task_20261124.py T-<模块>.<序>
# 先预演（不落盘、不删除）：
python plan/runtime_evidence/tools/archive_task_20261124.py T-<模块>.<序> --dry-run
```

工具会自动完成：
1. 四文件 ＋ `docs/` 打包为 `plan/archive/任务归档_T-<模块>.<序>_{{标题}}_<日期>.md`（保留五个小节）；
2. 在 `plan/archive/README.md` §1 **归档索引**登记一行；
3. 在**一级任务** README 的二级清单标记「✅ 已闭合 · 已归档」；
4. **删除** 本目录。

> **归档件内容冻结** —— 更正走新版本 `..._v2.md`，旧版保留。
> 归档区是**受控文档区**，规则见 `plan/README.md` §1.2 与 `plan/archive/README.md`。
> **不得**再在本目录追加新任务 —— 新任务**另建目录**。
