# 任务编号册（Task Registry）· **编号控制的唯一真相源**

> **本文件是编号分配的唯一真相源。** 任何"下一个可用编号是多少"的问题，
> **只**以本文件为准；`plan/README.md` §7 与 `plan/template/README.md` 只做引用。
>
> **本文件是受控文档。** 改编号 ⇒ 先改这里，再改引用处。

---

## 0. 为什么需要编号册（**问题陈述**）

**旧口径的缺陷**：二级任务编号 `T-nn` 按**创建顺序**递增，**不按模块分组**。
后果是**同一模块的工作散落在互不相邻的编号里**，例如：

| 缺陷 | 具体表现 |
|---|---|
| **模块被多点切分** | 存储层 `M-10` 被 `T-3.01` / `T-4.01` / `T-3.02` / `T-10.01` / `T-5.01` / `T-10.02` **六个**任务同时触及 |
| **语义错位** | 「池子变更」（`T-3.01`~`T-4.02`）与「数据库分离」（`T-10.01` / `T-10.02`）**编号不连续**，看起来像同一条线 |
| **漏做难查** | 只看编号**看不出**某模块还剩几件事没做，必须回查代码 |
| **误判回归范围** | 「这个任务属于哪个模块」无法从编号回答 ⇒ 回归范围容易被放大 |

**新口径**：**一个模块 ⇒ 一段连续编号**。模块是**编号的分组单位**，不是编号的**内部顺序**。

---

## 1. 编号格式（**模块内分组**）

```
一级任务：  P-nn-标题                    ← 方案 / 计划级
二级任务：  T-<模块号>.<组内序号>        ← 执行级，**按模块分组**
验收编号：  AC-<模块号>.<组内序号>      ← 与二级任务一一对应
```

| 段 | 含义 | 取值 | 规则 |
|---|---|---|---|
| `P-nn` | 一级任务号 | `P-01`、`P-02`… | 全局递增，**不复用** |
| `<模块号>` | 改动模块编号 | `M-3` → `3`；`M-10` → `10` | **取该任务的**主改动模块**（见 §2 判定规则）** |
| `<组内序号>` | 模块内序号 | `01`、`02`… | **在该模块内**从 `01` 递增，**不复用** |
| `AC-…` | 验收编号 | 与二级任务**同段** | 一一对应，同号不同前缀 |

> **示例**：`T-3.01` ＝ 模块 `M-3`（方向层）的第 1 件事；
> `T-10.02` ＝ 模块 `M-10`（存储层）的第 2 件事。
> **读法**：`T-<模块>.<序>` ⇒ **一眼看出属于哪个模块**。

---

## 2. 主改动模块的判定规则（**唯一归属，不许挂靠**）

一个二级任务**必须**有**恰好一个**主改动模块。判定顺序：

1. 任务**声明**的改动模块集合中，**编号最小**的那个 = 主改动模块；
2. 若集合中有**多个**模块且无法判定主次 ⇒ **拆成两个任务**，不要合并；
3. **不允许**「主模块 A ＋ 附带 B」这种挂靠式组合，除非 B **是被 A 强制的**（如"方向层落地"必然要碰授权模块 `M-9`）。

> **反例（本次已发生）**：`T-10.01`「测试套件生产库零写入」与 `T-10.02`「记录存储剥离」同属 `M-10`，
> 却因编号按创建顺序分配而**不相邻**，并且与池子类任务 `T-3.01`~`T-4.02` 混在同一编号序列里。
> ⇒ 新口径下它们归入 `T-7.03.x` 段，**与池子类的 `T-3.x`/`T-4.x` 段完全分开**。

---

## 3. 一条硬规则（**不同模块不得混在一个任务里**）

> **一个二级任务只服务于一个模块。**

| 允许 | 禁止 |
|---|---|
| 一个任务**主改** `M-n`，并**附带**被 `M-n` 强制牵连的模块 | 一个任务**平铺**两个**独立**模块的工作（如「池子变更」＋「数据库分离」塞进一个任务） |
| 跨模块的**弱耦合**可拆成两个任务，用**模块级前置**表达顺序 | 用**任务号依赖**把两个模块绑在一起（模块级前置才是唯一的顺序表达） |

**判定口诀**：*「这个任务做完，哪个模块的测试必须重跑？」* ⇒ 答案**不止一个且两者平级** ⇒ **拆开**。

## 4.3 存储层 `M-10` 的**分任务规则**（**不同存储职责 ⇒ 不同任务**）

> **一条硬规则**：**存储层的三类分离职责，必须是三个独立任务、三个独立编号。**
> 它们落在**同一模块**（都改存储层），但**验收口径、回归边界、闭合判据各不相同**。

| 编号 | 职责 | 分离什么 | 验收口径 | 状态 |
|---|---|---|---|---|
| **`T-10.01`** | 生产库**写**隔离 | 测试路径**不写**生产库 | 生产库文件字节级**零变化** ＋ 只读打开 | ⬜ 11 项未完成 |
| **`T-10.02`** | **记录存储**剥离（剩余项） | 链上瞬时数据**不进**持久化存储 | 记录根目录**不存在** ＋ 保留期清理生效 | ⬜ 6 项未完成 |
| **`T-10.03`** | **复核库**分离 | 复核记录**独立成库** | 复核库**独立**且可独立归档 | ⬜ 9 项未完成 |
| **`T-10.04`** | **广播交易记录**分离 | 广播交易记录**独立成库** | 广播交易记录**独立**且可独立归档 | ⬜ 9 项未完成 |

**为什么必须拆开**（**这正是本册要防止的复发**）：

| 合并的后果 | 说明 |
|---|---|
| **验收口径串味** | 「写隔离」的判据是**生产库字节不变**；「库分离」的判据是**独立库存在且可归档**。两者混在一个 checklist ⇒ 勾掉一条不代表另一条闭合 |
| **回归边界放大** | 写隔离只跑**只读打开**相关测试；库分离要跑**归档/保留期**相关测试。合并 ⇒ 每个任务都跑两套 |
| **闭合节奏不同步** | 写隔离可能当天闭合；库分离要等数据迁移窗口。合并 ⇒ 快的被慢的**拖住**，或快的**顺带**勾掉慢的 |
| **授权边界混淆** | 库分离**可能要写库授权**；写隔离**绝对不许写**。合并 ⇒ 授权判断失焦 |

**拆分后如何表达顺序**：只写**模块级前置**（如「`T-10.04` 的前置模块是 `M-10`」），
**不写任务号依赖**（`T-10.02` 不写「等 `T-10.01` 完成」）。

## 5. 新建任务的标准动作（**编号控制**）

```powershell
# 1. 查本文件 §4.2 ⇒ 确定主改动模块 M-n 与该模块的下一个可用序号
#    （同模块内递增；不同模块互不影响 —— 这就是"独立编号控制"）

# 2. 按模板生成目录
$TASK="T-10.05"; $ACC="AC-10.05"
New-Item -ItemType Directory -Force "plan/tasks/<一级>/tasks/$TASK"
Copy-Item "plan/template/TASK_TEMPLATE.md"        "plan/tasks/<一级>/tasks/$TASK/PLAN.md"
Copy-Item "plan/template/SCOPE_GUARD_TEMPLATE.md"  "plan/tasks/<一级>/tasks/$TASK/SCOPE_GUARD.md"
Copy-Item "plan/template/CHECKLIST_TEMPLATE.md"    "plan/tasks/<一级>/tasks/$TASK/checklist.md"
Copy-Item "plan/template/DOCS_README_TEMPLATE.md"   "plan/tasks/<一级>/tasks/$TASK/docs/README.md"

# 3. 在本文件 §4.2 的对应模块行**登记一行**（编号册即时生效）
# 4. 在一级任务 README 的二级清单**登记一行**
# 5. 在专题清单登记一行
```

**纪律**：
- **不同模块 ⇒ 各自独立的序号段**，**互不消耗**。M-10 的任务做到 `T-10.09`，
  **不影响** M-5 的 `T-5.04`。
- 编号**永久不复用**。任务闭合归档后，其编号**永久保留在本文件**（状态改为 ✅ 已归档）。
- **不许**跨模块"顺延"：M-5 的下一个号**永远**是 `T-5.xx`，不是 `T-6.xx`。

## 6. 编号与**回归范围**的关系（**为什么这样能省时间**）

| 规则 | 说明 |
|---|---|
| **回归范围 ＝ 改动模块集合** | 与编号**无关**，与 `SCOPE_GUARD.md` 声明的模块集合有关 |
| **未改动模块不重跑** | 编号只回答"归属哪个模块"，**不**决定跑多少测试 |
| **同模块的任务可共享回归** | 同属 `M-n` 的任务，改动落在**同一批文件** ⇒ 回归命令相同 ⇒ 可合并执行 |
| **跨模块的组合回归只在整体闭合时** | 一级任务全部二级闭合后跑**一次** |

> **编号的作用是「定位」，不是「耦合」。** 编号让"这个任务属于哪个模块"可以一眼回答；
> 测试范围由**改动模块集合**决定。两者**解耦**。
