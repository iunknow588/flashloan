### 10. TASK-150｜闭环身份第二维度：方向池子集合可独立复核

**背景**：闭环身份 = **资金锚点 + 方向池子**，但当前实现中**只有地址路径这一半真正参与判定**。

**已核实的缺口**（2026-11-20 只读 + 源码核验）：`flashloan/rs-src/src/worker_pool.rs:2825` 的 `apply_closed_loop_identity` 会比对 `routePoolIds`（回退到顶层 `poolIds`）与 Manager 发布的 `identity.pool_ids`，不一致即报 `manager_closed_loop_pool_identity_mismatch` 并 fail-closed。但：

| 核验点 | 读数 |
|---|---|
| 主网 44 条 review payload 中提及 `routePoolIds` 的 | **0** |
| 主网 44 条 review payload 中提及 `poolIds` 的 | **0** |
| `poolIds` 实际出现位置 | `quote.candidate_pools` / `quote.route.hopCandidates`（嵌套，非顶层键） |
| Manager 侧 `manager_v4_reviews.pool_ids_json` | 44/44 非空（**权威数据存在**） |

结论：`route_pool_ids` 恒为 `None`，**该校验分支永不参与判定**。现状**结果正确**（身份确实由有序地址路径唯一决定，池集合本就是该路径的函数），但这道「方向池子」这一半是**哑保险** —— 它无法独立发现「地址路径对了但池集合被篡改」这类缺陷。

**要做的事**：把**逐路由池路径**经 `routePoolIds` 送进 review 配置，使池集合成为身份判定的**可校验第二维度**。验收要点：

- [ ] review 配置中 `routePoolIds` 承载**该路由实际使用的有序池 ID 列表**，与 Manager `pool_ids_json` 语义一致（有序、逐跳对齐）。
- [ ] `apply_closed_loop_identity` 的池集合比对**真实参与判定**：构造「地址路径正确但池集合不一致」的样本，必须报 `manager_closed_loop_pool_identity_mismatch` 且 fail-closed，**不得**沿用 Manager 的池集合或容量。
- [ ] 比对为**顺序敏感**（方向池子有方向）；比较前统一做小写/去空白归一，但**不得**去重、**不得**重排。
- [ ] 缺失池集合的处理必须**显式**：要么显式判定为不可校验并记录状态，**不得**静默跳过校验后宣称身份已完整匹配。
- [ ] **不得**引入任何兜底池集合、默认池或空集合默认值来"通过"校验；失败即 fail-closed。
- [ ] 回归测试覆盖：一致通过 / 不一致 fail-closed / 缺失显式三类。
- [ ] 主网只读复跑后核对：44/44 review 的池集合校验状态可读，且与 `manager_v4_reviews.pool_ids_json` 同口径一致。

**边界**：本任务只补齐**校验能力**，**不改变**现有身份语义（身份仍以有序地址路径为键），**不合并**同锚点方向闭环，**不引入**任何旋转能力。
