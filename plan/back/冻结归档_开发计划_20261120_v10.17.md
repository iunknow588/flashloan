# Robinhood 主网自愈编排器开发计划 v10.17（2026-11-20）

## 1. 目标与完成定义

构建链无关的代币→池→闭环→复核→广播自愈链。所有交易量、容量和盈亏结论由 Rust 内核使用当前内存状态计算；只有证据完整、状态新鲜、利润为正且权限符合时才允许进入广播。实现完成与生产稳定是两个不同结论：生产稳定须连续 3 个至少 30 分钟的窗口满足 `blockers=[]`、`missingValue=0`、`positive>0`，且复核、广播请求和链上回执可关联。

## 3. 架构约束

### 3.1 内存对象处理约束（MIO-1..MIO-8）

- **MIO-1** SQLite 只在初始化/持久化/审计时读写；review/depth 处理循环不得逐条 SQL 查询业务状态。
- **MIO-2** 全局内存上下文持有池、闭环和运行时快照；运行期计算只消费该上下文。
- **MIO-3** token decimals 是内存上下文的一部分，金额缩放必须使用对应 token 的精度。
- **MIO-4** WSS/监控器更新内存快照；状态版本和新鲜度必须随计算证据传播。
- **MIO-5** Review Manager 通过 Rust 内核/管理接口消费业务状态，不由 Python 另建权威路径。
- **MIO-6** Python 只消费内核发布的金额、利润、路线和状态，不重算、不拼接闭环身份。
- **MIO-7** Rust 内核发布有符号利润及 `signedPnl.amount`，包含 raw 值、币种/精度、来源和测量状态；测得零与未测量严格区分。
- **MIO-8** 每条链使用独立 SQLite、chain ID、RPC、权限和内存状态，禁止跨链读取或写入。

### 3.2 闭环身份与路径匹配

闭环起点是权威业务身份的一部分。对相同的有向边序列，仅改变起点后得到的路径，在当前系统中仍是不同闭环，不进行旋转归一化或合并。Rust catalog 必须按 Manager 发布的完整有序身份精确匹配；精确匹配失败时不借用其他闭环的 loop key、pool IDs、capacity、估值或阈值，并 fail-closed 返回可定位的 identity mismatch。对应开放任务为 `TASK-149`，验收为 `AC-214`。

`TASK-149` 的修改边界：

- 身份键由完整有序 token 序列构成，起点参与比较；比较为精确匹配，不做循环位移、不做符号级近似。
- lookup miss 是正常终态，不得回退到“任意同集合路径”或“最近邻身份”。
- 关闭条件是旋转路径必然 lookup miss，且 miss 后不继承任何被借用闭环的容量、估值、阈值与池身份。
- 该任务不改变 Manager 发布身份的责任，也不新增 Python 侧兜底；Python 继续只消费 Rust 权威结果。
- 修复落在 Rust 闭环目录与身份匹配层及其桥接测试，不在 healer、Python 复核或脚本层做路径规整。

### 3.3 级联与计算边界

- 处理顺序固定为代币→池→闭环→复核→广播；某层失败只关闭该层执行路径并继续诊断，不删除候选项或越级放行。
- 关键 token 字段优先由代币管理器修复；只有无法修复的关键字段才允许删除，且必须清理所有依赖引用。池代币精度以 token admission 为权威。
- 闭环身份匹配遵循 §3.2 的起点与有序路径契约；缺少精确身份时按未解决依赖处理，不得猜测或复用其他闭环的容量与估值。
- Rust 负责单 tick 起始量、跨 tick 最佳金额、容量和利润。跨 tick 使用真实闭环输入/输出和既有 double/halve 搜索，不执行 tick 遍历；单 tick 初值为 0 时不得启动跨 tick。
- 未测量的金额或利润必须缺值并附责任原因；不能用默认零、历史估算或 SQL 回填伪装测量。
- 广播前检查正利润、具体金额、链/账户/nonce/gas/目标/快照/授权和幂等性。无明确授权不得真实提交。

## 4. 目录职责与脚本位置裁决

- 仓库根 `scripts/` 保持为仓库级 CLI、运维、诊断、迁移、审计和验证工具入口；它由根 README、`.replit`、pytest、Python imports 和现有调用路径引用。本轮不迁移该目录。
- `scripts/tool/` 放共享 CLI、链配置、清理和配置验证工具；`scripts/tools/` 放较窄的协议/运行探针；`scripts/tests/` 放这些脚本自身的测试。
- `flashloan/tools/` 放 Rust Manager crates 及其业务工具；`flashloan/tools/test-token_create/scripts/` 是该 Hardhat/ethers 子项目内部工具，不与根级 Python scripts 混为一类。
- `flashloan/src/` 与 `flashloan/app_runtime/` 放运行时业务代码和应用测试；`plan/` 只放计划、清单、checklist、证据、归档与计划辅助脚本，不作为通用可执行工具的迁移目标。
- 后续若需重组脚本，先提出独立迁移任务，扫描路径依赖并以兼容入口、测试和文档更新作为验收；不得在计划整理中顺手移动。

## 5. 阶段与执行顺序

1. **P0：闭环身份精确性**：先移除运行时按 token 符号旋转匹配的身份借用；精确身份未命中时 fail-closed，并报告 Manager identity mismatch。
2. **P0：容量根因与 review 完整性**：修复单 tick capacity 不可用、金额梯形缺最佳量以及缺失盈亏的来源；重新运行主网 review，逐条保留 Rust 测量证据。
3. **P0：估值与链库契约**：保持 USDG identity 与 ETH/WETH 路径单位一致；核验主网复核实际 fee/gas/PnL 单位，补齐测试网权威闭环前置数据。估值覆盖本身不等于 review 通过。
4. **P1：测试网同构验证**：恢复并验证 RPC/WSS，从当前链状态刷新池，dry-run 检查 admission/scope/skip reason；仅在存在至少两个合法候选且依赖 checksum 闭合后 apply、构建 Manager loops、复核。
5. **P1：全链级联和自动准入**：测试代币、池、闭环、复核各层责任路由、失败幂等和自动解除限制；主网与测试网使用同一业务逻辑、独立 DB。
6. **P1：广播安全演练**：在 review 全量新鲜且存在正利润时运行 dry-run；授权和测试网错误自愈演练通过后，另行申请真实广播授权。当前禁止因“实现完成”而默认提交。
7. **P2：稳定性观察**：只有真实回执可关联时启动三个 30 分钟窗口，记录确认盈亏、gas、借款费、失败、状态新鲜度和模型偏差。
