# 文档完善记录 v9.3（2026-11-13）

## 1. 本轮目标

在不改变既有业务裁决、不写生产数据库的前提下，把活动计划从“阶段列表”提升为可执行的责任、依赖、SDK 和证据体系。

## 2. 主要完善

1. 新增十类组件的责任矩阵，明确 token、pool、candidate、closed-loop、review、broadcast、composite、RuntimeCore、Manager API 和 Python 的边界。
2. 将 `flashloan/app_runtime` 明确纳入 P0 架构审计，Python 只允许桥接、配置、展示、运维和临时兼容。
3. 明确 `uniswap-v4-sdk` 为当前基础，重点复用 `PoolManagerLens`、`SimpleTickDataProvider` 和精确数学。
4. 将 `Dex-Math-Core-rs` 设为候选数学引擎，只允许先做 parity、舍入、性能、许可证和维护性评估，禁止形成双生产 authority。
5. 将 `arena-core` 延后到 single-tick 生产基线稳定后的离线压力测试和回测。
6. 新增任务责任/依赖矩阵、Definition of Ready、Definition of Done 和 SDK 变更交付物。
7. 补充备用池清理配置语义、同版本竞态约束和 `app_runtime` 架构守卫验收项。

## 3. 保持不变的硬约束

- USDG 在经济计价上替代 USD，但外部 fiat 价格源和 TVL 不进入池深准入。
- 股票代币必须具备 USDG 可兑换性；核心/测试豁免；扩展代币受深度和传递关系约束。
- 仅接受固定费率 `0 < fee <= 30000`，动态费率池全部排除。
- 版本 1 每跳只允许 single-tick；跨 tick 接口保留但不进入主路径。
- 候选每方向 TOP-5、推荐 TOP-1；备用池受控清理；池表总量不超过 3000。
- 未经显式授权不得写生产库；W7/W8 和二进制替换需要停机窗口。

## 4. 未完成状态

- 本轮只完善文档，没有执行 SDK 替换、生产物化、production prune、W6、W7 或 W8。
- `Dex-Math-Core-rs` 与 `arena-core` 均未被声明为已集成。
- 活动任务和验收状态以 v9.3 三份根目录文档为准。
