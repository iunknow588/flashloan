## 5. M3-2 修正范围

1. 以 YC/ZC 已知 token universe、fixed fee<=3000、no-hook 的 eligible 池作为 completeness 口径；38664 个 generic 池不参与判断。
2. `database_state.complete=true` 时扫描模式应使用 `incremental`；eligible explicit-zero 是终态，不视为 incomplete；仅当 eligible 作用域存在 unknown 流动性时才允许回退全量扫描。
3. 候选 backfill 继续按方向 `<5` 触发，`MIN_DIRECTION_CANDIDATE_POOLS=1`、`MAX_DIRECTION_CANDIDATE_POOLS=5` 保持不变。
4. explicit-zero 池作为增量终态，不重复进入普通扫描；候选不足时只走方向回补。
5. 回归覆盖 `flashloan/app_runtime/tests/unit/test_robinhood_v4_sqlite_rebuild_tool.py`：generic unknown 不触发 block 0 扫描；eligible unknown=0 时 scan mode 为 incremental；eligible zero 仍为 incremental；eligible unknown>0 才允许 `full_forced_db_incomplete`；某方向候选数 `<5` 才进入方向回补；每方向最多 5 个候选。

## 8. 安全边界

- 禁止手工修改 evidence、SQLite、`latest.json` 或运行时 API。
- 禁止跨 RPC 重发广播；RPC failover 只用于只读复核。
- 禁止把 `replacement transaction underpriced` 作为提高 gas 重试的触发条件；出现该错误视为同 nonce pending 冲突，停止广播后由策略框架自动核对 nonce/回执并落终态。
- 错误处置不依赖人工复核：所有错误经策略矩阵解析为确定动作和状态迁移，人工只读告警与审计。
- 禁止擅自启动、重启、kill 生产进程；生产扫描启动必须用户确认。
- 禁止将历史 success 伪造成在线记录或作为 M9-1 依据。
- 在线库写操作前先备份并先 dry-run。
- 38664 个 generic 池不作为 YC/ZC 盲扫对象；候选回补仅在方向候选少于 5 时触发。
