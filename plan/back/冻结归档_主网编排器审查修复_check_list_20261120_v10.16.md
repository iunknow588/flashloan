# 主网自愈编排器审查修复 Checklist v10.16（2026-11-18）

> 本文只列未完成验收条件；所有项目保持 `[ ]`，完成后先保存机器证据和人工摘要，再从活动文档移入 `back/`。

## 0. 编号与架构约束

- 活动任务稳定编号：`TASK-141..TASK-146`；验收编号：`AC-211..AC-212`。既有编号不复用。
- Rust 全局内存内核对象是系统事实源。Rust 调用管理对象；Python 纯消费展示，不执行交易量、容量、利润或路线拼接计算。
- 初始化读链专属 SQLite；WSS 更新内存对象；内存处理结果经队列进入管理器持久化。深度计算不执行 SQL。
- 代币→池→闭环→复核→广播顺序固定；生产依赖解决后自动解除限制，不永久关闭生产库。
- 最佳量为 0 且利润为 0 必须是有测量标识的有效结论；未测量保持缺值。
- 真实广播是外部副作用，需要明确授权；只有确认正利润、金额、状态、权限与目标后方可执行。

## 2. P0｜闭环复核与自愈

- [ ] 复核管理调用闭环管理，并由 Rust 内核使用内存对象完成计算；Python 不计算金额。
- [ ] 每条 active review 明确含最佳交易量 raw 值、是否测量、带符号利润 raw 值、币种/精度、状态快照和选路依据。
- [ ] 测量到最佳量为 0 的记录显示利润 0，且不被归为 `data_incomplete`；未运行 ladder 的占位零不能冒充测量。

### TASK-146｜全范围代币/池/闭环依赖级联

- [ ] 代币缺符号/精度等关键字段时先调用代币管理器修复；仅无法修复的关键字段允许删除，并同步清理闭环依赖引用。

- [ ] 池无效/状态异常时修复目标为池管理器；闭环缺边/路径失效时目标为闭环管理器；复核缺利润时目标为复核管理器调用闭环管理器。
- [ ] 级联执行幂等，失败不会丢失候选项；生产库只有当前层依赖解决并通过回归后才自动解除限制。
- [ ] 各层的处理结果经 Rust 队列持久化到对应链 SQLite；深度更新由内存对象完成，无 SQL 深度计算。
- [ ] 同一核心故障在两链同构测试；数据差异可归因为链特定状态，不修改链无关核心算法绕行。

### TASK-144｜广播管理器修复与正利润准入
