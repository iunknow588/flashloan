## 2. P0｜金额、状态和复核正确性

### TASK-141｜生产库自动准入解除与全链自愈

生产、测试链使用相同的代币→池→闭环→复核→广播逻辑；依赖满足后自动开放相应层。独立 DB、链配置及权限不得混用。每轮记录阻塞项并继续修复，不把生产库永久关闭作为结果。

### TASK-142｜Rust 单 tick 初始量与跨 tick 输入输出算法

以单 tick 最佳交易量作为跨 tick 初值；使用原有非递归 double/halve 算法，跨 tick 基于合约输入/输出，不加入 tick 遍历。零初值不启动跨 tick；Rust 独占金额计算，Python 不传递金额字段。修复 `token_library_catalog` 是 view 时被 table-only 检查漏掉的问题，并覆盖真实 SQLite schema 测试。

### TASK-143｜复核利润完整性和 Manager/legacy 归并

复核管理调用闭环管理和全局内存内核对象。所有复核必须带明确有符号利润、币种/精度、测量状态和所选金额。测量到最佳金额为 0 时利润明确为 0；没测量时保持缺值并定位上游错误。Manager 与 legacy 行以稳定路线身份去重并保留明确利润事实。

### TASK-145｜USDG 计价语义和覆盖完整性

代码已加入 USDG identity valuation：USDG 借款锚的一个整 token 对应 `10^USDG_decimals` raw USDG；单测覆盖不依赖自兑换池。主网重物化后为 88/88 有估值（ETH 28、USDG 54、WETH 6），但整链复核尚未运行，待 review 输入确认费/gas/盈亏各字段单位一致后方可关闭。其他代币缺可用兑换/精度时标记 coverage gap，不以 0 或默认汇率替代。

### TASK-147｜测试网有效候选/池覆盖与 RPC 恢复

2026-11-18 复核修正此前判断：AMZN 在 `stocks` 主库为 `admitted`；它在 `extension` 库的 `candidate_only` 是合法的派生重叠成员，不是闭环阻塞，不得为此重复准入。测试网 `core4` 候选边只有 USDG→AMZN 一个不同候选，虽有 first/third 两条方向推荐，但 M4 的 Y-Z 观察需要同一锚下至少两个不同 token 才能组成方向；当前 `direction_count=0`，于是闭环为 0、`skipped_token_count=1`。当前 core4 scope 仅 1 个 active pool；36 个 raw pool 的 scope dry-run 跳过 35 个（`depth_ineligible=17`、`no_core_anchor=6`、`token_not_admitted=12`）。candidate-exchange scope dry-run 有 5 个 active pool，但并未形成现有锚点组间的第二个有效候选。

本轮深度工具对测试网 36 个池进行只读 RPC 测量失败：配置的 RPC 主机 DNS 解析失败（endpoint probe host lookup failed）。因此不能确认 35 个池的实时 liquidity/tick，也不能安全 apply 深度或 scope。先修复/验证测试网 RPC/WSS 配置，再由池管理器从实时链状态刷新并 dry-run 分类；依据代币管理器正式分类和可用池结构确定合法的第二候选路径。不得手工改 `admission_status`、提升 extension overlap、放宽 fee/hook/流动性准入，或从历史数据回灌 loops/depth。待方向数大于 0 后按候选边→候选兑换观察→闭环顺序受控重建，验证 loopCount>0 与上游版本/checksum 一致，再进行 review 与广播 dry-run。
