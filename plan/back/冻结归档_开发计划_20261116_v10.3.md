## 2. 项目目标与完成定义

### 2.1 总目标

交付一个可审计、可回滚、默认 fail-closed 的 Robinhood 主网套利闭环：Rust manager 负责 token、pool、edge、exchange、closed-loop、review、broadcast 和 composite 权威逻辑；Python 仅通过 RuntimeCore/Manager API 调用；生产写入、Authority 切换和广播均受显式授权与停机窗口控制。

### 2.2 版本 1 范围

允许：

- 多跳闭环，但当前业务闭环固定为恰好 3 hops。
- 每一跳按最终实际输入量进行 single-tick 精确复核。
- YC、Y-Z、ZC 等既有闭环结构，由 `closed_loop_manager` 统一管理。
- 链上 Quoter 仅作为影子对照、偏差归因或受控降级路径。
- 跨 tick 接口和离线算法保留，作为后续版本输入。

禁止：

- 跨 tick 结果进入候选排序、最佳交易量、收益复核、广播或生产闭环。
- Python 新增或保留 token/pool/route/review/broadcast 权威判断。
- 动态费率池进入备用、观察、候选、推荐或闭环角色。
- 外部 fiat 价格源、TVL、相关性、`li<1` 或 `market_depth_exhausted` 成为池深准入依据。
- 未授权写生产库、切换 Authority、广播或替换被锁定二进制。

### 2.3 最终完成定义

系统同时满足以下条件才可宣布版本 1 完成：

1. 每个生产结论只有一个 Rust authority，Python 重复业务判断已退役并受架构守卫约束。
2. `core4 = [core, stocks]`、`candidate_exchange = [core, stocks]` 成为唯一主路径 scope；扩展库仅审计，测试库仅保留数据库和启动校验用途。
3. 所有生产池满足固定费率 `0 < fee <= 30000`、非动态费率、hook/深度规则，生产池表总量不超过 3000。
4. 候选池每方向 TOP-5、推荐池每方向 TOP-1，推荐池为候选池确定性子集，消费者不跨状态版本。
5. 每条闭环恰好 3 hops，所有 hop 命中 active candidate pool，并按最终输入量证明 single-tick。
6. P0-8/P0-9/P0-2/P1、ARCH-2b/D4-d、ARCH-3、ARCH-4-B/C、W6/W7/W8、生命周期和运维门禁全部通过。
7. ARCH-4 影子旁路连续 7 天、纯内存观察连续 30 天，且不可归因差异为 0。
8. 生产写入有授权、备份、恢复演练、checksum、幂等报告和明确回滚点。
9. 回归、编码、证据、观察和广播门禁全部通过，活动 checklist 已清零并完成归档。

## 5. 执行原则与变更等级

### 5.1 变更等级

| 等级 | 允许动作 | 授权要求 |
|---|---|---|
| L0 只读 | 审计、查询、读取快照、生成报告 | 无生产写授权；不得改变运行状态 |
| L1 本地开发 | 修改代码、单元测试、数据库副本 dry-run | 不得连接生产写路径 |
| L2 测试网/副本 | 测试网 apply、生产一致性副本演练、恢复演练 | 记录目标库和证据路径 |

| L4 Authority/广播 | Authority 切换、正式广播、二进制替换 | 用户显式授权 + 批准停机窗口 |

### 5.2 统一门禁

- 任何阶段必须先满足 Definition of Ready，再进入执行。
- 所有未知、陈旧、缺失、跨版本、不一致状态均 fail-closed。
- 生产写入前必须显示目标库绝对路径、chain id、操作模式和预计变更行数。
- 单一授权窗口内必须先备份，再 migration，再数据修复/物化，最后做只读复验。
- 不以“页面可见”“无异常日志”“报告文件存在”替代结构化验收。
- 每完成一个 checklist 项，先写机器 JSON 和人工摘要，再登记归档索引，最后从活动 checklist 删除。

## 7. 详细工作包

### 7.1 M0-A｜P0-8 Single-tick 容量与状态突变

**目标**：冻结 P0-8 的方向判定、流动性变化、token0/token1 容量公式、最终输入量复核和合约三态处理，使任何广播请求都能证明每个 hop 在最新状态下不跨 tick。

**主要任务**：

1. 将折算后 `M_cap` 接入最佳交易量选择器，保证 `amount_in <= M_cap`，超限时截断或稳定拒绝。
2. 用规范化 `PoolKey.token0/token1`、`zeroForOne`、预期/当前 `sqrtPriceX96` 和同输入 exact-output 单调性判定状态好坏。
3. 实现致命变化、状态变坏、状态变好三态；单闭环 revert 与批次其他闭环隔离。
4. `currentLiquidity != expectedLiquidity` 时精确重算单 Tick delta；无法重算时 fail-closed。
5. token1 使用线性 sqrtPrice 距离比例；token0 额外包含倒数价格项；统一向下取整并处理零分母/溢出。
6. 放大倍率设置硬上限；链上使用当前 Tick 的 `sqrtPriceLimitX96`，并保留 `amountOutMinimum` 利润锁。
7. 容量放大仅生成候选上界，随后按最终输入量重跑逐 hop exact-output 与 single-tick 复核。
8. 发布每跳 tick 状态、`single_tick_max_token0_raw`、`single_tick_max_token1_raw` 的副本物化影响报告。

**责任组件**：`pool_manager`、`review_manager`、`manager_contracts`；`composite_manager` 负责版本编排。

**测试矩阵**：

- 方向：zeroForOne/oneForZero × token0/token1 × 价格上移/下移。
- 流动性：不变、增加、降低、归零、未知。
- 边界：同 tick、恰到边界、跨 tick、零分母、极端倍率、U256 溢出保护。
- 闭环：三跳正常、任一 hop 缺状态、任一 hop 漂移、最终输入量变化、批内单闭环失败隔离。
- parity：链下 SDK、合约计算、链上 `eth_call` 的输出与失败码一致。

**交付物**：算法 ADR、方向测试向量、单元/集成/parity 报告、状态变化 JSON、物化 dry-run 影响报告。

**完成门禁**：checklist §1.2 全部满足，跨 tick/未知状态不产生广播请求，P0-8 证据可由独立人员复算。

**估算**：3–5 个工作日；依赖已归档的 P0-6/P0-8 代码基线。

### 7.2 M0-B｜P0-9 数据库副本与历史迁移一致性

**目标**：在不写生产库的前提下，证明历史源、四库 membership、pool scope 和四类消费者的 projected target 完整、稳定、可追溯。

**主要任务**：

## 12. 风险与应对

| 风险 | 触发信号 | 应对 |
|---|---|---|
| single-tick 方向判定错误 | parity 或方向向量不一致 | 阻断广播，回到 M0-A，增加规范化方向向量 |
| 流动性变化沿用旧容量 | liquidity 变化但 M_cap 未重算 | fail-closed，要求精确 delta 或拒绝 |
| uint128 截断 | capacity 字段经 INTEGER/i64 读取 | schema 使用 TEXT，增加最大值往返测试 |
| 历史迁移不可追溯 | projected target 与源不一致 | 阻断 M1，补 lineage 和身份冲突清单 |
| 生产版本混合 | 消费者 checksum/state version 不同 | 单窗口重建全部消费者，失败则整体回滚 |
| legacy 再次成为权威 | UI/运行时读取 `v4_closed_loops` | Manager API 过滤、架构守卫和调用链审计 |
| 观察窗口假通过 | 缺样本、差异被丢弃或伪造为 0 | 保存逐笔原始证据，缺样本视为 blocked |
| WSS/RPC 不可信 | stale、断连、速率超限 | 停止清理/晋升/广播，启用限速和恢复检查 |
| 二进制与源码不一致 | binary-source-match 失败 | 禁止部署，重建 release 并复验 checksum |
| 回滚不可用 | 备份未验证或恢复失败 | 禁止生产 apply，先在副本恢复演练 |

## 13. 停止条件

出现任一条件立即停止当前阶段，不得通过人工解释继续推进：

- RPC/WSS 不可信、状态版本漂移、快照陈旧或跨块不一致。
- 动态费率池、扩展库或测试库成员进入版本 1 主路径。
- 任一 hop 最终输入量跨 tick，或 single-tick capacity 无法证明。
- projected target、checksum、row count、schema、scope 或消费者版本不一致。
- 生产无备份、恢复演练失败、授权文本缺失或停机窗口未批准。
- orphan 非零、旧 label 残留、幂等重跑产生非预期变化。
- 回归新增失败、二进制与源码不一致、架构守卫失效。
- `safeToAutoBroadcast` 依据不完整或 review source 存在未解释分歧。
