# 按链独立 SQLite 数据库开发计划（2026-10-27）

## 1. 背景与目标

当前所有链共用 `flashloan/src/runtime/local_store.sqlite3` 一个 SQLite 文件：

- `database_path.py` 的 `resolve_database_path()` 只按“显式 database_url -> FLASHLOAN_KV_PATH -> 默认 local_store.sqlite3”解析。
- Web 页面切换链只改 URL `chain_id` 参数，数据库路径不会随链变化。
- 主网 `4663` 与测试网 `46630` 的池子、闭环、候选、交易记录混在同一个 3.6GB 文件里，运维和备份成本高，且链间数据互相污染风险大。

目标：

1. 每条链使用独立 SQLite 文件，例如 `local_store_4663.sqlite3`、`local_store_46630.sqlite3`。
2. 用户在页面切换链后，后续请求自动读取该链的数据库文件。
3. 扫描、复核、执行、维护等后台线程按任务所属链使用对应数据库。
4. 提供一次性分库工具，把现有 `local_store.sqlite3` 中的链数据按链拆分到新文件，保留全局注册表/配置数据。

配置分层：

- 系统配置 `.env`：控制 `FLASHLOAN_CHAIN_DATABASES` 开关、`DEX_ACTIVE_CHAIN_ID/DEX_ACTIVE_NETWORK` 后台活动链、运行目录。
- 链公开 JSON：`flashloan/src/chains/<network>/chain.json` 新增公开字段 `database.sqlite_file`，每条链可配置自己的 SQLite 文件名，文件中不包含任何私密数据。
- 链 SQLite：`<runtime_dir>/<database.sqlite_file>`，例如 `local_store_46630.sqlite3`。

## 2. 可行性分析

结论：可行，且现有架构已经为这种改造预留了清晰落点。

- Web 层已经有大量 `database_url_or_none()` 统一入口，只要让路径解析支持“当前请求链上下文”，所有页面/API 自动跟随。
- 数据库业务表基本都带 `network` + `chain_id` 列，可按链精确拷贝/过滤；`chain_markets`、`chain_info`、`chain_configs` 等全局注册表可完整复制到每个链库，保证链选择器可列出全部链。
- Rust worker 的 `submit_group` 已显式传 `database_path`，复核/执行可以按任务链写对应库；扫描/复核线程只要在执行点套上链作用域即可。
- 风险点：现有 `local_store.sqlite3` 约 3.6GB，不能简单整体复制两份；需要用“新库建 schema + 按链拷贝”的迁移方式。生产切库前先做 dry-run 报告，再受控重启；分库报告遇到不在 `_CHAIN_UNIVERSE` 中的 `(network, chain_id)` 作用域表时显式标记 `unsupported_chain_scoped_tables`，不静默留空。

## 3. 设计

### 3.1 链数据库上下文

新增 `core/db/chain_database_context.py`：

- 用线程局部栈保存当前链作用域 `(chain_id, network, source)`。
- 提供 `chain_database_scope(chain_id, network=None, source=...)` 上下文管理器，支持嵌套。
- Web `before_request` 从 `chain_id` 查询参数进入作用域，`teardown_request` 退出。
- 扫描线程的 `run_forever/_scan_one`、复核管线的 `run_once` 按任务 `chain_id` 进入作用域。

### 3.2 路径解析规则

`resolve_database_path()` 调整为：

1. 显式 `database_url` 参数仍然优先，保证 CLI/工具可覆盖。
2. 若 `FLASHLOAN_CHAIN_DATABASES` 开启且有链上下文，先读取该链 `chain.json` 的 `database.sqlite_file`，未配置时回退 `local_store_<chain_id>.sqlite3`（与默认库同目录；若设置了 `FLASHLOAN_KV_PATH` 则取该路径所在目录）。
3. 再回退 `FLASHLOAN_KV_PATH`。
4. 最后回退默认 `local_store.sqlite3`。

`FLASHLOAN_CHAIN_DATABASES` 默认关闭，避免未分库时请求链页面意外创建/读到空文件；`run.py` 检测到链库文件存在后自动开启，形成“先分库、后重启”的安全切换顺序。

### 3.3 分库迁移工具

BNB 是作为“共享标的数据”被其他链使用的，不能按 BNB 自身的 `(network, chain_id)` 拆分。最终方案是 BNB 使用独立共享库 `local_store_bnb.sqlite3`：

- `bnb_market_observations` 与 `bnb_market_snapshots` 只存在于 BNB 共享库，不复制进 4663/46630 等链库。
- `rs_bridge` 的 5 个 BNB 读写/采集函数默认指向 `local_store_bnb.sqlite3`，链库线程读取 BNB 数据时自动走共享库。
- `run.py` 启动独立后台维护线程，按 `FLASHLOAN_BNB_COLLECTOR_INTERVAL_SECONDS`（默认 60 秒，最小 60）采集 BNBUSDT 快照写入共享库。
- bnb chain.json 公开配置 `database.sqlite_file=local_store_bnb.sqlite3`，不含私密数据。
- 当前 BNB 两张表源数据为 0 行；共享库由 `ensure_bnb_shared_schema` 创建完整 schema 后由维护线程写入。

新增 `scripts/split_chain_sqlite.py`（Python 标准库 + sqlite3）：

- 只读打开源 `local_store.sqlite3`。
- 对每个目标链创建 `local_store_<chain_id>.sqlite3.tmp`，先建完整 schema。
- 全量复制全局表：`chain_registry*`、`chain_configs`、`chain_info`、`chain_contracts`、`chain_data_files`、`chain_flows`、`chain_markets`、`kv_entries`、`kv_meta`。
- 按 `network + chain_id` 精确复制所有链作用域表，例如 `v4_exchange_pools`、`v4_closed_loops`、`dex_candidate_*`、`market_observation_*`、`cow_execution_*`、`chain_tokens`。
- 写入 `kv_meta.chain_database_split` 元数据，原子替换目标文件。
- 支持 `--dry-run` 输出各链行数预估，支持 `--force` 重建，不修改源文件。

### 3.4 后台线程链路

- `DexOpportunityScanner`：`run_forever` 的周期扫描、队列扫描，以及 `scan_now/scan_async` 的直接扫描，都在 `_scan_one(chain_id=...)` 外层进入链数据库作用域。
- `FixedRefreshPipeline.run_once`：执行 `refresh_fn(task)` 时按 `task.chain_id` 进入链数据库作用域。
- `rust_closed_loop.get_native_pool`：记录已创建池子的 `database_path`；当当前链作用域对应的路径与池子不一致时，先 stop 旧池再按新路径重建，避免跨链复用错误 DB。
- `run.py` 启动后台时，对活动 DEX 链先 `ensure_database_schema` + 幂等 seed，再启动扫描器。

## 5. 验收

- `FLASHLOAN_CHAIN_DATABASES=1` 时，`chain_id=4663` 请求解析到 `local_store_4663.sqlite3`，`chain_id=46630` 解析到 `local_store_46630.sqlite3`。
- 两个链库都有完整 schema、全局 `chain_markets`、各自链的池子/闭环/候选/交易记录。
- 扫描线程写测试网库，手动复核写对应链库，Rust worker 的 `database_path` 与当前链一致。
- 未分库前 `FLASHLOAN_CHAIN_DATABASES` 保持关闭，现有行为不变。
- 主网 `4663` 不注册周期扫描，不把主网加入 watched chain。

## 6. 回退方案

- 设置 `FLASHLOAN_CHAIN_DATABASES=0` 并受控重启，恢复统一 `local_store.sqlite3`。
- 分库工具不修改源库；删除新链库不影响源数据。
- 不手工修改 evidence/SQLite/latest.json，不随意备份或提交 `.env`。
