> 本文档保留链运行时大对象重构的目标、实施和验收细节。

## 1. 重构结论

系统对外只保留一个“链运行时大对象”入口。页面、API、scanner、maintenance、Rust 执行组件和闭环状态机都从这个对象取得当前链上下文，不再各自读取链配置、拼接数据库路径或维护一份当前链状态。

大对象负责内部一致性。切换链不是修改若干散装变量，而是由大对象一次性解析并加载目标链的完整运行数据：链配置、SQLite、Rust pool、scanner、maintenance、闭环状态机、广播门禁和页面快照。切换成功后，外部只能看到新的完整对象；切换失败时保留旧对象并返回明确错误。

SQLite 仍是持久化事实源；内存大对象是运行时组合和一致性边界，不取代 SQLite，也不把所有业务数据复制成一个全局缓存。

## 2. 对外唯一入口

```text
ChainRuntimeRegistry
  └── active: ChainRuntimeContext
        ├── chain          链、网络、market、protocol 配置
        ├── database       当前链 SQLite 路径和只读访问边界
        ├── native_pool    当前链 Rust worker pool
        ├── scanner        当前链扫描器门面
        ├── maintenance    当前链维护 worker 门面
        ├── closed_loops   当前链闭环对象/状态机门面
        ├── broadcast      当前链广播门禁与执行队列门面
        └── page_context   UI/API 只读页面上下文
```

业务代码首选：

```python
runtime = chain_runtime_registry.current()
runtime.switch_chain(chain_id)       # 只由大对象完成整套切换
page = runtime.page_context()
```

模块级旧函数（例如 `get_native_pool()`、`native_worker_status()`）只作为兼容层，内部必须转发到按链 registry，不得再创建第二套“当前链”状态。

## 3. 核心对象职责

### 3.1 ChainRuntimeRegistry

- 按 `(chain_id, network)` 注册 `ChainRuntimeContext`。
- 维护 `active_chain_id`，提供 `current()`、`get(chain_id)`、`switch_chain(chain_id)`。
- `switch_chain()` 先构造并校验完整目标对象，成功后原子替换 active 引用；失败不破坏当前运行对象。
- 无 `chain_id` 的后台调用只能使用已明确设置的 active 对象；禁止静默回退测试网数据库。

### 3.2 ChainRuntimeContext

- 保存一条链的不可变身份和明确的 `database_url`。
- 组合 Rust pool、scanner、maintenance、闭环状态机和广播门禁。
- 暴露统一的 `status()` 和 `page_context()`，使 UI/API 不必跨模块拼装状态。
- 负责启动、暂停、关闭自己的子组件；关闭目标链不得停止其他链。

### 3.3 PageContext

- 只读页面快照，包含 chain、market、scanner、closed-loop、broadcast、permissions 和来源数据库。
- 在请求/页面边界生成，不作为长期业务缓存。

## 4. Rust pool 按链隔离

当前的进程级单一 `_POOL` 必须改为：

```python
_POOLS_BY_DATABASE: dict[str, Any]
_POOLS_BY_CHAIN: dict[int, str]
```

同一数据库路径复用同一个 pool；不同链即使同时运行也不能互相 stop/rebuild。`pool_for_chain(chain_id)` 解析该链数据库后取对应 pool。全局 reset/stop 仅用于进程退出或显式维护操作。

## 5. 实施阶段

1. **文档和契约**：固定单一入口、原子切换、SQLite 事实源、兼容层边界。
2. **Rust pool registry**：按规范化数据库路径复用 pool，补齐按链 status/submit/start/stop。
3. **运行时大对象**：新增 `ChainRuntimeRegistry`、`ChainRuntimeContext`、`PageContext`，完成注册、加载、切换、关闭和状态汇总。
4. **组件接入**：scanner、maintenance、closed-loop 和 broadcast 通过 context 解析数据库及 pool；移除各自的隐式当前链来源。
5. **Web 接入**：请求边界只生成一个 `g.chain_runtime`/`g.page_context`，页面和 API 优先使用该对象；保留旧 scope 兼容。
6. **测试和验证**：覆盖双链同时存在、切链原子性、pool 不互停、数据库一致性、旧入口兼容和进程重启恢复。
7. **运行验收**：先测试网观察 review terminal 和 broadcast terminal，再评估主网门禁；没有真实可执行路线时只报告“持续复核、未触发广播”，不得伪造广播记录。

## 6. 验收标准

- 切换链只调用一次 `runtime.switch_chain(chain_id)`，所有子对象的 chain/database/pool 一致。
- 测试网和主网 pool 可以同时驻留，切换 active 链不会停止另一链 worker。
- 任意 review cycle 都有成功、失败或明确 `execution_not_requested` 终态；请求过广播的闭环必须有成功或失败终态。
- 页面/API 的状态来源可追溯到当前 `PageContext.source_database`。
- 无 chain scope 时显式返回 `database_scope_required`，不静默使用测试网。
- 旧模块级入口仍可运行，但只作为兼容转发，不拥有独立状态。

## 7. 回滚和安全边界

- 不修改既有 SQLite 表结构，不手工补写运行记录、evidence 或 readiness。
- 目标 context 构造失败时保留旧 active context。
- 主网广播开关只有在具备明确授权后才允许改变；本重构本身不自动打开主网广播。2026-10-30 用户已明确要求打开主网 4663 广播开关，才将其从只读状态受控打开。

## 9. 2026-10-30 后续架构收敛项（未实施，先文档后代码）

以下内容已写入统一计划 `plan/后续开发计划_20261030.md` 第 3.3 节，本文档补充重构侧目标；未完成前不算 M2-11 收敛完结。

### 9.1 Rust 配置入口与全局运行对象

现状：

- `ClosedLoopWorkerPool` 构造参数 `database_path` 由 Python 桥传入；
- Rust 仅在没有该参数时调用 `default_database_path()` 读取 `FLASHLOAN_KV_PATH/FLASHLOAN_DB_ROOT`；
- Rust 没有按 `chain_id` 动态解析 active chain 的配置对象，切换链仍依赖 Python 重新求值并传参。

目标：Rust 入口有全局运行配置对象（可作为 `SQL_LITE_DB`/`RuntimeConfig` 的组合实现），保存当前 chain/network/database_path/pool 等最新值；Python 切换链时只更新大对象，Rust 读取始终是最新实时数据。显式 `database_path` 参数只能作为兼容覆盖，不能成为唯一事实源。

验收：

- 切链后不传 `database_path` 的 Rust 查询/提交落入新库；
- 无 active chain 时显式 `database_scope_required`；
- 显式传参行为与旧调用兼容；
- 定向测试覆盖全局读取、显式覆盖、无 scope。

### 9.2 Web/UI 大对象唯一入口

现状：`PageContext` 已存在，但 Web 层仍有散装 `database_url()`/`panel_call("database_url")` 调用，未完成逐路由收敛。

目标：Web/API 只读 `g.chain_runtime`/`g.page_context`；页面配置数据按“一个 PageContext 大对象，内部多个具体对象”组合；切换链只整体更换来源，不在页面层出现第二个入口。

验收：

- 散装取数据库调用逐文件核对并收敛；
- `sourceDatabase` 与当前 PageContext 一致；
- 无 scope、指定 chain_id、active 切换三类 Web 路径均有定向测试。
