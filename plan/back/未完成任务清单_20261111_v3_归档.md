## 10. 口径更正（持续有效）

- **`非卡号并发说明`**：Rust `max_workers` 实际为 **16**；
  healer `--candidate-limit 1` 只限制每轮**主动 repair 请求数**，与 worker 线程数无关。
- **最佳交易量极小的根因**：`probeRecords` 长度全为 1（阶梯从未展开，
  `bestAmount` 实为初始 1.0 token 的二分下界）+ `balances` 缺 `token0`/`token1`
  → `maxProbeAmountRaw` 回退为 64 tokens 固定上限。
  **代码侧根因已修**（`balances` 现写入 token 计价储备与容量）；
  生产侧待 `depth --apply` 铺开后 `ladderIncomplete` 应自然归零。
  `best_amount_ladder_incomplete` fail-closed **是安全网，不得放宽**。
- **"65e0 利润"中约 40% 是复核错误**：`route_unprofitable` 且 `probeRecords=0`
  与 11 probe 的合法无利润必须分开统计。
- **估算正收益不是利润**：来自 `native_contract_rate_delta_estimate` 且 `bestAmount`
  缺失的正值不得计入利润总额。完整 24h 窗口 `positiveEstimateOnly=165`；
  观察 epoch 裁剪后 `76` —— **差异来自 epoch 而非回归**。
- **并发与容量不是瓶颈根因**：实际瓶颈是闭环引用的池已被清理
  （318 跳中 38 跳失联，涉及 38 条闭环）。
- **深度主判据**：**链上价格冲击容量**（token 计价，ε = 10 bps）。
  `liquidity_index` 不是深度信号；`estimated_tvl_usd` 仅作排序 tie-breaker。
- **USD 价格不参与执行判断**：ETH / 股票价格源不体现套利交易价值，
  不得参与准入、容量或门禁判定。
- **池深结论**：~~`market_depth_exhausted`~~ **作废**；
  "不得依据 TVL 下架 token 对"的约束继续有效。
- **工具版本是门禁的一部分**：部署的 `pool-manager` 若不认识
  `ensure-indexes` / `ensure-depth-schema` / `depth`，healer 会以
  `stopped="tool_deployment_gap"` 与 blocker `pool_manager_commands_missing`
  **明确停下**，不再静默跳过容量铺设。
- **Rust 容量不得饱和**：池容量是有限的链上量。输入溢出时的 `u128::MAX`
  哨兵值曾被读成「价格冲击 0」，使容量被误判为无穷大；现已由
  `reserve_ceiling()` 封顶，并由跨语言一致性测试锁定。
- **漂移是部分失联不是完全脱节**：原写「42/106 环池零命中」有误——
  实测 **0 条零命中、38 条部分命中**；修复动作是重建闭环而非重建候选集。
