# 未完成任务清单 v9.4（2026-11-13 重排版）

> **唯一活动任务清单。** 2026-11-11 完整正文及 v9.1–v9.3 快照均位于 `back/`。已完成事项不得留在本文件中；完成后必须移动到 `back/` 并从本清单删除。

## 0. 执行原则

1. **Rust Manager 权威**：代币、池、候选边、候选交易池、闭环、复核、广播和组合编排的功能逻辑必须位于对应 Rust manager；Python 只负责 RuntimeCore 桥接、配置输入、页面展示和历史兼容。
2. **生产写入需授权**：未经用户明确授权，不得写 `flashloan/db/local_store_4663.sqlite3`。
3. **停机动作需窗口**：W7/W8、二进制替换和 Authority 切换必须取得停机窗口。
4. **版本 1 只做 single-tick**：每跳不得跨 tick；跨 tick 接口保留但不优化、不进入主路径。
5. **准入约束**：固定费率 `0 < fee <= 30000`；动态费率池排除；hook、深度和池角色约束继续生效。
6. **USDG 口径**：经济学意义上 `1 USDG == 1 USD`；USDG 替代 USD 的计价作用，但不得把外部 fiat 价格源或 TVL 引入深度准入。
7. **RPC 预算**：QuickNode 免费额度不超过 15 req/s；pool-manager 默认 8 req/s、batch 50。
8. **SDK 优先但 authority 唯一**：优先使用成熟 Rust SDK；任何新数学 SDK 必须先完成 parity、舍入、性能、许可证和回滚评估，不得形成双生产 authority。
9. **`app_runtime` 边界**：`flashloan/app_runtime` 必须纳入架构审计；Python 页面和任务只能调用 RuntimeCore/Manager API，不得直接恢复 fee/token/pool/route/review/broadcast 业务判断。

## 10. P8｜池生命周期、WSS 与 3000 池上限

- 备用池：最近 3 天有交易，且满足基本深度、固定费率和 hook 限制；清理开关默认关闭，只有正式运行且数据量达到配置阈值后才可启用；按每 3 个自然日的当日 24:00（即次日 00:00）清理。
- 候选池：每方向 TOP-5，不清理，动态更新。
- 推荐池：每方向 TOP-1，不清理，动态更新。
- WSS 缺失或状态不可信时，备用池清理 fail-closed 停用。
- 动态费率池不得进入备用、候选或推荐角色，也不得参与晋升排序。
- 池表总量不得超过 3000；超过时按角色保护、交易活跃度、深度、费率、更新时间确定性淘汰。
- 清理配置必须显式包含：启用开关、数据量启用阈值、3 日保留窗口、Asia/Shanghai 调度时区、WSS 健康门禁、单次最大删除量和 dry-run/apply 模式；具体配置名由 Rust `pool_manager` 定义。
- 候选/推荐动态刷新与备用池清理必须使用同一 pool state version，避免先清理后晋升造成竞态。
- 验收：监听→状态更新→活跃判定→晋升/降级/淘汰全链路验证。
