## 目标与口径

- 只推进 Robinhood V4 测试网实盘观察，不扩多链；
- 执行依据必须是实时行情/链上 Quoter（`dex_quote_routes`、live Quoter 或 `eth_call`），历史快照只作审计，不作可执行计划；
- 测试网广播开关保持 `true`，持续观测自动扫描产生的实时交易机会；
- 方向完成门槛为 1 条活跃候选，5 仅作推荐池数量上限；
- 除 `TZ -> TA -> TB` 主动测试注入流动性外，其他闭环不自行注入流动性；
- 主网、paused-deploy、executor canary 广播保持 `false`；
- readiness 只由 CLI 写入，禁止手工改 `latest.json`；
- 无 signed 数值时 P&L 保持 `null` + `missingReason`，不写零占位；
- SQLite 是提交记录唯一在线存储，旧 JSONL 只作历史迁移源或归档审计；
- 提交记录只展示复核通过且预期盈利为正后进入链上广播的提交类记录（成功/失败），复核记录独立展示在 `/dex/submissions/review`，两者不混同；
- 所有结论必须来自命令输出或 evidence 文件，不伪造链上结果；
- 参数/搜索模式调整前必须有链上 mulch 或 ladder 降额 evidence；
- 只读复核遇到 RPC 传输失败时自动切同链备份 RPC，广播仍只走单一选定 RPC、不跨节点重复提交；
- 可自主推进与等待外部依赖分开排期；外部未就绪前保持 fail-closed，只记录最近一次核对时间；
- F3 的 RPC failover 实现与隔离 worker 验证已收口；生产启用与后续观察转 M3-2；F5 的 `pool.stop()` 停止语义已收口；
- `readyForTransactionPreflight=true` 由链上报价复核自动计算（净利过提交阈值、每跳价格影响 <=10 bps、最佳交易量 `bestAmountConfirmed`），不手工设置。
- 链上复核具体数值（`selectedProfitRaw/selectedProfitAmount`）只在 Rust 合约 `eth_call`/preview 返回原生值时有意义；`NoProfitableRoute()` / `previewBestPoolDetailed unavailable` 无 eth_call 净利数值，展示时必须与 SQLite 参考 P&L 分开标注。

## 初始交易量为 0 的专项说明（2026-10-25）

- 现象：`TZ -> TB -> TA -> TZ` 等 native attempt 页面显示“初始测试交易量：0.00000000 TZ”，但任务配置实际按 borrow decimals 生成 `initialAmountRaw=max(1, 10^decimals)`（18 decimals 时即 1 TZ），不会把 0 作为测试量。
- 根因：Rust 外层 `official_v4_preview_and_ladder_inner` 在 pool preview / detailed preview 失败的无利路径只输出 `selectedAmountRaw=0x0`、`selectedProfitRaw=0x0`，没有回传 `initialAmountRaw`；Python `_native_worker_evidence` 拿不到初始量后用 `selectedAmountRaw` 兜底，于是 0 被当作初始测试量写入。
- 本记录（SQLite `id=29715`，`created_at=2026-10-24T22:58:47Z`）同时附 `previewBestPoolDetailed unavailable` 与 `probe_records=[]`，说明实际没有执行 ladder 探测，0 不是真实“用 0 金额测试”。
- 修复（M6-3）：Rust `v4_no_profit_payload` 与最终 payload 补回 `initialAmountRaw`/`minProfitRaw`；Python 对缺失或 `0x0` 占位保持 `null`/“未记录”，不再回填 0；旧记录中已写入的 0 属历史数据缺陷，新写入不再产生。
