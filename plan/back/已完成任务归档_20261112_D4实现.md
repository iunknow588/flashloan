## 2. 锁定的决策（本次实现严格遵守）

1. **零 USD 依赖**（"ETH 价格源与股票价格都不影响套利执行"）
2. 容量判据 = 链上价格冲击容量，**token 计价**，ε = 10 bps
3. `estimated_tvl_usd` 仅作排序 tie-breaker / 人工观测；**绝不依据 TVL 下架 token 对**
4. `best_amount_ladder_incomplete` **fail-closed 不放宽**
5. `capacityGate.verdict=unknown` ≠ 故障（仅 `DEX_V4_CAPACITY_GATE_REQUIRE_MEASURED=1` 时阻断）
6. USDG 规范地址 `0x5fc5360d0400a0fd4f2af552add042d716f1d168`（dec 6）
7. **无生产写入授权**；生产库一律 `file:...?mode=ro`
8. 不停止/重启守护器与 `run.py`；不 commit、不建分支；保留全部既有未提交改动

### 2.1 为什么拒绝"USD 价值漏斗"（用户建议中的美元折算部分）

生产 88 条闭环借入代币实测：

| 借入代币 | 闭环数 | USD 稳定币 |
|---|---|---|
| ETH | 38 | 否（原生） |
| SPY | 30 | 否 |
| GOOGL | 6 | 否 |
| WETH | 4 | 否（封装原生） |
| SPCX / CRCL / MU | 8 | 否 |
| TZ | 2 | 是 |

⇒ **42/88（47.7%）借入股票代币**，**86/88（97.7%）借入既非 ETH 也非 USD 稳定币**的代币。
此类标的在 Robinhood Chain 内**不存在链上稳定可靠的 USD 价格**，
链下报价源又已被明令禁止进入执行判据 ⇒ `cap_in_usd` 对绝大多数闭环**无法求值**。

**采纳的等价表达（token 计价）**：

```text
cap_path      = min(binding_capacity[hop] for hop in path)   # token 计价
required_amt  = gas_profit / unit_profit                     # 覆盖 Gas 所需仓位
若 cap_path < required_amt  ->  路径经济不可行，一票否决（不进 24 步搜索）
start = clamp(cap_path * frac, required_amt, cap_path)
```

| **D4-c** | `flashloan/app_runtime/tests/unit/test_d4_capacity_informed_ladder.py`（12 项）+ `execution.rs` 4 项 Rust 测试 | 覆盖起点落窗、失败分支向上收敛、首探随容量变化、经济门禁短路/放行、`bounded_double` 不越上界 |

| **D4-e** | `execution.rs`（零探测短路）+ `worker_pool.rs::economic_floor_gate_blocks_broadcast` | 经济不可行路径在阶梯入口即返回 `status="economically_infeasible"`、`attemptedCount="0x0"`、`attempts=[]`（**零次链上探测**）；广播门禁 + 执行队列路由均拦截；**池子本身仍保留在候选集** |

**生效链路**：`route_config["economicFloorGate"]` → `route_payload` → `live_onchain_evidence` → 广播门禁。

**拉黑边界（严格遵守用户约束）**：

| 分类 | 处置 | 理由 |
|---|---|---|
| 容量 < 经济下限（覆盖不了 Gas） | **拉黑出执行链路**（`dust_unprofitable`），**保留在候选集**供人工观测 | 无论币价如何都不可能盈利 |
| 容量 < 0.001 token 但 >= 经济下限 | **保留探测**（D4-a 容量感知起点使其可被覆盖） | 可能存在高单位利润的稀薄套利 |
| 依据 USD 价值低而拉黑 | **禁止** | 依赖被明令禁止的 USD 价格源；97.7% 闭环无可靠链上 USD 价 |

### 4.1 失败归因核验（**关键，非走过场**）

26 项失败与基线数量一致，但仍逐项核验了 2 个可疑项
（`test_native_pool_registry_replaces_python_pool_cache`、
`test_scanner_records_preflight_failed_when_native_rpc_config_unavailable`，
二者单独运行**通过**、随组运行**失败**，疑为跨测试污染）。

**核验方法**：对 D4 代码做**逐块手术回退**（Python helper + 调用点 + Rust 短路 + Rust 广播门禁
+ payload 传播），在同一 2 文件子集上重跑。

| 条件 | 子集失败数 |
|---|---|
| 保留 D4 | **4** |
| **移除 D4** | **5** |

⇒ **移除 D4 后失败集合反而扩大**，证明这些失败是
**跨测试污染型既有失败**（`test_architecture_guards.py` 先执行污染了
`test_rust_closed_loop_worker_bridge.py` 依赖的全局状态），**与 D4 无因果关系**。
**结论：零新增失败。**

> 附带发现：该污染本身是一个**独立的测试卫生缺陷**，已登记为后续项
> （非 D4 范围），建议对 `test_architecture_guards.py` 做全局状态隔离。
