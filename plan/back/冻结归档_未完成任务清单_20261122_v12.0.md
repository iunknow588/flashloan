### 0.1 排序原则（本轮新立，绑定性）

本清单的**执行顺序**由下列三条原则决定，**不是**由任务编号决定：

1. **功能完善优先**：能在离线环境完成、且能提高系统功能正确性的工作**排在最前**。
2. **性能优化最后**：性能调优类工作**一律排在全部功能性任务之后**，不得提前占用实现窗口。
3. **耗时/需授权的测试靠后**：实盘广播、长时间窗口、需要写库授权的动作**排在最后**，且必须在其前置全部闭合后才启动。

**推论**：**任何任务的关闭都不得依赖尚未启动的耗时段**。§2 的功能性任务一旦闭合，系统功能即为完整；
§3 的耗时段只负责**取实盘读数**，不负责补功能。

### 0.3 写库分类学：**基础框架库** vs **动态记录**（**绑定性规则**）

> **使用者指示（2026-11-21）**：*"基础框架库要实盘写入，动态记录可以不写。"*

本项目一切"写生产库"的表述，必须落到**下面两类之一**。**把两者混为一谈是错误**，
尤其**不得**把"基础框架库写入"挂到"需单独授权"的闸门下。

| 类别 | 内容 | 性质 | 处置规则 |
|---|---|---|---|
| **基础框架库**（baseline framework） | DDL / migration / 表结构 / 列 / 约束 / 索引 / 视图 | 结构性、版本化、**幂等**、**保数据**（不重写业务行）、与链上实时状态无关 | **验证通过 ⇒ 必须实盘写入目标生产库**（该链的 DB）。**不需额外授权。** |
| **动态记录**（dynamic records） | review / depth / ladder / PnL / closed loop / broadcast attempt 等测量与运行记录 | 每次运行都变；受"**实测零 ≠ 未测**"、"**不历史回填**"、"**需当前链状态**"约束 | **可以不写**；要写时按 §3 的授权流程走 |

**判定口径**：一次写入若**不改变任何测量值、只让结构与代码对齐**，就是**基础框架库**；
若**写入的是某时刻的测量结果**，就是**动态记录**。

**推论（第 55 轮已落实）**：迁移 `011..013` 属**基础框架库**（纯 DDL、保数据、不涉及任何
动态测量值回填），因此**在两条链的 DB 上直接写入，不需单独授权**。详见 §2.2。

### 2.2 TASK-154｜ETH 与 WETH 两个独立资金锚点（**不做互相转换**）

**使用者指示（2026-11-21）**：**"不要用 WETH 偿还 ETH。这是浪费。"**

**真实表述（已与代码核对，作为本任务的正式口径）**：ETH 与 WETH 是**两个不同的资金锚点**，在 V4 中**不存在**"闪电贷借贷关系"这种需要跨锚点结算的东西。
凡是涉及 ETH 与 WETH 的闭环，**全部使用各自锚点的资金代币结算**：ETH 锚点的闭环就用 ETH 结算，WETH 锚点的闭环就用 WETH 结算。
**它们就是两个闭环** —— 不要把 ETH 转成 WETH，也不要把 WETH 转成 ETH。在 V4 中它们就是两个独立的锚点代币，**不要特殊处理就可以了**。

已写入开发计划 **§3.3.1**（绑定性架构规则）与 **§7.12**（协议分析与实测证据）；本任务负责把它变成**可独立核验的验收项**。

**为什么是语义规则而不只是省 gas**：把 ETH 转成 WETH（或反向）会**改变闭环的锚点** —— 借出币种与偿还币种不再属于同一个锚点，这在语义上就已经不是同一个闭环了；同时还要付出两次 ERC-20 `transfer` + `approve` 的 gas。

**代码现状（已核对，实现已自然成立）**：
- 闭环身份 = 资金锚点 + 方向池子；`loop_key = "{anchor_address}:{y_address}:{z_address}"`（`flashloan/tools/closed_loop_manager/src/lib.rs` 约 2390 行）。**锚点地址在键里** → ETH 锚点闭环与 WETH 锚点闭环**键值不同**，天然是两条闭环。
- `address(0)` 在本系统里是**普通地址**：`normalize_address()`（`flashloan/tools/manager_contracts/src/ids.rs` 约 272 行）只做小写 + 长度 + 十六进制校验，**无任何特判**；单测 `native_zero_address_is_valid_and_distinct_from_weth`（约 323 行）已断言两者 `currency_key()` 不相等。**不要新增 `isNative` / `isAddressZero` 分支。**
- 请求构建层已按锚点自然成立：`build_v4_flash_executor_request()` 强制 `first_input == token && third_output == token`（约 604–610 行），请求体只带**一个** `token` 字段与 `finalToken`（约 626–630 行）；`route_currency()`（约 517 行）只读各池自己的 `currency0`/`currency1`。
- **第 54 轮新增**：执行请求与闭环锚点的**绑定守卫**已落地（见 §2.1 `TASK-155`），把"各闭环用各自锚点结算"从**约定**升级为**内核强制**。
- 结算对象 = 锚点代币（内核注释约 2188–2193 行：*"The borrow token is the anchor token…"*），实测 `path[0]==path[-1]==anchor` **164/164** 命中。

**已知的仓库侧事实**（可直接核验，主网 chain 4663）：`manager_v4_closed_loops` 共 164 条，其中 **ETH 锚点（`address(0)`）26 条**、**WETH 锚点（`0x0bd7…ad73`）6 条**，**键完全分离**；
两者 USDG 估值 **2461669444** vs **1804537685**（**不同估值**），各 18 小数；token 库中 ETH = `token_kind='native'`、WETH = `token_kind='wrapped_native'`。
路径中**经过** WETH 池（ETH 锚点有 4 条）或 `address(0)` 池（WETH 锚点有 4 条）是**池自身的计价币种属性**，**不等于**锚点资产被转换。

**验收项**（见 checklist `TASK-154`）：
① ETH 锚点闭环的实盘请求 `token` 字段为 `address(0)`，WETH 锚点闭环为 WETH 地址 —— 各自等于本闭环锚点；
② 请求体中**不存在**任何跨锚点转换动作（无 wrap/unwrap、无 ETH↔WETH 换币）；
③ 不新增"原生 ETH 特殊处理"分支：`address(0)` 走与普通地址**完全相同**的代码路径；
④ 路径中经过异种锚点池时，**该段**按该池自身币种计价，**闭环锚点不变**。
