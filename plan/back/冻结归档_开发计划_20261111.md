### 1.1 最终完成定义

主网编排器达成**持续、稳定、可核对**的状态：

1. 每分钟一轮复核，产出**具体**最佳交易量（`bestAmountConfirmed=true`，
   阶梯已展开），而非"预期盈亏数字"。
2. 池深结论基于**链上价格冲击容量**（token 计价，ε=10 bps），零外部 fiat 价格源依赖。
   （**USDG 取代 USD 的计价作用**——`R-11`；但深度判据本身不需要计价换算。）

5. 广播前门禁 fail-closed：任何未测量、未确认、过期、版本不符都**停下**。

### 2.3 不可违反的执行判断

1. **外部 fiat 价格源不参与任何套利执行判断；USDG 已取代 USD 的计价作用。**
   - **作废对象 = "外部 fiat 价格源"**（预言机 / 交易所指数价 / 人工报价 / 股票 USD 价）。
     根因不是"美元无价值"，而是**大量代币根本没有兑换渠道**，任何 USD 价都取不到。
   - **USDG 在绝大多数情况下有兑换渠道**，所以 **USDG 取代 USD 承担计价单位**：
     `1 USDG == 1 USD`（经济学意义）是其定义属性，见 `R-11`。
   - **可作判据的经济量一律以 USDG 表述**：经济下限、承载能力、名义价值、Gas 成本折算
     都用**同额 USDG**，**不需要**预言机 / 交易所指数价 / 人工报价。
   - `estimated_tvl_usd` 仍仅排序 tie-breaker 与人工观测，**不作任何门槛**；
     `usdg_amount_decimal` / `capacityBindingRaw` 才是可作判据的计价量。
   - **边界**：USDG 取代 USD 只作用于**经济量表述与经济类门禁**；
     **深度/容量判据仍禁止引入计价换算**（深度是池子自身代币计量，ε=10 bps）。
2. **`best_amount_ladder_incomplete` fail-closed 是安全网，不得放宽。**
   归零靠数据修复，不靠放宽门禁。
3. **不得依据 TVL 结论下架任何 token 对。**
   唯一的下架依据是**股票代币无法与 USDG 兑换**（`R-12`），
   这与 TVL 无关。
4. **容量未测量 ≠ 故障**；仅在 `DEX_V4_CAPACITY_GATE_REQUIRE_MEASURED=1` 下升级为阻断。
5. **一个 blocker 不遮蔽另一个**（`code` + `secondaryBlockerCodes`）。
6. **部署二进制必须与源码一致**（`pool_manager_binary_out_of_sync`）。
7. **扫描量 ≠ 并发量**（`scanRequestCount` 与 `workerConcurrency*` 分列）。
8. **不改生产库除非获得显式授权**；本计划的 W1–W5 全部只读或只改代码。
9. **股票代币准入必须绑定 USDG 可兑换性**（`R-12`）：
   不能与 USDG 兑换的股票代币**不得**进入股票代币表，
   因此**也不会**进入资金池代币。核心代币、测试代币无此约束；
   扩展代币不要求自身估值，但其经由股票/核心代币与 USDG 保持关系，
   该约束**逻辑上传递成立**。

### 3A-2. ARCH-2b-2 闪电贷手续费口径归因与修正（**2026-11-13，已完成**）

**根因**：链下模拟器把闪电贷手续费硬编码为 **5 bps**，而生产链路上
**链上根本不收手续费**。这造成了一个**系统性、且与池状态无关**的偏差，
此前被误记在"陈旧本地状态"名下。

**链上事实（逐笔取证，非推断）**：

生产路由走 `OfficialV4FlashArb` 语义，**直接向 Uniswap V4 PoolManager
借币**（`runArbitrageBest(tokenZ, keysets, directionsets, amountIn, 1)`，
末位 `1` 是 `minProfit = 1 wei` 的利润下限，**不是手续费**）。合约结算为
`required = amountIn + minProfit`，V4 PoolManager 本身**不收闪电贷费**。

副本库中 12 条独立对比的链上 revert 逐条解码后**完全一致**：

| 字段 | 链上值 |
|---|---|
| `requiredRepay` | `1000000000000000001` = 本金 + **1 wei** |
| 有效手续费 | **0 bps** |
| 链下模拟器假设 | **5 bps** = `500000000000000` raw |
| 逐笔差额 | **恰好等于 5 bps 费用**（17/17 条 `offline_v4_sqlite_route_snapshot` 命中） |

**修正（架构仍在 Rust 管理器内）**：

| 职责 | 归属 |
|---|---|
| 从链上结算推导有效手续费 | `review_manager::effective_flash_fee_bps` |
| 判定假设费与链上费是否一致 | `review_manager::chain_fee_matches` |
| 手续费假设偏差的独立归因 | `ParityAttribution::FlashFeeAssumption` |
| 遗留 5 bps 残差识别（历史证据） | `review_manager::legacy_fee_residual` |
| 默认值（链上事实） | `review_manager::DEFAULT_FLASH_FEE_BPS = 0` |
| Python | 仅转发，**零数学** |

关键设计：**手续费不再由常量决定，而由链上自己的结算推导**。
链上手续费是 owner 可变的适配器参数（`setFlashSourceAdapter(..., feeBps, ...)`），
因此推导优先于假设；`CHAIN_MIN_PROFIT_RAW = 1` 被单独识别为**利润下限**，
不得当作手续费。

Python 侧同步区分了两个概念（此前混为一谈）：

| 常量 | 含义 | 值 |
|---|---|---|
| `CHAIN_FLASH_LOAN_FEE_BPS` | **链上真实手续费**（链上事实） | `0.0` |
| `DEFAULT_FLASH_LOAN_FEE_BPS` | **链下预检余量**（gas / 滑点 / 状态漂移的门槛） | `5.0` |

预检余量**不得**进入：链下算本的净收益、链上要求偿还的金额
（`repayAmountRaw`）。后者此前被 5 bps 虚增 0.05%，是**真实生产缺陷**。

### 3A-3. ARCH-2b-3 复现时间池状态对齐（2026-11-13，已完成）

**根因（方法论错误，不是算本错误）**：
复盘只能用「记录那一笔当时看到的市场」来复现「那一笔的结论」。
原实现拿**当前本地快照**去比较一层发事前的记录，这是比较两个不同的市场，
结果必然偏差，且偏差量不能归因于算术。这是本轮最重要的口径修正。

**关键发现：记录本身就携带了它当时的池状态**。
`cow_execution_reviews.payload_json` → `quote.candidate_pools[]` 里每个池都带有
`sqrtPriceX96` / `liquidityIndex` / `fee` / `tickSpacing` / `token0` / `token1` / `liquidityReadAt`，
且 `poolPathKey` 与 `candidate_pools` 的顺序一致。这意味着**复现准确的输入就在记录里**，
不需要再去猜「当时市场是什么样」。

**池深度单位的确认（逐条取证）**：
记录里的 `liquidityIndex` 就是存储表的 `liquidity_index` 列，而该列的定义是 `L / 1e18`。
对副本库 179 条记录逐条比对（常数与离散度）：
按 `liquidityIndex × 1e18` 还原一类正确的条数是 **179 / 179**，按原值的是 **0 / 179**。
因此 `LIQUIDITY_INDEX_SCALE = 1e18` 是唯一正确口径。

> 注：JSON 写出器对大指数使用科学计数法（如 `9.901032566577074e+17`），
> 解析必须同时支持普通写法与科学计数法，否则会静默丢掉池状态。

**修正（功能性任务仍在 Rust 管理器内）**：

| 职责 | 归属 |
|---|---|
| 从记录仓储读取复现时间池状态 | `review_manager::extract_review_time_pool_states` |
| 池深度指数 → 原始流动性的精确换算 | `review_manager::review_time_liquidity` / `decimal_times_power_of_ten` |
| 复现时间状态优先于当前快照 | `review_manager::merged_pool_states` |
| 已完全解释的归因 | `ParityAttribution::ReviewTimeStateExplained` |
| Python | 仅转发，**零数学、零表读取** |

边界不变：复现时间的池状态来自 **Review Manager 自己的表**（`cow_execution_reviews`），
因此它属于 Review Manager；当前快照仍然只通过 **Pool Manager 公开 API** 读取，
并仅在记录未携带状态时作为回退。

## 10. 阶段 ARCH-4：内存池取代 `eth_call`（**分阶段，先并行对照**）

### 10.1 目标与迁移策略

用**本地内存池状态**取代链上 `eth_call` 预览，把每次广播前的链上往返从
**50–100ms** 降到**微秒级**。但**不是一次性切换**，而是**三阶段渐进**：

| 阶段 | 做法 | 出口条件 |
|---|---|---|
| **A｜并行对照** | 内存池与 `eth_call` **同时运行**，逐笔对照两者结果 | `executable` 不一致 **= 0**，且**不可归因**差异 **= 0** |
| **B｜影子旁路** | 内存池作为**主**计算源，`eth_call` 保留为**影子校验**（只记录不阻塞） | 影子差异率长期为 0，且 `eth_call` 可随时回切 |
| **C｜纯内存** | 关闭 `eth_call`，仅用内存池；保留**链上快照比对**（ARCH-3）兜底 | 见 §10.4 门禁 |

> **关键原则**：**先证明等价，再切换**。
> 绝不"先关 `eth_call` 再验证"——那会把内存池漂移直接变成链上回滚与 Gas 损失。

### 10.1.1 差异处理策略（**2026-11-12 裁决，重要**）

**核心：差异归因失败 = 标记异常 + 修正本地内存；执行继续按 `eth_call` 的结果。**

差异出现时**分两步**，两步**互不排斥**：

**第 1 步：判断 `eth_call` 本身是否可信**（这是**执行**决策的前提）

| `eth_call` 可信性判断 | 依据 | 处理 |
|---|---|---|
| **可信**（正常情况） | RPC 正常、返回结构合法、未报错、与链上状态自洽 | **直接按 `eth_call` 的结果执行**；同时**修正本地内存**的缺陷 |
| **不可信** | RPC 超时/报错、返回畸形、节点异常、链上已变更 | **阻断**，回退到既定降级路径（重新拉状态 / 暂缓执行） |

> `eth_call` 一般不会出错——它是**链上权威**。因此**默认按"可信"处理**：
> 用它的结果继续跑完后续流程，同时把差异**记下来并修**。
> **只有当有具体证据表明 `eth_call` 本身不可信时，才阻断。**
> 不能反过来——不能因为"本地内存算错了"就阻断一条本来正确的执行。

**第 2 步：处理本地内存的偏差**（这是**缺陷修复**）

| 情形 | 处理 |
|---|---|
| 差异**可归因** | 记录归因（如池状态版本不同、tick 边界跨越、费用口径不同、舍入差异） |
| 差异**归不出因** | **标记为异常**（anomaly）写入异常台账，**并修正本地内存的计算逻辑** |

**这意味着**：

1. **执行决策权始终在 `eth_call`**。内存池**永远不**阻断执行，
   也**永远不**覆盖 `eth_call` 的结论。
2. **异常不是事故，是待修缺陷**。归不出因的差异是**必须被修正**的对象，
   修正目标是让两者**重新一致**，而不是"绕过它"。
3. **异常必须落到"改代码"，不只是"记一笔"**。修正对象是**本地内存的
   计算逻辑**（状态同步、tick 边界、费用口径、舍入、精度），
   修正后需回归到与 `eth_call` 一致。
4. **不得**把"标记异常"当作"可以带着异常继续推进阶段 C"。
   阶段 C 的门禁仍要求差异归零——**异常必须在切换前清零**。
5. 异常台账需要记录：差异字段、量级、首次出现时间、影响的路径、
   当前的归因状态（`unexplained` / `explained` / `fixed`）、
   以及**已落地的修正**（改了哪段逻辑、回归结果）。
6. **阻断的唯一合法理由是 `eth_call` 不可信**，而不是"内存算错了"。
   反过来，**内存算错时也绝不阻断**——否则一个本地缺陷就能冻结全链路。

> **与"fail-closed"原则的关系**：池深、容量、广播门禁的 fail-closed
> **不受影响**——那些是"数据不可信就不执行"。本条讲的是**两个都可信的
> 计算源之间的对照观测**：`eth_call` 是链上权威，它可用就不需要阻断；
> 只有当它**不可用**时，才需要另一个源顶上。

### 10.5 与"池子生命周期"的强依赖

内存池取代 `eth_call` 的前提是**池子状态有持续的、可靠的更新来源**。
因此**观察池 3 天 TTL 清理必须配套消息监听**：

- 观察池的 TTL 淘汰**依赖 WSS 监听**保证"不活跃"判定准确；
  没有监听，TTL 会误杀活跃池，或让死池长期占用资源
- **推荐池与备用池不参与 TTL 淘汰**（`core_pools` 物理隔离，永不清理）
- 三者是一个**一体机制**：监听 → 状态更新 → 活跃判定 → 晋升/降级/淘汰
- **WSS 监听缺失时，TTL 清理必须停用**（fail-closed），而不是盲删

### 10.6 风险与不可违反项

- **不得**在阶段 A/B 关闭 `eth_call`
- **不得**用内存池结果直接发交易而不经链上比对（ARCH-3 未上线前）
- **不得**在内存池状态版本落后时"照旧发车"——必须停止
- 内存池**不是**权威源；链上状态永远是最终裁判
- **不得**因为归因失败就阻断执行（见 §10.1.1）；异常要**修**，不要**挡**

## 11. 阶段 VAL-4：USDG 计价的经济准入门禁

### 11.1 裁定与意图

**裁定（2026-11-12）**：资金池都可以用 USDG 衡量。

- **股票池（关键约束，`R-12`）**：一个股票代币如果**不能与 USDG 兑换**，
  就**不应进入股票代币表**，因此**也不会进入资金池代币**。
  后续动态刷新，发现有 USDG 兑换路径之后，**再加进股票池**。
- **核心代币 / 测试代币**：**无此约束**。核心库承载本链自身的计价与抵押资产，
  测试库承载刻意与市场脱钩的夹具，二者都不以市场测量为准入条件。
- **扩展池**：**不要求自身估值**。它的约束是**承载能力**——
  扩展代币的池子必须能承载资金池的量；若连最低初始交易量
  （1 token 或 10 USDG）都承接不了，即为**灰尘池子**，**应予排除**。
- **扩展代币与 USDG 的关系是传递性的**：扩展代币经由**股票代币或核心代币**
  与 USDG 保持关系，而前者受 `R-12` 约束、后者是 USDG 本身的计价锚，
  所以该约束在逻辑上仍然成立——只是不表现为"扩展代币自身必须有估值"。
- 因此中间池子**并非没有评价标准**：它的评价维度是
  **承载能力**（能否承载最小经济位置），而非自身价值。

> **`R-11`（USDG ≡ USD）**：USDG 是本链的计价资产与稳定币锚，
> 经济学意义上 `1 USDG == 1 USD`。因此以 USD 表述的经济量
> （例如"这笔交易值多少美元"）可用同额 USDG 表述，
> **不需要**任何外部 fiat 价格源。
> 这**不**改变深度判据：深度始终是**池子自身代币计量的链上价格冲击容量**
> （ε=10 bps），从未退化为 USD 阈值比较。
> 落地位置：`flashloan/config/depth_policy.json` → `usdgPegPolicy`。
> `allowedUses` 显式包含 `usdg_replaces_usd_denomination` /
> `economic_quantity_denominated_in_usdg` / `stock_library_usdg_exchange_requirement`；
> `forbiddenUses` 显式排除 `depth_admission` / `capacity_admission` /
> `core_library_membership` / `test_library_membership` / `extension_library_membership` /
> `broadcast_amount_sizing`。

### 11.2 与其他门禁的边界

| 门禁 | 作用对象 | 判定基准 | USDG 口径 |
|---|---|---|---|
| **VAL-4 经济门禁** | **代币库成员关系**（股票池：USDG 可兑换性；扩展池：USDG 承载能力） | USDG 估值 / USDG 承载能力 | 是 |
| `capacityGate` | 单池可成交容量 | token 计价，ε=10 bps 容量 | 否（排序键亦**不含** `estimated_tvl_usd`，仅作人工观测） |
| 深度分带 | 池子规模 | 真实储备 / 容量 | 否 |
| 广播门禁 | 是否发车 | 已确认利润 + 最佳交易量 | 否 |

> **不得因为本门禁的估值为零而把代币对下架**（现有硬约束保持）；
> 也**不得把估值结果用作容量门禁**。
>
> **注意**：这里"估值为零"指的是**无法与 USDG 兑换**（`no_route`），
> 而不是"估值很低"。后者（低于经济下限）是**dust**，
> 同样不构成下架依据（`R-05` / `R-06`）。
> 唯一允许的成员关系撤销依据是 `R-12`：**无法与 USDG 兑换**。

**关键语义决策**（不得改变）：

1. **门禁只移除成员关系，绝不新增**。新增必须走
   "重新分类 + 物化"，以保证每处成员关系都有来源。
2. **"未测量" 与 "不可估值" 严格区分**：
   仅 `no_route` 是真负；`api_unavailable` / `api_error` 一律记为 unknown → **pending**。
   未测量的股票代币会被移出股票池，但记入 `pending` 而非 `excluded`
   ——它不是"没有价值"，只是"还没问过"，下一次刷新自动补回。
3. **扩展池的 dust 判定只看承载能力**，不要求中间代币自身有 USDG 估值。
4. **门禁不参与**深度 / 容量 / 广播门禁，只决定**代币库成员关系**。
5. **`R-12` 的库级约束**：`library_requires_usdg_exchange()` 是唯一
   声明点——只有 `Stocks` 为真；`Core` / `Test` / `Extension` 为假。
   门禁本体通过该声明决定作用范围，因此要求与实现**不可能分叉**。
6. **`R-11` 的锚定比值显式化**：`usdgPegPolicy.pegRatio = 1`，
   `deviationToleranceBps = 0`（不容忍任何偏离）。
   比值写成显式数值而非隐含假设，是为了让报告能落下可审计的比值字段，
   并且让锚定一旦偏离就在**一个**地方显式失败。
