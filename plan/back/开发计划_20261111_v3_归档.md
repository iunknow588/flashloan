## 1. 计划目标

本轮开发只服务于 Robinhood Mainnet `4663` 的 Uniswap V4 DEX 套利链路，
按以下顺序收敛：

0. ~~**先让数字可信**~~ —— ✅ 已完成（S1，归档）。
1. ~~**再修深度度量**~~ —— ✅ 已完成（S1.5，归档）。
2. ~~**让池子工具能连网并算出真实容量**~~ —— ✅ 已完成（S2.5'，本批）。
   池深主判据换成**链上价格冲击容量**（≤ 10 bps，token 计价），零 USD 依赖。
3. ~~**然后补门禁（S2）**~~ —— ✅ 已完成（归档）。
   让编排器能正确识别候选集↔闭环集脱节、修复链死锁与归因缺失，
   并把 **capacity 覆盖 Gas** 接入广播前 preflight。
4. **之后重建闭环（S3）**：在停机窗口内重建闭环，
   消除 **38/106 环部分失联**（318 跳缺 38 跳）。
5. **再推权威收敛（S4）**：Token → Pool → Candidate → Closed-loop → Review →
   Broadcast → Composite 迁移到 Rust Manager。
6. **最后治理（S5）**：UI/API 收口、长期盈利统计、日志轮转与命名兼容。

### 1.1 最终完成定义

- 主网闭环 `106` 条全部指向候选集内真实存在的池，`pool_ids` 命中率 `100%`。
- **四方** `pool_scope_checksum`（`pool_scope_config` / `manager_dex_candidate_library_state`
  / `manager_v4_closed_loop_library_state` / `manager_market_observation_library_state`）
  完全一致，且 `consumers_need_rebuild` 经验证为**真值零**而非字段伪错。
- **部署的 `pool-manager` 二进制与源码一致**：命令集探测通过
  （`AUD-P0-6`），否则编排器必须以 `stopped="tool_deployment_gap"` 明确停下。
- 池深度判据满足：**capacity 是唯一主判据**（价格冲击 ≤ 10 bps，token 计价）。
  候选集内每个池都有非零 capacity 与 `balances.token0/token1`；
  `estimated_tvl_usd` **仅作排序 tie-breaker 与人工观测**，不作任何门槛。
  ~~`corr(log10(liquidity_index), log10(TVL)) > 0.7`~~ **已作废**。
- 每条复核都有明确 `bestAmount`（非 `none`）与明确 PnL；
  `positive(executable)` 数量与广播 attempt 终态可对账。
- 每个数据范围仅一个权威写入模块，不长期双写；切换后旧写入立即关闭。
- 所有生产结论绑定 `scope + authority + PID + 数据库 checksum + 观察窗口`；
  工程测试与 dry-run 不替代生产验收。

### 2.3 不可违反的执行判断

1. **USD 价格不参与套利执行判断。** ETH / 股票价格源在套利环境中无法体现
   交易价值，因此**不得**引入价格源参与准入、容量或门禁判定。
   `estimated_tvl_usd` 仅保留为排序 tie-breaker 与人工观测字段。
2. **深度算法修好之前，不重建闭环。** S2.5' 已把判据换成 token 计价 capacity，
   但生产库尚未铺开容量数据，因此 **S3 必须晚于生产铺开**。
3. **深度算法修好之前，不下架任何 token 对。**（保留约束，自 S1.5 起持续有效）
4. **不因 `unpriced` 判定池无效。** 缺价不等于池浅；缺数据时必须 fail-closed，
   不得回退 0，也不得据此下架。
5. **闭环重建必须停机**，不得在守护器与 `run.py` 运行中执行。
6. **口径修正先行。** 数字不可信时，任何门禁判断都是噪声。
7. **只读盘点可并行，破坏性操作一律串行。**
8. **不得改写历史证据**；新结论使用新时间戳。
9. **工具版本是门禁的一部分。** 部署的 `pool-manager` 若不认识
   `ensure-indexes` / `ensure-depth-schema` / `depth`，healer 必须以
   `stopped="tool_deployment_gap"` 明确停下，**不得静默跳过**容量铺设。
10. **容量不得饱和。** 池容量是有限的链上量；任何
    `u128::MAX` 哨兵值都不得被读成「价格冲击 0」。
11. **容量未测量 ≠ 故障。** `capacityGate.verdict=unknown` 表示该 hop 容量
    尚未测量，默认不阻断；生产铺开后用
    `DEX_V4_CAPACITY_GATE_REQUIRE_MEASURED=1` 升级为阻断。

### 7.1 关键语义决定：未知容量**不阻断**

`AUD-P2-2`（容量覆盖 Gas 进 preflight）实现时暴露一个必须先定的问题：

生产深度尚未铺开（`capacityRowCount=0`），若把"容量未知"当作阻断条件，
**100% 的路由都会被拦死**——不是安全，是停机。因此语义定为：

| 状态 | 判词 | 是否阻断 | 说明 |
|---|---|---|---|
| 容量已知且足够 | `pass` | 否 | 正常放行 |
| 容量已知且不足 | `insufficient` | **是** | `capacity_insufficient`，池选择缺陷 |
| 容量未测量 | `unknown` | **否** | 池索引覆盖缺口，非市场结论 |

升级为阻断由 env 开关控制：

```powershell
$env:DEX_V4_CAPACITY_GATE_REQUIRE_MEASURED = "1"   # 深度铺开后再启用
```

配套约束：

- 容量门禁**不得污染**已因其它原因失败的复核的 `blockers`（首个失败才是可执行根因）。
- Rust `capacity_gate_blocks_broadcast` 只在 `blocked == true` 时阻断；
  **缺少** `capacityGate` 字段不再阻断。
- `capacity_unknown` **不进入** `_PREFLIGHT_BLOCKED_AUTO_REASONS`。

#### 7.5.3 `AUD-P2-6` Rust 容量 `u128::MAX` 饱和缺陷（本批最重要）

且 `priceImpactBps = 0.0`。根因是 `spot_amount_out()` 用 256 位乘法计算
`amountIn * sqrtP^2 / Q192`，输入接近 `u128::MAX` 时中间积回绕到 `2^64-1`，
于是 `amount_out >= spot_out` 对任意巨额输入成立，冲击被读成 **恰好 0**，
二分搜索遂把饱和值当成真实容量。

修复（`flashloan/tools/pool_manager/src/depth.rs`）：

- `spot_amount_out()` 改用 SDK 的 **512 位精确 `mul_div`** 并钳制上限；
- 新增 `reserve_ceiling()`（512 位 `mul_div` 计算虚拟储备上限）；
- `spot_out > ceiling` 时返回错误；
- `solve_capacity()` 上界钳制在 `ceiling` 内。

效果：`0x2077…` 从 `2^128-2` 变为 `99938943274133825410`（10.0 bps），
`0x509c…` 变为 `2130400100532712269`（10.0 bps）。

> **Python 侧本来就是正确的**（任意精度整数），Rust 是偏离的一方；
> 修复后两者逐池一致（相对误差 ≤ 6.3e-9）。
