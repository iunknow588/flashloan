## 1. 本轮一句话结论

闭环链路存在一个**数据库解析分裂**的生产缺陷：claim 与 complete 写入两个不同的 SQLite 文件，导致闭环永久停在 `preflight_running`；本轮修复该缺陷并加装**生产库写入守卫**，随后全量回归门禁**首次达到全绿（unit 2624/0、functional+integration 398/0、Rust 全绿）**。

生产侧**未写库、未广播、未部署、未切网、未换 Authority**；主网 `manager_v4_reviews` 仍为 0，**主网尚未产生套利广播交易**。

## 2. FIX-R21-01｜闭环数据库解析分裂根因修复（TASK-107 / AC-171）

### 2.1 现象

闭环一旦被 claim 就永远停在 `preflight_running`，**永远到不了 `preflight_failed`**。

### 2.2 根因

| 步骤 | 原实现 | 解析来源 |
|---|---|---|
| `mark_group_submitted` / `claim_review_before_submit` | `closed_loop_consumer.resolve_runtime_database(...)` | 消费者解析器 |
| `complete_loop` / `scope_error_isolation_active` | mixin 自己的 `_native_database_url(chain_id)` | chain runtime registry |

两者不一致时：**claim 写进 A 库、complete 写进 B 库**，闭环因此永久搁浅。

### 2.3 修复

在 `flashloan/src/dex/runtime/dex_opportunity_scanner_rust_mixin.py` 中引入**单一权威解析器**：

- `_closed_loop_database_url(chain_id, network)`（约 366 行）——闭环所有步骤共用；
- `_chain_scoped_database_url(chain_id, network)`（约 423 行）——按被处理链解析链级库；
- `_has_pinned_native_database()`（约 436 行）——识别实例显式 pin。

新语义（三条顺序规则）：

1. **实例显式 pin 优先**：若 `self.__dict__` 含 `_native_database_url`，尊重调用方注入（消费者解析器对非空参数原样返回）。
2. **消费者解析器权威**：解析结果为 `None` → 直接返回 `None`，该 scope 无库，**禁止回落到别的链的库**。
3. **链级 scope 绑定**：若按 `chain_id`/`network` 解析出的链级库与解析结果不同 → 采用链级库。进程默认链是**主网链 4663**，因此测试网扫描绝不能写进主网库。

调用点统一为 `database = self._closed_loop_database_url(chain_id, network)`。

## 3. FIX-R21-02｜生产库写入防护（TASK-108 / AC-172）

### 3.1 事件

测试曾把 fixture 行写入**真实主网库**（`local_store_4663.sqlite3`）与**真实测试网库**（`local_store_46630.sqlite3`）。

### 3.2 守卫

在 `flashloan/app_runtime/tests/conftest.py` 增加 autouse fixture `_guard_real_chain_databases`：

- 拦截 `core.db.storage_business_io` 的 `execute` / `executemany` / `replace_rows` / `transaction` / `delete_rows`；
- 若目标 DB 的 `resolved.parent` 命中真实链库目录 → 抛 `AssertionError`；
- **必须**同时对按名 import 的模块再 patch 一遍：`dex.runtime.closed_loop_state_machine`、`dex.runtime.closed_loop_consumer`（模块级 `from ... import execute` 绑定会使仅 patch 定义模块失效）；
- 读路径**不拦截**，因此仍可读取真实 chain metadata。

> 早期尝试的「root 重定向守卫」方案无效（`robinhood-testnet/chain.json` 的 `database.sqlite_dir="../../db"` 已把路径重定向回真实库目录），故最终采用**写入口拦截**方案。
