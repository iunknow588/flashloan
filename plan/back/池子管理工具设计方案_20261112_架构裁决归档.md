# 池子管理工具设计方案（Robinhood Chain V4）— 架构裁决与落地计划

> 版本：2026-11-12
> 适用范围：`flashloan/tools/pool_manager` 及其上下游（`v4_pool_index.py`、`rust_closed_loop.py`）
> 权威口径：链上价格冲击容量（token 计价，ε = 10 bps），**零 USD 依赖**
> 状态：**评审裁决 + 分阶段落地计划**

---

## 0. 总体裁决

**方向正确，数据层不可照搬。**

提案的核心主张——"链下全量极速计算 + 链上轻量快照仲裁与微调"、
"内存与持久层分离"、"事件驱动全局监听"——**与本链的实际瓶颈一致，应当采纳**。
但提案给出的**数据层物理设计**（`core_pools` / `watch_pools` 双表）
会**重新引入本项目刚刚付出代价才消除的双源漂移问题**，必须否决。

一句话结论：

> **采纳"职责分层"，否决"物理分表"。**
> 容量主判据、经济可行性护栏、整数运算这三项**代码库里已经满足**，
> 不要重做；真正要做的是**补齐传播链路**（已由 D5/D6 完成）与
> ✅ **ARCH-2 链下等价回归已完成**（2026-11-12）——链下 3 跳模拟器 + 与链上 preview
> 的等价回归已落地；**"盲发直推"的前置能力具备**，但模拟器**尚未接入生产链路**（ARCH-2b），
> 且 ARCH-3（链上快照比对 + 降级数组）未实现 ⇒ **链上仍无最后一道防线**。

## 1. 与仓库现状的对照（逐条）

### 1.1 提案主张 vs 实际

| 提案项 | 裁决 | 依据 |
|---|---|---|
| `core_pools` / `watch_pools` 物理双表 | ❌ **不采纳** | `pool_scope_config` 已是 scope 权威源（`scope_key` + `library_checksums_json` + `materialized_checksum`）。再建一张物理池表，正是产生当前 `pool_scope_drift` 阻塞的**双源漂移**模式 |
| `GlobalState` 三段式（`token_registry` / `pool_states` / `directional_index`） | ⚠️ **部分采纳** | 内存视图合理，但必须**只读派生自** `pool_scope_config` + 快照表，不得成为第二个写入权威源 |
| Watch 池 3 天 TTL `DELETE` | ❌ **不采纳** | `recent_swap_active` 在**全部 4669 行快照中为 NULL**，目前**没有任何事件新鲜度信号**可供 TTL 依据。凭空造 TTL 会误杀真实池 |
| 候选池 Top-5 / 每方向推荐池 | ⚠️ **采纳但需先定义排序键** | 候选表 `is_first_hop_recommended=1` 为 **100** 条、`is_third_hop_recommended=1` 为 **100** 条，但**"每方向 Top-5"的主排序键尚未定义**（容量？价格影响？净利润？） |
| `cap_in_usd < 10 USD` 粉尘过滤 | ❌ **不采纳** | 生产 88 条闭环中 **42 条（47.7%）借入股票代币**（SPY/GOOGL/SPCX/CRCL/MU），**86 条（97.7%）借入既非 ETH 也非 USD 稳定币**的代币。此类标的**链上不存在可靠 USD 价格**，USD 门槛在物理上不可评估 |
| 容量感知双向阶梯 + 24 步极值锁定 | ✅ **已实现** | D4-a/b/d/e（2026-11-12）：`start=clamp(cap*frac, required, cap)`、失败分支向上倍增、`economicFloorGate` 零 USD 依赖 |
| 纯整数 / U256 运算 | ✅ **已满足** | `v4_pool_capacity.py` 全整数除法；Rust `f64` 仅用于排序与 RPC 限流，**不参与盈亏计算** |
| `amountOutMinimum` | ❌ **概念错误** | Uniswap V4 **没有** `amountOutMinimum`；对应参数是 **`sqrtPriceLimitX96`** |
| 硬编码 `gasLimit = 500000` | ❌ **当前不采纳** | 生产广播 **0 笔**，`cow_execution_attempts` / `manager_v4_review_broadcast_requests` 均 0 行，**3 跳闪电贷 gas 未实测** |
| 局部 Tick 缓存（±5% `tickLiquidityNet`） | ❌ **无收益** | 容量仅由 `(sqrtPriceX96, liquidity, fee)` 决定；代码库内**不存在** `tickBitmap` / `tickLiquidityNet`，缓存无对象可缓存 |
| 纯 WSS 增量更新 | ✅ **采纳（P3）** | 当前为 HTTP 日志分页 + `extsload` 批量读；ARCH-2 前置已就绪 |
| SQLite 异步批写（`mpsc` + 5s/100 条） | ⚠️ **部分采纳（P5，低优先）** | WAL + `synchronous=NORMAL` 已启用；需先量化写放大 |
| 链上快照比对 + 降级数组 | ✅ **采纳（P3）** | 需合约改造；ARCH-2 链下等价回归**已通过**，可启动 |
| 废弃链下 Quoter、盲发直推 | ⏸️ **仍暂缓** | ARCH-2 已通过，但**模拟器未接入生产链路**（ARCH-2b），且 ARCH-3 未实现 ⇒ 链上无兜底 |

## 2. 修订后的目标架构

```text
┌──────────────────────────────────────────────────────────────┐
│  唯一权威源（SQLite，WAL）                                     │
│  ├─ pool_scope_config        ← scope 权威（scope_key/checksum）│
│  ├─ v4_exchange_pool_liquidity_snapshots  ← 实测容量（只读源） │
│  └─ dex_candidate_pools      ← 候选 + 传播后的 balances      │
└──────────────────────────────────────────────────────────────┘
              │  只读派生（禁止第二写入源）
              ▼
┌──────────────────────────────────────────────────────────────┐
│  内存派生视图（进程内，可重建，不持久化）                      │
│  ├─ token_registry   ← chain_data_registry（已有）            │
│  ├─ pool_states      ← DashMap<PoolId, Arc<PoolState>>       │
│  └─ directional_index← 每方向推荐/候选（排序键待定）          │
└──────────────────────────────────────────────────────────────┘
              │
              ▼
┌──────────────────────────────────────────────────────────────┐
│  链下计算引擎                                                 │
│  ├─ 容量感知阶梯（D4）                                         │
│  ├─ 经济可行性门禁（token 计价，D4-d）                        │
│  └─ 链下 3 跳模拟器 + 与链上 preview 等价回归（ARCH-2）✅已完成 │
└──────────────────────────────────────────────────────────────┘
              │
              ▼
┌──────────────────────────────────────────────────────────────┐
│  链上轻量仲裁（ARCH-3，合约改造后）                            │
│  预期快照比对 → 偏离超阈值 revert / 降级数组                   │
│  V4 滑点参数是 sqrtPriceLimitX96（非 amountOutMinimum）        │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 三条硬边界

1. **单一写入权威**：`pool_scope_config` + 快照表 + 候选表。
   内存结构**只读派生**，进程重启后可完全重建。
2. **零 USD 依赖**：准入、经济性、分带**一律 token 计价**。
   `estimated_tvl_usd` 仅作**排序 tie-breaker 与人工观测**。
   **任何门禁不得引用 USD 阈值**；**不得依据 TVL 下架 token 对**。
3. **缺失测量必须保持缺失**：无实测快照 ⇒ 容量为 `None` ⇒ 安全退化，
   **不得伪造为零**，更不得据此放行。

### 3.1 ARCH-1 补充：排序键必须先定义

提案的"每方向推荐池 + Top-5 候选"需要**明确的主排序键**。建议（待评审）：

```text
主键：capacityBindingRaw DESC        （链上实测，token 计价）
次键：priceImpactBps ASC             （同等容量下冲击更小者更优）
末键：pool_id ASC                    （稳定，保证确定性）
禁止：estimated_tvl_usd 作为主键      （与深度无关，且会引入 USD 依赖）
```

> 现状：候选表 `is_first_hop_recommended=1` 为 100 条、`is_third_hop_recommended=1` 为 100 条，
> 但**未按上述排序键生成**。该项应并入 ARCH-1 一并落地。

### 3.2 ARCH-2 是整条链的"闸门"

提案中"废除链下 Quoter、零 RPC 验证、直发排序器"是**收益最高**的一步，
也是**风险最高**的一步。当前之所以不能做：

```text
链下计算必须与链上 previewArbitrageBestAmount 数值等价
  ├─ 当前只有单跳数学（v4_pool_capacity.py）
  ├─ 缺 3 跳串联
  └─ 缺 parity 回归
```

**没有 parity 回归就盲发 = 必然亏损**（提案自己也承认"本地计算是绝对真理"，
但这个前提**尚未被验证**）。因此：

> **ARCH-2 是 ARCH-3（合约降级）与"盲发直推"的共同前置。**
> ARCH-2 已于 2026-11-12 通过（见 `未完成任务清单_20261111.md` §0.6.7）。
> **但 `best_amount_ladder_incomplete` fail-closed 仍不得放宽**——
> 它归零靠**数据修复**（W6 铺开），不靠放宽门禁；
> 且链上兜底（ARCH-3）尚未就位。

## 4. 与已归档批次的关系

```text
S1 → S1.5 → S2.5' → S2 → S2.5'' → S2.5''' → W1–W5 → W6(只读+副本) → D4 → D5/D6
                                                                            │
                                                                            ▼
                                                              ARCH-1 → ARCH-2 → ARCH-3/4
```

**D5/D6 的意义**：在 ARCH-2 之前，链下容量计算已经能拿到**真实容量**
（`_liquidity_cap_raw()` 12/12 符号返回非 `None`），
这为 ARCH-2 的"3 跳串联"提供了**可信的单跳输入**。
若 D5/D6 未修复，ARCH-2 即便实现，链下也会因为拿不到容量而**退化为无深度感知的模拟器**。
