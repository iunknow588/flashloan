## 0. 为什么需要编号册（**问题陈述**）



**旧口径的缺陷**：二级任务编号 `T-nn` 按**创建顺序**递增，**不按模块分组**。

后果是**同一模块的工作散落在互不相邻的编号里**，例如：



| 缺陷 | 具体表现 |

|---|---|

| **模块被多点切分** | 存储层 `M-10` 被 `T-方授储.01` / `T-方闭储.01` / `T-方储.01` / `T-储.01` / `T-候储.01` / `T-储.02` **六个**任务同时触及 |

| **语义错位** | 「池子变更」（`T-方授储.01`~`T-方闭.01`）与「数据库分离」（`T-储.01` / `T-储.02`）**编号不连续**，看起来像同一条线 |

| **漏做难查** | 只看编号**看不出**某模块还剩几件事没做，必须回查代码 |

| **误判回归范围** | 「这个任务属于哪个模块」无法从编号回答 ⇒ 回归范围容易被放大 |



**新口径**：**一个模块 ⇒ 一段连续编号**。模块是**编号的分组单位**，不是编号的**内部顺序**。

## 1. 编号格式（**编号 + 名字**）



> **编号 = 唯一检索号；名字 = 识别标签。** 两者分离 ⇒ **改名便宜，引用稳定**。



### 1.0 三类编号总览



```

一级任务：  P-nn-标题                          ← 方案 / 计划级

二级任务：  T-<索引>.<序号>                    ← 执行级，**按索引分组**

验收编号：  AC-<索引>.<序号>                   ← 与二级任务一一对应

文档：      D-<nnn>-<名字>.md                  ← **受控文档级**（见 §5）

```



| 段 | 含义 | 取值 | 规则 |

|---|---|---|---|

| `P-nn` | 一级任务号 | `P-01`、`P-02`… | 全局递增，**不复用** |

| `<索引>` | **模块索引** 或 **组合索引** | `储`、`方授储` | 见 §1.1 / §1.2；**≤ 2 字符/模块** |

| `<序号>` | 索引号段内序号 | `01`、`02`… | **在该索引号段内**从 `01` 递增，**不复用** |

| `AC-…` | 验收编号 | 与二级任务**同段** | 一一对应，同号不同前缀 |

| `D-<nnn>` | **文档唯一检索号** | `D-001`…`D-097` | 全局递增，**永不复用**（见 §5） |



> **示例**：`T-方授储.01` ＝ 组合索引 `方授储`（= `M-3`＋`M-9`＋`M-10`）的第 1 件事；

> `T-储.02` ＝ 模块索引 `储`（`M-10`）的第 2 件事。

> **读法**：`T-<索引>.<序>` ⇒ **一眼看出涉及哪些模块**。



### 1.0.1 **两级编号体系**（**模块级 ≠ 文档级**）



| 层级 | 编号 | 作用 | 谁用它 |

|---|---|---|---|

| **模块级** | `M-n`（+ 索引） | 表达**回归范围**、**前置顺序** | 测试守护、前置关系 |

| **文档级** | `D-nnn` | 表达**唯一检索**、**归档定位** | 引用、归档索引 |



> **两者互不替代。** 任务编号回答「改哪个模块」；文档编号回答「哪份文件」。

> **不要**用任务编号代替文档编号（同名文档在多目录存在，见 §5.3）。



---



### 1.1 模块**索引**（**每个模块一个唯一索引 · 不超过 2 字符**）



> **模块索引 = 模块的**短名**，用于**编号**与**定位**。

> 取值可以是**数字、字母、汉字** —— 唯一硬性要求是：**唯一** ＋ **不超过 2 字符**。



| 模块 | 名称 | **索引** | 主要代码落点 | 该模块的任务编号前缀 |

|---|---|:---:|---|---|

| `M-1` | 池管理器（链上池状态 / 深度 / 边界） | `池` | `flashloan/tools/pool_manager/` | `T-池.xx` |

| `M-2` | 证据通道（证据落库 / 清理） | `证` | `flashloan/tools/manager_db/` | `T-证.xx` |

| `M-3` | 方向层（方向池物化 / 评分 / 准入） | `方` | `flashloan/tools/directional_pool_manager/` | `T-方.xx` |

| `M-4` | 闭环层（闭环集合 / 容量折叠 / 兜底） | `闭` | `flashloan/tools/closed_loop_manager/` | `T-闭.xx` |

| `M-5` | 候选层（选池宇宙 / 费率标签 / 边界层） | `候` | `flashloan/tools/candidate_edge_pool_manager/`、`candidate_exchange_pool_manager/` | `T-候.xx` |

| `M-6` | 复核层（复核发布 / 金额利润） | `复` | `flashloan/tools/review_manager/` | `T-复.xx` |

| `M-7` | 广播层（广播准入门槛 / 请求生成 / 回执） | `广` | `flashloan/tools/broadcast_manager/` | `T-广.xx` |

| `M-8` | 编排层（依赖图 / 路由 / 组合） | `编` | `flashloan/tools/composite_manager/` | `T-编.xx` |

| `M-9` | 授权与回滚（授权维度 / 守卫 / 回滚脚本） | `授` | `flashloan/tools/manager_contracts/src/authority.rs` | `T-授.xx` |

| `M-10` | 存储层（schema / 迁移 / 记录剥离） | `储` | `flashloan/db/`、`flashloan/tools/manager_db/` | `T-储.xx` |

| `M-11` | 链配置与常量（chain.json / 深度策略 / 参数） | `链` | `flashloan/chains/`、`flashloan/config/` | `T-链.xx` |



> **索引的三条硬规则**：

> 1. **唯一** —— 全树内**不得**有两个模块用同一索引；

> 2. **≤ 2 字符** —— 便于**口述**、**手写**、**拼接**；

> 3. **不复用** —— 模块撤销后其索引**永久不再分配**。



### 1.2 **跨模块**编号（**组合索引**）



> 任务**只服务一个模块**时，编号即该模块的索引（`T-池.01`）。

> 任务**跨多个模块**时 ⇒ 用**组合索引**：**把涉及到的模块索引按模块号大小依次拼接**。



| 规则 | 说明 |

|---|---|

| **拼接顺序** | **按模块编号从小到大**（`M-3` → `M-9` → `M-10`），**不是**按索引的字典序 |

| **拼接结果** | 每个模块的索引**各取 1 字符**依次相连 ⇒ 组合索引长度 = 涉及模块数 |

| **示例** | 方向层(`M-3`) ＋ 存储层(`M-10`) ⇒ **`方储`** ⇒ 任务编号 `T-方储.xx` |

| **示例** | 方向层(`M-3`) ＋ 授权(`M-9`) ＋ 存储层(`M-10`) ⇒ **`方授储`** ⇒ `T-方授储.xx` |

| **示例** | 复核层(`M-6`) ＋ 广播层(`M-7`) ⇒ **`复习`** ⇒ `T-复习.xx` |



> **为什么按模块号排序**：模块号是**既有的稳定顺序**（`M-1` < `M-2` < …）。

> 若按索引字典序，则 `M-10`(储) 会排在 `M-3`(方) 之前 ⇒ 同一个组合出现**两种拼法** ⇒ 编号不可复算。

> **按模块号排序 ⇒ 组合索引是唯一确定的、可从模块集合反推的。**



> **组合索引与主改动模块**：跨模块任务的**号段**由**组合索引**决定（不是主改动模块单独一段），

> 这样**「编号 ⇒ 涉及哪些模块」可以一眼反查** —— 这正是编号的作用（**定位**，不是耦合）。



## 2. 编号索引的判定规则（**可复算，不许挂靠**）



一个二级任务的**编号索引**由它的**改动模块集合**唯一决定，**无需人工裁决**：



1. **只改一个模块** ⇒ 索引 = 该模块的索引（模块内索引）；

2. **改多个平级模块** ⇒ 索引 = **各模块索引按模块号 `M-n` 升序拼接**（组合索引）；

3. **改的是平级模块却无法拆开** ⇒ **拆成两个任务**，不要合并；

4. **不允许**「主模块 A ＋ 附带 B」这种**挂靠式**组合 ——

   被强制牵连的模块**也进组合索引**，因为它确实被改动了。



> **为什么不再设「主改动模块」**：旧口径用「主改动模块」决定号段，

> 会让**被强制牵连**的模块**查不到自己的任务**（编号只显示主模块）⇒

> 回归范围与编号**对不上**。

> 组合索引把**所有被改动的模块**都显式写进编号 ⇒ **看编号即知回归范围**。



> **反例（本次已发生）**：`T-储.01`「测试套件生产库零写入」与 `T-储.02`「记录存储剥离」

> 同属 `M-10`，却因旧编号按创建顺序分配而**不相邻**，且与池子类任务混在同一序列里。

> ⇒ 新口径下它们归入 `T-储.xx` 索引段，**与池子类的 `T-方*.xx` 段完全分开**。



---



## 3. 一条硬规则（**不同模块不得混在一个任务里**）



> **一个二级任务只服务于一个模块。**



| 允许 | 禁止 |

|---|---|

| 一个任务**主改** `M-n`，并**附带**被 `M-n` 强制牵连的模块 | 一个任务**平铺**两个**独立**模块的工作（如「池子变更」＋「数据库分离」塞进一个任务） |

| 跨模块的**弱耦合**可拆成两个任务，用**模块级前置**表达顺序 | 用**任务号依赖**把两个模块绑在一起（模块级前置才是唯一的顺序表达） |



**判定口诀**：*「这个任务做完，哪个模块的测试必须重跑？」* ⇒ 答案**不止一个且两者平级** ⇒ **拆开**。

| 编号 | 职责 | 分离什么 | 验收口径 | 状态 |

|---|---|---|---|---|

| **`T-储.01`** | 生产库**写**隔离 | 测试路径**不写**生产库 | 生产库文件字节级**零变化** ＋ 只读打开 | ⬜ 11 项未完成 |

| **`T-储.02`** | **记录存储**剥离（剩余项） | 链上瞬时数据**不进**持久化存储 | 记录根目录**不存在** ＋ 保留期清理生效 | ⬜ 6 项未完成 |

| **`T-储.03`** | **复核库**分离 | 复核记录**独立成库** | 复核库**独立**且可独立归档 | ⬜ 9 项未完成 |

| **`T-储.04`** | **广播交易记录**分离 | 广播交易记录**独立成库** | 广播交易记录**独立**且可独立归档 | ⬜ 9 项未完成 |



**为什么必须拆开**（**这正是本册要防止的复发**）：



| 合并的后果 | 说明 |

|---|---|

| **验收口径串味** | 「写隔离」的判据是**生产库字节不变**；「库分离」的判据是**独立库存在且可归档**。两者混在一个 checklist ⇒ 勾掉一条不代表另一条闭合 |

| **回归边界放大** | 写隔离只跑**只读打开**相关测试；库分离要跑**归档/保留期**相关测试。合并 ⇒ 每个任务都跑两套 |

| **闭合节奏不同步** | 写隔离可能当天闭合；库分离要等数据迁移窗口。合并 ⇒ 快的被慢的**拖住**，或快的**顺带**勾掉慢的 |

| **授权边界混淆** | 库分离**可能要写库授权**；写隔离**绝对不许写**。合并 ⇒ 授权判断失焦 |



**拆分后如何表达顺序**：只写**模块级前置**（如「`T-储.04` 的前置模块是 `M-10`」），

**不写任务号依赖**（`T-储.02` 不写「等 `T-储.01` 完成」）。

## 4.4 新建任务的标准动作（**编号控制**）

```powershell
# 1. 确定本任务的**改动模块集合** ⇒ 按 §1.1 / §1.2 算出**编号索引**
#    （单模块 ⇒ 该模块索引；多模块 ⇒ 各模块索引按模块号 M-n 升序拼接）
# 2. 查本文件 §4.2 ⇒ 取该**索引号段**的下一个可用序号
#    （同索引号段内递增；不同索引号段互不影响 —— 这就是"独立编号控制"）

# 3. 按模板生成目录
$TASK="T-储.05"; $ACC="AC-储.05"
New-Item -ItemType Directory -Force "plan/tasks/<一级>/tasks/$TASK"
Copy-Item "plan/template/TASK_TEMPLATE.md"        "plan/tasks/<一级>/tasks/$TASK/PLAN.md"
Copy-Item "plan/template/SCOPE_GUARD_TEMPLATE.md"  "plan/tasks/<一级>/tasks/$TASK/SCOPE_GUARD.md"
Copy-Item "plan/template/CHECKLIST_TEMPLATE.md"    "plan/tasks/<一级>/tasks/$TASK/checklist.md"
Copy-Item "plan/template/DOCS_README_TEMPLATE.md"   "plan/tasks/<一级>/tasks/$TASK/docs/README.md"

# 4. 在本文件 §4.2 的对应**编号索引**行**登记一行**（编号册即时生效）
# 5. 在一级任务 README 的二级清单**登记一行**
# 6. 在专题清单登记一行
```

**纪律**：
- **不同编号索引 ⇒ 各自独立的序号段**，**互不消耗**。索引 `储` 的任务做到 `T-储.09`，
  **不影响** 索引 `候` 的 `T-候.04`。
- 编号**永久不复用**。任务闭合归档后，其编号**永久保留在本文件**（状态改为 ✅ 已归档）。
- **不许**跨索引"顺延"：索引 `候` 的下一个号**永远**是 `T-候.xx`，不是 `T-复.xx`。
- **不许**"挂靠式"编号：被改动的模块**全部**进组合索引（见 §2 规则 4）。

## 5. 文档编号（**编号 + 名字**）



> **文档编号 = 唯一检索号；名字 = 识别标签。**

> **改名很便宜**（只替换名字段）；**引用很稳**（引用编号永不失效）。



### 5.1 格式



```

文件名：  D-<n>-<名字>.md          例： D-042-现状与可行性分析.md

标题行：  # D-<n> <名字>          例： # D-042 现状与可行性分析

引用：    写 `D-042`（不写名字）    例： 见 `D-042` 的 §2

```



| 段 | 含义 | 规则 |

|---|---|---|

| `D-` | 文档编号前缀 | 固定 |

| `<n>` | **唯一检索号** | **从 `1` 递增**，三位补零，**永不复用** |

| `<名字>` | 识别标签 | **可自由替换**；替换只需改文件名 + 标题行 + 引用处 |



### 5.2 `D-0`：**内部综合文档**（保留号）



| 号 | 含义 | 范围 |

|---|---|---|

| **`D-0`** | **内部综合文档** | 目录导航 `README.md` 与各类 `*_TEMPLATE.md`（模板） |



> **`D-0` 是保留号，不分配给任何具体业务文档。**

> 它标识「体系内部结构件」——**没有独立内容、只承担索引/模板职责**的文件。

> 业务文档**一律从 `D-1` 起**。



### 5.3 为什么「编号」与「名字」分离



| 痛点 | 只有名字 | 只有编号 | **编号 + 名字**（本方案） |

|---|---|---|---|

| 改名 | 要改所有引用 | 改名不影响引用，但**看不懂** | **改名字段即可**，引用写编号不受影响 |

| 检索 | 同名文档（13 份 `01-现状与可行性分析.md`）**无法区分** | 唯一但无提示 | **既唯一又有提示** |

| 归档 | 名字易冲突 | 编号永不复用 | 归档件保留原编号 |

## 6. 编号与**回归范围**的关系（**为什么这样能省时间**）



| 规则 | 说明 |

|---|---|

| **回归范围 ＝ 改动模块集合** | 与编号**无关**，与 `SCOPE_GUARD.md` 声明的模块集合有关 |

| **未改动模块不重跑** | 编号只回答"归属哪个模块"，**不**决定跑多少测试 |

| **同模块的任务可共享回归** | 同属 `M-n` 的任务，改动落在**同一批文件** ⇒ 回归命令相同 ⇒ 可合并执行 |

| **跨模块的组合回归只在整体闭合时** | 一级任务全部二级闭合后跑**一次** |



> **编号的作用是「定位」，不是「耦合」。** 编号让"这个任务属于哪个模块"可以一眼回答；

> 测试范围由**改动模块集合**决定。两者**解耦**。
