## 2. 根因裁定

### 2.1 结论（一句话）

> **主网跑不出套利，不是门禁太严，是「复核发布链路」在 Rust 生产侧根本不存在。**
> 复核库停在上一次闭环代（v14），**当前代（v19）的复核一条都没有**；
> 唯一还在往复核库灌数据的通道是**历史遗留转换器**，它把每条证据的
> `executable` **写死为 `false`** ⇒ **Rust 侧的两道执行门禁从未被触发过**
> ⇒ **任何复核都不可能成为广播请求**。

### 2.2 证据链（逐环可查）

**(a) 门禁的触发条件是上游的 `executable`** —— `review_manager/src/lib.rs`：

```rust
let single_tick_verdict = run_arbitrage
    .filter(|run| run.ok && run.executable)      // ← 永远为 None
    .map(|run| evaluate_final_single_tick_gate(input, closed_loop, run));
let transition_verdict = run_arbitrage
    .filter(|run| run.ok && run.executable)      // ← 永远为 None
    .map(|run| evaluate_final_state_transition_gate(input, closed_loop, run));
```

`executable` 为假 ⇒ 单跳容量门禁与状态迁移门禁**都不跑** ⇒
`hop_sqrt_price_limits` 恒空 ⇒ **广播请求恒为 0**。

**(b) 上游证据只有一个来源，且写死 `executable: false`** —— `scripts/mainnet_arbitrage_healer.py`：

```python
"runArbitrage": {"ok": signed is not None,
                 "executable": False,          # ← 恒假
                 "blockNumber": None, "signedPnl": signed, "diagnostics": diagnostics},
```

同一函数把静态预览标成 `"historicalEvidence": True`、`"automaticBroadcastEligible": False`
⇒ 它是**历史转换通道**，**不是**生产通道。

**(c) Rust 生产侧没有别的调用点** —— 全仓只有
`manager_api/src/lib.rs` 的 HTTP 路由在调 `run_reviews_write`，
其证据**全部来自上面的 Python 转换器**；
`rs-src`（真正的生产运行时）**一次都没有调过**。

**(d) 与之相符的读数** —— `completed_count = 0`、`broadcast_request_count = 0`、
`attempts = 0`、`diagnostics = 0`。**四个 0 互相印证。**

### 2.3 三个「红」的判读（**停工级别**）

按 `D-038 §失败场景判读表`：

| 现象 | 级别 | 判据落点 |
|---|---|---|
| 复核库停在 **v14**，当前代 **v19** 复核为空 | 🔴 **红** | 「主库 schema 判定口径」类 —— 复核与闭环**不同代** |
| `executable` 恒假 ⇒ 执行门禁**从未**运行 | 🔴 **红** | 「判定口径」类 —— 门禁被**旁路** |
| 广播请求 **0**、尝试 **0** | 🔴 **红** | 「钱」类 —— 主网**没有任何产出** |

⇒ **本波次必须先修这条链路**，再谈其它。

## 3. 设计裁定（三条，**不放宽任何门禁**）

| # | 裁定 | 理由 |
|---|---|---|
| **C-1** | **复核发布必须发生在 Rust 生产侧**（`rs-src` 的复核产出路径），**不是** Python 侧、**不是** HTTP 路由 | 使用者既有原则：**Python 侧无自有数据处理逻辑**，只用内存对象的实际值，管理动作调 **Rust 实现** |
| **C-2** | **`executable` 不得由调用方声明** —— 它必须是**门禁自己的结论**；上游只负责提供「测到了什么」（金额、盈亏、路由、池） | `executable: false` 由外部写死 ⇒ 门禁形同虚设。**把判定收回门禁内部**才是 fail-closed |
| **C-3** | **全量提交**：证据条数 **必须**等于闭环目录条数、且每个 `loop_key` **都**在目录里；否则**拒绝发布** | `replace_review_rows` 先 `DELETE ... WHERE network/chain_id/protocol/scope_key` 再全量 `INSERT` ⇒ **部分提交 = 抹掉其它闭环的复核** |

### 3.1 「实测零盈亏」不是「缺值」（**最容易写错的一条**）

`positive = 0` / `negative` 是**完整的测量结论**，必须原样落库为
`not_executable` ＋ 真实 `signed_pnl`；
**一旦降级成 `data_incomplete`，就重演今天这 150 条**。

---

### 3.2 内存对象处理约束（**MIO-1..MIO-9 · 继承，一条不改**）

> 本波次**不改**架构约束。以下条款从 `D-013-开发计划_20261123.md` §3.1 **原文继承**，
> 仍然生效；`T-复编.01` 的每一处实现都必须**同时**满足它们。

- **MIO-1** SQLite 只在初始化 / 持久化 / 审计时读写；review / depth 处理循环不得逐条 SQL 查询业务状态。

- **MIO-2** 全局内存上下文持有池、闭环和运行时快照；运行期计算只消费该上下文。

- **MIO-3** token decimals 是内存上下文的一部分，金额缩放必须对应 token 的精度。

- **MIO-4** WSS / 监控器更新内存快照；状态版本和新鲜度必须随计算证据传播。

- **MIO-5** Review Manager 通过 Rust 内核 / 管理接口消费业务状态，不由 Python 另建权威路径。

- **MIO-6** Python 只消费内核发布的金额、利润、路线和状态，**不重算、不拼接闭环身份**。

- **MIO-7** Rust 内核发布有符号利润及 `signedPnl.amount`，含 raw 值、币种 / 精度、来源和测量状态；
  **测得零与未测量严格区分**。

- **MIO-8** 每条链使用独立 SQLite、chain ID、RPC、权限和内存状态，禁止跨链读取或写入。

- **MIO-9** 记录读取由 **Rust Manager 拥有**：复核 / 广播 / 闭环目录 / 闭环身份的读取走 Manager 接口；
  **Python 侧不得直查 manager 拥有的表**，不得把记录缓存为内存对象当权威；
  Manager 未发布的读数**如实显示为未测量**，不得由 Python 代为推导。

## 5. 记录层两个任务的**口径订正**（`T-储.03` / `T-储.04`）

> 这两个任务的 checklist 是**在「独立 SQLite 库」方案定稿前**写的，
> 与**已落地**的方案（复核 ⇒ **JSONL**、套利 ⇒ **月度 SQLite**）有**两处**字面冲突。
> 订正原则：**以已落地并经使用者裁定的方案为准**，改**判据**，不改**实现**。

| 原判据 | 冲突点 | 订正后判据 |
|---|---|---|
| 「独立库 DDL 登记到 `manager_db/src/migrate.rs`」 | JSONL **没有 DDL**；登记进主库会**违反**「主库 schema 零新增」 | **不适用**：复核记录**无 DDL**；主库 `manager_db/` ＋ `schema_policy.json` **零 diff** |
| 「主库不再新增复核记录行（增量 = 0）」 | 主库**保留当前代**复核（它是当前代的唯一权威） | 「**主库只保留当前代**；历史增量**全部**落 JSONL 审计流」 |
| 「写入采用背压等待（`send().await`），不丢记录」 | **只对套利记录成立** | 套利记录：`try_send` 失败 ⇒ **同线程同步兜底**，**不丢**；复核 JSONL：`try_send` 失败 ⇒ **丢弃 ＋ 计数**（审计流可丢，**不得参与判定**） |

### 5.1 复核记录**可读回**的口径

「可读回」= **JSONL 审计流**能还原复核集合：`upsert` / `removed` 逐条重放 ⇒
还原集合与主库当前代**逐条相等**（`loopKey` 集合相等）。
**不是**「主库零复核行」。

### 5.2 保留期策略（**复核与套利不同**）

| 树 | 保留期 | 常量 | 清理方式 |
|---|---|---|---|
| `review_record_jsonl/` | **30 天** | `REVIEW_RETENTION_DAYS = 30` | 定时任务删**过期日期文件夹**，删除台账落 `record_maintenance/cleanup_<YYYY-MM>.jsonl` |
| `broadcast_transaction_db/` | **永久** | `TRADE_ARCHIVE_MONTHS = 0` | **无自动清理路径**；清理必须经**显式命令 ＋ 人工审批** |
