## 0. 约束

### 0.0 写库分类学（**绑定性规则 · 继承 + 池子重构落点**）



| 类别 | 内容 | 性质 | 处置规则 |

|---|---|---|---|

| **基础框架库**（baseline framework） | DDL / migration / 表结构 / 列 / 约束 / 索引 / 视图 | 结构性、版本化、**幂等**、**保数据**、与链上实时状态无关 | **验证通过 ⇒ 必须实盘写入目标生产库**（该链的 DB）。**不需额外授权。** |

| **动态记录**（dynamic records） | review / depth / ladder / PnL / closed loop / broadcast attempt 等测量与运行记录 | 每次运行都变；受「实测零 ≠ 未测」「不历史回填」「需当前链状态」约束 | **可以不写**；要写时按 §2 的授权流程走 —— **例外（v2.2）**：**广播链路**的运行记录随**广播默认放开**而**自动写入**，**不单独**走授权流程（§0.0.1 / `BC-1`） |



**判定口径**：一次写入若**不改变任何测量值、只让结构与代码对齐**，就是**基础框架库**；

若**写入的是某时刻的测量结果**，就是**动态记录**。



**池子重构落点**（与任务清单 §0.3「回归范围的唯一判定规则」一致）：



| 动作 | 归类 | 需授权 |

|---|---|---|

| migration `20261123_015_directional_pool_schema.sql`（两张新表 + 索引） | **基础框架库** | **否** |

| 闭环跳表新增四列、闭环主体新增一列（`ALTER TABLE ADD COLUMN`） | **基础框架库** | **否** |

| `manager_contracts` 共享类型 + 折叠函数同形改造 | **代码**（非写库） | **否** |

| 方向池表**行的物化**（写入 `directional_output` / `input_capacity_raw` / `tick` / `liquidity` / `price` 等快照复算量） | **动态记录** | **是** |

| 闭环层的选池切换与重物化（闭环集合变化） | **动态记录** | **是** |



> **如实说明**：方向池表**不含任何新采集的链上事实**——每一行都是「基础池表 + 深度快照表」的纯投影。

> 因此“方向表行是否应归基础框架库”存在**另一种读法**（纯投影 ⇒ 与结构同批写入，不需单独授权）。

> **该归类只改变授权路径，不改变任何一行代码。**

> **裁定**：交易机会**实时变化**，历史记录**一般不具有再现性** ⇒ **广播授权默认放开**，

| 真实广播**尝试记录** / **回执** / **已实现盈亏**落库 | **动态记录**（广播链路） | **否**（同上） |

| 广播**被拒绝**的记录（利润 ≤ 0 / 未测量 / 超时 / 配置缺失） | **动态记录**（广播链路） | **否**（`BC-3` 要求**拒绝也留痕**） |

### 0.1 排序原则（**绑定性 · 继承**）



1. **功能完善优先**：能在离线环境完成、且能提高系统功能正确性的工作**排在最前**。

2. **性能优化最后**：性能调优类工作**一律排在全部功能性任务之后**。

3. **耗时 / 需授权的测试靠后**：实盘广播、长时间窗口、需要写库授权的动作**排在最后**。

   （广播虽**默认放开**，但它**含真实交易**且**耗时**，仍排在最后。）



### 0.2 归属类验收（**继承 M-1..M-5 + 本版新增 M-6**）



| # | 断言 | 落点 | 判定 |

|---|---|---|---|

>

> **M-6 的具体守卫落点（v1.1 补齐 · 必做）**：`M-3` 的守卫
