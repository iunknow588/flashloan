## 3. 架构约束

### 3.1 内存对象处理约束（**MIO-1..MIO-9 · 继承，一条不改**）



- **MIO-1** SQLite 只在初始化 / 持久化 / 审计时读写；review / depth 处理循环不得逐条 SQL 查询业务状态。

- **MIO-2** 全局内存上下文持有池、闭环和运行时快照；运行期计算只消费该上下文。

- **MIO-3** token decimals 是内存上下文的一部分，金额缩放必须使用对应 token 的精度。

- **MIO-4** WSS / 监控器更新内存快照；状态版本和新鲜度必须随计算证据传播。

- **MIO-5** Review Manager 通过 Rust 内核 / 管理接口消费业务状态，不由 Python 另建权威路径。

- **MIO-6** Python 只消费内核发布的金额、利润、路线和状态，**不重算、不拼接闭环身份**。

- **MIO-7** Rust 内核发布有符号利润及 `signedPnl.amount`，含 raw 值、币种 / 精度、来源和测量状态；

  **测得零与未测量严格区分**。

- **MIO-8** 每条链使用独立 SQLite、chain ID、RPC、权限和内存状态，禁止跨链读取或写入。

- **MIO-9** 记录读取由 **Rust Manager 拥有**：复核 / 广播 / 闭环目录 / 闭环身份的读取走 Manager 接口；

  **Python 侧不得直查 manager 拥有的表**，不得把记录缓存为内存对象当权威；

  Manager 未发布的读数**如实显示为未测量**，不得由 Python 代为推导。



> **本版补充（不新增约束，只是点名）**：方向池表一旦落表，它就是 **Manager 拥有的业务表**（MIO-9 适用）；

> 方向一旦成为“选哪个池”的判定依据，它就进入了**运行时路径**（MIO-2 适用）。

> 两者合起来即 checklist 的 **M-6**。



### 3.2 方向池架构约束（**DPO-1..DPO-12 · 绑定性**）



- **DPO-1（真相源唯一）**：方向**只有一个真相源** —— 方向池表的 `direction` 列。

  旧方向键字符串、运行时反推、路由地址推导，全部**降级为校验或删除**，

  **不得**与真相源**并行生效**。

- **DPO-2（方向锚定池自身的 token 序 · C-1）**：

  `direction = 0` **恒为** `token1 → token0`（`zero_for_one = false`，输入 = **高地址**代币）；

  `direction = 1` **恒为** `token0 → token1`（`zero_for_one = true`，输入 = **低地址**代币）。

  **不得**按锚点、按路由、按池列表位置解释方向。

- **DPO-3（`pool_id` 语义不变是投影 · C-2）**：`manager_v4_closed_loop_hops.pool_id` /

  `base_pool_id` 的语义**不变**，仍是 V4 base pool id。方向信息由**新增列**承载。

  真相源是方向行，`pool_id` 是**投影**，二者必须在**同一次写入**里从**同一行**方向池导出。

- **DPO-4（排序口径定死且限同代币对内 · C-3）**：选池主序固定为

  **方向精确输出降序 → tick 序降序 → fee 升序 → base_pool_id 升序**；

  **不得**改回 `liquidity_index`（方向对称、不表示深度，仓库自己已明文否定）。

  序位的比较范围**限 `(pair_key_id, direction)` 内**，**禁止**跨代币对比较 raw 容量。

- **DPO-5（池对象必须自带方向）**：所有参与闭环的池对象**必须**携带方向字段。

  方向**不得**以平行数组 / 平行参数与池集合分离传递（**B-4**）。

- **DPO-6（单向数据流）**：基础池表 / 快照表 → 方向池表 → 方向池内存对象 → 闭环。

  **不得**反向写回基础池表；方向层**不得**采集任何新的链上事实。

- **DPO-7（基础池表不变）**：基础池子信息的**表结构与写入语义不变**。

  方向层是**新增的一层**，不是对基础池表的改写。

- **DPO-8（门禁不放宽）**：方向池**只能**作为“选哪个池”的判定依据，

  **不得**作为“多少链路可行”的判定依据。

  容量折叠口径、单跳容量门禁与路径最小值口径、路径容量下限、USDG 估值与利润门禁、

  复核盈利符号与广播门禁、执行链价格限制与状态迁移门禁，**一律不动**。

- **DPO-9（准入约定不得突破 · 2026-11-23 新增 · 绑定性）**：

  方向池**只**投影**池管理器已准入**的基础池 —— 即 `pool_status = 'active'`，

  且**固定费率**（`0 < fee <= 30000`）、**特殊费率为 0**、**无 hook**

  （`hooks = 0x0000000000000000000000000000000000000000`）、**非动态费率**。

  依据：`pool_manager/src/scope.rs:1167-1188` —— 带 hook ⇒ `blocked`，

  动态 / 特殊 / 费率越界 ⇒ `invalid`，**只有全清才是 `active`**。

  **实测**（主网 4663）：两张池表的 `active` 行 **86 / 92** 个，

  `dynamic_fee = 0`、`special_fee = 0`、`hooks = 0x0`、费率 **29..30000**。

  **必须**新增守卫：任何方向行指向**非 active** / **动态费率** / **带 hook** 的基础池 ⇒ **判定失败**。

- **DPO-10（Python 侧无自有数据处理 · 2026-11-23 新增 · 绑定性）**：

  **方向池的物化、排序、准入、去重、边界重算，全部只在 Rust 侧**；

  Python 侧**只**消费内存对象里的**实际值**，

  **不得**在 Python 里重算方向、排序、代币映射、容量或准入判定。

  依据：Python 侧的取数通道是 Rust 桥（`rs-src`），

  内存对象**直接调用** Rust 管理工具（池管理器 / 闭环管理器 / 复核管理器），

  **Python 不拥有任何池数据处理逻辑**。方向层**不得**打破这一分工

（与 §3.4 的 M-6 例外一致 —— 例外**仅限** `TASK-166` 的只读影子比对）。

- **DPO-11（三层职责分离 · 2026-11-23 新增 · 绑定性）**：

  方向池的判定被拆成**三层**，**三层互不越界**（裁定 §1.3）：



  | 层 | 职责 | 有阈值？ | 归属 | 变更权限 |

  |---|---|---|---|---|

  | **L1 准入** | 这个池**够不够格** | ✅ **有** | Rust kernel ＋ `depth_policy.json` | 改**要**重新标定并走门禁 |

  | **L2 排序** | 谁**排在前面** | ❌ **无** | `pool_depth_sort_key` | 改**要**重审主序（`01 §4.1`） |

  | **L3 截断/分层** | **取几个** | ❌ **无** | `direction_pool_score.py:382` `limit` | 改**只**改一个常量 |



  **三条纪律**（违反即判定失败）：

  1. **L3 的取值不得携带任何质量语义** —— `MAX_DIRECTION_CANDIDATE_POOLS = 5` 是**容量旋钮**，

     不是「至少要 5 个才算好」；**不得**被当作门禁来调。

  2. **L3 不得反向影响 L1** —— **不得**为了凑够 5 个而放宽任何一条准入判据

     （实测 **72.8 %** 的方向链上无池，凑数会把闭环送进容量门禁失败）。

  3. **L1 的阈值永远独立于 L3 的数量** —— L2 的排序结果才是质量判断的依据。



  依据：`direction_pool_score.py` 模块 docstring ——

  *"The **admission** decision belongs to the Rust kernel… this module only consumes

  that verdict and **never carries a private copy of an admission threshold**."*

- **DPO-12（参数与读数的分类判据 · 2026-11-23 新增 · 绑定性）**：

  任何数字在进入代码或配置前，**必须**先归类（裁定 §1.2）：



  ```text

  「参数（旋钮）」= 改变它 ⇒ 系统**行为**跟着变

                    ⇒ 因此**可以**由人设定，且**不需要**外部理由

  「读数（仪表盘）」= 改变它 ⇒ 系统**行为不变**，只是**观测值**变了

                    ⇒ 因此**不能**由人设定（否则等于「规定系统必须显示 5.77 %」）

  ```



  ⇒ **参数回答「做多少」，读数回答「发生了什么」。**

  ⇒ **三个阈值（`_MID_CHANGE_RATE_` / `_LOOP_NET_RATE_` / `_PROFIT_DROP_`）全部是输出量**，

  **没有资格**做参数 ⇒ 一律以「**读数 ＋ 观察线**」写入文档与报告；

  ⇒ **观察线命中不否决**任何阶段，只**升级归因**并要求人工复核

  （判读表：门禁 vs 观察线，见裁定 §1.2 / §5.1）；

  ⇒ **候选池数量**（`MAX_DIRECTION_CANDIDATE_POOLS`）是**旋钮**（改它系统行为就变）⇒ **保留为参数**。



### 3.3 写库分类学落点（**已内联原主计划 §3.3.0 · 含池子专项判定**）

**方向池的运行时排序与去重，只在 Rust 侧。**



### 3.5 闭环身份与路径匹配（**继承 · 不变**）



- 闭环身份由**内核**计算并随路线结果发布，**Manager 存储**它，消费者**读取**它。

- **身份是可选的**：对未发布任何闭环的目录发布，路线**没有**身份 —— 这是**缺失**，不是**不匹配**。

- 路径匹配必须**精确有序**；**未匹配不得猜测**。



**本版补充**：方向池**不改变** `loop_key` 的计算规则。

同一闭环里一个池子只算一次，不因方向拆成两条 ⇒ 方向池**不会让任何闭环多出一条**（见 04 §5.4）。



### 3.6 级联与计算边界（**继承 · 不变**）



- 金额 / 容量 / 利润**只能**由 Rust 内核从**当前内存状态**计算。

- **禁止**用历史数据回填掩盖当前计算缺陷。

- **禁止**把复核阶段的预期金额当作已实现盈亏。



### 3.7 广播准入约束（**BC-1..BC-5 · v2.2 新增 · 绑定性**）



> **背景（使用者裁定，2026-11-23）**：交易机会**实时变化**，历史记录**一般不具有再现性**。

> 因此**不再需要**「先取得独立授权、再过门禁、再广播」这类**人工审批**步骤 ——

> 等到授权批下来时，机会早已消失。**广播授权默认放开**，

> 但**必须确认复核正向利润**才广播执行。



**BC-1（唯一准入门槛 · 绑定性）**



广播**默认放开**：**不需要**任何额外的人工授权、审批或凭据。

广播的**唯一准入门槛**是**复核正向利润确认**，由**机器**判定，以下五条**同时**满足才可发送：



| # | 条件 | 判据来源 | 不满足时 |

|---|---|---|---|

| 1 | `run.ok == true` | `runArbitrage` 返回值 | **不生成广播请求** |

| 2 | `run.executable == true` | `runArbitrage` 返回值 | **不生成广播请求** |

| 3 | **净正向利润 > 0**：`signed_pnl.amount > 0`，且**已测量** | 复核签名盈亏 | **不生成广播请求** |

| 4 | 复核新鲜度满足 **120s 自动广播门禁** | `review_is_fresh_for_automatic_broadcast()`（`MAX_AUTOMATIC_BROADCAST_REVIEW_AGE_SECONDS = 120`，含 30s 时钟容差） | **不生成广播请求** |

| 5 | 复核完整性满足：金额 `measured` / PnL 非 `missing` / `bestAmountMissing = 0` | 复核记录 | **不生成广播请求** |



**这五条与既有门禁是同一套判据**，**没有新增宽松项**，只是把「是否放行」的**决定权**

从**人工审批**改成**机器判定 + 正向利润确认**。



**链 / 账户 / 限额 / 时间窗口的定性改判（v2.2）**：



| 项 | v2.1（旧） | **v2.2（新）** |

|---|---|---|

| 链 | 授权凭据的一项 | **运行时配置**；缺失 ⇒ **拒绝发送** |

| 账户 | 授权凭据的一项 | **运行时配置**；缺失 ⇒ **拒绝发送** |

| 限额 | 人工审批的一项 | **自动护栏**；超限 ⇒ **自动停止发送**（**不需要人批准**） |

| 时间窗口 | 人工审批的一项 | **运行参数**；不在窗口内 ⇒ 本轮**不发送** |



> **「默认放开」的确切含义**：**免掉人工审批**，**不是**「无条件广播」。

> 上述任何一条不满足 ⇒ **不发送**，且**不得**以「已默认放开」为由绕过。



**BC-2（拒绝路径先于首次真实广播 · 绑定性）**



默认放开意味着**机器门禁是唯一挡在真实交易前的东西**（v2.1 时还有人工授权在前）。

因此以下两项**必须先于第一次真实广播闭合**，二者都是**硬前置**：



- `T-广.01` 的**四类拒绝路径**（`profit<=0` / 利润或金额未知 / 状态陈旧 / 权限错配）

  **逐条真实触发并留证**；

- `T-复广.02` 的**门槛谓词**、**六类负向验证**与**逐次审计留痕**闭合。



**BC-3（三种「不广播」的区分 · 绑定性）**



| 情形 | 定性 | 处置 |

|---|---|---|

| `positive = 0`（测得零） | **真实业务结论**（链上不盈利） | **如实保留为测量结果**；**不广播**是**正确处置**，**不是**缺陷 |

| 净正向利润 `< 0`（测得负） | **真实业务结论** | 同上 |

| 利润 / 金额**未测量**（`missing`） | **未测量** | **不广播**；**不得**当作零、**不得**当作不匹配、**不得**当作可放行 |



**不得**为凑 `positive>0` / `L3>0` / `L4>0` / 闭环数而**放宽**任何门禁。



**BC-4（授权边界 · 绑定性）**



本规则族**只改广播链路**。以下**一律不受影响**，仍按原授权流程走：



- migration apply（`20261123_015_directional_pool_schema.sql`）；

- 方向池表**行的物化**（§3.3 落点）；

- 闭环层**选池切换与重物化**（§3.3 落点）；

- `DIRECTIONAL_POOL_MANAGER_AUTHORITY` 授权维度（**方向池写端点**，与广播无关）；

- 方向池回滚脚本的 `--apply` 模式（§3.3 推论 2）。



> **一句话**：**广播链路放开，池子重构的工程写入不放开。**



**BC-5（逐次审计留痕 · 绑定性）**



默认放开必须**更严**地留痕 —— 不是更松。每次广播必须能回答「**凭什么发这一条**」，

且以下字段**必须落库可查**（缺一即为**未通过**）：



复核标识 / `signed_pnl.amount` / 复核年龄（秒）/ 幂等键 / 链标识 / 账户标识 /

限额判据 / 广播时间戳 / 结果（**尝试** / **回执** / **拒绝原因**）。



**不得**只留结果不留理由；**不得**只留金额不留其余判据。

### 3.8 记录存储约束（**RS-1..RS-12 · v2.6 新增 · 绑定性**）



> **背景（使用者裁定，2026-11-23）**：主 SQLite 已 **8.01 GiB**，复核记录与套利记录**应当剥离**：复核记录落**按日 JSONL**、套利记录落**按月 SQLite**，**主 SQLite 信息维持不变**。**可行**（技术方案 05 §一 · 10 条裁定），但**必须**受本约束族约束。详细规格见 [`06-记录存储剥离开发计划.md`](./D-010-记录存储剥离开发计划.md)。



**RS-1（改动范围 · 绑定性）**



**只允许**改动两个 crate：`flashloan/tools/review_manager/` 与 `flashloan/tools/broadcast_manager/`。**主库 DDL / 迁移 / `schema_policy.json` / `manager_db` / `composite_manager` / `manager_api` / `rs-src` / Python 侧 / 闭环层 / 方向池层 / 池子管理器 一律不动。** ⇒ **主网库全程只读**，**零数据迁移**（实测：主库套利 / 广播相关表 **0 行**）。



**RS-2（读路径零变更 · 绑定性）**



下列公开函数**签名与语义一字不改**：`read_review_snapshot` · `read_review_page` · `read_broadcast_status` · `read_broadcast_snapshot_page`。⇒ 三个消费 crate **零 diff**。**新增**的读取能力只能以**新函数**提供（如 `read_review_record_health()` / `read_trade_archive_summary()`），**不得**替换既有函数。



**RS-3（三层权威 · 绑定性）**



| 层 | 载体 | 参与判定 |

|---|---|---|

| **L1 主库** | 当前代物化视图 + 状态行 + 幂等台账 | ✅ **是** |

| **L2 月度库** | 已终结套利记录 | ✅ 是（幂等 / 回执关联） |

| **L3 JSONL** | 逐代复核审计流 | ❌ **永不** |



**RS-4（JSONL 不参与判定 · 绑定性）**



复核 / 广播的**任何**机器判据**不得**读取 JSONL。理由：JSONL **可丢、可缺、可截断** ⇒ 用它做判定 ⇒ 判定结果**不可复现**。**守卫**：`G-2`（源码级扫描）。



**RS-5（写入顺序 · 绑定性 · 安全级）**



**先写月库、后动主库**；**记录写入只在事务提交之后**。违反 ⇒ 可能出现「主库已瘦身、月库没写」⇒ **记录永久消失** / **幂等锚点丢失**。**守卫**：`G-1`（源码级 + **故障注入**）。



**RS-6（幂等锚点不可删 · 绑定性 · 安全级）**



终结的套利记录**绝不**从主库**删除**行；归档只做**瘦身**（清空体积列）。`status` **不改**（CHECK 只允许 `pending/success/failed`）、**不新增列**、**不新增表**。⇒ 幂等锚点（`attempt_id`）**永远在主库** ⇒ **重复广播风险 = 0**。



**RS-7（精度口径 · 绑定性）**



`signed_pnl_raw` 是**带符号十六进制**（实测 `-0x2ee726109c1`，**0/14** 是十进制）。**逐字节原样保留**；**绝不**转十进制、**绝不**进 JSON 数字、**绝不**用 `signed_pnl_amount`（`REAL` / f64）做权威。



**RS-8（多币种不合并 · 绑定性）**



实测 `signed_pnl_currency` 有 **WETH / SPY / TZ** 三种 ⇒ 聚合**必须按币种分组**；**禁止**跨币种求和；**禁止**在 SQL 里 `SUM()`。**「过去 N 个月的总利润」这个口径本身不成立** —— 只能给**每币种**的精确合计。



**RS-9（JSONL 格式 · 绑定性）**



**一行一个 JSON 对象**（JSONL），**严禁** JSON 数组；**金额只写字符串**；**无值不写键**（不写 `null`）。末尾一次写入中断 ⇒ **最多丢最后一行**，其余行**必须**完好可解析。



**RS-10（反压分级 · 绑定性）**



| 通道 | 满时策略 | 理由 |

|---|---|---|

| JSONL 复核审计流 | **`try_send` 丢弃 + 计数** | 审计流**可丢**；**绝不能**拖慢复核物化 |

| 月度套利库 | **背压等待**（`send().await` / `blocking_send` / 单次同步兜底） | 套利记录**不可丢** |



**一句话**：**可丢的流宁可丢，不可丢的流宁可等。** **禁止**在持有主库事务 / 锁时做磁盘 IO。



**RS-11（保留期 · 绑定性）**



复核 JSONL **30 天**（`Q-2`）；**月度库永不自动删除**（**财务凭据**）。清理任务**只删** `<主库目录>/review_record_jsonl/` 子树里的**日期文件夹**；**绝不触碰** `<主库目录>/broadcast_transaction_db/`；每次删除**写台账**（落 `<主库目录>/record_maintenance/`）；越界路径**必须被拒**。



**RS-12（门禁不放宽 · 绑定性）**



本规则族**只改「记录落在哪儿」**，**不改「怎么判」**。复核完整性 / 新鲜度 / 容量 / 利润 / `BC-1` / 幂等 / 回执关联 **逐条不变**；**一条都不放宽**。**JSONL 不是新的放行依据。**



**RS-13（目录布局 · v2.7 新增 · 使用者裁定 · 绑定性）**



两棵记录树**与主库同目录**（主库在 `flashloan/db/` ⇒ 记录也在 `flashloan/db/`）：



| 树 | 布局 | 拆分维度 |

|---|---|---|

| 复核审计流 | `review_record_jsonl/<network>/<chain_id>/<YYYY-MM-DD>/<方向闭环>.jsonl` | **按日期建文件夹 · 按方向闭环拆文件** |

| 广播交易记录 | `broadcast_transaction_db/<network>/<chain_id>/<YYYY-MM>/trades.sqlite3` | **按月份建文件夹 · 全部方向闭环同库** |

| 清理台账 | `record_maintenance/cleanup_<YYYY-MM>.jsonl` | 永不清理 |



**方向闭环文件名**：闭环键含 `:`（Windows 文件名不允许）⇒ **安全化 + 原键 SHA-256 前 12 位**，

保证「不同闭环不同文件、同一闭环同一文件」。



**广播侧不拆文件的理由**：月度库要回答「这个月这个链赚了多少」，**按币种分组**的合计

必须在**同一个库**里算（`RS-8`）；拆成每闭环一个库会把「跨闭环求和」变成 N 次连接。

闭环维度由 `loop_key` **列**承担，不靠文件分片。
