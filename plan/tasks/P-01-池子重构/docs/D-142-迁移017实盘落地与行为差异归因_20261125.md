### 5.2 机制（代码级）

中跳的候选层取自市场观察（`closed_loop_manager/src/lib.rs:2930` 附近）：

```text
middle_tier = [ yz.optimal_pool_id ]  ++  [ yz.pool_ids 中其余的池 ]
```

`yz.optimal_pool_id` 是**主序**（无 optimization id），`yz.pool_ids` 的其余项是**备序**
（`middle-rank-N`）。因此：

* 迁移前，主序 = **旧的流动性下标口径**；迁移后 = **方向层 rank-1**；
* 主序换人 ⇒ 备序整体平移 ⇒ **组合数变化**；
* 方向层主序开关 `FLASHLOAN_CLOSED_LOOP_DIRECTIONAL_PRIMARY` **缺省即开**，
  候选列表会再按方向层序位排一次 ⇒ **主序最终就是方向层 rank-1**。

⇒ **迁移把中跳主序的权威从旧口径交给了方向层**，这正是
`20261125_017` 迁移文件自述的目的（"方向层接管了闭环的主序…流动性下标不再是权威"）。
**这不是回归，是重构的最后一公里被补上。**

## 6. **新发现（超出迁移本身）**：方向层没有自动刷新路径

不变式审计 `audit_directional_invariants_20261125.py` 在核 I-9 时暴露：

| 读数 | 值 |
|---|---|
| 方向行总数 | 692 |
| **身份列**（12 列）与基础池表不一致的格数 | **0** |
| **快照列**（`sqrt_price_x96`/`tick`/`liquidity`/`price`/`depth_status`）与快照表不一致的格数 | **1250** |
| 方向表物化时刻 | **2026-11-23 22:46**（此后未再物化） |
| 方向行内 `liquidity_read_at` 范围 | 2026-11-17 20:00 → **2026-11-22 13:21** |
| 快照表最新 `liquidity_read_at` | **2026-11-25 00:44**（即今天） |

> **订正**：快照列的不一致格数是 **994**（不是 1250）；
> 报告：`plan/runtime_evidence/reports/directional_invariants_postapply_20261125.json`。
> 逐项读数：**8 / 9 PASS**，唯一 FAIL 即本项；
> 方向行 **692**、可比 **436**、漂移 **83** 行、**994** 格、无快照覆盖 **256** 行。
> 其余 8 项（I-9 身份面 0 不一致、I-7 522/522、I-12 522/522、
> `direction_mismatch` 0、I-16 0、每池两行 0 异常、序位连续 0 断档）在重建前后**一致**。

**本轮补一条机制事实**：`composite-manager materialize-arbitrage` 的三段是
**候选边 → 候选交换 → 闭环**，它**读**方向层、**不物化**方向层
（方向行的唯一生产写入方是 `directional_pool_manager/src/lib.rs:1785`）。
⇒ 本轮重建后 `directionalPoolVersion` 仍是 **2**、校验和不变 —— 这不是遗漏，
而是「方向层没有自动刷新路径」的**直接证据**。

**归因**：方向层的**身份列**逐列来自基础池表，**快照列**逐列来自
`v4_exchange_pool_liquidity_snapshots`（`directional_pool_manager/src/lib.rs:1124` 与 `:1232`）。
身份列 **0** 不一致 ⇒ 投影本身忠实；快照列不一致是因为**方向层自 11-23 起没有被重新物化**，
而快照表已被流动性 worker 刷新到今天。

**为什么没有自动刷新**：

* `composite-manager materialize-arbitrage` **只读**方向层状态
  （`read_directional_pool_status`），**不物化**方向层；
* 真正写方向层的是 `directional_pool_manager` 自己的例程与
  `POST /v1/directional-pools/rebuild`；后者需要
  `DIRECTIONAL_POOL_MANAGER_AUTHORITY=manager`；
* runtime 的 7 个维护 worker 里**没有方向池 worker**
  （`v4_broadcast_execution_worker` / `v4_candidate_yc_zc_worker` /
  `v4_closed_loop_worker` / `v4_dex_overview_worker` / `v4_market_observation_worker` /
  `v4_onchain_review_worker` / `v4_pool_liquidity_worker`）。

**含义**：闭环的容量门禁正在用 **2–8 天前**的 tick 状态判断
（`input_capacity_raw` 与单 tick 边界都来自方向行）。
这是**本次重构的核心层**，却是唯一没有自动刷新的一层。
