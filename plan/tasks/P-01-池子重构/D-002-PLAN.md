## 1.0 编号逻辑（**本一级任务的编号从哪来**）

> **本节是固定部分。** 一级任务与二级任务**各自**声明自己的编号逻辑。

| 项 | 值 |
|---|---|
| **本任务编号** | **`P-01`** |
| **编号作用域** | **跨模块**（一级任务是**容器**，覆盖多个模块） |
| **编号索引** | **不适用** —— 一级编号**不按模块分组**，它是**方案 / 计划级**的容器编号 |
| **二级编号的分组依据** | **各二级任务自己的编号索引**（模块内索引 或 组合索引，见各二级任务 `PLAN.md` §1.0） |
| **同号段其它任务** | **无** —— `P-nn` 号段**每个一级任务独占**，不复用 |

**为什么一级编号不按模块分组**：一级任务声明**整体目标 + 总边界 + 模块级波次**，
它本身**跨越多个模块**（本次为 `M-3` … `M-10`）⇒ 无法归属单一模块号段。
**模块分组只发生在二级**：`T-<索引>.<序>` 让每个二级任务的归属**一眼可辨**。

**各模块号段占用情况**：

| 模块 | 名称 | 任务数 | 已占用编号 |
|---|---|---:|---|
| `M-3` | 方向层 | 2 | `T-方授储.01`、`T-方储.01` |

| `M-5` | 估值与数据源 | 3 | `T-候储.01`、`T-候.01`、`T-候.02` |
| `M-6` | 复核发布层 | 3 | `T-复编.01`、`T-复.01`、`T-复.02` |
| `M-7` | 广播层 | 3 | `T-复广.01`、`T-广.01`、`T-复广.02` |
| `M-8` | 候选池层 | 2 | `T-编.01`、`T-候编.01` |
| `M-10` | 存储层 | 4 | `T-储.01`、`T-储.02`、`T-储.03`、`T-储.04` |

**规则**：

1. **一级编号 `P-nn` 全局递增、不复用、不按模块分组**。
2. **二级编号 `T-<索引>.<序>` 按其编号索引分组**；每个二级任务在**自己的** `PLAN.md` §1.0 声明。
3. **验收编号**与二级任务**同号段**（`AC-<索引>.<序>`）。
4. **一个二级任务只服务一个模块**；跨模块任务用**组合索引**（改动模块索引按模块号 `M-n` 升序拼接）编号，**不设**「主模块 ＋ 附带模块」的挂靠式编号。
5. **不同模块的序号互不消耗** —— 一个模块做到 `.09` **不影响**其它模块的 `.04`。
6. **前置与顺序只按模块号 `M-n` 表达** —— **禁止**写「等 `T-x.yy` 完成」。

**登记**：编号的唯一真相源是 [`plan/D-001-TASK_REGISTRY.md`](../../D-001-TASK_REGISTRY.md) §4。

### 1.1 一级任务存在的理由

池子重构**不是一个可一次闭合的代码改动**，而是**一组**相互独立的改动：

- 每个二级任务**触及的模块不同** ⇒ **回归范围不同**；
- 每个二级任务**可独立完成** ⇒ 一个不闭合**不阻断**其它；
- 每个二级任务**各自有独立的证据与验收** ⇒ 混在一起无法逐条勾选。

因此：**边界放一级，执行放二级**。
一级**只**回答「整体要达成什么、边界在哪、怎么分解」；
二级**只**回答「这一块怎么改、怎么测、怎么判定闭合」。

### 1.2 不做什么（**范围外**）

- **不**在本目录写具体代码改动步骤 —— 那是二级任务的事；
- **不**在本目录做**跨二级**的混合验收 —— 二级之间**不耦合**；
- **不**因「有新二级任务」重跑未改动模块的测试。

### 2.3 执行步骤

| 步 | 动作 | 完成判据 |
|---:|---|---|
| **1** | 读 `tasks/<T-nn>/checklist.md`，确认每条验收项**当前状态** | 全部条目已知 |
| **2** | 只改**该二级任务**改动模块内的代码 | 改动文件全部落在该二级任务的落点内 |
| **3** | 跑**该二级任务自己**的回归范围 | 全绿 |
| **4** | 逐条勾选该二级任务的 `checklist.md` | 每条都有**实测证据** |
| **5** | **二级闭合 ⇒ 立即归档**（移出 `tasks/`） | 归档件存在 ＋ 索引已登记 |
| **6** | 更新本目录 §2.1 该行状态 | 状态准确 |

### 2.4 三条执行纪律

1. **编译 ≠ 测试** —— 只改接口签名时，`cargo build --offline --workspace` 足够。
2. **跨 crate 的公开接口改动**才加跑**调用方**的测试；**内部实现**改动不需要。
3. **Python 侧同理** —— `flashloan/app_runtime/tests/unit/` 有大量文件，
   **只跑受影响的那几个**。
