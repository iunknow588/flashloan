# `P-01-池子重构`｜修改范围守护（Scope Guard · 一级）

> **本文件是一级的范围契约。** 它定义**整体允许改什么**、**总回归跑什么**、**禁止碰什么**。
> **各二级任务另有自己的 `SCOPE_GUARD.md`** —— 二级**只管自己**那块。
> 违反本契约 ⇒ **本一级任务不算闭合**。

---

## 2. 总回归（**只在全部二级闭合后跑一次**）

> **这是唯一的例外**：一级在**全部**二级闭合后做一次**整体**回归。
> 目的**不是**重跑各二级的测试（那些已在各自闭合时跑过），
> 而是确认**跨二级组合**后**整体**仍成立。

```powershell
# 整体架构边界（跨模块的依赖方向、禁止项）
pytest flashloan/app_runtime/tests/unit/test_architecture_guards.py

# 跨 crate 公开接口的组合编译
cargo build --offline --workspace
```

> **除这一步外，一律不得跑全量。**

## 3. 触碰边界（**禁止触碰**）

| 对象 | 禁止理由 |
|---|---|
| `M-1` 数据采集层 | **不在**本一级总改动模块集合内 |
| `M-2` 内核对象层 | **不在**本一级总改动模块集合内 |
| `M-11` 工具与脚本 | 仅**工具本身**可改，不得改业务语义 |
| 除上表以外的全部模块 | 未改动模块不跑、不碰 |

---

## 4. 范围变更流程（**先扩后跑**）

若发现必须触碰**不在** §1 模块集合内的模块：

1. **先扩范围** —— 在本文件 §1 增列该模块，同步改 `PLAN.md` §1；
2. **记录原因** —— 在 `PLAN.md` 追加一行说明；
3. **后施工** —— 然后才动该模块；
4. **后重跑** —— **只**跑扩范围后模块的测试，**不**回头跑全部。

> **禁止**先改了再补登记。

---

## 5. 授权边界

| 动作 | 需要授权？ | 说明 |
|---|---|---|
| 写**生产库** | **是** | 真正写生产库的任务（见二级任务各自登记）才需要授权 |
| **广播** | **是** | 真实广播需单独授权 |
| 改 schema | **否** | DDL 属基础框架库 |

> **授权只跟着「真正写库 / 真广播」走** —— 不再重复索要。
