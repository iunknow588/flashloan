## 4. 架构裁定（六条）

### 4.1 裁定一：**记录路径不依赖「实时的广播请求行」**

`manager_v4_review_broadcast_requests` 由复核层**每代整体替换**：
`replace_review_rows`（`review_manager/src/lib.rs:3164-3186`）对
`manager_v4_review_diagnostics` / `manager_v4_review_broadcast_requests` / `manager_v4_reviews`
先 `DELETE` 再 `INSERT`。

⇒ 它是**当前代的快照**，不是历史。§2.1 的 `reviewCompletedCount 1 → 0` 就是这一行为的实盘读数。

若回写依赖它，则「广播发出 → 回执返回 → 回写落库」这几秒里只要市场变了、下一代发布把该行删掉，
这笔**已经上链**的事实就**永久丢失**。

**裁定**：回写**不要求**请求行存在；准入判据（`BC-1` / `BC-2`）**管的是「要不要发」，不是「要不要记」**。

### 4.2 裁定二：**元数据来自复核行，不来自运行时**

闭环身份（`anchor_token_key_id` / `path_*` / `pool_path_key` / `pool_ids` / 容量锚 / 逐跳价格上限）
由 `manager_v4_reviews` 里该 `loop_key` 的那一行提供 —— **复核层拥有身份**，
所以**尝试行与复核行不可能各说各话**。

**该复核行不存在 ⇒ 明确失败**（`BroadcastError::ReviewRowMissing`），**绝不拿猜的值凑一行**。

### 4.3 裁定三：**准入与记账是两条线**

回写路径**不调用**准入、**不放宽**任何门禁（`offchainGasGate` / `capacityGate` / `economicFloorGate` / `hopPriceLimitGate`）。
门禁决定**发不发**，记账决定**记不记**；两者互不引用、互不代偿。

### 4.4 裁定四：**回写不经过闭环状态机**

闭环状态机与广播工作线程是**并列**的两条线路（用户口径 2026-11-25）。
回写挂在**广播工作线程执行完任务之后**，不进入状态机、不等待状态机、也不被状态机阻塞。

### 4.5 裁定五：**要么成功，要么失败，没有降级**

记账失败**不吞**、**不回滚已发生的广播**（交易已经在路上，回滚不了）：
错误写进 `payload["broadcastRecord"]` ⇒ 随广播结果一起可见。
广播层不新增第二条兜底通道（既有 `note_trade_publish_failure` 保持原样）。

### 4.6 裁定六：**尝试的身份由运行时命名，广播层不另起一套**

上了链的用 `runtime:{network}:{chain_id}:{txHash}` ⇒ 同一笔交易重放是**同一行**（更新，不新增）；
没上链的用「闭环 ＋ 状态 ＋ 时刻」⇒ 同一闭环的两次失败是**两行**。

广播层**只校验不重命名**（`attempt.attempt_id` 为空 ⇒ `InvalidRequest`）
⇒ **行里的身份**与**载荷里回给内核的身份**永远是同一个字符串。
