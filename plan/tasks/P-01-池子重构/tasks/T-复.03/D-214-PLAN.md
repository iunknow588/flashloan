## 1. 身份与范围

| 项 | 值 |
|---|---|
| **任务编号（纯 ID）** | **`T-复.03`** |
| **验收编号（纯 ID）** | **`AC-复.03`** |
| **标题** | 复核审计流按小时分文件（**日期目录与保留期清理不变**） |
| **优先级** | P1 |

### 1.1 用户口径（**本任务的全部依据**）

> 「复核数据太多，不便于分析，请复核管理器的工作方式，把按照日期存储文件的方式修改为按照小时生成新文件库（名字同样包括年月日），这样每个复核文件的大小都可控。」
>
> 「**另外，按照小时存文件，不影响按照日期生成目录，因此，清理按照日期清理目录的功能不需要修改，实现需要做调整。**」

### 1.2 口径澄清（**两条事实**）

1. **审计流是只写不读的外部数据。** 复核结论全部在内存对象里；
   落盘的 JSONL 是**外部生成的动态记录**，运行时不分析它。
   ⇒ 因此**不需要**为它做任何「读取侧」的性能设计，
   只需**把文件大小控制住**（这正是按小时分文件的全部目的）。
2. **日期目录不变 ⇒ 保留期清理不变。** 保留期清理从一开始就是
   **按日目录**实现的（`collect_day_folders` 收集 `<network>/<chain>/<day>`，
   `review_day_is_removable` 判定后 `remove_dir_all` 整目录删除）。
   它**从不看文件名** ⇒ 文件名里多一个**小时**后段，清理逻辑**一行都不用改**。

## 2. 改动清单（**文件级**）

| # | 文件 | 改动 | 口径 |
|---|---|---|---|
| 1 | `flashloan/tools/review_manager/src/records.rs` | `review_file_path(dir, day, hour, loop_key)` → **`<日期目录>/<闭环干名>_<YYYYMMDD-HH>.jsonl`** | **目录保留日期**，文件名带小时 |
| 2 | 同上 | 新增 `pub fn review_hour_stem(day, hour) -> String`（例 `20261126-20`） | 小时桶的名字有**唯一**生成处 |
| 3 | 同上 | `line_day(line)` → **`line_hour(line)`**（取 `observedAt` 的 UTC 时） | 行归属小时由**它自己的时间戳**决定 |
| 4 | 同上 | `JsonlWriter` 的句柄键 `(NaiveDate, String)` → **`(NaiveDate, u32, String)`** | 一个句柄 = 一天 × 一小时 × 一个闭环 |
| 5 | 同上 | `rotate(day)` → **`rotate(day, hour)`**（只保留**当前小时**的句柄） | 跑很多天的写者不会每个小时留一个句柄 |
| 6 | `flashloan/tools/review_manager/src/lib.rs` | 跟随新签名的调用点 + `use chrono::Timelike` | 调用点**必须**一起改，否则编译不过 |

### 2.1 **没有**改动的部分（**这是本任务的关键**）

| 函数 | 状态 | 原因 |
|---|---|---|
| `review_day_folder(day)` | **原样** | 日期目录的名字**不变** |
| `review_day_from_folder(name)` | **原样** | 目录名格式**不变** |
| `collect_day_folders(...)` | **原样** | 只收集第 **3** 层的**目录**，不看目录里的文件名 |
| `review_day_is_removable(...)` | **原样** | 判据是**目录名里的日期** vs 保留期 |
| `purge_expired_review_files(...)` | **原样** | 整目录 `remove_dir_all`，**逐行改写从无** |
| `read_review_record_health()` | **原样** | 读的是**计数器**，不是文件名 |
| 读侧（归档/汇总） | **原样** | 审计流**不参与任何决策**，没有按文件名的读取方 |

> **一句话**：**目录维度没动 ⇒ 清理维度不需要动。**
> 保留期清理从第一天起就是「**按日期目录整目录删除**」，
> 小时只进了**文件名**，所以**清理功能一行未改**（§3 的回归证明这一点）。
