# D-103 `T-复编.02`｜利润等价性与 `profitDrop` 实测

> **本文档回答一个问题**：闭环层切到**方向池**之后，同一条闭环的**有效利润**变了没有，
> 变了多少，**为什么**变。
>
> **本文档不回答**「复核发布是否落地」—— 那是本任务另一组验收项，
> 由 `docs/D-104-复核完整性实测.md` 承担。

---

## 1. 口径（**先定口径，再取数**）

### 1.1 为什么这项只能在复核层测

闭环层**不存利润**。闭环表里只有 `single_tick_capacity_anchor_raw`
（折叠后的单 tick 容量），利润是**复核层按实时价**算出来的。
⇒ 利润等价性与 `profitDrop` **只能在 `M-6`（复核层）测**，
这正是 `M-4`（闭环层）把这两项**如实移交**本任务的原因。

### 1.2 三条裁定

| 项 | 裁定 | 依据 |
|---|---|---|
| **`profitDrop` 是什么** | **受影响闭环有效利润的中位数跌幅** | `D-012` §4.1（20% 是**观察线**，**不是门禁**） |
| **比较对象** | 同一闭环的**新旧路径**（池 + 方向 + 容量） | `D-047` §1.1 移交说明 |
| **利润用什么算** | **内核自己的算术**：`review_manager::build_hop_chain` + `review_manager::simulate_route` | **不得**在探针里复刻第二套舍入规则 |

### 1.3 「同一价格快照」怎么保证

新旧两条路径**必须在同一次读数上比较**，否则比的是两个时刻的价格。
本探针的做法：

1. 从 **当前实盘库**读一次池状态
   （`v4_exchange_pools JOIN v4_exchange_pool_liquidity_snapshots`，
   由 `pool_manager::read_pool_parity_states_on_connection` 提供）；
2. **两条路径复用这一份状态**重放。

⇒ 快照时间：三组分别为 `2026-11-24T06:25:35.756529900Z` /
`06:25:36.121664200Z` / `06:25:36.424702700Z`；
池数：`poolsRequested = 52`、`poolsWithState = 52`（**100% 有状态**）。

## 2. 三代闭环目录（**实测，不是推断**）

| 代次 | 库文件 | `closed_loop_version` | 闭环 / 跳 | `hop_direction` 分布 | 容量为空 / 为零 |
|---|---|---:|---:|---|---|
| **v15** | `local_store_4663.sqlite3.bak_closedloop_directional_20261124` | 15 | 168 / 504 | `NULL` × **504** | 0 / 0 |
| **v18** | `local_store_4663.sqlite3.bak_tfangbi_20261124` | 18 | 168 / 504 | `0` × 250、`1` × 254 | 0 / 0 |
| **v19** | `local_store_4663.sqlite3`（实盘） | 19 | **174** / 522 | `0` × 261、`1` × 261 | 0 / 0 |

**关键事实**：**v15 的 504 个跳全部没有方向**（`hop_direction IS NULL`）。
v15 是**方向化之前**的基线，不是「方向化之后又换了池」的基线。
⇒ 三组对比的**含义**各不相同：

| 对比 | 跨越的变更 | 用途 |
|---|---|---|
| **v15 → v18** | 方向化切换（**池层 + 闭环层**） | **`profitDrop` 的主测量** |
| **v18 → v19** | 备用池接线（**+6 闭环 / +18 跳**） | **利润等价性**的逐个核对 |
| **v15 → v19** | 上述两项合计 | 合计口径 |

### 2.1 方向的语义（**从内核源码确认**）

`review_manager::build_hop_chain`（`flashloan/tools/review_manager/src/parity.rs`）里：

- 路由**花掉 token0** ⇒ 低地址 → 高地址 ⇒ 方向 **1**；
- 路由**花掉 token1** ⇒ 高地址 → 低地址 ⇒ 方向 **0**；
- `hop_direction` 为 `NULL` ⇒ **回退到路由自身的代币序**（`derived_zero_for_one`）；
- 存的方向与推导方向**不一致** ⇒ **该跳被丢弃**，并记入 `direction_mismatches`。

这与「**0 = 从高地址兑换低地址，1 = 从低地址兑换高地址**」的约定一致。

### 3.2 「利润等价性」的**逐个**核对

**v18 → v19（备用池接线）**：**168 / 168 逐个相等**，不等 **0** 条。
这是**逐个**核对的结果（探针对每一条共有闭环比较新旧利润，
相等计一次、不等计一次），**不是**中位数。

**v15 → v18**：**未受影响闭环 = 0**（168 个闭环的方向全变了），
⇒ 「路径未变的闭环利润应当相等」这一条**在本组没有样本**。
该组的等价性改用**同金额重放**核对（见 §3.3）。

### 3.3 归因：**跌幅来自容量包络，不是路线变差**

对**旧容量为正**的 4 个可测闭环，把**新旧两条路径放到同一个金额**（旧容量）上重放：

| 闭环（缩写） | 旧容量 | 新容量 | 容量比 | 旧利润 | 新利润 | **同金额（旧容量）上的旧利润** | **同金额上的新利润** | 收益率变化 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `0x5fc5360d…:0x0000…:0xdf0992e4…` | 134 | 25 | 0.1866 | 74 | 12 | **74** | **74** | −13.08 % |
| `0x5fc5360d…:0x7066a64c…:0xdf0992e4…` | 132 | 25 | 0.1894 | 73 | 12 | **73** | **73** | −13.21 % |
| `0xdf0992e4…:0x5fc5360d…:0x0000…` | 2413874451613 | 511287708386 | 0.2118 | 1341780343522 | 251893481037 | **1341780343522** | **1341780343522** | −11.37 % |
| `0xdf0992e4…:0x5fc5360d…:0x7066a64c…` | 2413874451613 | 511287708386 | 0.2118 | 1342998373226 | 252141034506 | **1342998373226** | **1342998373226** | −11.36 % |

**读法**：

1. **同金额上，新旧利润逐个完全相等**
   （74/74、73/73、1341780343522/1341780343522、1342998373226/1342998373226）
   ⇒ **路线本身的算术没有变差**。
2. **有效利润跌了 81–84 %**，是因为**各自容量上的利润不同**：
   新路径的有效金额只有旧路径的 **18.7 % ~ 21.2 %**，
   而同金额的利润一样 ⇒ 跌幅**由容量包络收缩带来**。
3. **收益率（利润 ÷ 容量）跌 11.4 % ~ 13.2 %**：
   这是「用更小的包络去装同样的单位利润」的算术后果，
   **不是**单位盈利能力变差（同金额利润相等已经证明这一点）。

### 3.4 其余 164 个闭环：**实测零**，**不是缺值**

在 **v15 → v18** 的 168 个共有闭环里，除去上面 4 个，其余 164 个的
**内核判定在两侧完全相同**：

| 内核判定 | 条数（旧） | 条数（新） |
|---|---:|---:|
| `not_profitable`（实测零利润） | **158** | **158** |
| `hop_2_failed:swap_amount_out_unavailable` | 5 | 5 |
| `hop_1_failed:zero_output` | 1 | 1 |
| （无原因 ⇒ 利润为正） | 4 | 4 |

⇒ **164 / 168 个闭环的判定逐条相同**，其中 164 个在两侧都**没有正利润**，
因而**没有相对跌幅**。这些是**实测结果**，按本任务清单的口径
「**测得零 / 负盈亏如实保留为测量结果，不得降级成缺值**」**如实保留**。

### 3.5 容量包络的总体变化（160 个容量变了的闭环）

| 项 | 读数 |
|---|---:|
| 容量**变大** | **51** |
| 容量**变小** | **109** |
| 容量**未变** | 0 |
| 新 ÷ 旧 的**中位数** | **0.4247** |

## 4. 结论（**按验收项逐条**）

| 验收项 | 结论 | 依据 |
|---|---|---|
| **利润等价性**（逐个相等） | **通过**（v18 → v19：**168 / 168 逐个相等**，不等 0） | §3.2 |
| **`profitDrop` 已实测一次** | **通过**（实测值 **82.3943 %**，样本 **4**，测量时点 2026-11-24T06:25:35Z，价格来源 `v4_exchange_pools JOIN v4_exchange_pool_liquidity_snapshots`） | §3.1 / §3.3 |
| **新旧路径的利润来自同一次测量** | **通过**（同一份池状态快照，两条路径共用；`poolsWithState = 52 / 52`） | §1.3 |
| **测得零 / 负盈亏如实保留** | **通过**（164 / 168 个闭环的判定在两侧逐条相同，其中 158 个是实测 `not_profitable`） | §3.4 |
| **结果写入本任务 `docs/`** | **通过**（本文档） | — |

### 4.1 样本量与边界的**如实登记**

1. **`profitDrop` 的样本量只有 4**（168 个受影响闭环里，旧路径有正利润的只有 4 个）。
   **中位数 82.3943 % 是这 4 个上的中位数**，**不得**被表述成「168 个闭环平均跌 82 %」。
2. **v15 → v18 跨越了池层与闭环层两项变更**
   （`directional_pool_version` 0 → 2，闭环方向从 `NULL` 变为显式 0/1）。
   本组读数归因到「**方向化切换整体**」，
   **不能**进一步拆成「池层贡献 x %、闭环层贡献 y %」——**该拆分未测量**。
3. **v15 的方向为 `NULL`**，重放时**回退到路由自身的代币序**。
   这与 v15 运行时当时的做法一致（内核源码 `build_hop_chain`），
   但它意味着 **v15 的方向不是「错的方向」，而是「没有方向」**。
4. **极小容量比**（最小 0.000152）出现在容量变小的闭环尾部，**未单独归因**。

### 4.2 与观察线的关系（**不是门禁**）

`D-012` §4.1 的 **20 %** 是**观察线**，**不是门禁**。
本次实测的 **82.3943 %** **超过**观察线，**如实记录**。
§3.3 给出的是**归因**（容量包络收窄，而非路线算术变差），
**是否接受这一收窄，属于业务口径，本任务不代为裁定**。
