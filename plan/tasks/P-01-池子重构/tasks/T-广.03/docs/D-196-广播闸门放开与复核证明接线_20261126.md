## 0. 触发口径（本轮唯一的用户指令）

> 「**这个可以把它放开了，只要复核有正收益，就应该广播测试了。**」

对照前序口径：「当前的主网系统**不需要额外的授权处理**，只要复核有正向利润空间，就可以广播复核」
「**要么成功，要么失败，没有降级处理**」「**广播与复核线程都工作在 Rust 侧**」「**核心任务：以产生持续稳定套利广播记录为目标，跑通处理流程**」。

⇒ 本轮要做的事只有一件：**把「复核有正收益」变成广播的准入条件**，
并把这条链路从「复核发布」一直接通到「月度库落下记录」。

## 2. 裁定（本轮七条）

| # | 裁定 | 落法 |
|---|---|---|
| **1** | **授权默认放开** | 已有（`broadcast_policy.rs`）；显式 `false` 仍可关闭 |
| **2** | **广播准入 ＝ 复核的正收益裁定** | 复核发布**正收益广播请求**（`request_status = generated`、`runOk`、`runExecutable`、`signedPnl > 0`、**三条**价格限值）⇒ 运行时**读回这份证明**再入队 |
| **3** | **经济性闸门不再否决，改成记录** | 运行时自算的**gas 门槛 / 容量 / 经济下限**对「复核已放行」的路线**只记录**（`payload.broadcastEconomicOverride`），**不拦**；对**没有复核证明**的路线**照旧拦截**（手工执行路径不受影响） |
| **4** | **正确性闸门不放宽** | **三条价格限值**必须齐全才允许广播：v1 只允许「每跳一个 tick 区间」成交，缺限值就会退回全局价格边界 —— 这条**永不放宽** |
| **5** | **证明从库里读回，不二次推导** | 限值只从 `manager_v4_review_broadcast_requests` 读；**运行时绝不自己再算一遍**（否则会有两个真相） |
| **6** | **时效窗口 ＝ 复核侧同一口径** | 请求年龄 **≤ 120 s**（复核侧生成请求用的就是这扇窗口）；未来时间容差 **30 s** |
| **7** | **没有降级** | 读不到证明 / 证明不全 / 请求陈旧 ⇒ **显式拒绝**（`payload.broadcastWake.reason`），**不偷偷直广播**、**不拿旧证明顶替** |

> **第 3 条的口径边界**：经济性阈值被记录而不是被执行，**只对「复核已经放行」的路线成立**。
> 复核自己的正确性裁定（`not_executable`）**仍然有效**——**复核没有放行的路线，运行时根本不会看到它的请求**，
> 因此「要么成功要么失败」在**每一层**都成立：复核判失败 ⇒ 没有请求；请求不完整 ⇒ 显式拒绝。

### 3.3 为什么「经济性闸门」可以只记录不否决

用户口径是「**只要复核有正收益，就应该广播测试**」。复核已经把**链上定价**做完了：
`runArbitrage` 是**对着链上当前状态**跑出来的正收益，三条价格限值是**复核证明过的 tick 区间边界**。
运行时自己那三道经济阈值是**另一层保守估计**（按 gas 折算的利润门槛、容量、经济下限），
它们在「复核已放行」时**只是观测值**：把它们记进载荷，操作者一眼能看到「这条路线本来会被哪道闸门挡下」。
**没有复核证明**的路线（例如手工执行）**照旧**受这三道闸门约束 —— 手工路径的行为**一字未改**。

### 5.1.3 **133** 条 `not_executable` 是什么（**不是**缺陷）

打开失败载荷，内层错误**只有一种**：

```json
{
  "error": "NoProfitableRoute",
  "rawError": "execution reverted",
  "revertSelector": "0x16301234",
  "receivedRaw": "0x3522f87213250",
  "requiredRaw": "0x355574530148a",
  "reportedNetProfitRaw": "-0x327be0ee23a",
  "executable": true
}
```

⇒ **链上套利合约自己回退了**：拿到的币比要的少（`received < required`），利润为负。
`executable = true` 说明**路线本身可执行**，只是**此刻不赚钱**。
这是**市场读数**，不是链路故障 —— 换句话说，**当前市场上没有套利**，系统如实报了出来。

### 5.1.4 那唯一的一条为什么还没广播

它发布于 **2026-11-26T05:56:22Z（13:56 本地）**，而 runtime 换新二进制是 **13:59:28** —— **早了两分钟**。
新二进制里的唤醒逻辑**当时还不存在**，那一条请求因此**没有人读回**。
它也已过了 **120 s** 窗口（现在约 **1000 s**），**不会被重播** —— 这是**对的**：
历史机会不可再现，重播一笔陈旧的正利润是拿旧证据交易。

⇒ **结论：链路是通的，缺的是一条*新鲜*的正收益复核**（新一代复核每轮会重新测；测出正收益且复核放行 ⇒ 发布 ⇒ 读回 ⇒ 入队 ⇒ 广播 ⇒ 月度库落行）。
**守候脚本**：`plan/runtime_evidence/tools/watch_broadcast_chain_20261126.py`（**按行的身份**播报，不再只在 0 → >0 时响一次）。

## 6. 诚实边界（本轮**没有**关掉的东西）

1. **复核自己的正确性门禁仍在**：正收益闭环被 `tick_range_changed` / `expected_amount_crosses_tick` /
   `final_input_exceeds_single_tick_capacity` 挡下时，**复核判它不可执行** ⇒ 不发布广播请求 ⇒ 运行时看不到它。
   这是**复核的判断**，不是广播闸门；本轮**不改复核的判断口径**（改它属于 `T-复核.01` / `M-4` / `M-7` 的范围）。
2. **实盘月度库的第一行取决于市场**：**133 / 136** 条 `not_executable` 的内层错误是 `NoProfitableRoute`
   （链上合约回退，**此刻不赚钱**）—— 这是**市场读数**，不是链路故障。当前这一轮里**没有**新鲜的正收益闭环。
3. **每轮复核读一次请求表**（每闭环一次只读打开）—— 当前表规模 ≤ **174** 行；量大后需要按轮缓存（本轮**不优化**）。
4. **跨月统计、落盘失败兜底**等低概率路径**仍留占位**（按用户口径「先留功能点，最后再实现降级」）。
5. **重启窗口会吞掉一条请求**：请求发布与 runtime 换二进制之间若跨过一次重启，那条请求就**没有人读回**，
   而且**不会**被重播（过了 120 s 窗口）。这是**设计如此**（陈旧机会不可再现），但**操作上**要知道：
   换二进制之后，**要等新一代复核**才有可广播的行。
