# D-198 单 tick 容量上限与每跳金额链

> 触发：`D-197` §2.4 读数「实盘 **3** 条真机会（`profitable_amount_found`）全被 `final_input_exceeds_single_tick_capacity` 挡住」
> 触发：实盘复核读数「`expected_amount_crosses_tick` **5** 行 ／ `tick_range_changed` **2** 行」（`D-197` 之前的代次）
> 归口：`T-广.03`（广播与复核的共同前置）· `M-13`（运行时内核）＋ `M-6`（复核管理器）

## 0. 一句话

> **两个闸门在用错误的量判定一条路由：**
> `F-2` 内核阶梯选额**没有上限**，一路翻倍到单 tick 容量之外 ⇒ 复核必然以
> `final_input_exceeds_single_tick_capacity` 拒绝；
> `F-3` 状态迁移闸门把**锚定本金**当成**每一跳**的输入金额 ⇒ 第二、三跳被自己的锚定价误杀。
> 本轮把两处口径改回物理事实：**阶梯只在已发布容量内搜索**，
> **每一跳用真正到达它的金额计价**。

## 1. 根因（实测，不是推断）

### 1.1 `F-2` 阶梯没有天花板

`flashloan/rs-src/src/execution.rs::official_v4_adaptive_best_amount_single_route_inner`
的金额阶梯**向上翻倍**时，唯一的约束是 `bounded_double(candidate, max_probe_raw)`。
而路由配置里**没有** `maxProbeAmountRaw` ⇒ `max_probe_raw = None` ⇒
`bounded_double` **不设上限** ⇒ 阶梯一路翻倍。

实盘那一跳的账（复核当时的读数）：

| 量 | 值 | 说明 |
|---|---|---|
| 折叠后的单 tick 容量 | `2_030_566_946_888_083` | 复核用 `final_input_exceeds_single_tick_capacity` 守的就是它 |
| 阶梯起点 | `1_015_283_473_444_041` | ＝ 容量的 **一半**（`ladderStartCapacityFraction = 0.5`） |
| 阶梯翻倍后的选择 | `4_061_133_893_776_164` | ＝ 容量的 **2 倍** ❌ |

⇒ 复核在**必然**拒绝这个尺寸。利润随金额增长时，阶梯还会**挑最大的那个**
⇒ 一条真机会被自己的搜索域挡在门外。

### 1.2 `F-3` 两道闸门口径不一致

复核里有两道**同族**的闸门，但它们对「这一跳拿到多少钱」的口径不同：

| 闸门 | 位置 | 每跳的输入金额 |
|---|---|---|
| 单 tick 闸门 | `review_manager/src/single_tick.rs::evaluate_route_single_tick` | **按链传递**：第一跳拿本金，后一跳拿前一跳的产出 ✅ |
| 状态迁移闸门 | `review_manager/src/lib.rs::evaluate_final_state_transition_gate` | **每跳都拿锚定本金** ❌ |

⇒ 第二、三跳的真实输入是**上一跳的产出**（**不同的代币、不同的单位**），
拿锚定本金去判它们 ⇒ 实盘 **5** 行被 `expected_amount_crosses_tick` 误杀。

## 2. 落地

### 2.1 `F-2` 内核：阶梯搜索的上限（`M-13`）

新增 `flashloan/rs-src/src/execution.rs:2818`：

```rust
fn derive_search_ceiling(
    capacity_limit_raw: &BigUint,
    max_probe_raw: Option<&BigUint>,
) -> BigUint
```

| 规则 | 裁定 |
|---|---|
| 上限是什么 | **已发布的容量**（`single_tick_capacity_raw`）—— 复核守的就是它 |
| 通用 `maxProbeAmountRaw` | 只能**收窄**上限，**不能放宽**（`min(容量, 探针上限)`） |
| 容量缺失 | 走既有的「容量未发布 ⇒ 阻塞」路径，**不改** |
| 跨 tick 搜索 | 它自己发布容量作为搜索覆盖 ⇒ **上限不变**，语义不受影响 |

阶梯的 **5 处**翻倍点全部改用这个上限
（`execution.rs:3414 / 3452 / 3459 / 3522 / 3555`），
载荷新增两个字段（**4** 个分支：预检失败 / 不盈利 / 找到盈利额 / 内层单次调用）：

```json
"searchCeilingRaw": "0x...",
"searchCeilingBasis": "folded_single_tick_capacity"
```

⇒ 阶梯**停在容量处**，选出的尺寸**一定** ≤ 容量 ⇒ 复核的容量门禁**必然放行**。

### 2.2 `F-3` 复核：每跳金额链（`M-6`）

`flashloan/tools/review_manager/src/lib.rs`：

| 改动 | 说明 |
|---|---|
| `HopAmount`（`lib.rs:2586`） | 一跳的三个量：`amount_in_raw`（到达这一跳的钱）、`expected_capacity_raw`（期望态下的精确单 tick 上界）、`amount_out_raw`（这一跳的产出） |
| `HopAmountFailure`（`lib.rs:2598`） | `CrossesTick` ／ `Unpriceable`（**失败即失败，无降级**） |
| `hop_expected_amount()`（`lib.rs:2612`） | 用**期望态**给「到达这一跳的金额」定价，产出「下一跳收到的金额」 |
| `evaluate_final_state_transition_gate`（`lib.rs:2467`） | 改为「**先解析每一跳的状态**（current / expected / tick_spacing，理由码不变）→ **再按链计价**」 |
| `HopTransitionVerdict.amount_in_raw`（`state_transition_gate.rs:84`） | 每一跳的裁决**带上它收到的金额** |
| `transition_hop_payload`（`lib.rs:3528`） | 诊断载荷新增 `"amountInRaw"` |

**口径**：理由码**一字未改**（`expected_amount_crosses_tick` / `expected_quote_unavailable` /
`expected_pool_state_unavailable` / `tick_spacing_changed`），改的只是**被比较的那个金额**。

**★ 两次启动失败的根因（如实登记）**：前两次启动（pid **18768** ／ **12740**）都以 `exit_code = 1` 退出，
stderr 写的是 `port 5000 could not be recycled and the next 200 ports are still occupied`。
根因**不是**本轮改动：`xray.exe`（pid **3452**）对 `[fc00::1]:5000` 保持着一条 **ESTABLISHED** 的**出站**连接
⇒ 运行时停下后该套接字仍在 ⇒ `0.0.0.0:5000` 绑不上；
而运行时随后扫描的 **5001…5200** 又被本机的**临时出站套接字**占满
（本机 **28,806** 条 ESTABLISHED；实测 `5001…5011` 绑定返回 `WinError 10013`）
⇒ 「下一个可用端口」这条退路**也**走不通。
等那条连接被回收后 **5000** 立即可绑，第三次启动（pid **24860**）成功。

> **教训（如实登记）**：`_port_in_use` 用「能否 bind `0.0.0.0:<port>`」判断占用，
> 它把 **Windows 保留端口** 与 **出站连接的临时端口**一并算成「占用」；
> 在这台机器上，**扫描窗口 200 个端口**不足以穿过临时端口的密集区。
> 本轮**不改**这段逻辑（属 `T-复编.02` 的运行期问题，且**不影响**正确性），留档待专案处理。
