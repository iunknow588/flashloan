# D-197 复核确认池与广播用池对齐

> 触发：用户口径「**闭环本身是固定的，涉及到的三跳代币也是固定的……三个池子的选择是在复核的时候确定的……复核本身就同步确认了池子地址。后续广播进程使用的是这个复核时候确认的池子。**」
> 触发：「**闭环里面可以装候选池子，后续当池子变动的时候，主池子不能套利的时候，可以考虑自己计算下候选池子是否可以继续套利。**」
> 触发：「**复核通过的闭环数据同步确认对应的池子数据，这个时候，选择的池子和主推荐池子是一致的……这条规则可以临时起个作用，就是主池子就是套利池子。**」

## 0. 一句话

> **复核确认的就是它定价的那三个池，广播用的就是复核确认的那三个池。**
> 之前两处都指向**目录里的池**（闭环的主推荐池），而复核实际定价的可能是**候选池**
> ⇒ 闸门按主池找期望状态、路由却走了备池 ⇒ `expected_pool_state_unavailable` ⇒ 一笔也发不出去。
> 本轮把「确认池」从**目录池**改成**定价池**，并加一道**临时守卫**：
> 确认池必须落在该跳的**选项集**（主池 ∪ 候选池）之内，越界即失败。

## 1. 三条口径 ⇒ 三条裁定

| 口径 | 裁定 | 落点 |
|---|---|---|
| 复核**同步确认**池地址；广播用复核确认的池 | 复核行 `pool_ids_json` ＝ **复核确认的方向池 id**；广播请求 `pool_ids_json` ＝ 同一份；广播侧再**逐跳核对**路由实际选中的池 | `review_manager/src/lib.rs`（`confirmed_directional_pools`）＋ `rs-src/src/worker_pool.rs`（`route_trades_the_confirmed_pools`） |
| 闭环可以装**候选池**；主池不能套利时可算候选 | 复核**允许**确认候选池，并写 `CandidateSubstitution` 诊断（主池没成交、候选成交了） | `review_manager/src/lib.rs`（`insert_candidate_substitution_diagnostic`） |
| **临时**规则：主池 ＝ 套利池（后续算法可能让选择不同于主推荐池，那时可能要换主推荐池） | 守卫落在**选项集**上：确认池 ∈ 该跳(主池 ∪ 候选池)。**主池 ＝ 套利池**这条更强的规则**留作后续任务**，因为它会随算法变化而失效 | `review_manager/src/lib.rs`（`hop_option_base_pools`）＋ §5 后续任务 |

## 3. 落地

### 3.1 复核侧（`flashloan/tools/review_manager/src/lib.rs` · `M-6`）

| 改动 | 说明 |
|---|---|
| `read_base_pools_of_directional_pools()` | **不再**按闭环目录过滤，读**整条方向层** ⇒ 复核可能选到的备池也在池状态里 |
| `review_time_pool_ids()` | 从 `quote.candidate_pools[].poolId` 读出**复核定价用的池**（按跳序） |
| `confirmed_hop_directional_pool()` | 确认池 ＝ **该跳选项集**里「base 池匹配 ＋ 方向匹配」的那个**方向池 id**。**从闭环自己的列表取**，不做全局搜索 —— 同一基础池在 `core4` 与 `candidate_exchange` 两个 scope 都存在（**168** 个），全局搜索会指错 scope |
| `confirmed_directional_pools()` | 逐跳确认；**链与报价的跳数不等**（某跳被跳过）⇒ 确认失败 |
| `confirmed_pool_path_key()` | 复核行的 `pool_path_key` ＝ `loop_key` ＋ 确认池（原来用目录的 `pool_path_key`） |
| 闸门链改用**报价池** | 单 tick 闸门与状态迁移闸门都按**复核定价的池**建链 ⇒ 修掉「路由走备池、闸门按主池找期望状态」的 `expected_pool_state_unavailable` |
| **守卫：确认池 ∈ 选项集** | 越界 ⇒ `not_executable` ＋ `pool_not_in_loop_options:hop_{i}:{pool}`；选项集为空 ⇒ `not_executable` ＋ `loop_options_unavailable:hop_{i}` |
| **诊断：`CandidateSubstitution`** | 定价走的是候选池 ⇒ 写诊断（主池没成交、候选成交了） |
| **守卫：阶梯没量过** | `bestAmountMeasured != true` 或 `probeCount == 0` ⇒ `data_incomplete` ＋ `ladder_not_measured:{status}`，**不得成为 `completed`**，不得生成广播请求 |
| 复核行 `pool_ids` | ＝ **确认的方向池 id**（原来 ＝ 目录的主池） |
| 广播请求 `pool_ids` | ＝ **同一份确认池**；且**必须三个**，否则写明原因、不生成请求 |

### 3.2 广播侧（`flashloan/rs-src/src/worker_pool.rs` · `M-13`）

`wake_broadcast_with_review_proof()` 在写载荷**之前**多一道核对：

| 读数 | 行为 |
|---|---|
| 载荷没有 `selectedRoutePayload.selectedKeys` | 不入队，`reason = "the reviewed route names no selected pools"` |
| 路由选中的池 ≠ 复核确认的池（**base 池 + 方向**逐跳比） | 不入队，`reason = "the route no longer trades the pools the review confirmed"` |

路由池 id 由**池键**现算（`pool_index::pool_id`），与方向层存的 `base_pool_id` **同源** ⇒ 两边可比。

### 3.3 「选项集为空」为什么不再放行

守卫初版是「选项集为空 ⇒ 不拦」（fail-open）。实测 §2.1 证明实盘 **522/522** 跳都有选项集，
所以这条退路**没有任何实盘价值**，只会给「复核确认了一个目录里没有的池」留下后门。
按「**要么成功，要么失败，没有降级处理**」⇒ 改成 fail-closed（`loop_options_unavailable:hop_{i}`）。

### 6.3 回归中发现并修掉的**两个真问题**

| # | 问题 | 症状 | 修法 |
|---|---|---|---|
| 1 | **方向池 id 的基础池段取错** | `worker_pool.rs::directional_pool_identity` 用 `rsplit_once(':')` 取「最后一段之前」当基础池 ⇒ 拿到的是 `dpool:v1:<net>:<chain>:<scope>:<base>` **整串**，与路由现算的池 id 永远不等 ⇒ **所有**正收益复核都被判成「路由不再交易复核确认的池」⇒ 一笔也发不出去 | 方向池 id 的形状是 `dpool:v1:<network>:<chain>:<scope>:<base pool>:<direction>` ⇒ 基础池是**倒数第二段**；改为 `prefix.rsplit(':').next()` |
| 2 | **测试夹具的池键顺序非法** | V4 的池键要求 `currency0 < currency1` ⇒ 夹具第三跳的 `currency0 = 0x3333… > currency1 = 0x1111…` ⇒ 池 id 算不出来 ⇒ 三个广播用例**一起**panic | 第三跳的键改成 `currency0 = 0x1111…` / `currency1 = 0x3333…`，方向随之改为 `zeroForOne = false`（方向池 id 末段 `0`） |

两个问题都是**本轮自己引入**的，且**都是上线前被回归抓住**的 —— 记在这里，因为它们**改变了
「确认池」这个概念的落法**：方向池 id 的**段位**是这套设计的地基，段位取错则整条确认链**静默失效**。

## 7. 诚实边界

- 本轮**未改**内核阶梯选额（**F-2**）⇒ 实盘那 **3** 条真机会**仍**会被单 tick 容量闸门挡住 ⇒ 广播记录**能否持续产生**仍取决于该缺口。
- 本轮**未改**闭环主推荐池的更换口径（**F-1**）⇒ 「主池 ＝ 套利池」这条**临时**规则仍成立，只是**放宽**到了「主池 ∪ 候选池」。
- 「候选顶替」只写**诊断**，**没有**任何机制把顶替结果**回写**进闭环目录 ⇒ 下一轮复核若仍选中同一备池，顶替会**反复**出现；这正是 **F-1** 要解决的。
