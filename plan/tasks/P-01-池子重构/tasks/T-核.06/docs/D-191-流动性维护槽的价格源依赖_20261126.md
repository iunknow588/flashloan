## 1. 一句话

流动性维护槽的**关键路径上挂着一个外部价格源**；
部署网络只放行链上 RPC 与 `api.gateio.ws`，**其余 11 个价格源全部超时**；
而失败的价格抓取**按池重试** ⇒ 槽从「整槽报错」退化成「**卡住不报错**」。

---

## 2. 链路

```
v4-maintenance-v4_pool_liquidity_worker  (Python 线程, 间隔 900 s)
  └─ run_pool_liquidity_tick
      └─ _run_pool_liquidity_tick_locked
          ├─ refresh_v4_live(...)                    ← 遗留 Python 测量段
          │    └─ v4_pool_index._liquidity_reserve_metrics(pool, state)   ← 每池一次
          │         └─ eth_price_usd()               ← 外部价格源（阻塞点）
          └─ _materialize_pool_liquidity_snapshots(...)  ← 快照表唯一写者（Rust 池管理器）
```

**顺序问题**：Python 段在 Rust 段**之前**。
价格抓取不通 ⇒ **Rust 那一段根本没机会执行** ⇒ 快照表停更。

---

## 3. 为什么是「卡住」而不是「失败」

`flashloan/src/dex/intent_trade/chains/robinhood/v4_pool_index.py`：

```python
# 失败时把缓存清空
ETH_PRICE_CACHE.update({"price": None, "source": None, "observedAt": None})
```

下一个池子再调 `eth_price_usd()` 时 `price is None` ⇒ **重抓全部源**。
每源 `_fetch_json(url)` 超时 **10 s** ⇒ 一轮 **≈ 30 s**；
本轮实测 **363 池** ⇒ **≈ 3 h** 才走完一个 tick。

⇒ 观测形态：**槽的 `refreshed_at` 停在旧值，既不前进也不报错。**
这比 `T-核.05` 的整槽 `error` 更难定位：`error` 至少会说出一条原因。

## 4. 修法（三条，都不是降级）

### 4.1 加一个**可达**的源

```python
ETH_PRICE_SOURCES = (
    ("gateio", "https://api.gateio.ws/api/v4/spot/tickers?currency_pair=ETH_USDT"),
    ("binance_us", ...),   # 后备
    ("kraken", ...),       # 后备
    ("coingecko", ...),    # 后备
)
```

解析只认 `currency_pair` ∈ {`ETH_USDT`, `ETH_USDC`} 的行，取 `last`；
列表里的别的交易对**不会被当成 ETH**。

**口径**：Gate.io 报价 **ETH/USDT**，携带 **USDT/USD 基差**；
`ETH_USD_PRICE_MIN/MAX`（默认 **500 / 20000**）继续作为带外拒绝闸门。

### 4.2 失败**冷却**（把「卡死」换成「失败一次」）

```python
ETH_PRICE_RETRY_COOLDOWN_SECONDS = 60   # 可配
```

一次失败被记住；冷却窗内的后续调用**直接返回这次失败**，不再抓。
⇒ 一个 tick 的代价从 **3 h** 降到 **30 s**，而且**槽会真的失败**（符合
「**要么成功，要么失败，没有降级处理**」）。

### 4.3 陈旧读数**自我刷新**

命中缓存时**额外校验 `_price_is_fresh()`**：
读数过了 `ETH_PRICE_MAX_AGE_SECONDS`（默认 **900 s**）就重抓，
不再把陈旧读数递出去 ⇒ **USD 估值列不再永久为空**。
