## 1. 缺陷（**生产在产 · 只读实测已复现**）

「**每个复核都有明确的盈亏数值**」在**已覆盖**的闭环上**已经成立**；真正没解决的是**覆盖**与**统计口径**。

| 读数（2026-11-28 14:1x · 生产库只读 ＋ 审计流对照） | 值 |
|---|---|
| `manager_v4_reviews` 总行 | **176**（`not_executable` **157** ＋ `data_incomplete` **19**） |
| 复核状态分布 | `not_executable` **157**（**全部有明确盈亏数值**，`missing_value = 0`）＋ `data_incomplete` **19**（其中 **17** 条缺明确盈亏） |
| `data_incomplete` 的成因 | 「`signed PnL is missing or incomplete`」**14** ＋ 「`not_reviewed_since:<时刻>`」**5** |
| `not_executable` 的成因 | 「`runArbitrage returned ok=false`」**135** ＋ 「`executable=false`」**15** ＋ 「`loop_options_unavailable:hop_0/1`」**6** ＋ 其他 **1** |
| **`completed` 行** | **0** ⇒ 广播门禁（新鲜的、明确盈利的复核）**永不可能放行** |
| 当前代次覆盖（`closed_loop_version = 73`） | active 闭环 **48**，本代次复核行 **29** ⇒ 覆盖 **29 / 48**，**缺 19** |
| 审计流对照（`audit_review_coverage_vs_audit_stream_20261128.py`） | 审计流 **46780** 行 / **180** 个闭环；`nullPnl = 0`、`positivePnl = 0`、`measuredForThisGenerationButNoRow = 0`；缺行 **19** 条中 **18** 条**今天测过**（`missingRowButAuditedToday = 18`、`missingRowNeverAudited = 0`） |
| 缺行 19 条的**审计代次** | **53**（8 条）／**54**（3 条）／**72**（7 条）⇒ 测的是**旧代次**，不是「没测」 |
| 主库里的复核 `CHECK` 约束 | 现役只允许 `completed` / `not_executable` / `data_incomplete` ⇒ **容不下** `retired` ⇒ 退役语义**写不进去** |
| 编排窗口口径 | `missingValue` 与「已离开目录」**混计** ⇒ 统计在**说谎**（今天 `data_incomplete_count = 19` **全部**是已退役行） |

**★ 结论（与前几轮的归因不同，按实测改写）**：

* 「复核没有明确盈亏」**已经不是问题**：已覆盖的 **157** 条 `not_executable` **全部**带**实测**盈亏数值（`missing_value = 0`），`nullPnl = 0`。
* 真正的问题是**覆盖**：当前代次只覆盖 **29 / 48**；缺的 **19** 条**不是没测**（审计流今天有 **18** 条记录、`measuredForThisGenerationButNoRow = 0`）⇒ 缺陷在「**测了但没落到当前代次的权威行**」这条**发布口径**上。
* 这 **19** 条**已不在当前目录**（管理器的 active 闭环里没有它们）⇒ 正确处置是**退役**（`retired` ＋ 原因），**不是**补数、**不是**继续算作「缺值」。

## 2. 缺陷链（**代码落点**）

| # | 位置 | 事实 |
|---|---|---|
| 1 | `flashloan/tools/review_manager/`（`records.rs` 文件头规则） | ① JSONL 流**不参与任何判定**，主库是当前代次**唯一权威**；② 月度库先写、主库行后瘦身；③ 签名盈亏**原样保留** |
| 2 | `manager_v4_reviews.review_status` 的 `CHECK` 约束 | 只允许三种状态 ⇒ `retired` **写不进去** ⇒ 退役语义**只能停留在文档里** |

| 4 | 编排层 PnL 窗口统计 | `missingValue` 与「已退役」**同计** ⇒ 「每个复核都有明确盈亏」的读数**被退役行污染** |
| 5 | 复核链上执行（`runArbitrage`） | **135** 条 `not_executable` 的成因是 `runArbitrage returned ok=false` ⇒ `completed` **0** 行 ⇒ 广播门禁**无输入** |

## 3. 目标状态（**可验收**）

1. **每个复核都有明确盈亏**：在产目录的每条闭环都有本代次复核行，**且**每行都有**实测**盈亏数值（`missing = 0`、`unconfirmed = 0`）。
2. **退役与缺值分开**：已离开目录的行 ＝ `retired` ＋ 原因（**不删行**、**不填数**、**不碰门禁**）；库统计 `retired_count` 与 `data_incomplete_count` **分开**。
3. **窗口口径分离**：编排窗口把 `missingValue` 与 `retiredReviews` **分开计数**；**在产目录**的判据**一字不改**。
4. **`ok=false` 有根因**：**135** 条 `runArbitrage ok=false` 归到**具体**链上原因（不是「失败」两个字）。
5. **可观测**：代次覆盖率（`29 / 48` → 目标 **48 / 48**）与审计流对照读数进报告。

## 4. 步骤（**每步都有退出条件**）

| 步 | 做什么 | 退出条件 |
|---|---|---|
| **S1 取证** | 把 **19** 条缺行逐条列出：当前代次、审计流代次、`data_incomplete` 成因、是否在 active 目录里 | 得到**逐条归因表**；「测了但没写进本代次」**条数**明确（不得写「未知」） |
| **S2 迁移 022** | `20261128_022_review_retirement_schema`：放宽 `review_status` 的 `CHECK` 以容纳 `retired` | 迁移**可应用** ＋ **可回滚**；生产库停在 **021** ⇒ 新旧**不可混用**（部署闸门） |
| **S3 退役判定** | `stored` 里**不在当前目录**的复核行 ⇒ 写 `review_status = 'retired'` ＋ `review_reason = 'closed_loop_left_catalog:<版本>'`，并**撤下**该闭环的广播请求 | 退役行**条数 ＝ 19**（或其它实测条数）；**不删**任何行；**不填**任何数 |
| **S4 统计分离** | `data_incomplete_count` 与 `retired_count` **分开**；管理器 API 与编排窗口**同口径** | 退役行**不再**计入 `missingValue`；两个口径**都能单独读出** |
| **S5 覆盖补齐** | 让在产目录的**每条**闭环都拿到本代次复核行（先解决「测了但没落本代次行」那条发布口径） | 代次覆盖 **29 / 48 → 48 / 48**；`measuredForThisGenerationButNoRow` 保持 **0** |
| **S6 `ok=false` 根因** | 把 **135** 条 `runArbitrage ok=false` 逐条归到**具体**链上原因（容量 / 定价 / 路由 / RPC） | 每条**归到一个原因**；无法归因的**数量明确列出**（不得含糊） |
| **S7 回归与实盘** | 只跑 `M-6` ＋ `M-10` 测试；生产读数 | 回归 **0 failed**；窗口 `missingValue` **19 → 0**；在产目录 **48 / 48** 仍**全有**明确盈亏，`positive` 读数**不变** |

## 6. 诚实边界

* 本任务**不伪造任何盈亏**：退役行**不填数**、**不填 0**；「每个复核都有明确盈亏」只对**在产目录**成立，目录外用**退役语义**表达，**不是**「补上数值」。
* 本任务**不删**任何复核行、**不改**任何历史代次、**不放宽**任何门禁。
* 本任务**不预判**市场：`ok=false` 的根因**可能**最终归到「链上确实不盈利」⇒ 那是**业务结论**，**不是**缺陷。
* 本任务**不代其它任务关闭**：常驻 worker 覆盖属 `T-核.09`（当前代次覆盖 **29 / 48** 的**前置**）；广播门禁与月度库属 `T-广储.01`。
