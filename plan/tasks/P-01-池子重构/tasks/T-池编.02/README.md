## 一句话

> **加载模式可以变窄「加载到内存的池子」，但绝不能让作用域「丢掉池子」。**
> 上一轮的缺陷正是把这两件事混成了一件：healer 硬编码 `core` 写进生产作用域，
> 重建时**删掉了股票池**（`deletedRows=14`）—— 池**从未离开主池表**，
> 缺的是**作用域的物化范围**，那 19 条股票路由因此变成不可定价。

## 第二轮（同任务续）

> 「**预期盈利全部是负数时，请一并检测最佳交易量（tick计算值），是否大于初始交易量（单tick计算值）**」
> —— 读数与结论见 [`docs/D-243`](docs/D-243-全负期望下的tick交易量比对与复核代次缺陷_20261128.md)。
> 一句话：**29 / 29 条当前代次复核的最佳交易量都没有超过单 tick 初始交易量**，
> 且**可执行域已被阶梯覆盖** ⇒ 负值是**测出来的**，不是缺口。
> 但同一条读数链上查出**真正的缺陷**：复核层的「当前」口径**只按 loop key 匹配**，
> 于是 **7 条陈旧代次**的复核被当成在产复核，复核层**误报绿**——
> 那些路由**从未对当前池集测过价**。修复后复核层**如实报红**并指名原因。
> **在产首周期**（自愈器按新代码重启）：动作 `repair_stale_generation_reviews` **已触发**，
> `evidenceCount = 0`、`materialization = null` ⇒ **没有任何盈亏被写回**；
> tick 比对 `compared = 33`、**最佳交易量大于单 tick 初始交易量 = 0** ⇒ **答案仍是「否」**；
> 剩下的 3 条陈旧代次闭环仍卡在运行时（**409 忙 / 404 未注册 / 超时**）⇒ **需要运行时重新注册常驻 worker**。
