## 2. 范围边界（**越界即缺陷**）

| 允许 | 禁止 |
|---|---|
| 让**默认加载模式**按作用域自身声明取值 | 把默认改成**另一个常量**（那只是把缺陷搬个地方） |
| 让审计判定从**精确相等**改成「**声明 ⊆ 已配置**」 | 把审计的判定改成**永真**（那会让缺库的作用域永远不被发现） |
| 让 healer **按审计声明的模式**请求重建 | 让 healer **自带**一份模式（那正是缺陷的来源） |
| 给 healer 加**收窄守卫**（请求模式会掉库就跳过） | 用「收窄守卫」掩盖**缺库**（守卫只挡收窄，不挡缺库） |
| 恢复生产作用域到**声明模式**并重建级联 | 手工**直接改** `pool_scope_config` 表（口径只走 manager 接口） |
| 跟随新默认值修正**断言旧默认值**的测试 | **放宽**断言（少断言、改成永真） |

## 3. 「**没有降级处理**」在本任务里的具体含义

1. **加载模式只有一个来源**：作用域的**声明**（`scope_definition().library_keys`）。
   默认值、审计判据、healer 请求的模式，三者**必须**由它推导，不得各写一份。
2. **默认永不窄于声明**：默认可以**更宽**（运维显式加宽是允许的），
   但**更窄**就是缺陷 —— 一次重建就会删掉池，且池不会自己回来。
3. **宽于声明不算 stale**：运维加宽的作用域**持有**声明要求的全部池，是**完整**的。
   把「更宽」判成 stale，会驱动 healer 去**收窄**，那正是本次事故的机制。
4. **收窄守卫只挡收窄**：缺库的现象要**加宽**修复，不能因为守卫而被跳过。
5. **审计不写任何盈亏数值**，不动任何门禁，不删任何历史行。
