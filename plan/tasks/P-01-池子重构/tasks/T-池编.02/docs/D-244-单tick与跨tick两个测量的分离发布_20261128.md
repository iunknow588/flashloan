## 1. 用户口径（本轮）

> 「**单tick 如果不盈利，应该单独列出来，因为单tick 不盈利，也不需要计算跨tick 了，这个应该从单独列出来，把跨tick 最佳交易量写成单tick 就可以，就可以判断出来是单tick没有盈利了。**」
>
> 「**不单独归类也可以，通过 最佳交易量（tick 计算值） 初始交易量（单 tick） 比较，可以看出是否是单tick不盈利，无需单独考虑，但是统计的时候，要统计出来。**」

两条口径合起来是**一句话**：**单 tick 与跨 tick 是两个测量**；单 tick 不盈利时内核**根本不启动**跨 tick，
所以「跨 tick 最佳交易量」这一格写的就是**单 tick 的值**；比较照做，**但统计必须把它数出来**。

## 2. 内核事实（**只读取证**）

### 2.1 跨 tick 的启动条件（`flashloan/rs-src/src/cross_tick_init.rs`）

| 读数 | 值 |
|---|---|
| 跨 tick 的种子 | **单 tick 最优金额**（`basis = single_tick_best_amount`） |
| 单 tick 最优金额为 **0** 时 | **绝不启动**跨 tick（`CrossTickDecision::NotStarted { reason: "single_tick_best_amount_zero" }`） |
| 其它不启动原因 | `cross_tick_inputs_unavailable` ／ `single_tick_best_amount_exceeds_cross_tick_capacity` ／ `single_tick_profit_above_threshold` |

⇒ **「跨 tick 最佳交易量 < 单 tick 交易量」在结构上不可能**：跨 tick 的种子**就是**单 tick 最优金额，
且单 tick 为零时**没有**跨 tick 结果。

### 2.2 内核**已经**发布、但被复核发布层**丢掉**的字段

`flashloan/rs-src/src/execution.rs`（`cross_tick_initialization()` / `cross_tick_review_with_search()`）：

| 字段 | 含义 |
|---|---|
| `crossTickReview.started` / `.reason` | 跨 tick 是否启动 ／ 为什么没启动 |
| `crossTickReview.seedAmountRaw` / `.capacityRaw` | 跨 tick 的种子与上限 |
| `singleTickBestAmountRaw` / `singleTickBestProfitRaw` | 单 tick 的最优金额与最优盈亏 |
| `crossTickReview.search` | 跨 tick **真正跑过**时的搜索结果 |

**但是**：生产复核行的 `static_preview` 与 `run_arbitrage` 里**既没有** `crossTickReview`，**也没有**
`singleTickBestAmountRaw` ⇒ **信息在复核发布链上被丢弃**（读数见 §3.2）。

## 3. 缺陷（两处）

### 3.1 `M-13`｜发布层不发布两个搜索的结果

`review_publish.rs::best_amount_calculation()` 只发布**单 tick** 的阶梯与最佳金额，
跨 tick 的判定（`crossTickReview`）与单 tick 的最优金额（`singleTickBestAmountRaw`）**都没有进入复核**。
⇒ 读者**无法区分**下面两种完全不同的情形：

| 情形 | 事实 | 读者看到的 |
|---|---|---|
| 跨 tick 跑了，但没赚到 | 单 tick 赚到了，跨 tick 域内无尺寸盈利 | 只有「最佳金额 ＝ 单 tick 的值」 |
| **单 tick 就没赚到** | 跨 tick **根本没跑**（`single_tick_best_amount_zero`） | 只有「最佳金额 ＝ 单 tick 的值」 |

### 3.2 `M-8`｜实测零被当成「金额」去比较（**上一轮 headline 的错误**）

`D-243` 的 headline「**最佳交易量（tick 计算值）> 初始交易量（单 tick）= 0 / 33 ⇒ 否**」**是无效比较**：

| 读数（生产库，只读） | 值 |
|---|---|
| `bestAmountRaw` | **全为 `0x0`** |
| `bestAmountSelectionBasis` | **全为 `native_rust_ladder_no_profitable_size_measured`** |
| `bestAmountZeroReason` | 「the amount ladder measured N size(s) and **none of them was profitable**」 |
| `probeCount` | **6 – 16** 级，**每一级 `profitable = false`** |
| `initialAmountRaw` | **全为正** |

⇒ `0x0` 是**实测零**（「阶梯量过了 N 个尺寸，**没有一个**赚钱」），**不是**「最佳交易量 ＝ 0」。
拿它和初始量比大小，得到的「否」**回答不了任何问题**；而真正的事实是：**单 tick 不盈利 ⇒ 跨 tick 从未启动**。

| 字段 | 含义 |

| `singleTickProfitable` | 单 tick 是否赚到 |
| `crossTickStarted` / `crossTickReason` | 跨 tick 是否启动 ／ 原因（`single_tick_best_amount_zero` 等） |

| `crossTickBestAmountBasis` | `single_tick_best_amount` ／ `cross_tick_search`（**说清这一格是哪一个搜索的数**） |
| `crossTickStatus` / `crossTickSearch` / `crossTickReview` / `searchMode` | 跨 tick 的状态、搜索摘要、判定与搜索模式 |

### 4.2 `M-8`｜自愈器：比较照做，单 tick 不盈利**单独计数**（`scripts/mainnet_arbitrage_healer.py`）

| 落点 | 内容 |
|---|---|
| `_single_tick_paid()` | 单 tick 是否赚到：**发布字段** → **选择基线**（`native_rust_ladder_*`）→ **探针记录** → `bestAmountMeasured`；**读不到 ＝ `None`（不猜）** |
| `tick_amount_comparison()` | 比较对象＝**跨 tick 最佳交易量**（跨 tick 没启动时**就是单 tick 的值**）；单 tick 不盈利 ⇒ **不比较**（`bestGreaterThanInitial = null`、`applicable = false`）、`verdict = single_tick_unprofitable_cross_tick_not_started`；逐行发布 `singleTickProfitable` / `singleTickUnprofitable` / `crossTickStarted` / `crossTickReason` / `crossTickBestAmountRaw` / `crossTickBestAmountBasis` |
| `audit_reviews()` 的 `tickAmount` 区块 | 新增 **`singleTickUnprofitable`**（单 tick 不盈利的条数）、**`crossTickNotStarted`**、`inspected`；`compared` 改为**真正比较过的条数**；`unknown` 只算「既不是单 tick 不盈利、又读不到数」的 |
| `pnl_snapshot()` | 同步新增 `inspected` / `singleTickUnprofitable` / `crossTickNotStarted`；日志行新增 `tickSingleUnprofitable=` |

**五态结论**（`verdict`）：

| 结论 | 含义 |
|---|---|
| **`single_tick_unprofitable_cross_tick_not_started`** | **单 tick 不盈利 ⇒ 跨 tick 从未启动**（内核规则）⇒ **不比较、不做后续计算** |
| `best_above_single_tick_start` | 最佳交易量 **>** 单 tick 初始交易量 —— 用户问题的**肯定**答案 |
| `best_not_above_start_executable_domain_covered` | 不大于，且可执行域已被阶梯覆盖 —— 负值是**测出来的** |
| `best_not_above_start_and_executable_size_unsearched` | 不大于，且有可执行尺寸没被搜过 ⇒ **缺口** ⇒ 触发重测 |
| `tick_amount_unknown` / `best_not_above_start_executable_domain_unknown` | 读不到 ⇒ **不猜** |

> **读法**：跨 tick 的结果若为 `0x0` 且 `crossTickBestAmountBasis = cross_tick_search`，
> 那说的是**跨 tick 域内没有尺寸盈利**（单 tick 是赚到的）；
> 若 `crossTickBestAmountBasis = single_tick_best_amount`，那说的是**单 tick 就没有尺寸盈利**。

## 5. 常驻 worker 的真实语义（**回答用户的问题**）

> 「**为什么需要常驻 worker 注册入口？常驻线程应该是固定启动，永不退出的吧？**」

| 问题 | 实测事实（只读） |
|---|---|
| 一个组有几条线程？ | **一个 group 一条**（`worker_pool.rs::spawn_group_worker`，**按需 spawn**，请求结束**不销毁**） |
| 线程会永不退出了吗？ | **不会**：**空闲 ≥ 60 s** 且该 group **没有 stored command** 时线程**退出**（`worker_idle_exits` 计数，`worker_pool.rs:6165-6245`） |
| 组的全集是谁决定的？ | 每轮扫描用「扫描载荷 ∪ manager 闭环目录」**重建** group 全集（`dex_opportunity_scanner_rust_mixin.py:620-760`）；请求的 group 不在全集 ⇒ `closed_loop_group_not_found`（**404**） |
| worker 预算是多少？ | `CLOSED_LOOP_WORKER_DEFAULT = 16`、`CLOSED_LOOP_WORKER_CEILING = 32`（Python）／**256**（Rust） |
| 「注册入口」的用途 | **按当前路由补一条常驻线程**（让该 group 在下一次请求前就在跑），**不是**「每次请求都要注册」；请求本身**自带** group 与路由 |
| manager 读失败的副作用 | `_native_manager_closed_loop_route_payload` 在 manager 读失败或 `dataSource != rust_runtime_core` 时返回 `None` ⇒ **读失败被误报成 404** |

⇒ **注册入口是「预热当前路由」的入口**，不是「常驻线程的生命周期管理」；
线程是**按需存在**的：路由不在当前 group 全集里 ⇒ 404；组忙 ⇒ 409。
