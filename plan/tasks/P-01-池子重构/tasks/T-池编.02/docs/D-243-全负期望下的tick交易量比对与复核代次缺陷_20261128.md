## 1. 用户口径（本轮的新任务）

> 「**预期盈利全部是负数时，请一并检测最佳交易量（tick计算值），是否大于初始交易量（单tick计算值）**」

### 1.1 为什么这个问题必须单独问

内核用**两次搜索**给一条路由定价：

| 搜索 | 起点 | 搜索域 | 门 |
|---|---|---|---|
| **单 tick** | 单 tick 容量产出的金额（**单 tick 初始交易量**） | 折叠后的**单 tick 容量** | Review Manager 的最终输入门 |
| **跨 tick** | 单 tick 最优点 | 折叠后的**深度容量** | 只在单 tick 找到正收益时才会启动 |

⇒ **预期盈利为负**这件事只是「**被搜过的那些尺寸**都不赚钱」，它**不回答**
「**tick 算出来的最佳交易量有没有超过单 tick 初始交易量**」。
这两件事必须**分开报**，否则一个负数会被当成「已经证明不赚钱」。

### 1.2 结论（**先说结果**）

| # | 结论 | 依据 |
|---|---|---|
| 1 | **最佳交易量（tick 计算值）没有一条大于单 tick 初始交易量**：当前代次复核 **29 / 29** 全为 `best ≤ initial`（`bestAmount` 全是实测零 `0x0`，`initialAmountRaw` 全为正） | §2.1 |
| 2 | **可执行域已被覆盖**：阶梯上行可达 ＝ `min(2×initial, 单tick上限)`，缺口 `> 1`（一个 raw 单位）的条数 **0** ⇒ 结论 `best_not_above_start_executable_domain_covered` | §2.1 |
| 3 | **跨 tick 域不可执行**：**21 / 36** 条的深度上限比单 tick 上限大 **2.4× – 30×**，但 Review Manager 的单 tick 门会以 `final_input_exceeds_single_tick_capacity` 拒绝超出单 tick 容量的最终输入 ⇒ 该域**藏不了可执行套利** | §2.2 |
| 4 | **★ 真正的缺陷在别处**：被算作「当前闭环」的复核里，有 **7 / 36** 条来自**陈旧代次**（`closedLoopVersion 54` vs 当前 **72**、`poolScopeChecksum` `sha256:9987e6cc…` vs 当前 `sha256:9ec36f1a…`、`candidateEdgeVersion 11` vs **17**、`observationVersion 14` vs **20**），`reviewed_at` 在 **2026-11-26 19:28–19:29**（**收窄作用域时期**） | §3.1 |
| 5 | **缺陷点 ＝ 复核层的「当前」口径只按 loop key 匹配** ⇒ 8 条陈旧代次复核被当成在产复核，贡献了 `matchedMissingPnl = 0` / `bestAmountMissing = 0` ⇒ **复核层报绿，而这些路由从未对当前池集测过价** | §3.2 |
| 6 | **第二个缺陷 ＝ 证据回写会「洗代次」**：`stored_review_evidence()` 不带 `closedLoopGeneration` ⇒ Review Manager 按「证据没写代次就用当前代次」归档 ⇒ **旧测量被重新贴上当前代次的标签** | §4.2 |
| 7 | **修复后复核层转为红**：`L4 reviews valid=False`、`productionState=review_stalled`、**原因 `a_closed_loop_does_not_carry_its_current_measurement`**、`blockers=[reviews, broadcast]` —— 这才是**诚实**的读数 | §4.4 |

> **诚实边界**：**没有伪造任何盈亏**、**没有填 0**、**没有放宽任何门禁**、**没有删任何历史复核行**。
> 「持续产生链上广播交易」**仍未达成**（无正利润复核 ⇒ 广播 attempts 恒 **0**，**市场条件**）。

## 2. 全负期望下的 tick 交易量比对（**用户第 3 步的补强**）

### 2.1 当前代次复核的实测读数（**2026-11-28 · 生产库只读**）

| 读数 | 值 |
|---|---|
| 在产闭环 | **36** 条（**108** 跳） |
| **当前代次**复核 | **29** 条（`closedLoopVersion = 72`） |
| 预期盈利为负 | **29 / 29**（`sum = -0.008950486957457295`） |
| **最佳交易量 > 单 tick 初始交易量** | **0 / 29** ⇒ **否** |
| **最佳交易量 ≤ 单 tick 初始交易量** | **29 / 29**（`bestAmountRaw` 全为 `0x0`，`initialAmountRaw` 全为正） |
| 探针级数 | **3 – 12** 级，金额跨 **0.001 → ~0.12**（**> 100×**） |
| 阶梯上行可达 | `min(2 × initial, 单tick上限)` |
| **可执行域缺口**（缺口 > 1 raw 单位） | **0 / 29** ⇒ `executableSizeUnsearched = 0` |
| 结论分布 | `best_not_above_start_executable_domain_covered` **29**；`best_above_single_tick_start` **0**；`tick_amount_unknown` **0** |

> **读法**：这条路由的**最佳交易量从来没有超过过单 tick 初始交易量**，
> 而且**可执行域已经被阶梯覆盖** ⇒ 「预期盈利为负」在**当前结构**上是**测出来的结论**，
> 不是「没测到」。**它不构成缺口，因此不触发复核重测**。

### 2.2 跨 tick（深度）域为什么**不能**藏可执行套利

| 读数 | 值 |
|---|---|
| 深度上限 > 单 tick 上限的条数 | **21 / 36** |
| 倍数区间 | **2.4× – 30×**（例：`SPY → ETH → MU → SPY` 单 tick **0.0601** ／ 深度 **1.8285** ＝ **30.43×**） |
| 合同侧事实 | 每一级阶梯上合约自身都 revert `NoProfitableRoute`（`revertSelector 0x16301234`） |
| 门 | `flashloan/tools/review_manager/src/lib.rs:3028` —— 最终输入超过单 tick 容量 ⇒ `final_input_exceeds_single_tick_capacity` ⇒ **不可执行** |

⇒ 深度域**超出可执行域**，它可以影响**报价**，但**不能**产生一笔**可广播**的交易。
因此**不把深度域列为缺口**；缺口只按**可执行域**（单 tick 容量）判定。

## 4. 修复清单（`M-8` · `scripts/mainnet_arbitrage_healer.py`）

### 4.1 代次判定

| 函数 | 作用 |
|---|---|
| `current_generation(manager_api)` | 读 closed-loop Manager 发布的代次指纹（闭环版本＋校验和、候选边版本＋校验和、观测层版本＋校验和、池作用域校验和） |
| `review_generation_status(row, generation)` | 比对 ⇒ **`current`** / **`stale`**（列出不匹配字段）/ **`unknown`** |
| `REVIEW_GENERATION_FIELDS` | 七个代次字段的**唯一**清单（发布名 ↔ 行内名） |

### 4.2 证据回写不再「洗代次」

`stored_review_evidence()` 现在把**该行自己的代次**复制进证据的 `closedLoopGeneration`：

```
closedLoopGeneration = {closedLoopVersion, closedLoopChecksum,
                        candidateEdgeVersion, candidateEdgeChecksum,
                        observationVersion, observationChecksum}
```

Review Manager 的口径是「**证据写了代次就按它归档，没写就按当前代次**」
（`flashloan/tools/review_manager/src/lib.rs:3504` 及其注释：
*relabelling the review would make an old measurement look like a fresh one*）。
healer 以前**没写** ⇒ 旧测量被**重新贴上当前代次的标签**。现在**写上**，旧复核就**保持旧**。

### 4.3 新增自愈动作

| 动作 | 触发 | 行为 |
|---|---|---|
| **`repair_stale_generation_reviews`** | `generation.readable` 且（`staleGeneration > 0` ∨ `unknownGeneration > 0` ∨ `loopsWithoutCurrentReview > 0`） | 对**没有当前代次复核**的在产闭环发起**新的实时复核**并 materialise（**走复核路径，绝不碰广播**） |
| **`repair_tick_amount`** | `tickAmount.executableSizeUnsearched > 0` | 对**可执行域有未搜尺寸**的闭环发起新复核并 materialise |

两条修复**都只发复核请求**，**都不碰广播**；「没有正利润复核 ⇒ 不广播」这条口径**没有被放宽**。
