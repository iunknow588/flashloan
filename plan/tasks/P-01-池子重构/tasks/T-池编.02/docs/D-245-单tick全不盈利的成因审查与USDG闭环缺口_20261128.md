## 6. ★ USDG 被整体跳过的根因链（本轮核心结论）

### 6.1 事实：USDG 本身完全健康

| 检查项 | 读数 |
|---|---|
| 代币库 | USDG（`robinhood:4663:0x5fc5360d0400a0fd4f2af552add042d716f1d168`）在 `token_core` **与** `token_extension` 两库中，admitted |
| 作用域池（core4） | USDG 相关池 **241** 个，其中 **active 5** 个：`0x319bac87e616`(fee 2500, deep)、`0x3bb34a44f1b2`(3000, deep)、`0x6fa3ee0048e7`(10000, deep)、`0xc105b8300ff6`(2400, medium)、`0xde9f85fdd9e0`(10000, deep) |
| 作用域池生效时刻 | 全部 `materialized_at = 2026-11-27T22:15:13.977846900Z`（**这一轮作用域重建时由 blocked/invalid 转为 active**） |
| 方向层（core4） | 上��� 5 个池**两个方向都是 rank 1、status=active**，费率 0.24%～1.0% |
| 方向层覆盖度（当前） | core4 作用域 **32 个 active 池 / 24 个 active 交易对 / 0 个「有池无排名」** ⇒ **方向层今天已经覆盖全部 24 对** |

⇒ **USDG 既不缺位数/符号，也不缺池子。** 它在候选代币库里，也在市场目录里。

### 6.2 事实：断点在候选边层

| 表（core4 作用域） | USDG 相关行 | 内容 |
|---|---|---|
| `manager_dex_candidate_anchor_tokens` | **8** | `yc_primary_pool_id = NULL`、`zc_primary_pool_id = NULL`（4 对 × 两个角色） |
| `manager_dex_candidate_pool_pairs` | **8** | `first_primary_pool_id = NULL`、`third_primary_pool_id = NULL`、`selection_basis = directional_pair_direction_rank` |
| `manager_dex_candidate_pool_recommendations` | **0** | 全表 104 行，**没有一行属于 USDG** |
| `manager_v4_closed_loop_skipped_tokens` | **8** | `no_completing_first_hop` × 4（anchor=USDG）、`no_completing_third_hop` × 4（candidate=USDG） |
| `manager_v4_closed_loops` | **0** | 36 条闭环的 `path_symbols_json` 只含 ETH / SPY / NVDA / MU / GOOGL / AMD，**USDG 一次都没出现** |

⇒ **候选边层把 8 个 USDG 交易对「发布出来了，但推荐集是空的」**：池数计了（`pool_count` 1～2），主池却是 NULL，推荐表里一行都没有。闭环层拿不到首/末跳候选，于是把 USDG 记成跳过。

### 6.3 ★ 因果链：重建链把消费方排在生产方之前

**2026-11-27 那一轮的全部物化时刻（UTC，取自各表自身的 `created_at`/`materialized_at`）**：

| 时刻 | 层 | 读数 |
|---|---|---|
| 22:15:13.979 | **作用域 core4 重建** | `pool_scope_config.last_rebuilt_at`；USDG 的 5 个池在此转为 active |
| 22:16:02.061 | 作用域 candidate_exchange 重建 | 同轮 |
| **22:17:32.402** | **候选边层**（candidate_version 17，recommendation_count 104） | 此刻读取方向层 ⇒ 读到的是**上一轮**的方向快照 |
| 22:17:32.582 | 观察层（candidate_exchange 作用域） | 同样读到旧方向快照 ⇒ 162 行 `optimal_pool_id = NULL` |
| **22:17:33.011** | **方向层**（core4，directional_pool_version 54） | **比候选边层晚 0.609 秒** ⇒ 这一轮才给 USDG 出 rank 1 |
| 22:18:01.477 | 闭环层（closed_loop_version 72） | 读到候选边层 v17（无 USDG 推荐）⇒ **8 条跳过记录** |

这 4 个时刻的顺序，与自愈编排器里写死的重建链**逐字一致**：

```python
# scripts/mainnet_arbitrage_healer.py（修复前）
MANAGER_REBUILD_CHAIN = (
    ("candidateEdge",      "/v1/candidate-edge-pools/rebuild"),      # 22:17:32.402
    ("candidateExchange",  "/v1/candidate-exchange-pools/rebuild"),  # 22:17:32.582
    ("directionalPools",   "/v1/directional-pools/rebuild"),        # 22:17:33.011  ← 生产方在后
    ("closedLoops",        "/v1/closed-loops/rebuild"),             # 22:18:01.477
)
```

而**候选边层与候选交换层读的都是方向层的排名**：

* `candidate_edge_pool_manager::read_directional_ranks` —— 从 `manager_v4_directional_exchange_pools` 读 `pair_direction_rank`；
* `candidate_exchange_pool_manager::read_directional_ranks` —— 同样从方向层读排名。

**⇒ 根因（一句话）：重建链把「读方向层的层」排在「写方向层的层」之前，候选边层因此用**上一轮**的方向快照发布；作用域里刚刚转 active 的 USDG 池在旧快照里没有排名，于是 8 个 USDG 交易对的推荐集为空，闭环层把「空推荐集」读成「市场没有候选」，USDG 全线出局。**

### 6.4 为什么它一直不自愈（三个「看不见」）

1. **候选边层不记录方向层版本**：`manager_dex_candidate_library_state` 只有 `pool_scope_checksum` 与代币库版本/校验和，**没有 `directional_pool_version` / `directional_pool_checksum`**。
2. **上游校验不覆盖方向层**：`candidate_edge_pool_manager::validate_expected_upstream` 只校验 `pool_scope_checksum` 与代币库版本/校验和 ⇒ 方向层落后一代**无人能看见**。
3. **闭环层的自检是绿的**：闭环层记的是 `directional_pool_version = 54`（**当前**版本，因为闭环层最后跑），`candidate_edge_version = 17`（也是当前版本，因为候选边层没再动过）⇒ 版本对得上，链条「看起来新鲜」。

⇒ 于是：**陈旧的不是某一张表，而是「候选边层用的那份方向排名」这一份派生数据**；它没有版本号，谁也检查不到它。

## 7. 修复（本轮已落地的代码）

* 没有任何方向层状态的库（从未跑过方向层的沙盒/测试库）**保持原行为**，不受影响。
