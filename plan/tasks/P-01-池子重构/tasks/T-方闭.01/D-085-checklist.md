# D-085 `T-方闭.01`｜备用池接线 · 测试目标 check list

**为什么单独立项**：已闭合·已归档 的裁定稿查出了**「备用池从未被消费」**这一实锤缺口

（裁定 §6.4）。它是**接线问题**，**不是阈值问题** ——

`optimizations` **456** 行**全部** `status='candidate'`、`temporary_override` **0 / 504**、

代码中**无任何** `candidate→active` 流转路径、`read_optimizations` 的 SQL **无 `WHERE status`**、

容量门禁失败即整条闭环 `continue` ⇒ **该表是「只写不读」的表**

⇒ **「最多 5 个候选」今天不起作用**（实测最大候选数仅 **4**）。



**验收前置**：`T-方授储.01` 闭合（备用池由方向层的**排序分层**产出）；

**必须早于** `T-方闭储.01`（否则 P2 验收时备用池仍是「只写不读」）。

**依据**：[**已闭合·已归档** 综合裁定与实施](../../docs/tec/D-012-TASK-166_综合裁定与实施_20261123.md) §5.2 / §5.3 / §6.4 / §7.1。



#### g.1 结构验收



- [ ] `optimizations` 的 `status` 存在**真实**的 `candidate → active` 流转路径

      （守卫须能**构造**该流转 ⇒ **非空洞**）

- [ ] `read_optimizations` 的 SQL **含** `WHERE status`（只消费**已生效**的候选）

- [ ] 容量门禁失败时**按序试下一个候选**（备用池），而**不是**整条闭环 `continue`

- [ ] **截断改分层**：落选池**留在备用池**，**不得**被丢弃

- [ ] `MAX_DIRECTION_CANDIDATE_POOLS` 的注释写明：**容量旋钮，不是阈值**



#### g.2 行为验收



- [ ] **恒等式**：`N == min(N_max, 合格池数)` 恒成立

- [ ] **不丢池**：同一 `(pair, direction)` 组内 **合格池数 == 候选数 ＋ 备用数**

- [ ] **序位连续**：候选序位 **1..N** 连续无缺号（保 **I-6**）；备用序位 **N+1..** 同样连续

- [ ] **顶替可判定**：同组内按主序键比较；主序键全同才比容量；再同则比 `pool_id`（**确定性**）

- [ ] **不得跨代币对**比较 `directional_output`（单位不同）

- [ ] 顶替后**重排序位**（否则出现两个序位 1 ⇒ 破坏 **I-6**）

- [ ] **不得**为凑够 `N_max` 而放宽任何准入判据（`DPO-11` 纪律 ②）

- [ ] **status 流转行数 ≠ 0** 的读数（接线**已生效**的直接证据）

- [ ] 容量不过时**下一个候选**被选中的对照读数



#### g.3 回归与边界验收



- [ ] 架构守卫全量通过（基线**只增不减**）

- [ ] 全量回归 **0 failed**（基线见任务清单 §7.2）

- [ ] **未**改动准入判据（`L1`）与排序主序（`L2`）的任何一条（`DPO-11`）

- [ ] **未**放宽任何门禁；**未**广播



#### g.4 与 `T-方闭储.01` 的关系（**顺序纪律**）



- [ ] `T-方闭.01` **闭合在** `T-方闭储.01` **之前**（否则 P2 的等价性验收**不含**备用池兜底能力）

- [ ] 若 `T-方闭储.01` 已开工 ⇒ `T-方闭.01` **让路**（两者都改 `closed_loop_manager` 的候选选择邻域）
