## 一句话

> **一轮复核要 5.4 分钟，不是线程不够** —— 链上读取被**单地址限速**卡在 **≤ 5 次/秒**
> （并发 **16** 只是让线程在限速锁上排队）；同时**投递**是串行的、**数据库每次操作**还要付 **13.8 ms** 的重开连接税。
> 本任务把**广播路由**从「组级标签一票否决」改成「**复核证明也能路由**」（没有证明时**仍然**要组级标签），
> 把**启动等待置 0** 改成**真的 0**（原来的 `or 16` 把「不等待」这个值吃掉了），
> 并把「广播仍然是 0」的原因定位到**具体闸门**（链上合约自己回退／容量小于最小探测量／tick 区间漂移）。

## 用户口径（本任务据此裁定的边界）

| 口径 | 落法 |
|---|---|
| 「**任何一个闭环，第二次复核出现结果，必然覆盖前一次闭环的结果**，这样，每个闭环**仅仅有一个当前的复核结果**」 | 承认为**系统语义**：复核行与广播请求**都是单槽**；本任务**不**引入「轮次」概念，也**不**把旧结果攒起来 |
| 「**盈利数据随时会失效**……让系统**启动时立即执行一次复核**更新过期数据」 | **启动即全量复核**：每扫描投递量**置 0** ⇒ 一次扫描把整个目录投进复核池 |
| 「**启动时等待时间置 0**，清理数据自动会开始的」 | 同上：**0 ＝ 不等待**（代码里 `0` 此前被 `or 16` 丢弃，**等于什么都没做**） |
| 「多复核工作线程并发，**不可能需要这么长时间**」 | 用**实测**回答：**不是**并发问题（并发 **16**，而链上读取速率先到顶）；瓶颈是**单地址限速** ＋ **串行投递** ＋ **重开连接** |
| 「确保系统**持续产生链上广播交易记录**」 | 链路已通（复核证明能进执行队列）；**仍为 0** 的原因是**市场/容量事实**，如实登记，不放宽判据 |

## 实盘读数（**2026-11-26 21:34–22:5x**）

| 项 | 读数 |
|---|---|
| 复核吞吐 | **32 次/分**（`reviews_done` **601 → 645** / **76 s**）⇒ 一轮 **≈ 5.4 min** |
| **等待 = 0 生效** | 当前实例（看护 **19888** ／ runtime **20656**，**22:05:01** 起）：`pendingTasks = 132` / `residentWorkers = 132` / `reviewQueue.claimed = 132` ⇒ **一次扫描把整个目录全量入组** |
| **清理自动开始** | `[review-stale] robinhood chain 4663: 73 of 174 closed loops went quiet, 0 broadcast requests withdrawn`（**每 scope 60 s** 一次） |
| 启动到第一条复核 | **8 min 19 s**（runtime **21:34:56** ⇒ 复核 **21:43:15**）＝ 第一代；**当前实例 8 min 2 s**（**22:05:01** ⇒ 复核 **22:13:03**）⇒ **两次一致**，且**不是**「等待参数」（等待**已是 0**） |
| 复核**行重写**速率 | **1 min** 内 **25** 行 ／ **2 min** 内 **47** 行 ／ **5 min** 内 **110** 行 ／ **10 min** 内 **142** 行 ⇒ **≈ 24 – 35 次/分**，**174** 行**一圈 ≈ 7 min** |
| 复核并发 | 算子 **48** ⇒ **生效 32**（Python `CLOSED_LOOP_WORKER_CEILING = 32` 截断）⇒ 实盘 `concurrencyLimit = 32`（第一代是 **16**）；Rust 上限 **256**，`.env` 未覆盖 |
| 覆盖语义（用户口径 ①） | 复核行**单槽**（**174** 行恒定），写入＝**`DELETE` ＋ `INSERT`** ⇒ 同一 `loop_key` 的 `created_at` 随复核前进 ⇒ **每个闭环只有一个当前复核结果** |
| 链上读取限速 | `execution.rs:55 throttle_rpc_call`，`DEX_RPC_MIN_INTERVAL_SECONDS = 0.2` ⇒ **≤ 5 次/秒**（**持锁 sleep**） |
| 端点实测 | publicnode **1.01 s**/次（单发）、quiknode **2.38 s**/次；**3** 个端点已废（**403**／DNS／**429**）；publicnode 在 **conc 32** 下 **10.47 次/秒**、**0 错误** |
| 数据库开销 | `query()` **13.8 ms** vs 原生 **0.22 ms**；剖面 **47%** 的 CPU 在「开连接 ＋ 解析路径」，**5%** 在真正的 SQL |
| 广播 | `manager_v4_review_broadcast_requests` **0 行**、`manager_cow_execution_attempts` **0 行**；`completed` **0**；正利润只有 **5** 行（**2** 行有 3/3 跳限值），量级 **1.2e-05** / **4.5e-07** USDG |

## 遗留（**不代任何其它任务关闭**）

| 编号 | 遗留 | 归属 |
|---|---|---|
| R1 | **单地址限速**（≤ 5 次/秒）＝ 一轮 **5.4 min** 的硬上限；提并发**无效** | `M-13` ＋ `M-7`（后续轮次） |
| R2 | **3 个 RPC 端点已废**（**403**／DNS／**429**）⇒ 故障切换每次都要先撞一次废端点 | `M-13`（后续轮次） |

| R4 | **正利润是灰尘级** ⇒ 即使门禁全通，一笔真实广播在手续费上也是**亏**的 | **市场条件**（不可由代码解决） |

| R6 | **Python 天花板 32 vs Rust 上限 256** 的不对称（算子 **48** 被截成 **32**）；**提并发不是提速杠杆**（实测 **16 → 48** 吞吐**不变**） | `M-13`（后续轮次） |
