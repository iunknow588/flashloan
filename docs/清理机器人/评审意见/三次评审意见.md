# 三次评审意见

日期：2026-07-30

本次评审聚焦 Aave v3 origin 对清算执行合约和机器人链下逻辑的影响。

## 1. 主要结论

当前方向可以继续，但必须将“可执行原型”升级为“可模拟、可回滚、可解释”的执行结构。

最关键的风险不是合约是否能调用 `liquidationCall`，而是链下参数是否符合 Aave v3.3/v3.7 后的真实清算规则。

## 2. 必须修正项

- close factor 不能硬编码，必须使用链上/数据 provider 估算值或静态模拟确认。
- liquidation rounding 对 liquidator 不利，利润模型必须增加 rounding buffer。
- 账户发现可以实时入库，但区块扫描进度必须保持连续。
- 账户注册表和健康度历史必须分表。
- 执行合约必须使用 SafeERC20。
- 主网真实提交前必须先做 callStatic。
- 需要 mainnet fork 测试脚手架，不再只依赖 mock。

## 3. 文档修正要求

- 新增 `14_AaveV3Origin对齐修正.md`。
- 在测试策略中补充 fork 静态模拟和 v3.7 rounding 边界测试。
- 在风控上线 checklist 中加入 callStatic、rounding buffer、close factor 验证。

## 4. 代码修正要求

- `contracts-bot` 合约迁移到 OpenZeppelin SafeERC20。
- `contracts-bot` 增加 fork 测试命令和跳过式 fork 测试文件。
- 增加静态模拟脚本，便于机器人提交前复用。
- 后续机器人侧增加清算执行 payload builder，将 `maxDebtToLiquidate`、`minCollateralSwapOut`、`minProfitAmount` 和 `swapPath` 结构化输出。

## 5. 验收标准

- mock 合约测试通过。
- fork 测试在提供 RPC 后可运行。
- 低利润交易必须回滚。
- 非 owner 调用必须回滚。
- 合约参数错误必须回滚。
- 文档与代码目录保持一致。
