# 最佳路线选择说明

整理日期：2026-10-07（测试网实测与主网只读预检已更新）

## 1. 设计意图

假设资金池代币为 A，与 A 相关的候选池 YC / ZC 选择了代币 B、C：

- A 到 B 共有 `x` 个有深度的池子；
- B 到 C 共有 `y` 个有深度的池子；
- C 到 A 共有 `z` 个有深度的池子；
- 固定三跳代币组合下，`A -> B -> C -> A` 的有池组合数为 `S = x * y * z` 条池子路径；
- `A -> B -> C -> A` 与 `A -> C -> B -> A` 是同一个闭环的两个相反执行方向，只能计为 1 条，不能计为 2 条；所有页面统一按 token 地址归一方向后去重；
- 闭环数量是链池索引与 V4 池动态变化的实时结果，不写死为某个固定值（例如 `44 / 200 / 500`），新增或删除池子都会改变 `S`。

因此需要解决的问题是：从 `S` 条路径中选择一条作为推荐路径。当前规则默认选择“每跳池子深度最大”的组合作为第一候选；后续在报价与路由页面发现盈利空间不足时，允许在候选池子之间自动换池，寻找更优秀的路径。

## 2. 当前工作流与数据归属

系统已经按以下五层职责拆分：

| 页面/阶段 | 保存的内容 | 当前实现 |
|---|---|---|
| 资金池 X | 可借贷资产与余额证据 | `flash_loan_pools` |
| 候选池 YC / ZC | 第一跳、第三跳的多个候选池 | `dex_pool_candidates` |
| 市场观察 | 第二跳的多个候选池、可达桥接对，不生成闭环 | `market_observation` |
| DEX 总览 | 实际形成 A-B-C-A 闭环路径、组合计数、粗测算 | `dex_overview` |
| 报价与路由 | 逐跳报价、最佳路线选择、候选替换 | `dex_quote_routes` |

候选池页面对第一跳（`x-y`）和第三跳（`z-x`）保留多份池子候选，并把“有深度且 TVL/深度最大”的池子作为第一优先级；市场观察对第二跳（`y-z`）保留多份桥接候选。市场观察页面不负责形成闭环，真正的套利闭环由 DEX 总览阶段基于这些候选构造，DEX 总览同样推荐第一优先级的深度池子。这些候选通过 `hopCandidates`、`hopCandidateCounts`、`hopCandidateCombinationCount`、`poolPathKey` 字段从 DEX 总览透传到报价路由页，因此报价与路由页面拿到的默认闭环就是候选池 → 市场观察 → DEX 总览一路推荐下来的第一优先级闭环。

**硬约束：DEX 总览是闭环的唯一形成层，报价与路由页面不得自行重建闭环。** 报价与路由页面只能复用 DEX 总览已经形成的 `arbitragePaths`，不能基于市场观察或候选池重新构造 `A -> B -> C -> A` / `A -> C -> B -> A`。如果上游没有形成闭环，应当在候选池、市场观察或 DEX 总览阶段解决问题，而不是让报价与路由页面绕过上游自行拼环。

## 3. 第一候选池选择

当前默认选择策略是 `tvl_depth_desc`：

- 每一跳先按“是否有可用流动性证据”排序；
- 可用池子内按 `TVL / 深度` 降序排列；
- 每一跳第一行作为默认工作池；
- 候选池列表仍然完整保留，供报价路由阶段换池。

候选池页面选出“深度最大的池子”作为第一优先级后，市场观察与 DEX 总览不再重新挑选其他池子，而是继续使用这一第一优先级池子构造闭环；报价与路由页面收到的默认闭环就是这一推荐闭环。

选择入口：

- `_select_best_pool_rows(...)` 的 `selector` 参数；
- `_hop_candidate_sets_from_pairs(...)` 的 `selector` 参数；
- 后续若需要改为“利润感知选择器”，只需注入新的 `selector`，不需要修改候选池生成流程。

### 3.1 候选池代表性缓存规则

候选池缓存允许限制为每对 `X` 个池，但缓存数据必须保留足够的代表性，不能只保留深度最大的几个：

- 每对 token 必须保留一个深度最大的池子；
- 每对 token 尽量保留一个最高价池子和一个最低价池子，作为价格区间上下沿；
- 其余槽位优先保留有流动性的池子，按深度降序、费率升序填充，尽量保留低费率池；
- 若某对 token 当前没有深度池，则从已索引池中按同一规则选出代表池，避免历史无深度池把页面撑到数万行；
- `X` 是“每对候选池缓存上限”，不是闭环数量硬编码。当前实现为每对最多 6 个池，主网静态候选缓存按五锚点 `ETH`、`WETH`、`USDG`、`USDE`、`TZ` 裁剪，规模保持有界；新增或删除链上池子会改变闭环数量，但候选缓存规模保持有界。

## 4. 报价与路由页面的最佳路线判断

报价与路由页面通过 `dex_overview_payload(...)` 拿到 DEX 总览已经形成的纵览路径，然后复用其中的 `arbitragePaths` 做报价分析；它不会再次调用闭环重建函数（`_route_framework_context_from_observation`），也不会从市场观察的快照中重新推出 `arbitragePaths`。代码中 Robinhood 报价路由入口 `_quote_routes_payload_for_robinhood_family` 和非 Robinhood 报价路由入口都只调用 `build_quote_routes_payload_from_overview(dex_overview_payload(...))`。该行为已通过 `test_quote_routes_consume_overview_without_rebuilding_closed_loops` 固化为回归约束。

对 DEX 总览传来的路径，报价路由会先对当前默认深度路径做报价分析：

1. 若当前路径已有正向盈利预期（`profitable = true`），直接保留当前深度首选路径；
2. 若当前路径没有正向盈利预期，则进入候选池替换搜索；
3. 替换搜索只基于已保存的 `hopCandidates`，不会重新遍历全量池子。

**约束：报价与路由页面不以深度作为替换优先级。** 池子替换只在推荐的第一优先级闭环没有利润时触发，并且只以价格/输出证据对候选池排序；即使某个候选池深度更大，只要其价格/输出不更优，也不会被选为替换池。DEX 总览路径会携带 `recommendedFirstPriority=true`，报价与路由页面只允许对这类第一优先级推荐闭环执行替换。

当前实现的替换算法：

- 路径方向可以是 `A -> B -> C -> A` 或 `A -> C -> B -> A`，统一用相对腿 `x-y`、`y-z`、`z-x` 表示；
- 只在每一跳都保留有流动性候选池的前提下进行替换；
- 默认只替换首尾两跳：`x-y` 与 `z-x`；
- 假设当前最佳路线为 `A -> B -> C -> A`，则：
  - 从 `A -> B` 的有流动性候选池中选择“价格/输出最优，可兑换出最多 B”的池子；
  - 从 `C -> A` 的有流动性候选池中选择“价格/输出最优，可兑换出最多 A”的池子；
- 反向路径 `A -> C -> B -> A` 使用同样规则：首跳选择可兑换出最多 C 的池子，尾跳选择可兑换出最多 B 的池子；
- 第二跳默认保持当前首选池，后续可通过注入 `replacement_selector` 扩展为任意一跳或多跳联合替换。

由于真实报价可能需要链上 Quoter，默认输出排序只读取池子已保存的 `quoteSummary` 输出/价格字段；如果候选池还没有静态价格证据，报价与路由页面也**不会退回到深度排序**，而是保留全部有流动性候选池生成有界变体，最终由 `route_quote_analysis_fn` 按实时报价价格/利润评估选择。替换搜索数量有上限，避免 `x * y * z` 组合爆炸。替换得到的路径是临时闭环，后续链上复核与链上广播交易都使用该临时闭环执行。

### 4.1 临时路径生命周期

候选替换选出的路径是报价与路由页面的**临时路径**，不是系统的全局默认路径：

- 替换结果只在当前报价/路由请求的本地 `route` 快照中生效，不写回 DEX 总览的 `arbitragePaths`，也不修改候选池或市场观察保存的候选集合；
- 临时路径会携带 `temporaryRoute=true`、`notForDefaultScan=true`、`executeLast=true`，并保留原始默认路径的 `referencePoolPathKey`；
- 扫描器去重时保留默认路径与临时路径为独立族，临时路径不会被提前删除，但也不会覆盖同 token 路径下的默认路径；链上复核按 `poolPathKey` 隔离临时路径，不复用默认路径的组缓存证据；
- 自动执行阶段会把默认路径排在前面，临时路径排在最后执行；
- 临时路径执行后只写入执行历史记录（`cow_execution_attempts` / `dex_route_test_recorder`），下次扫描仍从 DEX 总览的默认深度路径重新开始，不会把已执行的临时路径作为默认候选；
- 扫描器快照合并时会优先保留非临时默认路径，避免临时路径证据覆盖默认路线。

## 5. 接口设计

新增的候选替换模块提供以下接口：

```text
output_leader_pool_ids(route, ...)
    根据价格/输出证据为指定腿选出候选池 ID，不使用深度排序。

replacement_route_variants(route, ...)
    生成有界的候选替换路径，默认替换 x-y、z-x。

build_route_variant(route, ...)
    把选中的池子写回 routePools / executionPools /
    preferredPools / strictQualityPools 与 hopCandidateSelection。

maybe_replace_route_with_better_candidates(...)
    报价路由入口：无盈利时评估候选变体，选择净利更高的路径。
```

`maybe_replace_route_with_better_candidates` 支持注入：

- `route_quote_analysis_fn`：候选变体的报价评估函数；
- `route_size_analysis_fn`：选中变体后的规模测算函数；
- `replacement_selector` / `output_selector`：未来替换为真实逐池报价排序；
- `replacement_legs`、`candidate_pool_limit`、`max_variants`：替换范围与数量上限。

## 7. 测试网实测与主网只读预检

### 7.1 测试网闭环结果

测试网（`46630`，RPC `https://rpc.testnet.chain.robinhood.com/rpc`）当前临时缩容为“稳定币 + `ETH` + `TZ`”，非稳定币只保留 `ETH`、`TZ` 两个池子，与主网形态保持一致。缩容只限制候选范围，不限制闭环数量；候选池、市场观察与 DEX 总览仍随链上 V4 池动态扩展。

本轮数据核对结果：

- 候选池页面按该范围命中 `2` 个直接交易对：`ETH -> USDT`、`ETH -> FRAX`；
- 市场观察同步查找范围代币之间的第二跳桥接池（如 `USDT -> FRAX` 或 `FRAX -> USDT`）；
- 当前链上 V4 池证据中不存在范围代币之间的稳定币-稳定币或 `TZ` 桥接池，因此 `DEX 总览 -> 报价与路由` 当前均为 `0` 条闭环，这是数据自然结果，不是过滤或数量上限导致；
- 已修复一个地址大小写敏感的 scope 匹配问题：此前 `_row_uses_observation_scope` 直接比较原始地址，混合大小写地址会被误排除，现已统一按小写地址匹配。

上一轮未缩容的全量测试网快照曾形成 `107` 条闭环（例如 `ETH -> AMD -> NFLX -> ETH`），当时验证了 `dex_overview_payload` 与 `dex_quote_routes_payload` 数量一致。缩容后若要继续演示算法，需要先在测试网为至少一对范围代币补充有流动性的桥接池（例如稳定币之间的 V4 池，或 `TZ` 对稳定币/`ETH` 的池子）。本轮没有执行任何测试网广播交易。

### 7.2 主网只读预检

Robinhood 主网（`4663`）只读预检结论：

- 链配置与 RPC 只读探测通过；
- `executionEnabled=false`、`broadcastEnabled=false`；
- 主网候选池缓存按五锚点 `ETH`、`WETH`、`USDG`、`USDE`、`TZ`（`TA`、`TB` 仅作为桥币）裁剪，保留最大深度、最高价、最低价，低费率池优先；
- 候选池静态缓存先过滤固定费率，再读取实时 V4 `Pool.State`；固定费率且实时 `liquidity > 0` 的池才会进入候选池页面与闭环构建；
- 当前候选缓存为 `41` 个池，市场观察 / DEX 总览 / 报价路由当前一致性为 `4` 条闭环，每条闭环的三跳池都携带实时 `liquidity`、`hasLiquidity=true`、`usableForObservation=true`；
- 闭环中任何一跳若没有深度，不会被放入闭环，因此会出现 `0` 条闭环或闭环数少于静态候选组合数，这是数据自然结果；如果出现某条闭环中 `usableForObservation=false` 或 `hasLiquidity=false`，应修复该边候选池 / 市场观察的深度来源，而不是让报价路由自行重建或忽略深度条件；
- 主网批量 `eth_call` 可能返回 `429`；候选池重建工具 `build_robinhood_mainnet_static_candidates.py` 支持 `--rpc-url` 指定备用 RPC，并在批量读取内按小 batch 处理，失败自动切换下一个已配置 RPC；
- 闭环数量是链池索引与 V4 池动态变化的实时结果，不写死为 `44 / 200 / 500`；
- 主网 DEX 发现证据、实时报价证据、执行器验证、闪电贷提供方与 fork 模拟均未通过，`dex_discovery`、`live_quote`、`execution`、`liquidation` 阶段为 `blocked` / `not_started`；
- 本轮主网只做了只读预检，未执行任何广播。


主网“测试”的正确边界是：先补齐主网池发现、实时 Quoter、执行器与闪电贷提供方证据，并在安全预检通过后才进入真实广播阶段；在此之前只允许只读预检与静态候选复核。

## 8. 2026-10-08 五锚点、页面职责与分片约束确认

本节是当前代码实现的最新口径，历史章节中的旧表达以本节为准。

### 8.1 主网五锚点

主网资金池固定为 5 个代币：`USDG`、`USDE`、`ETH`、`WETH`、`TZ`。候选池只以这 5 个为资金池锚点；`TA`、`TB` 不再做任何特殊处理，它们是依赖候选池子动态发现的普通桥币。`TA/TB/TZ` 不是套利目标，只用于测试发现问题，因此不会在代码里写死 TA/TB 专用逻辑。

资金池主文件必须持续保留这 5 个锚点：

- `borrowableSymbols = [ETH, WETH, USDG, USDE, TZ]`；
- `observationAnchorSymbols = [ETH, WETH, USDG, USDE, TZ]`；
- 不允许再混入 `ETH:USDG` 之类的复合符号，也不允许回落成旧的 27 锚点集合。

### 8.2 页面职责与互斥

1. 资金池与候选池是同一个描述面的两种视图，同一时间只能选中一个标签。资金池是静态文件，描述第一条和第三条链支持的第一/第三跳代币种类；候选池在前者基础上动态增加 `YC/ZC` 代币集合。两者由池子流动性共同决定，因此候选池中的代币与资金池代币之间必然存在流动性池。
2. 市场观察在 `YC/ZC` 之间构建池子，按资金池代币分组列出该锚点下 `YC/ZC` 的全部有深度交易池，含动态费率/特殊费率池，并明确标注 `dynamicFee`、`specialFee`。市场观察不负责形成闭环。
3. DEX 总览只挑选固定费率且有流动性的池子，构造并汇总全部推荐闭环；任何一跳缺深度或不是固定费率，都不会进入闭环。
4. 报价与路由页面只复用 DEX 总览已经形成的闭环，不能自行重建闭环。默认收到的是按深度第一优先级推荐的闭环；当推荐闭环没有正向盈利预期时，才在 `hopCandidates` 内按价格/输出优先替换，生成只存在于本页面的临时路径。

### 8.3 强制分片

`observation.json` 和 `overview.json` 都是紧凑索引，行数据写入独立的 `shards-observation/`、`shards-overview/`，主文件不再保留大列表副本。旧完整 JSON 备份不再参与加载，也不保留为兼容路径。

### 8.4 四个问题的当前确认结果

1. 候选池页面：已按 5 个资金池锚点提供全部第一跳/第三跳代表池。当前主网缓存为 5 个 anchor group、29 个直接 pair、41 个代表池，均来自静态文件，不再出现 27 个旧锚点或 2.4 万行池。
2. 市场观察页面：已提供 5 个锚点下的完整 YC/ZC 集合，并给出有深度池的全部 45 个 bridge pair、60 个有深度池，其中 20 个为特殊/动态费率池，均已显式标注。候选池 `YC/ZC` 由池子动态发现，不再依赖 YC/ZC 相关性过滤，也不与候选池构成循环依赖。
3. DEX 总览页面：第二跳 `YC-ZC` 池取自市场观察的完整深度序列，但只有固定费率且有流动性的三跳池进入闭环。当前主网为 4 条闭环，每条闭环三跳均带 `hopCandidates`、`recommendedFirstPriority=true`、`routeRecommendationBasis=tvl_depth_desc`。
4. 报价与路由页面：从 DEX 总览分片读取全部 4 条推荐闭环，不会自己重建闭环；闭环数量随链上池动态变化，不硬编码为 44 或任何固定值。

那 4 条闭环是对当前固定费率+流动性子图的真实结果，而不是“只能两条”：

- `ETH -> USDE -> USDG -> ETH`
- `USDE -> ETH -> USDG -> USDE`
- `USDG -> ETH -> USDE -> USDG`
- `TZ -> TB -> TA -> TZ`

`A -> B -> C -> A` 与 `A -> C -> B -> A` 仍按同一条闭环处理，页面统一只计一次。其他中间代币（如 PEPE、SAEGIS 等）虽然市场观察里有深度池，但其它两跳不满足固定费率+流动性，所以当前不构成闭环；这是图数据结果，不是截断或硬编码。
