## 新增或修改流程

1. 先写/改单测，保证不依赖真实 RPC；网络类能力用 mock 验证 payload 形状。
2. 跑对应测试文件，再跑全量单测。
3. 扩了架构边界时，检查 `test_architecture_guards.py` 里的
   `transitional_cross_imports`、文件行数和禁 import 列表。
4. 改了 Rust 后先 `cargo test`，再本地 `maturin develop --release` 验证 Python
   能导入 7 个执行原语。
5. 涉及页面闭环时，重跑
   `test_dex_surface_payload_apis_are_distinct`。
6. 最后按 Acceptance Record 的命令逐条验收并更新文档。

## Rust 构建

```powershell
# 本地验证
.\flashloan\rs-src\scripts\build_release.ps1 -Target develop

# 发布 wheel
.\flashloan\rs-src\scripts\build_release.ps1 -Target wheel

# 导入检查
python -c "import flashloan_rs; print(flashloan_rs.__name__)"
```

`pyproject.toml` 已固定 `maturin>=1.5,<2.0`。命令行默认是 develop，用于本机
`python -c "import flashloan_rs"`；wheel 用于打包。构建脚本会打印 Python、
Rust、maturin 版本，发布时把版本写进记录。

Rust 不可用的机器上 `rust_available()` 返回 False，Python 只保留只读/显式兼容
分支，不提供 Python 写库回退。
