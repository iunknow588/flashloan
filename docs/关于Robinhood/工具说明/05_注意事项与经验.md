# 注意事项与经验

## 协议范围

- 当前版本只支持 Uniswap V4，其他 DEX/借贷协议下一版本再支持。
- 页面、广播、闭环都只认 `protocol=uniswap_v4`。
- Morpho 只做只读调研，`observation_only=true`，不进入 static-call 或自动执行。

## 安全边界

- 主网 `4663` fail-closed：外部 evidence 和 readiness 未齐之前
  `broadcastEnabled=false`，禁止主网广播。
- 主网证据与测试网证据必须隔离，主网模块不得读取测试网 evidence。
- Rust 不可用时仅保留只读/显式兼容分支，不提供 Python 写库回退。
- 广播文件不允许顶层 `import eth_account`；`Account` 只允许出现在函数内的
  Rust 不可用分支。

## 增量刷新与方向回填

- 增量刷新不回旧区块的前提是：数据库里所有池都有明确流动性快照，且没有残留
  零流动性的“锚点代币”池。数据库为空或全零流动性时，守卫会强制全扫描。
- 真实零流动性的池应在刷新后删除，否则一个无流动性锚点会让整条链回刷。
- 方向定义固定为：正向 `小地址 -> 大地址`，反向 `大地址 -> 小地址`。
- 每个方向的目标是 5 个活跃候选池 + 1 个推荐池；作为物理池，一个池同时服务
  正反两个方向，跨方向要去重。
- 回填从最新区块向前检索；每个方向凑满 5 个活跃候选就停止；一直找不到时，
  最多检索到池创建区块（SQLite 中已存的最早 Initialize 块）就终止。
- 反过来，不要因为某个 provider 不能查大范围就把全局步长缩小。先轮换 provider，
  全部失败再按 `min_chunk_size` 减半，并重新计算分段起点。
- 测试网官方/publicnode RPC 不稳定时，把 evidence 标记为阻塞项，等 RPC 稳定
  再跑，不要在真实链上做无限重试。

## 冷导入性能

- 纯 SQLite 重建（`skip_index=True, skip_liquidity=True`）必须零 RPC。
- 目标 `<2s`；实际 2026-10-17 为 8.27s，已按用户确认归档为非阻断优化项，不
  阻塞安全/evidence 任务。

## 改动纪律

- 不新增 SQLite schema、页面字段或 public API payload。
- 不把页面刷新建入业务表；页面只读。
- 新文件加入架构守卫的 `transitional_cross_imports` 或行数白名单时要同时补
  guard 断言。
- 网络类测试用 mock RPC 验证 payload 形状，不依赖真实链。
- 验收命令全跑完后，再拆分提交：代码、测试、文档、evidence/gitignore 清理。
