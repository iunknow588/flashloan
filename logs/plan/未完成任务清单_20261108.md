## 1. 状态与范围

### 1.1 状态定义

| 状态 | 含义 |
|---|---|
| `待开始` | 已拆解出可执行内容，尚未开始实施 |
| `进行中` | 已有代码、分析或部分证据，但未达到完成标准 |
| `部分完成` | 工程、临时库或 shadow 已完成，生产 authority/运行验收未完成 |
| `阻塞` | 前置任务、authority 或运行态不可用，当前不能进入验收 |

任务只有在依赖满足、证据包完整且全部完成标准通过后，才能移入已完成归档。

### 1.2 证据等级

| 等级 | 典型证据 | 可证明的边界 |
|---|---|---|
| `工程` | `py_compile`、单测、Rust `fmt/check/test` | 代码契约和局部行为；不能证明生产已加载或已迁移 |
| `隔离` | 临时库、copy DB、dry-run、shadow、compare-only | 迁移或切换方案可执行；不能证明生产 authority 已变化 |
| `生产` | 维护窗口 apply、rollback、服务重启加载、生产只读复核 | 指定 PID、authority、版本和 checksum 下的生产行为 |
| `观察` | 连续窗口、30 分钟 JSONL、错误率和资源采样 | 指定时间窗口内的稳定性；窗口外的结论需重新采集 |

同一任务可以依次取得多种证据，但低等级证据不能替代高等级证据。当前
`P0-2.3` 的 `138 passed` 和 `P0-2.5` 的 `20 passed` 都只属于工程证据。

- Testnet `46630` 仅用于隔离回归，不进入主网覆盖率和生产验收数字。

## 7. 统一执行与证据模板

每项任务按以下顺序执行：

1. 只读基线：记录任务、scope、authority、数据库路径、schema、SHA256、数量、
   进程和观察窗口。
2. 依赖检查：确认前置任务、上游版本和 authority；不满足时标记阻塞，不绕过。
3. 隔离验证：单测、临时库、copy DB、compare-only 或 shadow；保留失败证据。
4. 受控写入：只在维护窗口执行 apply；先记录备份、checksum 和回滚命令。
5. 后置复核：重算数量、checksum、终态、孤儿、缺失和 scope 越界。
6. 证据登记：记录命令、退出码、开始/结束时间、success/failed/pending/idle 和
   异常处置。
7. 归档同步：完成项进入 `back/已完成任务归档_20261107.md` 或后续连续归档，
   并从本清单删除。

证据包至少绑定：

```text
task
scope
authority
databasePath
schemaVersion
databaseSha256
command
exitCode
windowStart
windowEnd
result
exceptionDisposition
```

失败停止条件：

- scope 不完整、混入其它 network/chain/protocol/market。
- source report、数据库或 schema checksum 不一致。
- 重复方向键、无法解析地址、跨 scope 冲突或无法证明一对一路径。
- copy DB 与生产前基线不可解释差异。
- rollback 未演练或 checkpoint 无法恢复。
- PnL 缺值、单位或来源不完整时尝试广播。
- Manager 不可用却回退业务 SQLite 或生成可写命令。
